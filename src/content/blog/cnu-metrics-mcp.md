## 起因

我经常要查诚勤指标中枢的数据。今天看看这学期有多少门课上了平台，明天看看某个学院的活跃教师数，后天要给某个系统做汇报，得把十几个指标的值凑齐。

平台有 OpenAPI，但每次都走同一套流程：sha1 签名换 token，token 会过期，接口偶尔抽风要重试，返回的 JSON 动辄几万行。这些逻辑我写过好几个探针脚本，散在项目的各个角落，每次用还得翻出来改改。

本质上是重复劳动：签名、重试、翻页、裁剪，每份探针都在重写一遍。而平时干活主要靠 AI 助手（Trae），让它直接读这些脚本再现场改，一来一回也费劲。

所以思路很自然：把这些调用逻辑沉淀成一个 MCP 服务器，让 AI 助手能直接调，我只负责说「查一下 XX 指标昨天的值」。

## 做了什么

仓库叫 [cnu-metrics-mcp](https://github.com/na57/cnu-metrics-mcp)，TypeScript + 官方 MCP SDK，两个依赖（SDK 和 zod），编译出来一个 stdio 进程，注册到 Trae / Claude Desktop 都能用。

只做了 5 个只读工具，覆盖查数的完整链路：

| 工具 | 干什么 |
|------|--------|
| `list_scenes` | 列出全部已发布场景（带 10 分钟缓存） |
| `list_metrics` | 按场景查指标清单，找到指标编码 |
| `get_metric_values` | 指标取值，支持过滤和多指标批量 |
| `get_metric_detail` | 指标明细数据（列 + 行 + total） |
| `get_dim_field_values` | 查某字段有哪些去重取值，用来拼 filters |

典型流程就是：列场景 → 找指标 → 取值。维度值拿不准时先查明细和去重值再拼过滤条件。

## 几个踩过的点

- **签名**：`sha1(username + secret + nonce + curTime)` 换 token。token 缓存起来并提前 60 秒判失效，业务请求撞到 401 就强制重取再重试一次，AI 调用方完全无感。
- **网络抖动**：ECONNRESET 这类瞬时错误按 200/600/1500/3000ms 退避重试；超时则不重试，直接报错——干等 45 秒再重试一遍没有意义。
- **输出裁剪**：MCP 的返回会进对话上下文，大 JSON 很烧 token。批量取值每个指标截断 100 行、指标释义截 160 字、去重值上限 200，够用就好。
- **文档不可全信**：接口手册和实际行为有出入（比如 detail 去重字段的参数名实际是 `columnAlias`），全部以真实平台实测为准，E2E 测试直接连真环境跑。

## 现在的效果

配置到 Trae 之后，原来「翻脚本 → 改参数 → 跑代码 → 复制结果」的流程，变成一句话的事。取值、对数、凑报表，AI 自己会走 list_scenes → list_metrics → get_metric_values 这条链。

代码已开源：[na57/cnu-metrics-mcp](https://github.com/na57/cnu-metrics-mcp)。里面没秘密，凭证全走环境变量，仓库里只有 `.env.example` 占位符，clone 下来填好配置就能用。

一个教训：那些「写过好几次、每次都是抄来抄去」的胶水代码，就是最该抽成工具的东西。探针脚本时代可以翻篇了。
