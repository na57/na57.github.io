主线

指数爆炸逼出两张入场券，两张券换来每个子问题只算一次

1动机：方案数指数增长，枚举与朴素递归双双爆炸
2结构：发现最优子结构 ＋ 重叠子问题（两张入场券）
3机制：状态设计 → 转移方程 → 记忆化 / 自底向上填表
4结果与代价：每个子问题只算一次；但状态设计无公式可循
这条链就是本章目录：钢条切割（环1）→ 两张入场券（环2）→ 矩阵链乘、LCS、记忆化对比（环3）→ LIS 反例（环4）。
动机

钢条切割：爆炸的不是问题难度，是同一子问题被算了又算

长度 i1234
价格 pᵢ1589

长度 4 共 $2^{3}=8$ 种切法：不切得 9，1+3 得 9，2+2 得 10（最优，r₄=10）。一般地有 $2^{n-1}$ 种。

$$r(n)=\max_{1\le i\le n}\bigl(p_i + r(n-i)\bigr),\quad r(0)=0$$
$$T(n)=1+\sum_{j \lt n}T(j)=2^{n}\ \Rightarrow\ n=4:\ 16\text{ 次调用}$$
n=4 的 16 次调用里，r(2) 被算 4 次、r(1) 被算 8 次；不同子问题只有 n+1 个。存答案、只算一次，指数变线性——这就是 DP 的起点。
定义

能进 DP 大门的两张入场券：最优子结构 ＋ 重叠子问题

🎫 入场券一 · 最优子结构（Optimal Substructure）
最优解内部包含子问题的最优解。证明套路＝剪切—粘贴：假设子解不最优，换上更优的，原解被改进，矛盾。
🎫 入场券二 · 重叠子问题（Overlapping Subproblems）
递归树中不同子问题只有多项式个，且同一子问题反复出现——缓存才有命中机会。钢条切割：仅 n+1 个。
$$\text{DP 可行性}\;\boldsymbol{=}\;\text{最优子结构（正确性）}\;\boldsymbol{+}\;\text{重叠子问题（效率）}$$
判定两步走：① 写递归式，剪切—粘贴验券一；② 数不同子问题个数（由参数取值范围决定），多项式则券二成立。
反例

缺一张券就报废：最长简单路径缺券一，归并排序缺券二

❌ 无最优子结构：最长简单路径
✅ q→t 最长简单路径经过 r，不代表 q→r 段是最长的——两段绕路可能共享顶点，拼起来不再简单，子问题不独立，剪切—粘贴失效（实为 NP 难，见第10章）。
❌ 无重叠子问题：归并排序
✅ 每次拆出的子数组内容互不相同，不同子问题每个只出现一次，缓存零命中、白耗空间——分治不需要存答案。
边界口诀：券一管「拼得对」（正确性），券二管「存得值」（效率）。判定重叠看参数取值，不看参数大小。
设计

矩阵链乘：状态记区间，转移枚举「最后一乘」的位置

链 A₁A₂…Aₙ，维度序列 ⟨p₀,p₁,…,pₙ⟩，Aᵢ 是 pᵢ₋₁×pᵢ 矩阵。目标：总标量乘法次数最少的加括号方案。

$$m[i][j]=\min_{i\le k \lt j}\Bigl(m[i][k]+m[k+1][j]+p_{i-1}\,p_k\,p_j\Bigr),\quad m[i][i]=0$$
📐 状态读法：子问题是区间 [i,j]；决策是最后一乘的位置 k；s[i][j] 记最优 k，用于重构。
🧭 填表顺序：按链长 ℓ = 2,3,…,n 递增（沿斜线），因为长链只依赖短链——依赖关系决定顺序。
手算

⟨30,35,15,5,10⟩：先填满链长 ℓ=2 与 ℓ=3 的格子

① ℓ=2（相邻两矩阵，只有一乘）

$$m[1][2]=30{\cdot}35{\cdot}15=\boldsymbol{15750}\quad m[2][3]=35{\cdot}15{\cdot}5=\boldsymbol{2625}\quad m[3][4]=15{\cdot}5{\cdot}10=\boldsymbol{750}$$

② ℓ=3 · m[1][3]：枚举 k=1,2，取小

$$k{=}1:\ 0+2625+30{\cdot}15{\cdot}5=\boldsymbol{4875}\ \checkmark \qquad k{=}2:\ 15750+0+30{\cdot}35{\cdot}5=21000$$

③ ℓ=3 · m[2][4]：同样枚举

$$k{=}2:\ 0+750+35{\cdot}5{\cdot}10=\boldsymbol{2500}\ \checkmark \qquad k{=}3:\ 2625+0+35{\cdot}15{\cdot}10=4375$$

手算

ℓ=4 定全局：最优 4000 次，最差 27000 次，差近 7 倍

① ℓ=4 · m[1][4]：枚举 k=1,2,3

$$k{=}1:\ 0+2500+1500=\boldsymbol{4000}\ \checkmark\quad k{=}2:\ 15750+750+10500=27000\quad k{=}3:\ 4875+0+4500=9375$$

② 用 s 表回溯括号方案：s[1][4]=1 → A₁·(A₂A₃A₄)；s[2][4]=2 → (A₂)·(A₃A₄)

$$\boldsymbol{(A_1\,(A_2\,(A_3\,A_4)))}\quad\text{共 } \boldsymbol{4000} \text{ 次；最差 } ((A_1A_2)A_3)A_4=27000$$

③ 复杂度：填 $\Theta(n^2)$ 个格子、每格枚举 $O(n)$ 个 k → 时间 $\Theta(n^3)$，空间 $\Theta(n^2)$。

设计

LCS：双前缀状态，末尾相等取左上 +1，不等取两侧最大

X = ⟨x₁…x_m⟩，Y = ⟨y₁…y_n⟩，找最长公共子序列（不要求连续）。设 c[i][j] = X 前 i 字符与 Y 前 j 字符的 LCS 长度。

$$c[i][j]=\begin{cases} c[i-1][j-1]+1 & x_i = y_j\\ \max\bigl(c[i-1][j],\,c[i][j-1]\bigr) & x_i \ne y_j \end{cases}\qquad c[0][j]=c[i][0]=0$$
🔑 口诀：相等取左上 +1，不等取两侧最大。相等时这对字符必可同时收入最优解。
💡 看到「两个序列对齐比较」（编辑距离、diff、序列比对），先想双前缀状态 c[i][j]。

实现

记忆化与填表渐近相同，差别只在常数、空间与「算哪些」

维度自顶向下记忆化自底向上填表
思维负担低：递归式即代码高：须设计依赖顺序
常数开销递归调用 + 缓存查询纯循环，更省
实际求解的子问题只算真正用到的全部算一遍
空间优化难可滚动数组压缩
适用场景状态稀疏、原型验证状态稠密、性能敏感
渐近相同：都 = 不同子问题数 × 单点转移代价。口诀：面试写记忆化，生产写填表。注意：重构方案需要历史值，滚动数组会丢。
反例

LIS 经典错误：只记长度的状态，连转移函数都写不出来

问题：最长递增子序列（LIS）。失败的设计：dp[i] = 前 i 个元素中 LIS 的长度，试图从 dp[i−1] 推出 dp[i]。

前缀 P = [1, 100]，dp = 2
追加 70 → [1, 100, 70]
LIS = [1,70] 或 [1,100]，长度 2
前缀 Q = [50, 60]，dp = 2
追加 70 → [50, 60, 70]
LIS = [50,60,70]，长度 3
dp 值相同 ＋ 追加元素相同 → 结果却不同 ⟹ dp 值不含转移所需的全部信息（LIS 末尾元素未知），转移函数不存在。
设计

正确设计：状态必须装下「做转移决策所需的全部信息」

$$dp[i]=1+\max\{\,dp[j]\;:\;j \lt i,\ a[j] \lt a[i]\,\}\quad\text{（集合为空时 } dp[i]=1\text{）};\ \ \text{答案}=\max_i dp[i]\ \boldsymbol{\ne}\ dp[n]$$

LIS 长度 = 4（如 [2,3,7,18]）。黄金检验：知道 dp 值，够不够决定下一步？不够就把缺的信息加进状态——但每加一维，子问题总数乘一个因子，状态数必须保持多项式。
避坑

本章三个高频误解：背方程、只验一张券、子串子串分不清

❌ 「动态规划就是递推，背下方程就行」
✅ 递推只是填表的机械动作；DP 的本质是发现结构（最优子结构＋重叠子问题），递推式只是结构的代数表达。会背不会判，换题就报废。
❌ 「有最优子结构就能高效 DP」
✅ 券一只保证正确，不保证高效：TSP 也有最优子结构，但状态数 2ⁿ 级，每个只算一次仍是指数。两张券同时验。
❌ 「LCS 就是最长公共子串」
✅ 子串要连续，不匹配清零；子序列不连续，不匹配取两侧最大。ABCBDAB 与 BDCABA：子串长 2，LCS 长 4，状态设计完全不同。
接口

动态规划求全、贪心求省：分水岭是「贪心选择性质」

每步决策枚举所有选择，取最优只挑眼前最好，不回头
需要的性质最优子结构 ＋ 重叠子问题最优子结构 ＋ 贪心选择性质
代价填整张表（如 Θ(n³)）一趟扫描，近乎线性

钩子：判定顺序——先验最优子结构（两者都要），再验贪心选择性质：成立用贪心，不成立回 DP。第9章就讲这条性质怎么证。
小结

三句话讲完第8章

1解决什么：方案数指数爆炸时，凭两张入场券把每个子问题只算一次，指数搜索压成多项式填表。
2核心机制：状态设计（信息足够做转移）→ 转移方程 → 记忆化 / 按拓扑序填表 → s 表或回溯重构方案。
3承上启下：Ch6–7 用现成图结构；本章自己设计状态；Ch9 问何时连表都不用填；Ch10 问 DP 也救不了时怎么办。
$$\text{DP 总代价}\;\boldsymbol{=}\;\underbrace{\text{不同子问题数}}_{\text{须多项式}}\;\boldsymbol{\times}\;\underbrace{\text{单点转移代价}}_{\text{须多项式}} \quad\text{——合上书也要能默写}$$
