动机

生成树有 n 的 n−2 次方棵，枚举注定失败

七个村庄接光纤：每条候选线路有造价，要求全网互通、总价最低——枚举所有方案行不行？

$$K_n \text{ 的生成树共 } n^{\,n-2} \text{ 棵};\quad n{=}7:\ 7^5 = 16807,\quad n{=}30:\ 30^{28} \approx 2.3\times 10^{41}$$
😇 只挑最便宜的边买
买着买着就漏了村子：局部便宜 ≠ 全局连通
🙂 把候选边全买下
一定连通但全是浪费：环上最贵边白花钱
💡 本章方案：先找「哪条边一定要、哪条边一定不要」的判定定理——下两页的割性质与环性质。
定义

最小生成树 = 全顶点 + V−1 条边 + 无环 + 总权最小

🌲 最小生成树（Minimum Spanning Tree）
连通无向带权图的子图，含全部顶点、|V|−1 条边、无环，且总权重最小

读法：在所有「全顶点、V−1 条边、无环」的子图里挑总权最小的那棵；它只优化总价，不保证任意两点间路径最短。
7.1

割性质：任何分割的最便宜跨边，买了必不亏

$$\text{割性质（Cut Property）：割 } (S,\,V{-}S) \text{ 的轻边（Light Edge）必属于某棵 MST}$$
  • 实例一：S = {a}，跨割边 a–b(7)、a–d(5) → 轻边 a–d(5)，必在某棵 MST 中（本章算出的那棵就有它）
  • 实例二：S = {a,d}，跨割边 a–b(7)、b–d(9)、d–e(15)、d–f(6) → 轻边 d–f(6)
💡 关键一跃：分组谈判时最便宜的跨组桥梁必买——Kruskal / Prim 只是两种「每步都能找到割轻边」的调度方式。
⚠️ 是「某棵」不是「每一棵」：等权边存在时可能有多棵 MST 分占不同轻边。
7.1

环性质：环上唯一最贵边，永远不用买

$$\text{环性质（Cycle Property）：环上唯一最重边必不在任何 MST 中}$$
  • 实例一：环 b–d–e–b，边权 9、15、7 → 最重 d–e(15) 必弃，绕行的 b–e(7) 永远更便宜
  • 实例二：环 d–f–e–d，边权 6、8、15 → 被排除的仍是 d–e(15)（全图最贵边）
💡 直觉：绕圈的电缆网里，最贵的那一段必然多余。
⚠️ 前提是「唯一最重」：最重边并列时，结论弱化为「存在一棵不含它的 MST」。
割性质发「买入许可」，环性质发「退货许可」——两条合起来 = 本章全部 MST 贪心算法的正确性根基。
7.2

Kruskal：按价格从小到大买，成环就退货

1排序：全部边按权重升序（O(E lg E)）
2判环：并查集（Disjoint-Set / Union-Find）——find(u) = find(v) ⟺ 加入即成环，摊还近 O(α(V))
3停机：选满 |V|−1 条边即收工
为什么对：成环 ⇒ 两端已被更便宜的边连通 ⇒ 它是环上最贵者（环性质，弃）；能买 ⇒ 它是某割的轻边（割性质，选）。
⚠️ Kruskal 维护的是一片森林，最后才合成一棵树：第 2 步的 c–e 与 {a,d} 毫不相邻，照样先买。

7.2

五条弃边全是环上最贵者——复杂度大 O 的 E log V

蓝边 = 选中的 6 条（总权 39）；灰边全是各自环上的最贵者——环性质的现场演示
$$T(V,E) = O(E\lg E) = O(E\lg V) \quad (\text{因 } E \lt V^2)$$
排序 O(E lg E) 占大头；E 次并查集操作摊还约 O(E·α(V))，被排序项吸收——α 是反阿克曼函数，慢到可当常数。
7.3

Prim：一棵树连续长大，每次接最便宜的枝

🌱 生长规则
每步在「一端在树 T 内、一端在 T 外」的边里选最轻者接上——恰是割 (T, V−T) 的轻边，割性质保证安全
🔑 key 与堆
key[v] = v 接到当前树的最轻边权（无边为 ∞）；最小优先级队列（Priority Queue）每次取 key 最小者入树
$$u^{*}=\arg\min_{v \notin T}\, \mathrm{key}[v] \;\Rightarrow\; (u^{*},\, \pi[u^{*}]) \text{ 是割 } (T,\,V{-}T) \text{ 的轻边} \;\Rightarrow\; \text{安全}$$
⚠️ 预防针：key 量「离树多近」（一条边的权）；Dijkstra 的 d 量「离源多远」（路径总长）——7.4 别混。

7.4

最短路的通用原子操作：借道 u 更划算就刷新

🎯 单源最短路（Single-Source Shortest Paths）
δ(s,v) = 所有 s→v 路径权的最小值，不可达为 ∞
🔧 松弛（Relaxation）
对边 (u,v)：若 d[u]+w(u,v) 比 d[v] 小，立刻刷新 d[v] 并记前驱 π
$$\boldsymbol{d[v] \leftarrow \min\{\, d[v],\; d[u] + w(u,v) \,\}}$$
读法：d 是「当前最好报价」，松弛就是听到更便宜的到货价立刻更新——Dijkstra 与 Bellman-Ford 的全部区别只在松弛顺序与轮数。

7.4

收敛引理：非负权保证「取出即定值」

$$\text{收敛引理（Convergence Lemma）：取出 } u \text{ 时 } \boldsymbol{d[u] = \delta(s,u)}$$
  1. 反设：u 是首个取出时 d[u] > δ(s,u) 的顶点
  2. 取点：最短路上首个未确定顶点 y′，其前驱 x′ 已确定
  3. 推出矛盾：x′ 出堆时已松弛 x′→y′，故 d[y′] = δ(s,y′) ≤ δ(s,u) < d[u]——堆顶该是 y′ 而非 u
⚠️ 非负权用在第 3 步：δ(s,y′) ≤ δ(s,u) 要求 y′⇝u 段边权非负——负权边会让「后来者居上」，已定值的顶点事后被更便宜路径追上。
7.4

负权边不需要成环，就足以杀死 Dijkstra

flowchart LR y(("y")) -->|"3"| t(("t")) t -->|"1"| x(("x")) x -->|"−4"| y
反例一 · 临界侥幸
9+(−4)=5 恰等于 d[y]=5，不更小；权再小即成负环
flowchart LR s(("s")) -->|"1"| a(("a")) s -->|"3"| b(("b")) b -->|"−3"| a
反例二 · 真失败（DAG 无环）
a(1) 先定值，之后 b 松弛出 0 < 1：真 δ(s,a)=0
负权边 = 「不保证对」而非「必然错」；工程正确姿势：有负权就上 Bellman-Ford。
7.5

Bellman-Ford：全体边松弛 V−1 轮，第 V 轮抓负环

1策略：每轮把全部 E 条边松弛一遍，重复 |V|−1 轮（Bellman-Ford Algorithm）
2封顶理由：无负环时最短路可取简单路径，至多 |V|−1 条边；第 i 轮覆盖「至多 i 条边」的全部最短路
3第 |V| 轮：仍能松弛 ⟺ 存在可无限绕短的负环（Negative Cycle）→ 报警
Dijkstra 每次拍板一个；Bellman-Ford 谁也不拍板，全体报价刷新 |V|−1 轮——边数上限就是轮数上限。
负环检测是设计功能，不是故障：负环可达的最短路是 −∞，算法职责是检测并报告，而不是给数字。

7.6

差分约束：负环就是「无解」的报警器

$$x_j - x_i \le c \iff \text{边 } i{\to}j \text{ 权 } c;\quad \text{可行} \iff \text{无负环}$$
  • ① x₂−x₁≤2 ⟹ 1→2 权 2　② x₃−x₂≤3 ⟹ 2→3 权 3
  • ③ x₃−x₁≤4 ⟹ 1→3 权 4　④ x₁−x₃≤−1 ⟹ 3→1 权 −1
  • ⑤ x₂−x₃≤0 ⟹ 3→2 权 0
加超级源点 s（Super Source）向各变量连 0 权边，跑 BF 得 x = (−1, 0, 0)：五条全过，④ 恰好取等——是它在拽紧解。
flowchart LR s(("s")) -->|"0"| x1(("x₁")) s -->|"0"| x2(("x₂")) s -->|"0"| x3(("x₃")) x1 -->|"2"| x2 x2 -->|"3"| x3 x1 -->|"4"| x3 x3 -->|"−1"| x1 x3 -->|"0"| x2

无解侧：① 改 x₂−x₁≤−3 → 环 1→2→3→1 权和 −1，三式相加得 0 ≤ −1 矛盾

⚠️ 方向别记反：被约束的变量 xj 是箭头终点，边永远是 i→j。
避坑

「某棵」不是「每棵」，key 不是 d，负权不是必错

❌ 「割的轻边必在每一棵 MST 中」
✅ 只保证「某棵」：等权时多棵 MST 分占不同轻边；环性质同理须「唯一最重」，并列时弱化为「存在一棵不含它」。
❌ 「Prim 的 key 与 Dijkstra 的 d 是一回事」
✅ key = 到当前树的最轻单边权；d = 到源点的路径总长（含累加项）。两者都只降不升，含义完全不同。
❌ 「含负权 Dijkstra 必错」「第 |V| 轮还能松弛是程序写错了」
✅ 负权只是「不保证对」（x→y(−4) 就侥幸对）；第 |V| 轮可松弛是在报负环——设计功能，不是故障。
