主线

一条因果链：找最大 → 堆 → 分区 → 下界 → 绕开比较

1反复取最大、不想重排全数组 → 堆：取最大与插入都 O(lg n)
2把取最大重复 n−1 次 → 堆排序：原地 O(n lg n)
3要更小常数 → 快排分区；最坏 Θ(n²) → 随机化
4比较排序还能更快吗 → 决策树下界 Ω(n lg n)
5绕开比较、用键的结构 → 计数 / 基数 / 桶，线性但有前提
动机

反复取最大：无序 O(n)、全序插入 O(n)，堆都要 O(lg n)

🏥 场景
进程调度、急诊分诊、事件模拟：永远先处理当前最重要的。
📋 无序数组
取最大 O(n)，插入 O(1)
📏 全排序数组
取最大 O(1)，插入 O(n)
✅ 堆（Heap）：取最大 O(1)，删除最大与插入都 O(lg n)——两头都占。
$$\text{最大堆性质：}\ A[\,\mathrm{PARENT}(i)\,] \ge A[i]$$
⚠️ 堆是局部偏序：父亲 ≥ 孩子，但兄弟之间、跨子树之间没有任何顺序保证。
定义

数组表示的三个导航公式：PARENT、LEFT、RIGHT

$$\boldsymbol{\mathrm{PARENT}(i)=\lfloor i/2\rfloor \qquad \mathrm{LEFT}(i)=2i \qquad \mathrm{RIGHT}(i)=2i+1}$$
例：下标 4 → 父亲 2，孩子 8、9；下标 5 → 父亲 2，孩子 10、11。
树高 = $\lfloor \lg n \rfloor$：n=10 或 n=15 时高度都是 3。
每步导航 O(1)，路径 ≤ 树高 ⟹ 堆上所有操作天然 O(lg n) 量级。
💡 不用指针，全靠下标算术——这是堆能塞进缓存、跑得快的结构原因。
操作

MAX-HEAPIFY：只有根不对的子树，下沉修复，O(lg n)

前提：LEFT(i)、RIGHT(i) 为根的子树都已是最大堆，只有 A[i] 可能太小。
动作：与较大孩子交换 → 对交换位置递归 → 最多沉到叶子。
$$T(i) = O(\text{子树高度}) = O(\lg n)$$
每层一次常数交换，路径 ≤ 树高 $\lfloor\lg n\rfloor$ —— 这就是全部成本。
💡 建堆、堆排序、EXTRACT-MAX 三处都要靠它。

算法

堆排序：建堆 O(n) + (n−1) 次 extract × O(lg n) = O(n lg n)，原地

✅ 选型：要原地 + 最坏保证选堆排序；要稳定选归并；要平均常数最小选快排。
⚠️ 堆排序不稳定：堆顶与堆末的长途交换必然打乱等值元素的相对顺序。
分治

PARTITION：一趟扫描切成「小 | 主元 | 大」，主元一次到位

分：PARTITION 一趟扫描重排为 ≤x | x | ≥x
治：递归排 A[p..q−1] 与 A[q+1..r]
合：什么都不做（比归并省掉合并）
$$\text{主元 } x=A[r],\quad i=\text{「}\le x\text{ 区的右边界」},\quad \text{返回 } q=i+1$$
💡 结束后只有主元就位；左右两段仍乱，但主元从此不再移动。

分析

最坏 Θ(n²)：每次 0 对 n−1，n=5 真账 5+4+3+2+1=15

$$T(n)=T(n-1)+\Theta(n) \;\Rightarrow\; T(n)=\Theta(n^2)$$
$$n=5:\quad 5+4+3+2+1=15=\frac{n(n+1)}{2}$$
✅ 固定 1:9 切分仍是 $\Theta(n\lg n)$：每层代价 n，深度 $\log_{10/9} n=\Theta(\lg n)$。
❌ 致命的是每次 0:(n−1)——已排序数组 + 固定末位主元必然触发。
💡 下一节的任务：让坏输入变成坏运气——把「必然」改成「小概率」。
修复

随机化快排：把「坏输入」变成「坏运气」

RANDOMIZED-PARTITION：随机抽下标 ↔ A[r]，再走普通 PARTITION。
最坏 Θ(n²) 仍在，但对任何输入都只剩小概率。
$$\boldsymbol{E[T(n)] = \Theta(n\lg n)}\quad\text{对算法的随机选择取期望}$$
⚠️ 期望对随机主元取，不是对输入分布取——敌手知道代码也造不出坏输入。
证明

指示器随机变量：$\Pr\{\,z_i \text{ 与 } z_j \text{ 比较}\,\}=\frac{2}{j-i+1}$

$$X_{ij}=\mathbf{1}\{z_i \text{ 与 } z_j \text{ 被比较}\},\qquad X=\sum_{i \lt j}X_{ij} \;\Rightarrow\; E[X]=\sum_{i \lt j}\Pr\{z_i \text{ 与 } z_j \text{ 比较}\}$$
$$\boldsymbol{\Pr\{\,z_i,z_j\text{ 比较}\,\}=\frac{2}{j-i+1}}\quad\text{（}\{z_i,\dots,z_j\}\text{ 中谁先当主元：两端才行）}$$
每对至多比较一次：比较只发生在主元与他人之间，比完主元退场；中间的 $z_k$（$i \lt k \lt j$）先当主元 ⟹ 两者永被隔开。
样例

n=4 真账：六对求和得 E[X] ≈ 4.83，对比最坏 6 次

元素对区间 j−i+1概率 2/(j−i+1)
(1,2)、(2,3)、(3,4)21（共 3 对）
(1,3)、(2,4)32/3（共 2 对）
(1,4)41/2
合计 E[X]—3×1 + 2×(2/3) + 1/2 = 4.83
$$E[X]=\sum_{k=1}^{n-1}(n-k)\cdot\frac{2}{k+1} \;\lt\; 2n\sum_{k=1}^{n-1}\frac{1}{k}\approx 2n\ln n=\Theta(n\lg n)$$
最坏 3+2+1=6 次，期望 4.83 次，省近 20%；n 越大差距越悬殊。
下界

决策树：$2^h \ge n!$ ⟹ n=3 时下界 h ≥ ⌈lg 6⌉ = 3

内部节点 = 一次比较；叶子 = 一个输出排列；树高 h = 最坏比较次数。
n! 种排列必须区分 ⟹ 叶子 ≥ n!；而高度 h 的二叉树至多 $2^h$ 片叶子。
$$\boldsymbol{2^h \ge n! \;\Rightarrow\; h \ge \lg(n!)}$$
$$n=3:\quad 2^h \ge 6 \;\Rightarrow\; h \ge \lceil \lg 6\rceil = 3$$
2 次比较至多区分 $2^2=4$ 种情形，装不下 6 种排列。
下界

$\lg(n!)\ge\frac{n}{2}\lg\frac{n}{2}=\Omega(n\lg n)$：每次比较只得 1 比特

$$h \ge \lg(n!)=\sum_{k=1}^{n}\lg k \;\ge\; \sum_{k=\lceil n/2\rceil}^{n}\lg k \;\ge\; \frac{n}{2}\lg\frac{n}{2}=\frac{n}{2}(\lg n-1)=\Omega(n\lg n)$$
信息论读法：区分 n! 种排列需 ≈ n lg n 比特；每次比较 ≤ 1 比特 ⟹ 比较次数 ≥ Ω(n lg n)。
💡 下界封死的是「纯比较 + 更快」的组合，不禁止任何具体算法——绕开比较即可破局。
线性

计数排序：数人数 + 算站位，Θ(n+k)，一次比较都不做

Θ(n+k)，k=O(n) 时即 Θ(n)——值即下标，直接定位，不做比较。

基数：d 轮 × 稳定子排序 Θ(n+k) ⟹ Θ(d(n+k))；子排序必须稳定，保住低位成果。
桶：[0,1) 均匀 → ⌊n·A[i]⌋ 分桶，桶内插排；期望 Θ(n)，分布倾斜退化 O(n²)。
⚠️ 用「键是什么」代替「键比谁大」——前提不满足时反而更糟。
对比

三种线性排序各吃一种前提；下界与线性不矛盾

算法键的前提时间稳定致命软肋

$$\boldsymbol{\text{主线答案：下界只管「靠比较获取信息」；计数排序一次比较不做，不在决策树管辖内}}$$
避坑

三个雷：堆≠有序、随机化≠消灭最坏、下界≠禁止线性

❌ 堆是一棵排序好的树
✅ 只保证父亲 ≥ 孩子；下标 5 的 7 大于下标 4 的 8 完全合法。全局第 k 大只能逐次 EXTRACT-MAX。
❌ 随机化把最坏情形消灭了
✅ Θ(n²) 仍在，只是小概率；期望对算法的随机选择取，对敌手依然安全。
❌ 计数排序 O(n) 与 Ω(n lg n) 下界矛盾
✅ 下界只管比较模型；计数排序零比较、值即下标，不在其管辖内。
