主线

三大难题各配一件启发式兵器，合力逼近一个 NP 难

1一条语句选哪几条指令 → 指令选择：树覆盖 + 最大口啃法（Maximal Munch）
2值放哪个寄存器 → 寄存器分配：getReg 两本账 + 纪律溢出；全局版是图着色
3先算哪棵子树 → 求值顺序：Ershov 数标出硬度，先算费寄存器的子树
4收束 → 块内联合最优是 NP 难；跨块活跃性分析指向第9章
这条链就是本章目录：三大难题（8.1）→ 目标机与代价（8.2）→ 树覆盖（8.3）→ getReg 与图着色（8.4）→ Ershov 序（8.5）。
动机

一句 x := x + 1 就能看出：机械查表替换必败

三地址码 x := x + 1 看上去是「查表替换」，真动手才发现每一步都是选择，花的是同一笔预算：寄存器与访存次数。

😇 查表替换派
LD R0, x ＋ ADD R0, R0, #1 ＋ ST x, R0：三条指令，代码体积膨胀 3 倍，还白占一个寄存器。
🙂 看清目标机
一条 INC x 就干完。同一条语句在不同上下文下最优选择不同——代码生成没有脱离上下文的答案。
💡 本章方案：带预算的翻译——选哪条指令、谁住寄存器、先算谁，花的是同一笔钱；块内联合最优是 NP 难，工程上全用启发式。
8.1

指令选择、寄存器分配、求值顺序，花的是同一笔预算

难题问的是什么选不好的反例
指令选择（Instruction Selection）一条三地址语句用哪几条指令实现x := x + 1 选 LD/ADD/ST 三条，体积膨胀 3 倍
寄存器分配（Register Allocation）众多名字挤几个寄存器，谁住、谁去内存两个寄存器算 (a+b)×(c−d)，溢出多花 ST/LD 各一条
求值顺序（Evaluation Order）子表达式先算谁、后算谁(a+b)×c：一种顺序峰值 2 个寄存器，另一种要 3 个
三者互相牵制：指令选择决定寄存器用量，分配受余量约束，顺序同时改变两者——块内联合最优是 NP 难，全部用启发式。

寄存器倒手免费，一沾内存就收税

$$\text{cost} = 1 + \sum \text{各源/目的操作数的寻址模式附加代价}$$
指令逐项拆解代价
LD R0, a1 + 0（R0 寄存器）+ 1（a 绝对地址）2
ADD R0, R0, R11 + 0 + 0 + 0（全寄存器）1

代价模型是指令的价目表：LD R1, *40(R0) 一条指令代价 2——比较代码用代价模型，不能数行数。
8.3

选指令就是铺地砖：用瓦片把表达式树不重不漏铺满

瓦片匹配的子树对应指令
T1叶子：内存名字 xLD R, x
T2内部结点 + ，两操作数已在寄存器ADD Rd, Rs, Rt
T3内部结点「下标取值」：基址常量 c + 寄存器下标LD R, c(Ri)
T4根：赋值到内存名字 aST a, R
最大口啃法（Maximal Munch）：从根开始，每步选能覆盖最多结点的瓦片啃掉，再对剩余子树递归。瓦片越大，砖缝（多余访存）越少。

8.4

两本账记账，三条纪律决定谁被腾出寄存器

📒 寄存器描述符（Register Descriptor）
每个寄存器当前持有哪些名字的值。
📗 地址描述符（Address Descriptor）
每个名字的值当前在哪些位置：某寄存器、内存、或两者。
getReg 情形动作
① 名字已在某寄存器直接用，零代价
② 有空寄存器LD 进来
③ 无空寄存器先挑「已有内存副本 / 此后不再活跃」的直接腾（免 ST）；都不行选「下次使用最远」的，先 ST 溢出（Spill）再腾

8.5

Ershov 数是每棵子树的「硬度表」：先啃硬骨头

$$\text{label}(\text{叶子})=1;\quad \text{label}(n)=\max(l,r)\ \ (l\ne r);\quad \text{label}(n)=l+1\ \ (l=r)$$
flowchart TB RT[乘 · 标号 2] --> PL[加 · 标号 2] RT --> C[c · 1] PL --> A[a · 1] PL --> B[b · 1]

(a+b)×c：根标号 2 → 两个寄存器可无溢出算完

📏 标号的含义
不溢出时计算该子树所需的最少寄存器数。
求值规则只有一句：先算标号大的子树。先啃硬骨头，算完只剩一个值占位，再算简单的手头宽松。

LD R0, cR0

峰值 3；仅 2 寄存器时被迫溢出：7 条 vs 5 条
先算出的值要一直占着寄存器等另一个操作数——占压时间决定峰值；先啃硬骨头，占压最短。
避坑

查表派、贪心即最优、乱溢出——三个坑都别踩

❌ 指令选择是机械查表：一条三地址码对应一条「标准」指令
✅ 最优选择依赖上下文（寄存器余量、操作数是否已在寄存器、后面还用不用）——没有脱离上下文的答案。
❌ 最大口啃法给出最优覆盖
✅ 它是贪心：瓦片重叠时，啃最大口可能逼剩余子树用贵瓦片；保底靠动态规划，工程上贪心＋好瓦片已足够好。
❌ 寄存器不够时随便溢出一个就行
✅ 先溢「已死 / 有内存副本」的（免 ST），再溢「下次使用最远、使用最少」的；例 8.4-B 溢 t1 而非 t3 会多一次重载。
