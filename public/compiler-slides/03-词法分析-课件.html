主线

规格变机器：正则 → NFA → DFA → 最小 DFA，一条链走到底

1字符流只是字节，机器需要词形说明书 → 正则表达式
2规格机器不会执行 → Thompson 构造拼出 NFA
3NFA 每步有多条路，无法直接跑 → 子集构造变成 DFA
4DFA 可能有多余状态 → 划分求精得到最小 DFA
5歧义靠最长匹配＋优先级裁决 → 记号流交给语法分析器
这条链就是本章的目录：五环对应讲义 3.2 正则表达式、3.3 Thompson 构造、3.4 子集构造、3.5 DFA 最小化。
动机

手写扫描器能跑，但换语言就得重写——认字必须与组句分家

第2章我们手工写了扫描器：读一个字符、用 peek 预读、判断是不是字母数字运算符。能跑，但有两个硬伤：

😣 手写派的痛
每换一种语言重写一遍；与语法分析器缠在一起，改一处动全身
😌 独立出来的收益
去空白与注释 · 统一归为 id · 按行扫描自带行列号报错
分工一句话：词法分析器（Scanner）把字符流切成记号流；语法分析器（Parser）在记号流上分析结构。本章只解决前一半。
定义

词素是实物，记号是类别标签，模式是类别的长相说明书

术语含义例子
词素（Lexeme）源程序中实际出现的一段字符if、count、3.14、<=
记号（Token）词素的类别，编译器内部的抽象名字if → if，count → id，3.14 → num
模式（Pattern）描述某类词素长什么样的规则标识符 = 字母开头，后接字母或数字
词素可以有无穷多个（id 对应 count、sum、x1……），记号只有有限个。扫描器的工作：读到词素 → 贴上记号标签。
例子

记号不是裸标签——它带着属性值一起交给下游

扫描器读 count = count + 1，产出五行「记号＋属性」：

词素记号属性
countid指向符号表中 count 的指针
=assign—
countid指向符号表中 count 的指针
+plus—

💡 下游不只要知道「这是一个标识符」，还要知道「这是哪一个」——名字与数值全靠属性带过去。
裁决

多个模式同时匹配：最长匹配先吃，优先级裁决平局

📏 最长匹配（Maximal Munch）
多个模式都能匹配当前前缀时，选吃掉字符最多的那个

扫到 <=：< 吃 1 个字符，<= 吃 2 个 → 整体识别为一个 relop，不拆成两个记号。

🥇 优先级裁决平局
吃得一样长时，定义顺序靠前的规则胜出

if 与 id 模式等长匹配 → if 的规则写在 id 前面，返回关键字；ifx 更长 → 由最长匹配归为 id。

口诀：最长匹配管长度，优先级管平局——关键字定义永远排在标识符之前。
规格

三种构造加三种运算，正则表达式就能写完所有词形

🧱 基本构造
ε（空串） · 单字符 a
🔧 三种运算
并 r|s · 连接 rs · 闭包 r*
优先级：* ＞ 连接 ＞ |，括号打破优先级。
扩展含义例子
r+正闭包：1 次或多次digit+ 一个或多个数字
r?可选：0 次或 1 次(+|-)? 可选符号
[a-z]字符类：范围内任选一个[a-zA-Z] 任意字母
💡 正则是规格说明书，不是执行程序：只说什么串合法，不说怎么去认。
规格

正则定义给模式起名字：id、num、relop 是本章三张底牌

letter → a | b | … | z | A | … | Z　　digit → 0 | 1 | … | 9　　id → letter ( letter | digit )*
记号正则定义说明
idletter ( letter | digit )*字母开头，后接字母或数字
numdigit+ ( . digit+ )? ( E ( + | - )? digit+ )?整数、小数、科学计数法
relop< | <= | = | <> | > | >=六种关系运算符
id 的第一个位置必须是 letter，digit 不在可选范围——所以 9abc 不匹配 id。

思想

DFA 的一个状态，就是 NFA 的一个状态集合

🌀 ε-闭包（ε-closure）
从状态集合出发，只走 ε-边能到达的所有状态——传递，走到没有新状态为止
👣 move(T, a)
从集合 T 中某个状态出发，读入字符 a 能到达的状态集合——这一步不走 ε
DFA 状态 = ε-闭包（ move(上一状态集, 当前字符) ）
读法：NFA 里「可能在这也可能在那」的迷茫，被 DFA 里「我正处在这个集合」的确定所替代。
演练

A 到 E 五个 DFA 状态，是六步 move＋闭包算出来的

① 初态：A = ε-closure({0}) = {0, 1, 2, 4, 7}（0 出发走 ε：加 1、7；从 1 再加 2、4）

✍️
暂停推导

从 A 出发：先算 move(A, a) 与 move(A, b)，各补一次 ε-闭包；再继续展开新状态，直到没有新集合。交付物：完整的 A–E 五状态清单。

② A 的出边：move(A,a)={3,8} → 闭包 {1,2,3,4,6,7,8} = B；move(A,b)={5} → 闭包 {1,2,4,5,6,7} = C

③ 继续展开：B 读 b → {1,2,4,5,6,7,9} = D；D 读 b → {1,2,4,5,6,7,10} = E（含 10，接受）

④ 收尾：C 读 a→B、读 b→C；E 读 a→B、读 b→C。共 5 个状态，没有新集合，收工。

求精

对未来行为完全一样的状态是等价的，就该合并

1初始划分：按接受 / 非接受劈成两组
2反复检查：同组两状态对某输入跳进不同组 → 拆开
3收敛：不能再拆时，每组是一个等价类，合并为一个状态
初始划分　Π₀ = { {A, B, C, D}, {E} }
💡 判断标准不是「长得像不像」，而是「对所有后缀的行为一致」——结构不同也能合并。
手算

三轮检查：第一轮拆出 D，第二轮拆出 B，第三轮 A、C 留下

① 第一轮看 {A,B,C,D}：A/B/C 读 a、b 都落组内；D 读 b → E（异组），拆出 D

Π₁ = { {A, B, C}, {D}, {E} }

② 第二轮看 {A,B,C}：B 读 b → D（异组），与 A/C 不一致，拆出 B

Π₂ = { {A, C}, {B}, {D}, {E} }

③ 第三轮看 {A,C}：读 a 都到 B，读 b 都回本组，行为完全一致，不再拆

最终 Π = { {A,C}, {B}, {D}, {E} }　—— 最小 DFA 共 4 个状态

避坑

本章最容易踩的三个雷：词素当记号、闭包算一层、正则当万能

❌ 把词素和记号混为一谈：「记号 if 就是字符串 if」
✅ 词素是源文件里的字符，记号是编译器内部的类别编码；词素无穷多，记号有限个。
❌ 以为 ε-闭包只算一层
✅ ε-闭包是传递闭包，走到没有新 ε-边为止：ε-closure({0}) 加 1、7 后，还要从 1 再加 2、4。
❌ 以为正则能匹配任意嵌套结构，如任意层数的配对括号
✅ 正则没有记忆，数不了未配对的左括号；配对括号要交给第4章的上下文无关文法。
