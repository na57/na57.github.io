动机

记号流是扁平的，光看它分不清先加还是先乘

词法分析（第3章）交来的东西：id + id * id —— 一串扁平记号，没有任何嵌套信息。

id + id * id　⇒　两种读法，两个结果
😇 读法一：先加后乘
把 id + id 当一个整体再乘 —— 违反了算术直觉，但扁平记号本身没说不行
🙂 读法二：先乘后加
把 id * id 当一个整体再加 —— 这才是我们要的树，可谁来替我们定？
💡 本章方案：用上下文无关文法描述嵌套，再用一张机械可查的表驱动分析 —— 不手写递归试错。

文法

同一个表达式语言，两条腿各用一套写法

⬆️ 自底向上（LR）用：原左递归文法
0: E′ → E（增广）
1: E → E + T　　2: E → T
3: T → T * F　　4: T → F
5: F → ( E )　　6: F → id
左递归天然表达左结合
⬇️ 自顶向下（LL）用：消除左递归后
E → T E′
E′ → + T E′ ｜ ε
T → F T′
T′ → * F T′ ｜ ε
F → ( E ) ｜ id
语言不变，形状变了
E 管加号、T 管乘号、F 管括号与原子 —— 层次结构把优先级和结合性「编码」进了文法。
拦路虎

左递归让递归下降死循环，消除它有固定模子

递归下降给每个非终结符写一个函数；E → E + T 意味着函数 E 一进门就不消耗输入再调自己 —— 直接死循环。

A → A α ｜ β　　⟹　　A → β A′，　A′ → α A′ ｜ ε

① 套到 E → E + T ｜ T：得 E → T E′，E′ → + T E′ ｜ ε

② 套到 T → T * F ｜ F：得 T → F T′，T′ → * F T′ ｜ ε

③ 另有小手术提取左因子：提出公共前缀避免反复试错（本章例子用不上，一句话带过）

按空格 / → 逐步展开推导

定义

FIRST 管开头，FOLLOW 管身后，两个集合消除两种不确定

🚪 FIRST 集（FIRST Set）
FIRST(α) = 串 α 能推出的所有首终结符；α 能推空则含 ε
回答：选这条产生式，输入的第一个符号可能是什么？
👥 FOLLOW 集（FOLLOW Set）
FOLLOW(A) = 句型中可能紧跟在 A 后面的终结符（含 $）
回答：A 推出了空串，下一个输入该期待什么？
看当前输入落在哪个集合里，就走哪条路 —— 选择从此可以查表
读法：FIRST 是每条产生式的「门脸招牌」，FOLLOW 是非终结符消失以后的「合法接棒者」。
手算

五个非终结符的 FIRST 与 FOLLOW，一次算全

非终结符FIRSTFOLLOW

T{ ( , id }{ + , ) , $ }

FOLLOW(F) 里的 * 来自 T → F T′ 且 FIRST(T′) 含 *：F 充当 T 的开头，T 后能跟 *，F 后也能跟 * —— 算 FOLLOW 永远只看「B 后面是什么」。
判定

LL(1) 三条全过，才配拥有「每格至多一条」的表

LL(1) = 从左向右扫描（L）＋ 最左推导（L）＋ 只向前看 1 个记号（1）。对每对产生式 A → α ｜ β 查三条：

①FIRST(α) ∩ FIRST(β) = ∅ —— 两条路的首符号不撞车
②α、β 中至多一个能推出 ε
③若 ε ∈ FIRST(β)，则 FIRST(α) ∩ FOLLOW(A) = ∅ —— 走空的路不与走实的抢输入
本章表达式文法三条全过 ⇒ 是 LL(1) ⇒ 可以无回溯预测分析。

驱动

表 ＋ 栈 ＋ 指针就能跑，右部必须逆序压栈

1匹配：栈顶终结符 = 当前输入 → 双双弹出，输入指针前进一格
2展开：栈顶非终结符 → 查 M[X, a]，弹出 X，右部逆序压栈（栈顶对准最左符号）
3接受 / 报错：栈与输入都只剩 $ → 接受；查到空格 → 确定的语法错误
预测分析器 = 一张表 M ＋ 一个栈 ＋ 一个输入指针
栈是「期待看到的符号序列」：终结符等着和输入对齐，非终结符等着继续展开，所以两者并存。

换腿

自底向上 = 反复找句柄、把它归约掉，直到只剩开始符号

✂️ 归约（Reduction）
把与某条产生式右部匹配的子串替换回左部非终结符 —— 是最右推导的逆操作
🧩 句柄（Handle）
当前这一步被替换的那个子串：位置正确（在栈顶）且时机正确的完整右部
id ⇒ F ⇒ T ⇒ T * id ⇒ T * F ⇒ T ⇒ E　（自底向上的归约链）
LL(1) 太挑文法（左递归必消、左因子必提）；LR 族直接吃原左递归文法 —— 这是换腿的动机。

避坑

本章最容易踩的三个坑，全和 FOLLOW 有关

❌ FIRST(T′) 只写 { * }
✅ T′→ε 使 ε 必进 FIRST：正确是 { * , ε }；漏了它，预测表 T′ 行少填 +、)、$ 三列。
❌ 算 FOLLOW 时盯着符号前面
✅ FOLLOW 只看「B 后面是什么」：* ∈ FOLLOW(F) 是因为 T → F T′ 且 FIRST(T′) 含 *，不是因为 T′ → * F T′ 里 * 在 F 前面。
❌ SLR 的 r k 填满整行
✅ 归约格只填 FOLLOW(左部) 那几列：状态 2 的 * 列若也填 r2，就和 s7 冲突，表根本造不出来。
小结

1解决什么：扁平记号流 → 嵌套语法树，且用表机械驱动，不手写递归
2核心机制：FIRST/FOLLOW 消不确定性 → LL(1) 预测表；LR(0) 项集记进度 ＋ FOLLOW 消冲突 → SLR 双表
