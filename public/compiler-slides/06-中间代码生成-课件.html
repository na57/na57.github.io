动机

m 种语言配 n 种机器，不该写 m×n 个编译器

第5章的 SDT 只是扳手，它留下的问题是：触发的动作到底产出什么？假设直接产出目标机器码——

$$m\text{ 种语言}\times n\text{ 种机器}\Rightarrow m\times n\text{ 个编译器}\qquad\text{插一层 IR}\Rightarrow m+n\text{ 个编译器}$$

🌊 在机器码上优化
面对的是机器细节的海洋，优化器无处下嘴
💡 本章方案：前端产 中间表示（Intermediate Representation, IR），后端消费 IR，优化器在 IR 上做文章。
定义

三地址码只有一条约束：每条指令至多一个运算符

三地址码（Three-Address Code）是一种低层 IR，典型形态：

$$x = y\ \mathrm{op}\ z\quad\text{（每条指令至多一个运算符）}$$
地址种类说明例子
名字（Name）源程序变量，经符号表指向其存储位置a、b、position
常量（Constant）源程序中直接出现的字面量60、3.14
临时变量（Temporary）编译器为暂存中间结果新造的名字t1、t2、t3
读法：「地址」不是三个内存地址，而是操作数位置的统称——名字、常量、临时变量都算地址。
实现

四元式把指令变成一张四列的表：op / arg1 / arg2 / result

x = a + b * c 的三地址码（先乘后加）

地址指令
1t1 = b * c
2t2 = a + t1
3x = t2

四元式（Quadruple）：赋值指令 arg2 留空

oparg1arg2result
*bct1
+at1t2
=t2x
读法：四元式让指令成为可存放、可重排的记录——优化器就在这张表上打算盘（第9章的主场）。
机制

增量翻译只要三个零件：E.addr 接力、gen 吐指令、new Temp 开新名

🏷️ E.addr
E 的值存放在哪个地址（名字或临时变量），不是值本身
📤 gen()
向输出流追加一条三地址指令
🆕 new Temp()
分配一个从未用过的临时变量名 t1、t2……
💡 增量翻译（Incremental Translation）：归约时顺手吐指令，不必先建语法树。
产生式语义规则
S → id = Egen(top.get(id.lexeme) '=' E.addr)
E → E₁ + E₂E.addr := new Temp()；gen(E.addr '=' E₁.addr '+' E₂.addr)
E → -E₁E.addr := new Temp()；gen(E.addr '=' 'minus' E₁.addr)
E → ( E₁ )E.addr := E₁.addr（不生成指令）
E → idE.addr := top.get(id.lexeme)（不生成指令）
演练

a = b + -c + d：归约顺序就是生成顺序，地址 100–103

① 归约 E → -E₁（E₁.addr = c）：E.addr := t1　→　100: t1 = minus c

② 归约 E → E₁ + E₂（b 加 t1）：E.addr := t2　→　101: t2 = b + t1

③ 归约 E → E₁ + E₂（t2 加 d）：E.addr := t3　→　102: t3 = t2 + d

④ 归约 S → id = E（a 接 t3）　→　103: a = t3

短路

控制流里的布尔表达式不算值，它是一段跳转代码

短路求值（Short-Circuit Evaluation）：or 左真即真、and 左假即假，右侧不再求值。

⚠️ 短路是语义，不只是省时间：x ≠ 0 and y/x > 1 —— x ≠ 0 先挡一道，y/x 才不会除零。
B → E₁ rel E₂ 生成的指令去向
if E₁.addr relop E₂.addr goto _真出口（成立时跳）
goto _假出口（不成立时跳）
💡 麻烦来了：生成这两条指令的那一刻，真出口和假出口的地址根本不存在——它们落在后面还没翻译的语句里。
回填

先上车后补票：指令号记进账本，地址定了统一还

回填（Backpatching）：跳转目标留空先生成，指令号记入链表，目标确定后统一补填——一趟扫描就够。

操作作用
makelist(i)造一个只含指令号 i 的新链表，返回表指针
merge(p₁, p₂)把 p₁、p₂ 两条链表合并，返回合并后的表指针
backpatch(p, i)把链表 p 里每一条指令的跳转目标补填为 i
📒 真链 truelist / 假链 falselist
B 上挂的两本账：所有「该跳真 / 假出口但还没填」的指令号（不是指令内容）
📍 M → ε
唯一职责是记下当前位置：M.instr := nextinstr（下一条待生成指令的地址）
方案

or 回填假链、and 回填真链——口诀：or 假才继续，and 真才继续

产生式语义规则
B → B₁ or M B₂backpatch(B₁.falselist, M.instr)；B.truelist := merge(B₁.truelist, B₂.truelist)；B.falselist := B₂.falselist
B → B₁ and M B₂backpatch(B₁.truelist, M.instr)；B.truelist := B₂.truelist；B.falselist := merge(B₁.falselist, B₂.falselist)
B → not B₁B.truelist := B₁.falselist；B.falselist := B₁.truelist
B → ( B₁ )B.truelist := B₁.truelist；B.falselist := B₁.falselist
B → E₁ rel E₂B.truelist := makelist(nextinstr)；B.falselist := makelist(nextinstr + 1)；gen('if' … 'goto _')；gen('goto _')
M → εM.instr := nextinstr
口诀：or 假才继续、and 真才继续——M 必须插在 or / and 与 B₂ 之间，因为 M.instr 要在 B₂ 生成之前取值。
手算

a<b or c<d and e<f（上）：先生成六条留空指令

短路控制流：六条指令恰好实现这张图

① B₁ = a<b：100: if a<b goto _／101: goto _　（B₁.tl={100}，B₁.fl={101}）；M₁.instr = 102

② B₂ = c<d：102: if c<d goto _／103: goto _　（B₂.tl={102}，B₂.fl={103}）；M₂.instr = 104

③ B₃ = e<f：104: if e<f goto _／105: goto _　（B₃.tl={104}，B₃.fl={105}）

a<b or c<d and e<f（中）：两次归约，两次 backpatch

④ 归约 and（B₂ and M₂ B₃）——and 真才继续，回填 B₂ 真链

B′.truelist := B₃.truelist = {104}；　B′.falselist := merge({103}, {105}) = {103, 105}

最终上交的「欠条」：B.truelist = {100, 104}，B.falselist = {103, 105}——等控制流语句来抵债。102 已还清，不在任何链上。
方案

if / if-else / while 共用一副骨架：真链接语句体，假链交上层

语句翻译方案要点
if-then
S → if M B then S₁		backpatch(B.truelist, M.instr)；S.nextlist := merge(B.falselist, S₁.nextlist)
if-then-else
S → if B then M₁ S₁ N else M₂ S₂		backpatch(B.truelist, M₁.instr)；backpatch(B.falselist, M₂.instr)；N → ε 生成「跳过 else」的 goto _，N.nextlist := makelist(nextinstr)；S.nextlist 三者 merge
while
S → while M₁ B do M₂ S₁		backpatch(S₁.nextlist, M₁.instr)；backpatch(B.truelist, M₂.instr)；S.nextlist := B.falselist；gen('goto' M₁.instr)
为什么 while 要两个标记？M₁.instr 记条件入口（循环体执行完跳回去），M₂.instr 记循环体入口（B 为真落进来）——要记两个地址；if 只记一个，所以一个 M 就够。
手算

while a<b do x=x+1（上）：两个 M 记地址，B 与循环体先生成

① M₁ → ε：M₁.instr = nextinstr = 100（条件入口，先记下）

② 翻译 B = a<b：100: if a<b goto _（B.truelist={100}）／101: goto _（B.falselist={101}）

③ M₂ → ε：M₂.instr = 102（循环体入口）

④ 翻译 S₁ = x = x + 1：102: t1 = x + 1／103: x = t1　——赋值无未决跳转，S₁.nextlist = {}

按空格 / → 逐步展开

手算

while a<b do x=x+1（下）：归约四动作，101 由上层回填到 105

① backpatch(S₁.nextlist = {}, M₁.instr = 100)：空表，无指令可改（不是这一步生成 goto 100）

② backpatch(B.truelist = {100}, M₂.instr = 102)　⇒　100 补填为 if a<b goto 102

③ S.nextlist := B.falselist = {101}——循环唯一出口，留给上层

④ gen('goto' M₁.instr)　⇒　104: goto 100（目标已知，直接写入，无需回填）

⑤ 上层回填：backpatch(S.nextlist = {101}, 105)　⇒　101 补填为 goto 105

避坑

本章三个高频错误：记反、误回填、把地址当成值

❌ or 回填真链、and 回填假链
✅ 记反整题崩盘。口诀：or 假才继续、and 真才继续——or 填 B₁ 的 falselist，and 填 B₁ 的 truelist。
❌ 104 那条 goto 100 是 backpatch 填出来的
✅ gen('goto' M₁.instr) 执行时 M₁.instr = 100 早已记下，目标直接写入；同理，叶子 E → id 只传地址、不生成指令，给 id 开临时变量是浪费。
❌ 三地址＝三个内存地址；E.addr 存的是值
✅ 名字、常量、临时变量都算「地址」，是操作数位置的统称；E.addr 装的是「结果存放在哪」，编译期还没有值。
