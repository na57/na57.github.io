主线

名字的住址问题分四步解决，末端是两笔代价

1三地址码里全是名字 → 名字住在哪：按寿命分代码 / 静态 / 栈 / 堆四区
2一次调用要记什么 → 活动记录七字段，调用序列与返回序列分工铺设
3嵌套过程的非局部变量 → 访问链按深度差跳，display 换成一次查表
4寿命不定的数据 → 堆与垃圾回收，代价是碎片与回收停顿
这条链就是本章目录：四区（7.1）→ 活动记录（7.2）→ 访问链与 display（7.3–7.4）→ 堆与回收（7.5）。
动机

三地址码全是符号，CPU 只认地址——名字必须安家

第6章留下的三地址码：x := t1、call quicksort, 2——全是名字。后端动工前先答三问：住哪个区、住多大、住多久。

😇 全放静态区？
quicksort 递归调自己，两份局部量 m、n 必须同时在场——一个地址放不下两个值。
🙂 全放栈上？
new 出来的对象、被闭包捕获的变量，比创建它的调用活得久——弹栈即毁装不下。
💡 本章方案：按寿命分租——寿命等于整个程序的住静态区，等于一次调用的住栈，说不准的住堆。
7.1

名字的住处由寿命决定：地址空间分四区

区域存什么大小何时确定寿命
代码区编译出的目标指令编译时整个运行期
静态数据区全局变量、static 变量、常量表编译时（可定址）整个运行期
栈（Stack）活动记录：参数、局部数据、返回地址调用时压入，返回时弹出一次调用期间
堆（Heap）运行时申请的数据（new / malloc）运行时，时机不定由程序或垃圾回收决定
三种策略：静态分配（Static Allocation）编译时钉死 · 栈式分配（Stack Allocation）随调用进退 · 堆式分配（Heap Allocation）时机交给运行时。
7.1

栈与堆对向生长，共用一整块空闲区

flowchart TB A[代码区] --> B[静态数据区] B --> C[堆：向高地址生长] C -. 中间是共用空闲区，相遇才算耗尽 .-> D[栈：向低地址生长]
两者需求都无法预知（递归多深？申请多少？）→ 从同一块空闲区两端相向推进，增长只是挪一个边界指针；同向生长会让中间空洞永远无法互借。
例子

能静态就静态：编译期定址零开销，递归逼出栈

例 7.1-A：静态区基址 4096，按声明顺序、4 字节对齐依次摆放：

名字大小编译期偏移运行时地址
全局整型 g404096
静态数组 buf[0..9]4044100
常量表16444140
$$\text{addr}(x) = \text{base}_{\text{static}} + \text{off}(x)\quad\text{——off 由声明顺序与对齐在编译期算定}$$
对 g 的引用直接写成绝对地址 4096，零运行时开销；但递归的两份局部值同时在场，静态区一个地址放不下——只能上栈。
7.2

一次调用领一个档案袋：活动记录的七个字段

过程的一次执行 = 活动（Activation）；它在栈上占的数据块 = 活动记录（Activation Record），俗称栈帧（Stack Frame）。

字段内容不存它会怎样
实在参数调用者算好的实参值被调用者拿不到输入
返回值交还给调用者的结果函数结果无处交接
控制链（Control Link）指向调用者的活动记录返回时栈无法弹回调用现场
访问链（Access Link）指向词法上直接外层的最近一次活动找不到外层声明的非局部变量
保存的机器状态返回地址、调用时的寄存器值不知回哪继续，调用者现场全乱
局部数据本过程声明的变量递归时新旧值互相覆盖
临时变量表达式中间结果（如 t1）寄存器不够时无处可溢出
7.2

调用序列铺床、返回序列收床：谁的信息谁负责

阶段步骤执行者为什么是它
调用序列算实参，写入被调用者帧的参数区调用者只有它知道传什么
保存返回地址（调用点下一条指令）调用者只有它知道调用点在哪
设控制链指向自己的帧；按规则设访问链调用者它知道自己帧位置与词法嵌套
调用序列保存将被覆盖的寄存器等机器状态被调用者只有它知道自己要用哪些
初始化局部数据，开始执行函数体被调用者局部数据只有它自己清楚
返回序列写返回值；恢复机器状态，按控制链弹栈跳回被调用者现场是它保存的，由它还原
分工铁律：只有自己知道的信息，由自己处理——这也是 ABI 与调用约定的来源。
7.3

一个 Pascal 快排，看清嵌套深度与词法外层

过程嵌套深度词法外层
sort（带数组 a、变量 x）1无
readarray / exchange / quicksort2sort
partition（用 a、v，调 exchange）3quicksort
嵌套深度（Nesting Depth）= 词法上被几层过程包住。访问链的一切计算都从深度出发。
flowchart TB S[sort 深度1：数组 a、变量 x] --> R[readarray 深度2] S --> E[exchange 深度2] S --> Q[quicksort 深度2：k、v] Q --> P[partition 深度3：i、j]

词法嵌套树：exchange 的外层是 sort——记住这点，后面要考。

7.3

同一时刻栈上五个活动：控制链回家，访问链认祖

flowchart TB S[sort 帧：a 在偏移12，x 在偏移56] --> Q1[quicksort（1，9）帧：k 在20，v 在24] Q1 --> Q2[quicksort（1，3）帧：k 在20，v 在24] Q2 --> P[partition（1，3）帧：i 在24，j 在28] P --> E[exchange（1，3）帧：i 在12，j 在16] Q1 -. 访问链 .-> S Q2 -. 访问链 .-> S P -. 访问链 .-> Q2 E -. 访问链 .-> S

实线 = 控制链（指向调用者）· 虚线 = 访问链（指向词法外层）——注意 exchange 跨过 partition 直达 sort。

7.3

建链只数深度：同级复制，外层走 np − ne + 1 步

情形含义被调用者的访问链
ne = np + 1直接嵌在调用者体内（quicksort 调 partition）= 调用者的帧本身
ne = np同级，词法外层相同（quicksort 递归调自己）复制调用者的访问链
ne < np声明在更外层（partition 调 exchange）沿访问链走 np − ne + 1 步，落点即是
演示：partition（深度 3）调 exchange（深度 2）→ 走 3 − 2 + 1 = 2 步：partition → quicksort(1,3) → sort。落点正是 exchange 的词法外层 ✓
演练

跳数等于深度差：沿访问链找非局部变量

$$\text{跳数} = n_p - n_a,\qquad \text{addr}(x) = \text{沿访问链解引用 }(n_p - n_a)\text{ 次后的帧指针} + \text{off}(x)$$

① v（声明于深度 2 的 quicksort）：走 3 − 2 = 1 步，partition → quicksort(1,3)；地址 = fpq2 + 24。

② a、x（声明于深度 1 的 sort）：走 3 − 1 = 2 步，partition → quicksort(1,3) → sort；addr(a[i]) = fpsort + 12 + 4×i，addr(x) = fpsort + 56。i = 3 时 a[3] 在 fpsort + 24。

③ 对照：exchange（深度 2）里访问 x，走 2 − 1 = 1 步：exchange → sort——沿控制链只会撞进 partition 的 i、j。

难点

控制链是回家的路，访问链是找词法祖先的路

🏠 控制链（Control Link，动态链）
指向调用者的活动记录；回答「谁调用我」；返回时用它弹栈；调试器的栈回溯沿它走。
🧭 访问链（Access Link，静态链）
指向词法直接外层的最近一次活动；回答「我的外层在哪」；找非局部变量只能用它。
exchange 的调用者是 partition，访问链却指向 sort——沿控制链找 a，只会撞进 partition 的 i、j。控制链随调用历史变化，而 a 永远声明在 sort：动态的路找不到静态的家。
C 没有嵌套函数，帧里通常只有控制链——这正是只学过 C 的人第一次见访问链会发懵的原因。
7.4

display：用一张小表把跳链换成查表

display（词法层显示器）：全局数组 d[]，d[k] 恒指向当前活跃、深度为 k 的最近活动的帧 → addr(x) = d[k] + off(x)，与深度差无关。维护：调用时存旧 d[k] 入新帧、令 d[k] 指向新帧；返回时恢复。

方案单次访问（深度5 → 深度1）每次调用/返回维护空间
访问链4 次间接访存 + 1 次取数 = 5 次设 1 条链：1 次写每帧 1 个指针
display1 次查 d[1] + 1 次取数 = 2 次存旧值 + 写新值 + 恢复：约 3 次写全局数组，长度 = 最大嵌套深度
合起来算：1 次非局部访问时 6 对 5 打平；100 次时 501 对 203，display 大胜；调用勤而查询少时维护费纯亏。嵌套普遍很浅（很少超 3 层），多数编译器用访问链就够。
7.5

空闲 300 却申请不到 250：堆的外部碎片

例 7.5-A：堆为地址 1000–1599 共 600 字节，初始一整块空闲。

步操作结果（占用 / 空闲）
1alloc(200) → AA: 1000–1199；空闲 1200–1599（400）
2alloc(200) → BB: 1200–1399；空闲 1400–1599（200）
3alloc(100) → CC: 1400–1499；空闲 1500–1599（100）
4free(B)空闲两块：1200–1399（200）与 1500–1599（100）
5alloc(250) → 失败空闲共 300 字节，最大的连续块只有 200
空闲总量够，却没有连续大块可用——碎片（Fragmentation）。合并相邻块、换适配策略只能缓解，不能根除。
7.5

引用计数怕循环，标记-清扫要停顿

机制做法优点致命短板
引用计数
（Reference Counting）		每对象记「几个指针指向我」，归零立即回收即时回收，开销均摊收不掉循环引用：环上计数都 ≥ 1，永不归零
标记-清扫
（Mark-and-Sweep）		从根（栈、寄存器、静态区的指针）标记可达对象，再扫堆回收未标记者能收循环垃圾：不可达即死需暂停程序遍历全堆（停顿）
栈是自动售货机，找零全自动；堆是仓库，必须有管理员盘点。Python：引用计数为主、循环检测 GC 为辅——双机制才补上循环引用这个洞。
避坑

本章三个高频误区，逐个扫雷

❌ 局部变量一定在栈上
✅ 栈分配的前提是寿命严格等于一次调用：被闭包带走会「逃逸」到堆，过大的局部数组栈装不下；递归过程的局部变量也绝不能住静态区。
❌ 控制链和访问链是同一个东西
✅ 控制链答「谁调用我」（动态），访问链答「词法外层在哪」（静态）。沿控制链找非局部变量必走错——partition 调 exchange 就是反例。
❌ display 严格优于访问链
✅ display 的维护费每次调用/返回照交，与查询次数无关。选型看「非局部访问次数 ÷ 调用次数」；嵌套浅时访问链就够。
