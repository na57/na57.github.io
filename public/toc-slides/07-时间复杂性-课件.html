主线

一把尺子五个刻度，从「要等多久」一路逼到 P 对 NP

1算得出的问题要等多久？——把耗时写成输入长度 n 的函数 f(n)
2大 O 记号只看渐近骨架：常数因子与低阶项一律忽略
3多项式时间 P 钉住「有效可解」——与机型无关的分界线
4NP 刻画「验证易」：证书 + 多项式时间验证者
5多项式归约 + Cook–Levin：逼出 NP 完全与 P 对 NP 悬案
这条链就是本章目录：7.1 大 O → 7.2 P → 7.3 NP → 7.4 归约与 NP 完全 → 7.5 Cook–Levin → 7.6 清误区。
动机

「可判定」不等于「算得动」：$2^n$ 步等于永远跑不完

第 5 章证明了一大批问题不可判定——但反过来，「可判定」也不够看：一个判定算法若要跑 $2^n$ 步，输入稍大就等于永远跑不完。

$$2^{40}\ \text{步} \approx 1.1\times 10^{12}\ \text{步}；\qquad 2^{100}\ \text{步，每秒十亿步也要约 } 4\times 10^{13}\ \text{年}$$
🔬 精确步数
依赖机器细节与指令集，换个机型就变——没有讨论价值
📈 渐近骨架
只问「输入变大时谁先失控」——这才是问题的内在难度
💡 本章方案：固定输入长度 n，记算法最坏步数为运行时间 f(n)，再用大 O 记号抽象。
7.1 定义

模型只差平方：单带要 $n^2$ / $n\log n$，多带只要 $n$

大 O：$f(n)=O(g(n))$ 若 $\exists\, c, n_0$，使 $n\ge n_0$ 时 $f(n)\le c\cdot g(n)$——上界不唯一，总报最紧的；小 o：$f/g\to 0$，严格低阶（如 $n\log n=o(n^2)$）。

$$f(n)=5n^3+2n^2+22n+6=O(n^3)\qquad(\text{取 } c=6,\ n\ge 10\ \text{时 } 2n^2+22n+6\le n^3)$$
判定 $A=\{0^k1^k\}$思路轮数总时间
M₁ 朴素配对（单带）往返划掉一对 0、1$n/2$ 轮 × $O(n)$$O(n^2)$
M₂ 隔位消去（单带）每趟隔位划去 + 奇偶校验$O(\log n)$ 轮 × $O(n)$$O(n\log n)$
M₃ 复制比对（多带）0 段复制到带 2，双头同步比对1 轮 × $O(n)$$O(n)$
关键一跃

「有没有多项式算法」与机型无关，但大 O 不等于实用

$$\text{任何 } t(n)\text{ 时间的多带机，都能被单带机在 } O\!\left(t(n)^2\right)\text{ 内模拟}$$
$$\boldsymbol{n^2 \text{ 与 } n^3 \text{ 算同一档；}\ n \text{ 与 } 2^n \text{ 才是两档——「是否存在多项式算法」划在任何合理模型上都一样}}$$
⚠️ 大 O 是渐近骨架，不是工程指标：$n^{100}$ 也是「多项式」，$0.001\cdot 2^n$ 在 $n\le 40$ 时反而更快。它回答「规模变大谁先失控」，不回答「这个实例跑几秒」。
7.2 定义

P ＝ 确定性单带机 × 多项式时间，「有效可解」就此钉死

🖥️ 确定性单带图灵机
故意用最朴素的机型——机型越弱定义越硬；反正模型间只差多项式
⏱️ 多项式时间
存在常数 k，步数 ≤ n 的 k 次方——门槛极低，k＝100 也算
$$\boldsymbol{P=\bigcup_{k\ge 1}\mathrm{TIME}(n^k)}$$
读法：所有「存在某个 k，能在 n 的 k 次方步内判定」的语言打包在一起。已知成员：PATH、素数判定（AKS, 2002）、最大流、线性规划。
7.2 手算

标记法四轮扫出通路：$O(n^3)$ 把 $n!$ 踩在脚下

① 给起点 s 打标记

② 扫全部边：a 已标记、b 未标记且有边 (a,b) → 标 b

③ 重复 ② 直到一轮没有新标记

④ t 被标记 → 接受；否则拒绝

$$\le n\ \text{轮} \times O(m)\ \text{每轮} = O(n\cdot m) = O(n^3)\ \Longrightarrow\ \mathrm{PATH}\in P$$

按空格 / → 逐步展开

flowchart LR s(("s")) --> a(("a")) a --> b(("b")) s --> c(("c")) c --> b b --> t(("t"))
标记顺序：s → a、c → b → t，共 4 轮 → 接受
对照：枚举所有路径有 $n!\approx (n/e)^n$ 条——超指数；标记法利用了可达性「可传递、可贪心扩展」的结构。
7.3 动机

PATH 加上「每个顶点恰好一次」——没人会解，给答案却能秒验

🟢 PATH（在 P 里）
有向图 s 到 t 有路即可——标记算法 $O(n\cdot m)$
🔴 HAMPATH（无人会解）
要求经过每个顶点恰好一次——至今无多项式算法（没人找到 ≠ 证明没有）
但有人递来一条声称可行的路径，你 $O(n)$ 就能核对：相邻顶点都有边吗？每个顶点恰好一次吗？——验证易、求解未必易，一大批自然问题都是这个脾气。
7.3 定义

NP ＝ 证书 ＋ 多项式时间验证者，CLIQUE 的证书就是 k 个名字

📜 证书 c（certificate）
答案的「证据」，长度 ≤ 输入的多项式——是「标准答案」
🧑‍⚖️ 验证者 V（verifier）
多项式时间算法——是「阅卷老师」
$$\boldsymbol{A\in NP \iff \exists\,\text{多项式时间 }V:\ w\in A \Leftrightarrow \exists c\ (|c|=\mathrm{poly}(|w|)),\ V\text{ 接受 }\langle w,c\rangle}$$

例 3：CLIQUE ∈ NP。证书 ＝ k 个顶点的名单；验证者逐对查边，共 $\binom{k}{2}=O(k^2)$ 对 ✓。但「找到」这份名单，已知最好仍是指数枚举。

等价定义：存在非确定图灵机多项式时间判定 A——「猜」对应证书 c，「验」对应 V（NP 名字的来源）。
关系

P ⊆ NP ⊆ EXPTIME 两环好证，「P ＝ NP？」无人能答

关系一句话论证
$P \subseteq NP$P 中的算法自己就是验证者：忽略证书直接判定
$NP \subseteq EXPTIME$证书只有 $2^{\mathrm{poly}(n)}$ 个候选，逐个验证即指数上界
$P \stackrel{?}{=} NP$未知——「验证易」是否蕴含「求解易」？
⚠️ NP 的 N 是 Nondeterministic（非确定），不是 Non-polynomial。恰恰相反：$P\subseteq NP$，NP 里的问题全都有指数级算法——读成「不可解」是本课程流传最广的错误。
7.4 定义

难度沿箭头传递：任一 NP 完全问题进 P，则 P ＝ NP

$$A\le_p B \iff \exists\,\text{多项式可计算 } f:\quad w\in A \Leftrightarrow f(w)\in B$$
  • 推论 ①：$A\le_p B$ 且 $B\in P \Rightarrow A\in P$（归约 + 解 B，多项式复合仍多项式）
  • 推论 ②：$A\le_p B$ 且 A 很难 $\Rightarrow$ B 至少同样难——难度沿箭头传递
$$\boldsymbol{B\ \text{是 NP 完全} \iff \text{① } B\in NP;\ \ \text{② } \forall A\in NP,\ A\le_p B\ (\text{NP 难})}$$
任一 NP 完全问题落入 P ⟹ P = NP——它们是 NP 中「最难」的一群：一荣俱荣，一损俱损。
7.4 手算 · 互动

三条规则把公式变成图：9 个顶点、跨组连边、k ＝ 子句数

$$\varphi=(x_1\lor x_1\lor x_2)\land(\neg x_1\lor\neg x_2\lor\neg x_2)\land(\neg x_1\lor x_2\lor x_2)$$

① 顶点：每个字面量的每次出现是一个顶点，按子句分组 —— 3 个子句 → 9 个顶点

② 边：两顶点连边 ⟺ 来自不同子句且标签不矛盾（x 与 ¬x 不连）——跨组全连，只删矛盾对

③ 目标：$k = $ 子句数 $= 3$；扫一遍公式即完成构造，$O(\text{子句数}^2)$，多项式 ✓

7.4 证明

满足赋值变出 3-团，3-团读回不矛盾赋值

⇒ φ 可满足 ⟹ 有 3-团
每个子句取一个真字面量：跨组 ✓（连边条件 1）；同真的标签不可能矛盾 ✓（条件 2）→ 两两有边，成 3-团
⇐ 有 3-团 ⟹ φ 可满足
同组不连边 ⟹ 3 个顶点各占一组；矛盾对无边 ⟹ 标签全赋真不冲突；每个子句收获一个真字面量

本例：团 $\{x_2@1,\ \neg x_1@2,\ \neg x_1@3\}$ 读回 $x_2=1,\ x_1=0$，回代三个子句全真 ✓

归约三板斧：① 给构造（多项式时间）② ⇒ 解变解　③ ⇐ 解读回解。⇐ 最易漏——必须论证目标解的「额外自由度」不会造假。
7.5 定理

tableau 把任意非确定计算冻成公式——SAT 是 NP 完全

$A\in NP$ ⟹ 非确定机 $N$ 在 $n^k$ 步内判定。把 $N$ 在 $w$ 上的一条分支铺成画面表（tableau）：$n^k\times n^k$ 的表，第 $i$ 行 = 第 $i$ 步格局。变量 $x_{i,j,s}$：第 $i$ 行 $j$ 列的格子是符号 $s$，共 $O(n^{2k})$ 个。

子句部件管什么规模
$\varphi_{\mathrm{cell}}$每格恰好一个符号$O(n^{2k})$
$\varphi_{\mathrm{start}}$第 1 行钉死为起始格局 $q_0 w$$O(n^{k})$
$\varphi_{\mathrm{move}}$每相邻两行是 N 的一步合法转移（逐 2×3 窗口查）$O(n^{2k})$
$\varphi_{\mathrm{accept}}$某格出现接受状态 $q_{\mathrm{accept}}$$O(n^{2k})$
$$\boldsymbol{\varphi=\varphi_{\mathrm{cell}}\land\varphi_{\mathrm{start}}\land\varphi_{\mathrm{move}}\land\varphi_{\mathrm{accept}}},\quad |\varphi|=O(n^{2k});\qquad \varphi \text{ 可满足} \iff N \text{ 接受 } w \iff w\in A$$
7.5 直觉

头一步最多移一格——所以 2×3 窗口就够看住整张表

格局 $i+1$ 与格局 $i$ 的差别只可能出现在读写头附近：头下符号改写、头左/右移一格，其余照抄。

$$\text{每个 } 2\times 3 \text{ 窗口合法} \iff \text{整步合法}；\qquad \text{合法窗口样式由 } \delta \text{ 决定，只有有限多种}$$

逐窗口枚举合法样式写成析取：每窗口 $O(1)$ 大，共 $O(n^{2k})$ 个窗口 ⟹ $\varphi_{\mathrm{move}}$ 仍多项式。

💡 一句话看穿 Cook–Levin：计算 = 一堆局部一致性约束；SAT = 约束满足的通用语言。格子像格子、起步像起步、步步像转移、结局像接受——任何 NP 问题的验证过程都能铺成 tableau，所以 SAT 难 ⟺「验证与求解的差距」本身难。
7.6 避坑

三个最流行的误解，一个比一个坑

❌ 「NP 就是不可解」
✅ NP 问题全有指数算法（枚举证书逐个验）。难算＝已知算法慢；不能算＝算法不存在——中间隔着整个第 5 章。
❌ 「P vs NP 只是理论游戏」
✅ 现代密码学（RSA、椭圆曲线）赌的就是「验证易、求逆难」；物流调度、芯片布线、蛋白质折叠全是 NP 难——追不追最优解全看这题答案。
❌ 「证明 NP 完全 ＝ 判死刑」
✅ 只排除「所有实例都多项式可解」；近似算法、参数化、特殊结构、工业 SAT 求解器（千万变量照跑）都是活路——是换赛道的信号，不是终点。
