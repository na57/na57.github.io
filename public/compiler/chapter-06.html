6.1为什么需要中间代码：语法树和机器码之间隔着什么

第5章给了我们 SDT 这把"扳手"：翻译规则挂在产生式上，随分析过程自动触发。但它留下一个问题——触发的动作到底产出什么？假设直接产出目标机器码，麻烦立刻上门：x86 有寄存器分配和寻址模式，ARM 有另一套；想换一个目标机，整个后端推翻重写；想在生成前做优化，面对的是机器细节的海洋。m 种源语言配 n 种目标机，就要写 m×n 个编译器。

出路是在语法树与机器码之间插一层中间表示（Intermediate Representation, IR）：前端只负责产出 IR，后端只负责把 IR 变成目标码，优化器在 IR 上做文章。m 个前端加 n 个后端，就覆盖了 m×n 种组合。本章使用一种低层 IR——三地址码（Three-Address Code）。

三地址码的形式约束只有一条：每条指令至多有一个运算符。典型形态是 x = y op z。指令里的"地址"只有三种：

地址种类说明例子
名字（Name）源程序中的变量名，经符号表指向其存储位置a、b、position
常量（Constant）源程序中直接出现的字面量60、3.14
编译器临时变量（Temporary）编译器为暂存中间结果而新造的名字t1、t2、t3

常见三地址指令一览（后两类本章只露脸，不展开）：

指令形式含义
x = y op z双目运算赋值（op 为 +、-、*、/ 等）
x = op y单目运算赋值（如 x = minus y）
x = y复制指令
goto L无条件跳转到标号 L
if x relop y goto L条件跳转（relop 为 <、>、== 等）
x = y[i]　/　x[i] = y数组读 / 写（寻址细节在 6.5 方向，本书后文展开）
param x / call p, n / return y过程调用三件套（第7章运行时环境展开）

三地址码是"文本"，落到编译器内部要变成可操作的数据结构。最常用的实现是四元式（Quadruple）：每条指令一条记录，固定四个字段——op（运算符）、arg1（第一操作数）、arg2（第二操作数）、result（结果）。字段用不上就留空。

完整例：x = a + b * c。运算符优先级决定先乘后加，三地址码把一个运算符拆一条：

地址指令
1t1 = b * c
2t2 = a + t1
3x = t2

对应的四元式表（赋值指令不用 arg2，留空）：

地址oparg1arg2result
1*bct1
2+at1t2
3=t2x

呼应第1章。第1章开场那个例子 position = initial + rate * 60，当时我们说"编译器会把它翻译成一组机器指令"。现在你可以写出它的三地址码版本：t1 = rate * 60；t2 = initial + t1；position = t2。从"隐约知道"到"随手写出"，就是本章的距离。

💡 关键一跃

三地址码是把语法树拍平成线性指令序列：每个临时变量名，恰好对应原树的一个内部节点。树没了，但求值顺序被显式固定下来——这正是后端需要的形态。

⚠️ 常见误区

两个误区。其一，"三地址"不是指三个内存地址——名字、常量、临时变量都算作"地址"，它是"操作数位置"的统称。其二，三地址码不唯一：t1 = b*c 与 t2 = a+t1 谁先谁后都可以，只要不破坏数据依赖；教科书给的是与语法树后序遍历一致的那种。

6.2表达式的翻译：E.addr、gen() 与临时变量怎么接力

上一节说清了"产什么"——三地址码。这一节回答"怎么产"：能不能不先建语法树、在语法分析的过程中直接把指令吐出来？可以，这叫增量翻译（Incremental Translation）：每条产生式归约时，顺手把对应的三地址指令追加到输出流里。

机制只有三个零件：

  • 属性 E.addr：表达式 E 的值存放在哪个地址（名字或临时变量）。注意不是值本身。
  • 函数 gen()：向输出流追加一条三地址指令。
  • 函数 new Temp()：分配一个从未用过的临时变量名（t1、t2……）。配合 top.get(id.lexeme) 从符号表取变量的存储位置。

把这三个零件挂到表达式文法上，得到如下 SDD 片段（用第5章的记法，语义规则在归约时执行）：

产生式语义规则说明
S → id = Egen(top.get(id.lexeme) '=' E.addr)把 E 的结果复制给变量
E → E₁ + E₂E.addr := new Temp()；gen(E.addr '=' E₁.addr '+' E₂.addr)先开新临时变量，再生成加法指令
E → -E₁E.addr := new Temp()；gen(E.addr '=' 'minus' E₁.addr)单目减
E → ( E₁ )E.addr := E₁.addr括号不生成指令，地址直接传递
E → idE.addr := top.get(id.lexeme)叶子：地址就是变量本身，不生成指令

完整手算例：a = b + -c + d。设指令从地址 100 开始。加法左结合，LR 分析的归约顺序是：先归约 -c，再归约 b + (-c)，再归约 (b + -c) + d，最后归约赋值。逐产生式走一遍：

步骤归约所用产生式动作生成的指令
1E → -E₁（E₁.addr = c）E.addr := t1；gen100: t1 = minus c
2E → E₁ + E₂（b 加 t1）E.addr := t2；gen101: t2 = b + t1
3E → E₁ + E₂（t2 加 d）E.addr := t3；gen102: t3 = t2 + d
4S → id = E（a 接 t3）gen103: a = t3

最终四元式表（地址 100–103）：

地址oparg1arg2result
100minusct1
101+bt1t2
102+t2dt3
103=t3a
💡 关键一跃

E.addr 是一根接力棒：每个子表达式算完，把"结果存在哪"交给父节点；父节点拿着两个孩子的地址，开一个新临时变量，生成一条指令。指令生成的顺序 = 归约的顺序，恰好就是安全的求值顺序。

⚠️ 常见误区

两个误区。其一，E.addr 存的是地址不是值——写"E.addr := E₁.addr + E₂.addr"是把两个地址拼成指令文本，不是把两个数相加。其二，叶子 E → id 不生成指令，只传递地址；给 id 也开临时变量是浪费，会凭空多出一堆复制指令。

6.3布尔表达式与短路：跳转地址还不知道，怎么生成跳转指令

表达式的翻译解决了，但程序里另一类式子更棘手：控制流条件。if (x != 0 && y/x > 1) 里的布尔表达式，你以为它要算出一个 0 或 1 存起来？其实绝大多数语言采用短路求值（Short-Circuit Evaluation）：or 左边为真就不再算右边，and 左边为假就不再算右边。这不只是省时间——x != 0 先挡一道，y/x 才不会除零，短路是语义的一部分。

短路求值告诉我们：控制流语境里的布尔表达式，本质不是"算出一个布尔值"，而是一段跳转代码——条件成立跳到"真出口"，不成立跳到"假出口"。翻译 B → E₁ rel E₂ 时生成两条指令：

指令形态去向
if E₁.addr relop E₂.addr goto _真出口
goto _假出口

问题来了：生成这两条指令的那一刻，真出口和假出口的地址根本不存在——它们落在后面还没翻译的语句里。难道要为此再扫描一趟源程序？不必。答案是回填（Backpatching）：先把目标留空，把这条指令的地址记在链表里随身带着；等目标地址确定了，回头统一补填。

回填机制的三个操作，签名与作用：

操作作用
makelist(i)造一个只含指令号 i 的新链表，返回表指针
merge(p₁, p₂)把 p₁、p₂ 两条链表合并，返回合并后的表指针
backpatch(p, i)把链表 p 里每一条指令的跳转目标补填为 i

配套的两个属性与一个标记：布尔表达式 B 挂两条链——真链（truelist，所有"该跳真出口但还没填"的指令号）和假链（falselist，同理）。标记非终结符 M → ε 的唯一作用是记下当前位置：M.instr := nextinstr（下一条待生成指令的地址）。

复合布尔表达式的翻译方案（本章最重要的一张表）：

产生式语义规则
B → B₁ or M B₂backpatch(B₁.falselist, M.instr)；B.truelist := merge(B₁.truelist, B₂.truelist)；B.falselist := B₂.falselist
B → B₁ and M B₂backpatch(B₁.truelist, M.instr)；B.truelist := B₂.truelist；B.falselist := merge(B₁.falselist, B₂.falselist)
B → not B₁B.truelist := B₁.falselist；B.falselist := B₁.truelist
B → ( B₁ )B.truelist := B₁.truelist；B.falselist := B₁.falselist
B → E₁ rel E₂B.truelist := makelist(nextinstr)；B.falselist := makelist(nextinstr + 1)；gen('if' E₁.addr relop E₂.addr 'goto _')；gen('goto _')
M → εM.instr := nextinstr

直觉先建立：or 是"左边为假才去算右边"，所以归约 or 时回填的是 B₁ 的假链（填上 B₂ 的入口 M.instr）；and 是"左边为真才去算右边"，回填的是 B₁ 的真链。记反是本章头号错误。

核心完整手算例：a < b or c < d and e < f。and 优先级高于 or，设指令从地址 100 开始。先把整个过程的控制流画出来：

flowchart LR A["a 小于 b？"] -- 真 --> T["B 为真出口"] A -- 假 --> C["c 小于 d？"] C -- 真 --> D["e 小于 f？"] C -- 假 --> F["B 为假出口"] D -- 真 --> T D -- 假 --> F classDef hot fill:#fbeedd,stroke:#c4651f,stroke-width:2.5px,color:#c4651f; classDef danger fill:#fae9e7,stroke:#b03a2e,stroke-width:2.5px,color:#b03a2e; class T hot; class F danger;

逐步生成（每步写出链表状态）：

  1. 翻译 B₁ = a<b（B → E₁ rel E₂）：B₁.truelist = makelist(100) = {100}，B₁.falselist = makelist(101) = {101}。
    生成　100: if a<b goto _　／　101: goto _
  2. M₁ → ε：M₁.instr = nextinstr = 102（这是 B₂ 的入口，先记下）。
  3. 翻译 B₂ = c<d：B₂.truelist = {102}，B₂.falselist = {103}。
    生成　102: if c<d goto _　／　103: goto _
  4. M₂ → ε：M₂.instr = 104。
  5. 翻译 B₃ = e<f：B₃.truelist = {104}，B₃.falselist = {105}。
    生成　104: if e<f goto _　／　105: goto _
  6. 归约 and（B₂ and M₂ B₃）：
    • backpatch(B₂.truelist = {102}, M₂.instr = 104)　⇒　指令 102 补填为 if c<d goto 104；
    • B′.truelist := B₃.truelist = {104}；
    • B′.falselist := merge({103}, {105}) = {103, 105}。
  7. 归约 or（B₁ or M₁ B′）：
    • backpatch(B₁.falselist = {101}, M₁.instr = 102)　⇒　指令 101 补填为 goto 102；
    • B.truelist := merge({100}, {104}) = {100, 104}；
    • B.falselist := B′.falselist = {103, 105}。

对照表——每条指令"生成时长什么样 / 回填后长什么样"：

地址生成时指令链表归属回填后指令
100if a<b goto _B₁.tl={100} → B.tlif a<b goto _（真出口，留给上层回填）

103goto _B₂.fl={103} → B.flgoto _（假出口，留给上层回填）
104if e<f goto _B₃.tl={104} → B.tlif e<f goto _（真出口，留给上层回填）
105goto _B₃.fl={105} → B.flgoto _（假出口，留给上层回填）

最终上交的"欠条"：B.truelist = {100, 104}，B.falselist = {103, 105}。它们要等 6.4 的控制流语句（if / while）来抵债。

💡 关键一跃

回填就是先上车、后补票：跳转指令照常生成，目标栏留空；留空不是遗忘，而是把指令号记进 truelist / falselist 这两本账里，一路带到归约出目标地址的那一刻，用一次 backpatch 统一还清。一趟扫描就够，不用回头重读源程序。

⚠️ 常见误区

三个误区。其一，or 回填 B₁.falselist、and 回填 B₁.truelist——记反整题崩盘，用"or 假才继续、and 真才继续"自查。其二，truelist 里存的是指令号（100、104），不是指令内容。其三，M.instr 必须在 B₂ 生成之前取值——这就是为什么 M 要插在 or / and 与 B₂ 之间。

6.4控制流语句的翻译：if / if-else / while 共用一副骨架

上一节结束在"布尔表达式交出两本欠条：truelist 和 falselist"。谁来还债？使用这个布尔表达式的语句。控制流语句的翻译方案只做两件事：把 B.truelist 回填到语句体的入口，把 B.falselist（连同语句自己的未决跳转）打包成 S.nextlist 交给上层——nextlist 与真链假链是同一种思想，只是从布尔表达式搬到了语句上："我执行完之后该跳去哪，由我的上下文决定"。

三种语句的翻译方案：

语句产生式与语义规则要点
if-then S → if M B then S₁：backpatch(B.truelist, M.instr)；S.nextlist := merge(B.falselist, S₁.nextlist) 真链落语句体入口；假链与语句体的未决跳转一起上交
if-then-else S → if B then M₁ S₁ N else M₂ S₂：backpatch(B.truelist, M₁.instr)；backpatch(B.falselist, M₂.instr)；S.nextlist := merge(merge(S₁.nextlist, N.nextlist), S₂.nextlist)；其中 N → ε { N.nextlist := makelist(nextinstr)；gen('goto _') } N 负责生成"跳过 else 分支"的那条 goto，它的指令号也是一张欠条
while S → while M₁ B do M₂ S₁：backpatch(S₁.nextlist, M₁.instr)；backpatch(B.truelist, M₂.instr)；S.nextlist := B.falselist；gen('goto' M₁.instr) 循环体尾接回条件入口；唯一的出口是 B 的假链

为什么 while 需要两个标记 M₁、M₂？因为要记住两个地址：M₁.instr 是条件 B 的入口（循环体执行完要跳回去），M₂.instr 是循环体 S₁ 的入口（B 为真时落进来）。if 只用记住一个，所以一个 M 就够。

完整手算例：while a < b do x = x + 1，设起始地址 100。逐步执行 while 方案，每次 backpatch 调用都写出来：

  1. M₁ → ε：M₁.instr = nextinstr = 100（条件入口，先记下）。
  2. 翻译 B = a<b（6.3 的方案）：B.truelist = {100}，B.falselist = {101}。
    生成　100: if a<b goto _　／　101: goto _
  3. M₂ → ε：M₂.instr = 102（循环体入口）。
  4. 翻译 S₁ = x = x + 1（6.2 的方案）：
    生成　102: t1 = x + 1　／　103: x = t1。
    赋值语句没有未决跳转：S₁.nextlist = {}（空表）。
  5. 归约 while，四个语义动作逐个执行：
    • backpatch(S₁.nextlist = {}, M₁.instr = 100)：空表，无指令可改（注意：不是这一步生成 goto 100）；
    • backpatch(B.truelist = {100}, M₂.instr = 102)　⇒　指令 100 补填为 if a<b goto 102；
    • S.nextlist := B.falselist = {101}——循环唯一出口，留给上层；
    • gen('goto' M₁.instr)　⇒　生成 104: goto 100（此时 M₁.instr 已知，目标直接写入，无需回填）。
  6. 上层回填：当包含本 while 的外层结构（例如顺序语句 S → S₁ M S₂）翻译到循环之后的第一条指令 105 时，执行 backpatch(S.nextlist = {101}, 105)　⇒　指令 101 补填为 goto 105。

最终指令序列：

地址指令来源 / 回填经过
100if a<b goto 102B 的条件跳转；truelist={100} 被 backpatch 到 M₂.instr=102
101goto 105B 的假链={101}=S.nextlist；由上层回填到循环外第一条 105
102t1 = x + 1循环体（M₂.instr=102）
103x = t1循环体
104goto 100while 方案的 gen('goto' M₁.instr)，目标 100 生成时已知
105…（循环外第一条指令）101 的跳转目标
💡 关键一跃

整个控制流翻译就是三种"接线"：真链接到语句体入口，假链接到下一条语句，循环体尾部接回条件入口。if、if-else、while 长得不同，但骨架完全一样——接线规则写在产生式的语义动作里，分析器走完，线就接好了。

⚠️ 常见误区

三个误区。其一，104 那条 goto 100 不是回填出来的——gen('goto' M₁.instr) 执行时 M₁.instr=100 早已记下，目标直接写入。其二，赋值语句的 nextlist 是空表，不要以为每条语句都带欠条。其三，S.nextlist 里的指令不是 S 自己回填的，是由包含 S 的上层结构负责——101 的 goto 105 就是上层补的。

中间表示（Intermediate Representation）
点击翻面 →

解决问题前端直接产机器码会机器相关、难优化、难移植；有 IR，m 种语言 n 种机器只需 m 个前端加 n 个后端。

概念卡 2
三地址码（Three-Address Code）
点击翻面 →
定义每条指令至多一个运算符、形如 x = y op z 的线性指令序列。
解决问题把树形表达式的求值顺序显式化，又抽象掉寄存器、寻址模式等机器细节。

概念卡 3
四元式（Quadruple）
点击翻面 →
定义三地址码的记录式实现：op、arg1、arg2、result 四个字段，一条指令一行。
解决问题让指令成为可存放、可重排的数据结构——优化器要移动和删除指令。
直觉一张四列表格，编译器后端在这张表上"打算盘"。
误区result 字段放的是名字不是值；赋值指令的 arg2 留空。
何时用第9章数据流分析与机器无关优化直接操作四元式序列。
概念卡 4
短路求值（Short-Circuit Evaluation）
点击翻面 →
定义or 左真即真、and 左假即假，右侧不再求值的布尔求值策略。
解决问题既是语义要求（x≠0 and y/x>1 防除零），又让布尔表达式天然变成跳转代码。
直觉闯关游戏：or 是第一关过了就通关，and 是第一关挂了就出局。
误区以为布尔表达式总要算出 0/1 存起来——控制流语境下根本不需要这个值。
何时用6.3 跳转代码与回填的语义基础。
概念卡 5
回填（Backpatching）
点击翻面 →
定义跳转目标未知时先生成留空指令并记录指令号，目标确定后统一补填的技术。
解决问题一趟扫描生成跳转代码时"目标在未来"的矛盾，免去第二趟扫描。
直觉先上车后补票：指令号是欠条，backpatch 是还账。
误区以为需要两趟扫描——欠条随身携带，一趟就够。
何时用6.3、6.4 全部布尔与控制流翻译；第8章生成汇编时以"标号"形式再见。
概念卡 6
真链 / 假链（truelist / falselist）
点击翻面 →
定义挂在布尔表达式 B 上的两条指令号链表：所有"该跳真 / 假出口但还没填"的指令。
解决问题跳转目标在 B 的上下文（if / while）里才确定，B 自己翻译时不知道。
直觉两本账："我欠真出口的钱""我欠假出口的钱"，交给上层抵债。
误区以为链表存指令内容——只存指令号；nextlist 是同款思想搬到语句上。
何时用6.3 布尔归约、6.4 控制流语句；习题与考试必考。

📝分层习题

L1 概念辨析

判断正误并说明理由：① "x = a + b * c" 是一条合法的三地址码指令。② 四元式 (op, arg1, arg2, result) 中 result 字段存放运算结果的值。

提示

① 回顾三地址码唯一的形式约束，数数运算符个数。② 区分"名字"与"值"——编译时刻有值吗？

完整解答

① 错。该指令含两个运算符（+ 与 *），违反"每条指令至多一个运算符"。必须拆成两条：t1 = b * c；x = a + t1。

② 错。result 存的是名字（变量名或临时变量名），即结果存放在哪个地址。中间代码生成发生在运行之前，此时根本不存在"值"。把字段理解成值，会导致无法理解"指令可以被重排"——重排的是记录，值是运行时才有的。

L1 概念辨析

下列关于回填的说法，哪一个是正确的？
A. 回填需要对源程序做两趟扫描，第一趟生成指令，第二趟补填地址。
B. truelist 里存放的是跳转到真出口的指令内容。
C. 归约 B → B₁ and M B₂ 时，执行 backpatch(B₁.truelist, M.instr)。
D. M → ε 的语义动作是 backpatch(nextinstr)。

提示

回忆"and 真才继续"的口诀；M 的唯一职责是什么；链表里存的到底是什么。

完整解答

C 正确：and 的语义是"B₁ 为真才需要算 B₂"，所以 B₁ 的真链应回填到 B₂ 的入口 M.instr。

A 错：回填一趟扫描即可，指令号记在链表里随身携带，地址确定时回头补填已生成的指令，不需要重读源程序。B 错：truelist 存的是指令号（如 100、104），不是指令文本。D 错：M → ε 的语义动作是 M.instr := nextinstr——只是记下下一条指令的地址，不做任何回填。

L2 手算推导

把 x = a * b + a * c 翻译成三地址码（从地址 200 开始），列出四元式表；再指出：如果后续优化要省掉一条乘法，它可以从哪两个角度入手？

提示

先乘后加，两个乘法谁先都可以。优化角度：一个看"重复出现的计算"，一个看"代数恒等式"。

完整解答

三地址码（a*b 与 a*c 次序可互换，这里从左到右）：

地址指令
200t1 = a * b
201t2 = a * c
202t3 = t1 + t2
203x = t3

四元式表：

地址oparg1arg2result
200*abt1
201*act2
202+t1t2t3
203=t3x

省一条乘法的两个角度：

① 公共子表达式消除：若程序中 a*b（或 a*c）在别处已被算过且 a、b 未变（例如后文还有 y = a * b + 1），则 t1 可直接复用，那次乘法不必重算——若表达式写成 x = a*b + a*b，则 200 与 201 完全重复，t2 := t1，直接省一条。

② 代数恒等式：a*b + a*c = a*(b+c)，可改写为 t1 = b + c；x = a * t1，两条乘法变一条。

两者都属于第9章机器无关优化的范畴——本章的翻译器只管忠实翻译，"看出来能省"是优化器的事。

L2 手算推导

用回填方案翻译 if a < b then x = 1 else x = 2（起始地址 100），写出完整指令序列，并逐个写出每次 backpatch 调用及其参数。

提示

产生式骨架 S → if B then M₁ S₁ N else M₂ S₂。别漏掉 N → ε 生成的"跳过 else"那条 goto——它也是一张欠条。

完整解答

逐步生成：

  1. 翻译 B = a<b：B.truelist={100}，B.falselist={101}。生成 100: if a<b goto _　／　101: goto _。
  2. M₁ → ε：M₁.instr = 102。
  3. 翻译 S₁ = x = 1：生成 102: x = 1。S₁.nextlist = {}。
  4. N → ε：N.nextlist = makelist(103) = {103}；gen('goto _') ⇒ 生成 103: goto _（跳过 else 分支的欠条）。
  5. M₂ → ε：M₂.instr = 104。
  6. 翻译 S₂ = x = 2：生成 104: x = 2。S₂.nextlist = {}。
  7. 归约 if-then-else：
    · backpatch(B.truelist={100}, M₁.instr=102) ⇒ 100 改为 if a<b goto 102；
    · backpatch(B.falselist={101}, M₂.instr=104) ⇒ 101 改为 goto 104；
    · S.nextlist := merge(merge({}, {103}), {}) = {103}。
  8. 上层在翻译到下一条语句（地址 105）时：backpatch(S.nextlist={103}, 105) ⇒ 103 改为 goto 105。

L3 建模应用

把下面这段"找数组前 n 项最大值"的程序翻译成完整三地址码（自己编排地址，数组元素按 8 字节寻址），并标出所有 truelist / falselist / nextlist 的最终去向：

while i < n do if a[i] > m then m = a[i]

提示

外层套 while 方案、内层套 if-then 方案。数组读 a[i] 拆两条：t = i * 8；t' = a[t]。注意内层 if 的 nextlist 会变成 while 循环体的 S₁.nextlist，最终被回填到循环条件入口。

完整解答

设起始地址 100。逐层生成：

  1. M₁ → ε：M₁.instr = 100。翻译外层条件 B₁ = i<n：生成 100: if i<n goto _（B₁.tl={100}）／101: goto _（B₁.fl={101}）。
  2. M₂ → ε：M₂.instr = 102。
  3. 翻译内层条件 B₂ = a[i]>m：先数组寻址，102: t1 = i * 8；103: t2 = a[t1]；再比较，104: if t2>m goto _（B₂.tl={104}）／105: goto _（B₂.fl={105}）。
  4. M₃ → ε：M₃.instr = 106。翻译内层语句体 m = a[i]（朴素翻译，重新寻址一次）：106: t3 = i * 8；107: t4 = a[t3]；108: m = t4。S.nextlist={}。
  5. 归约内层 if-then：backpatch(B₂.tl={104}, M₃.instr=106) ⇒ 104 改为 if t2>m goto 106；内层 if 的 nextlist := merge(B₂.fl={105}, {}) = {105}。
  6. 归约外层 while（S₁ 即内层 if，S₁.nextlist={105}）：
    · backpatch(S₁.nextlist={105}, M₁.instr=100) ⇒ 105 改为 goto 100；
    · backpatch(B₁.truelist={100}, M₂.instr=102) ⇒ 100 改为 if i<n goto 102；
    · S.nextlist := B₁.falselist = {101}；
    · gen('goto' M₁.instr) ⇒ 109: goto 100。
  7. 上层把 {101} 回填到循环外第一条指令 110：101 改为 goto 110。

解析：D 对——while 唯一的出口是"条件为假"，所以 S.nextlist := B.falselist。A 错：B.truelist 已被 backpatch 到循环体入口 M₂.instr，不再是未决跳转。B 错：S₁.nextlist 已被 backpatch 到循环条件入口 M₁.instr（循环体执行完要回去再测条件）。C 错：这是 if-then 的公式，搬到 while 上会把已还清的 S₁.nextlist 又当成欠条上交。
