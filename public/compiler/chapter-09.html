9.1优化之前先划地盘：基本块与流图

上一章结束时，我们手里是一段长长的三地址码序列。想优化它，第一个问题是：在多大的范围内优化？逐句看，看不到「这句算了两遍」；整段看，跳转让顺序乱成一团。编译器的做法是先把代码切成若干基本块（Basic Block）：一段最长的不含跳转的直线代码——只能从第一句进入，从最后一句离开，中途不跳出也不跳入。

为什么基本块是优化的天然单位？因为块内控制流是平凡的：只要进了第一句，后面每句都必然执行、且只按书写顺序执行。于是块内可以放心地做公共子表达式消除、复写传播，不必担心「跳走」带来的意外。

划分算法（首领规则）。先把每条「首领」语句找出来，首领到下一首领之前的全部语句就是一个基本块。三条规则：

  1. 整个序列的第一条语句是首领；
  2. 任何跳转的目标语句是首领；
  3. 紧跟在跳转语句之后的那条语句是首领。

本章用一个贯穿到底的示例程序。源代码（int 数组按 4 字节寻址，所以下标 i 要乘 4 作偏移）：

💡 关键一跃

基本块是「控制流的原子」：块内直线到底，块间才有岔路。优化因此分两层——块内靠局部恒等变换，块间靠流图上的数据流分析。本章 9.2 只在 B3 里打转，9.3 起就要看图说话了。

⚠️ 常见误区

以为「基本块 = 一个语句序列里任意切一段」。错：首领规则求的是最长直线段——把 (4)…(14) 再切成两块并不违法，但会让块内优化看不全、白丢机会。反过来，把 (2) 并进 B1 就错了：别人能跳到 (2)，它必须独立成块。

9.2块内的三板斧：公共子表达式、复写传播、死代码

9.1 把地盘划好了，主战场是 B3 的 12 条语句。先不碰循环结构，只在块内做三件最安全的事。盯着原始代码看三秒钟就能发现浪费：(3)、(5)、(10) 三条都在算 4 * i。

第一板斧：公共子表达式消除（Common Subexpression Elimination）。若表达式 E 在前面已经算过，且从那时到现在 E 的运算分量都没被重新定值，那么再算一遍纯属浪费——直接用上次的结果。在 B3 内扫描：

2(10) t8 = 4 * i 同理，(3) 到 (10) 之间 i 未被改删 (10)，把 (11) 里的 t8 换成 t1同上：同一个 i，同一个乘积

第二板斧：复写传播（Copy Propagation）。形如 x = y 的复写语句之后，凡是能用 y 的地方尽量用 y，让 x 的引用消失。看末尾两句：t9 = i + 1; i = t9。第二句是复写，它说「i 现在的值就是 t9」，而 t9 除了这一句再无别的用处——干脆把定值直接写给 i：

变换前变换后为什么语义不变
t9 = i + 1

第三板斧：死代码消除（Dead Code Elimination）。定值之后再也不被使用的语句就是死代码，删掉。上一步里 t9 的定值已随复写传播一起消失；判定「死活」的标准是活跃性——离开这条语句时变量还会不会被读。三板斧之后 B3 从 12 条瘦到 10 条，而且两条乘法、两次访存的方向已经清清楚楚。

💡 关键一跃

三板斧的共同套路：先找一个「两处必相等」的事实，再把其中一处换掉，最后删掉变空的语句。公共子表达式靠「运算分量没变」，复写传播靠「x 就是 y」，死代码靠「没人再读」——每个变换背后都站着一个「为什么相等」的理由，这个理由在 9.5 会被数据流分析严格化。

⚠️ 常见误区

以为「两个表达式字面相同就能消」。错：还必须确认从上次计算到这次使用之间，所有运算分量都没有被重新定值。若 (5) 和 (3) 之间插了一句 i = i + 1，两个 4 * i 字面相同、值却不同，消掉就改语义了。块内靠眼睛能查，跨块就必须靠到达定值分析（9.5）。

回忆 9.2-1

从第一次计算到第二次出现之间，表达式的所有运算分量都没有被重新定值。满足时两次的值必相等，替换不改变语义。

点击翻面 →

复写传播把 x = y 之后的 x 引用都换成 y，往往使 x 的定值语句（或 y 的临时定值）无人再读，变成死代码；死代码消除负责收尾删除。一个制造垃圾，一个倒垃圾。

9.3循环里的钱最好赚：不变式外提与全局公共子表达式

块内的便宜捡完了。但真正的浪费在循环里：一句代码若被循环执行 n 次，把它从循环里拿出去一次，就省下 n − 1 次。9.2 后的循环体里有一条可疑语句：t5 = x + 1——x 在循环里从不改变，1 是常量，每次迭代却都重算一遍。

这就是循环不变式（Loop-Invariant）：运算分量在循环内都不改变的表达式。把它搬到循环之前只算一次，叫循环不变式外提（Loop-Invariant Code Motion），落脚的块叫前头块（Preheader），插在循环入口之前。

但不是所有不变式都能提。外提前必须逐条检验前置条件（龙书给出的充分条件）：

  1. 被提语句所在的基本块支配循环的所有出口，或者被定值的变量离开循环后不再活跃（本例 t5 在 B4 无人使用，满足后者）；
  2. 循环中该变量只有这一条定值（t5 只在 (7) 定值一次 ✓）；
  3. 循环中对它运算分量的使用，其到达定值不能来自循环内这条语句之外的其他循环内定值（x 在循环内根本没有定值 ✓）。

三条全过，外提安全。B1 变为 i = 0; t5 = x + 1，循环体里删掉 (7)。

顺便收获一次全局公共子表达式消除。看 B4 的 (15) v = x + 1：它与外提到 B1 的 t5 = x + 1 字面相同。这次跨越了基本块，条件更严——需要确认从 B1 到 B4 的任何路径上 x 都没被重定值（查流图：x 只在程序开头定值 ✓），且 B1 支配 B4（所有到 B4 的路都经过 B1 ✓）。于是 (15) 改成 v = t5。反例对照：假如 B4 里有一句 w = a[i]，需要算 4 * i——它和 B3 里的 t1 = 4 * i 字面相同，却不能消：B3 里算 t1 时的 i 是循环内的值，到达 B4 的 i 已是 n，两次计算的运算分量来自不同定值。这就是全局消除必须查「到达定值」的原因。

外提前外提 + 全局公共子表达式消除后

💡 关键一跃

循环优化的本质是把「每次迭代都付的钱」改成「进循环前付一次」。外提对付不变式，强度削弱（9.4）对付归纳变量——一个是把计算搬走，一个是把计算变便宜。

⚠️ 常见误区

以为「不变式无脑外提总是安全」。反例：若循环体在某条路径上可能一次都不执行，而提出的语句可能出错（如除以零、数组越界）或改变被读的值，外提就会让本来不执行的语句强制执行。前置条件里的「支配所有出口或不活跃」正是在防这类事故。

9.4把乘法变加法：归纳变量与强度削弱

循环体里还剩一条乘法每次迭代都算：t1 = 4 * i。它和不变式不同——值确实每次都变，但变得极有规律：i 每次加 1，4 * i 就每次加 4。

形如「每次迭代增加同一个常量」的变量叫归纳变量（Induction Variable）：i 是基本归纳变量，t1 = 4 * i 属于 i 的归纳变量族（线性函数 4i + 0）。强度削弱（Strength Reduction）把乘法换成加法：引进新变量跟踪 4 * i，进循环前初始化，每次迭代加 4。

完整推导（一步不跳）。设新变量仍叫 t1：

步骤动作依据
1前头块加初始化：t1 = 4 * 0 = 0（一般形式 t1 = 4 * i₀，i₀ 是 i 的初值）进循环时 i = 0，t1 应等于 4·i = 0
2循环体里 t1 = 4 * i 改为直接使用 t1 的当前值维护不变式「t1 ≡ 4·i」
3在 i = i + 1 之后补一句 t1 = t1 + 4i 增 1 ⟹ 4·i 增 4，加法跟上
4复写传播与死代码消除收尾中间引入的临时名被清掉

还能再进一步：归纳变量消除。削弱之后，i 在循环体里只剩两个用处：判断 if i >= n 和自我递增 i = i + 1。判断可以改写到 t1 身上：i >= n ⟺ 4·i >= 4·n ⟺ t1 >= n4（前头块预计算 n4 = 4 * n）。于是 i 整个变成死代码，删掉 i = 0 与 i = i + 1。最终全章示例的优化终点：

对比账：原始循环体 12 条语句、每次迭代 2 次乘法（4*i 与 t4*t5）；现在 7 条、1 次乘法。n = 1000 时省下约 5000 条中间指令和 1000 次乘法。语义为什么不变：每一步都只替换了「必相等」的值——4·i 与 t1 在每轮迭代开始时相等（归纳不变式，可对迭代次数做数学归纳证明），i >= n 与 t1 >= 4n 在 i ≥ 0 时等价。

💡 关键一跃

强度削弱把「位置相关的贵运算」换成「增量相关的便宜运算」：乘法换加法只是一档，同思路还能把幂运算换乘法、把数组寻址换指针自增。识别前提是变量随循环线性变化——这正是数据流分析能自动发现的事实。

⚠️ 常见误区

以为「见到循环里的乘法就削」。两个坑：① 若乘数不是归纳变量而是每次随机变化，没有增量规律可循，削弱无从谈起；② 归纳变量消除改写循环判断时，若步长或初值为负、或循环可能溢出，t1 >= 4n 与 i >= n 的等价性会被破坏——优化器必须先确认符号与范围，否则宁可不削。

削弱后 i 只剩循环判断和自增两个用处；把判断改写到族内变量上（i >= n ⟺ t1 >= 4n），i 就再无读者，其定值成为死代码，可一并消除。

9.5凭什么敢改：数据流分析与保守原则

前面每条优化后面都跟着一句「为什么语义不变」，理由全是「某个值到这里一定还等于那个值」。这种事实不能靠眼睛瞄，要靠一套系统在流图上算出来——数据流分析（Data-Flow Analysis）。它的典型代表是到达定值（Reaching Definitions）：问「变量 x 的哪些定值，可能沿着某条路径到达这个点」。

为每个基本块 B 定义两个集合：gen[B]（B 内生成、且块尾仍有效的定值）与 kill[B]（B 内对同一变量的重定值，把别处的定值杀掉）。然后解前向方程组：

IN[B] = ⋃P 是 B 的前驱 OUT[P]　　OUT[B] = gen[B] ∪ ( IN[B] − kill[B] )

完整手算例。取一个简化小流图（变量只有 i 和 s，共 4 条定值）：

flowchart TB B1["B1：d1 i = 0；d2 s = 0"] --> B2["B2：循环头判断"] B2 --> B3["B3：d3 s = s + t2；d4 i = i + 1"] B3 --> B2 B2 --> B4["B4：出口"] classDef hot fill:#fbeedd,stroke:#c4651f,stroke-width:2.5px,color:#c4651f; class B2 hot;
图 9.2　到达定值手算用的小流图。B2 有两个前驱（B1 与 B3），正是「并」发生的地方。

先算 gen/kill（d1 定 i、d2 定 s、d3 定 s、d4 定 i；同变量的定值互相杀）：

块gen（本块生成且活到块尾的定值）kill（本块杀掉的别处定值）
B1{d1, d2}{d3, d4}（B3 里对 s、i 的定值全被杀）
B2∅（判断语句不定值）∅
B3{d3, d4}{d1, d2}
B4∅∅

初始：所有 IN/OUT 为 ∅。按 B1 → B2 → B3 → B4 的顺序迭代，第一轮：

块IN = 各前驱 OUT 之并OUT = gen ∪ (IN − kill)
B1∅（无前驱）{d1,d2} ∪ (∅ − {d3,d4}) = {d1,d2}
B2OUT[B1] ∪ OUT[B3] = {d1,d2} ∪ ∅ = {d1,d2}∅ ∪ ({d1,d2} − ∅) = {d1,d2}
B3OUT[B2] = {d1,d2}{d3,d4} ∪ ({d1,d2} − {d1,d2}) = {d3,d4}
B4OUT[B2] = {d1,d2}{d1,d2}

第二轮（第一轮的 OUT 反馈回来，回边 B3 → B2 开始起作用）：

块INOUT相比上轮
B1∅{d1,d2}不变
B2{d1,d2} ∪ {d3,d4} = {d1,d2,d3,d4}{d1,d2,d3,d4}✱ 变了：回边把 B3 的定值带回循环头
B3{d1,d2,d3,d4}{d3,d4} ∪ ({d1,d2,d3,d4} − {d1,d2}) = {d3,d4}OUT 不变
B4{d1,d2,d3,d4}{d1,d2,d3,d4}✱ 变了

第三轮各集合不再变化——到达不动点，迭代结束。读法示例：B2 入口处的 i 可能来自 d1（首次进循环）也可能来自 d4（上一圈迭代），两者都「到达」——所以 9.3 说「B3 里算 t1 时的 i 与 B4 处的 i 不是同一回事」，凭据就在这里。

活跃变量分析（Live-Variable Analysis）简述：方向相反（后向），方程是 IN[B] = use[B] ∪ ( OUT[B] − def[B] )，OUT[B] 取各后继 IN 之并；回答「离开这点后变量还会不会被读」。9.2 删 t9、9.4 删 i，判活的都是它。

💡 关键一跃

所有数据流分析都是同一个模子：给每块定 gen/kill（或 use/def）局部事实，沿流图边反复「并/交 + 传递」直到不动点。方向（前向/后向）、汇合运算（并=可能，交=必然）、传递函数三选一组合，就得到到达定值、活跃变量、可用表达式等不同分析。

⚠️ 常见误区

以为「分析算不出 = 可以优化」。恰恰相反，全章奉行保守原则：宁可不优化，不可改语义。分析只能回答「必然成立」的事实；凡是不能证明安全的变换，一律不做。指针别名、数组下标越界都可能让分析给出「也许被改」的答案，优化器就只能收手——这不是无能，是底线。由此也引出本章的两个遗留问题：① 先做哪个优化收益不同（阶段排序问题）；② 过程内分析看不到函数调用彼岸，极限已至——过程间分析与硬件级并行，交给第10、11章。

📝分层习题

L1 概念辨析判断并说明理由：「只要两段代码算出的结果相同，优化器就可以把其中一段换成另一段。」
提示

想想「结果相同」是只指这一条语句的输出，还是包括之后所有可观察的行为？副作用和活跃性扮演什么角色？

完整解答
错误。「结果相同」只是必要条件之一，远非充分：① 被替换的语句可能有副作用（数组存储、函数调用、可能的异常如除零），换顺序或删掉会改变可观察行为；② 替换后变量的活跃性可能改变，波及后续的寄存器分配与死代码判定；③ 「相同」必须在当前上下文中可证明——这正是数据流分析的工作，不能证明时按保守原则不许换。所以正确说法是：只有在能证明语义等价（含副作用与活跃性）时才可以替换。

逐条对照首领三规则，注意「一定」两个字。

C 错。首领三规则是：第一条、跳转目标、跳转之后那条。跳转语句本身不是天然首领——它只有当恰好是别的跳转的目标（或第一条）时才是首领。例如本章 B3 里的 (14) goto (2) 就只是块尾而非首领。A、B、D 正是三规则原文。

句1：这章解决什么问题？——
参考答案：不改变程序语义的前提下，让中间代码跑得更快——把翻译前就存在的重复计算、无效语句和循环内浪费，系统地找出来并消掉。
