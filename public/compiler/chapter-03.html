3.1为什么词法分析要独立成一个阶段

第2章我们手工写了一个扫描器，每次读一个字符、判断它是不是字母、数字、运算符。代码能跑，但每换一种语言就要重写一遍，而且和语法分析器缠在一起，改一处动全身。这带出一个问题：能不能把"认字"这件事从"组句"里拆出来，单独做、单独换？

答案是把编译器前端劈成两半：词法分析器（Lexical Analyzer / Scanner）负责把字符流切成记号流，语法分析器（Parser）负责在记号流上分析结构。第4章会专门讲语法分析；本章只解决前一半。

切分之前，先把三个最容易混淆的术语钉死：

  • 词素（Lexeme）：源程序中实际出现的一段字符，比如 if、count、3.14、<=。
  • 记号（Token）：词素的类别或抽象名字，比如 if 的记号是 if，count 的记号是 id，3.14 的记号是 num。
  • 模式（Pattern）：描述某类词素长什么样的规则，比如"标识符 = 字母开头，后接字母或数字"。
💡 关键一跃

词素是"实物"，记号是"类别标签"，模式是"类别的长相说明书"。扫描器每次读到一段词素，就贴上一张记号标签，顺便记录属性值（比如 id 的名字、num 的数值）。

记号不是裸标签，它带属性（Attribute）。例如读到 count = count + 1，扫描器产出：

词素记号属性
countid指向符号表中 "count" 的指针
=assign—
countid指向符号表中 "count" 的指针
+plus—
1num整数值 1

词法分析器独立出来的工程好处：

  • 去空白与注释：语法分析器不用关心空格、换行、注释，只看到干净的记号流。
  • 统一标识符：把 count、sum、x1 都归为 id，语法规则里只写 id 一次。
  • 行列号报错：扫描器天然按行扫，记录每个记号的行列号，出错信息才能指到人看懂的行。

还有一个扫描时的核心原则：最长匹配（Maximal Munch）。当多个模式都能匹配当前前缀时，选能吃掉最长字符的那个。比如 <= 应该识别为一个记号 relop，而不是先识别 < 再识别 =。

⚠️ 常见误区

误区：把"词素"和"记号"混为一谈，说"记号 if 就是字符串 if"。错。词素 if 是源文件里的两个字符；记号 if 是编译器内部的一个枚举值或整数编码。词素可以有无数个（如 id 对应 count、sum、x1），记号只有有限个。

3.2用什么描述记号：正则表达式

上一节说了要把词法分析独立出来，但独立之后拿什么来"描述"每类记号的长相？不能再用自然语言，必须给机器能读、能机械执行的规格。这就是正则表达式（Regular Expression）。

正则表达式由三种基本构造和三种运算组成：

  • ε：空串，不匹配任何字符。
  • 单字符 a：匹配字符 a 本身。
  • 并 |：r|s 匹配 r 或 s 匹配的任意串。
  • 连接：rs 匹配先 r 后 s 的串。
  • 闭包 *：r* 匹配 r 的 0 次或多次重复。

优先级：* > 连接 > |。括号用来打破优先级。

为了方便书写，常用扩展运算符：

运算符含义例子
r+正闭包：r 的 1 次或多次重复digit+ 匹配一个或多个数字
r?可选：r 出现 0 次或 1 次(+|-)? 匹配可选符号
[a-z]字符类：a 到 z 任意一个字符[a-zA-Z] 匹配任意字母

多个正则表达式可以起名字、分层定义，这叫正则定义（Regular Definition）：

letter → a | b | … | z | A | … | Z
digit → 0 | 1 | … | 9
id → letter ( letter | digit )*

本章后面反复用到的三个正则定义：

记号正则定义说明
idletter ( letter | digit )*字母开头，后接字母或数字
numdigit+ ( . digit+ )? ( E ( + | - )? digit+ )?整数、小数、科学计数法
relop< | <= | = | <> | > | >=六种关系运算符
💡 关键一跃

正则表达式是"规格说明书"，不是"执行程序"。它只说明什么串合法，不说明怎么一步步去认。把规格变成执行，是后面两节的事。

⚠️ 常见误区

误区：以为正则表达式可以匹配任意嵌套结构，比如"任意层数的配对括号"。错。正则表达式没有记忆，数不了未配对左括号的数量；配对括号需要上下文无关文法（第4章）。

3.3从正则到机器：Thompson 构造

正则表达式只是规格，机器不认规格，只认状态转移。Thompson 构造回答：给定任意正则表达式，怎么机械地拼出一台等价的 NFA？

不确定有限自动机（NFA，Nondeterministic Finite Automaton）和 DFA 的差别在于：同一状态对同一输入符号可以有多条出边，还可以有 ε-转移（不读字符就跳）。这让它非常灵活，但也无法直接执行——机器每一步不知道选哪条路。

Thompson 构造的五条基本规则，每条规则只引入少量新状态：

flowchart TB subgraph basic["基本规则"] direction LR A1["i"] -->|"ε"| A2["f"] B1["i"] -->|"a"| B2["f"] end subgraph combine["组合规则"] direction TB C1["i"] -->|"ε"| C2["r 的 NFA"] C1 -->|"ε"| C3["s 的 NFA"] C2 -->|"ε"| C4["f"] C3 -->|"ε"| C4 D1["i"] --> D2["r 的 NFA"] --> D3["s 的 NFA"] --> D4["f"] E1["i"] -->|"ε"| E2["r 的 NFA"] E2 -->|"ε"| E3["f"] E1 -->|"ε"| E3 E3 -->|"ε"| E1 end
图 3.1 Thompson 构造的五种基本片段：ε、单字符、并、连接、星。

关键观察：每条规则最多新增 2 个状态（新的初态和新的终态）。因此正则长度是 n，Thompson 构造出的 NFA 状态数 ≤ 2n。

现在做本章最重要的完整手算例：为正则 (a|b)*abb 构造 NFA。

按构造规则，从内到外逐层拼装：

  1. 字符 a：状态 2 -a→ 3
  2. 字符 b：状态 4 -b→ 5
  3. 并 a|b：新初态 1、新终态 6；1 -ε→ 2、4；3 -ε→ 6、5 -ε→ 6
  4. 星 (a|b)*：新初态 0、新终态 7；0 -ε→ 1、7；6 -ε→ 1、7
  5. 连接 abb：在 7 后接 a（7-a→8）、b（8-b→9）、b（9-b→10）

最终 NFA 恰好 11 个状态，编号 0–10：

💡 关键一跃

Thompson 构造的精髓是"局部替换"：把正则表达式看成一棵语法树，每个树节点对应一个 NFA 片段，片段之间只用 ε-边缝合。因为每条规则只加 2 个状态，所以整个 NFA 的大小和正则表达式长度成正比。

⚠️ 常见误区

误区：以为 NFA 的 ε-转移可以"随便加"。错。ε-转移是构造规则精确给出的，多一条少一条都会改变识别的语言。手算时必须严格按五条基本规则拼。

3.4从 NFA 到 DFA：子集构造

NFA 很灵活，但机器执行不了——每一步面对多条 ε-边和多条同符号出边，不知道选哪条。要执行，必须把 NFA 变成确定有限自动机（DFA，Deterministic Finite Automaton）：每个状态对每个输入符号只有唯一出边，没有 ε-转移。

子集构造的核心思想：DFA 的一个状态 = NFA 的一个状态集合。读入一个字符后，DFA 从"当前可能处于哪些 NFA 状态"跳到"读完这个字符后可能处于哪些 NFA 状态"。

两个必须钉死的定义：

  • ε-闭包（ε-closure）：从某个 NFA 状态集合出发，只走 ε-边能到达的所有状态的集合。
  • move（T, a）：从集合 T 中某个状态出发，读入字符 a 后能到达的 NFA 状态集合（先不走 ε）。

对上面的 (a|b)*abb NFA 做完整手算：

第一步：求初态

A = ε-closure({0}) = {0, 1, 2, 4, 7}

第二步：求 A 的出边

  • move(A, a) = {3, 8}；ε-closure({3, 8}) = {1, 2, 3, 4, 6, 7, 8} = B
  • move(A, b) = {5}；ε-closure({5}) = {1, 2, 4, 5, 6, 7} = C

第三步：求 B 的出边

  • move(B, a) = {3, 8}；闭包 = B（自环）
  • move(B, b) = {5, 9}；ε-closure({5, 9}) = {1, 2, 4, 5, 6, 7, 9} = D

第四步：求 C 的出边

  • move(C, a) = {3, 8}；闭包 = B
  • move(C, b) = {5}；闭包 = C（自环）

第五步：求 D 的出边

  • move(D, a) = {3, 8}；闭包 = B
  • move(D, b) = {5, 10}；ε-closure({5, 10}) = {1, 2, 4, 5, 6, 7, 10} = E

第六步：求 E 的出边

  • move(E, a) = {3, 8}；闭包 = B
  • move(E, b) = {5}；闭包 = C

DFA 共有 5 个状态：A、B、C、D、E。A 是初态；E 包含原 NFA 的接受态 10，因此 E 是唯一接受态。

💡 关键一跃

子集构造把"不确定性"变成了"状态"。NFA 里"可能在这里，也可能在那里"的迷茫，被 DFA 里"我正处于这个集合"的确定所替代。代价是状态数可能指数膨胀，但对词法分析器而言，实际语言的状态数通常很小。

⚠️ 常见误区

误区：以为 ε-闭包只算一层。错。ε-闭包是传递闭包，必须一直走到没有新的 ε-边为止。比如 ε-closure({0}) 不仅要加 1 和 7，还要从 1 继续加 2 和 4。

3.5DFA 最小化

子集构造保证"正确"，不保证"最省"。DFA 里可能混进等价状态——它们对未来的行为完全一样，却占着不同的编号。最小化要回答：怎么把等价状态合并，得到状态数最少的 DFA？

方法叫划分求精（Partition Refinement）：先把所有状态按"接受/非接受"劈成两组，然后反复检查——如果同组里两个状态对某个输入符号跳到不同组，就把它们拆开。直到不能再拆为止。

继续上例，对 5 状态 DFA 做完整手算：

初始划分：接受态一组，非接受态一组

Π₀ = { {A, B, C, D}, {E} }

第一轮检查：看 {A, B, C, D} 内部

  • A：a→B（组内），b→C（组内）→ 行为一致
  • B：a→B（组内），b→D（组内）→ 行为一致
  • C：a→B（组内），b→C（组内）→ 行为一致
  • D：a→B（组内），b→E（异组）→ 与 A/B/C 不一致，拆出
Π₁ = { {A, B, C}, {D}, {E} }

第二轮检查：看 {A, B, C} 内部

  • A：a→B（组内），b→C（组内）→ 一致
  • B：a→B（组内），b→D（异组）→ 与 A/C 不一致，拆出
  • C：a→B（组内），b→C（组内）→ 一致
Π₂ = { {A, C}, {B}, {D}, {E} }

第三轮检查：看 {A, C} 内部

  • A：a→B（{B}组），b→C（{A,C}组内）
  • C：a→B（{B}组），b→C（{A,C}组内）
  • 两者行为完全一致，不再拆分

最终划分 Π = { {A,C}, {B}, {D}, {E} }，最小 DFA 有 4 个状态。把 {A,C} 合并为新状态 AC，转换表如下：

可以证明：对语言 (a|b)*abb，4 个状态是下限。直观地说，必须记住"最近是否看到了 abb 的后缀进度"，四种进度对应四种必不可少的状态。

💡 关键一跃

最小化的本质是"按未来行为分类"。两个状态只要对所有可能的后缀输入都给出相同的接受/拒绝答案，它们就是同一个状态。划分求精只是把这个定义机械化了。

⚠️ 常见误区

误区：以为最小化可以合并"看起来相似"的状态。错。判断标准不是结构相似，而是"对所有后缀的行为一致"。两个状态哪怕结构完全不同，只要行为等价就能合并。

解决问题把"认字"从"组句"中拆出来，让扫描器只输出类别和属性。
直觉词素是实物，记号是标签，模式是标签的说明书。
误区把记号和词素混为一谈，以为记号就是字符串本身。
何时用第3章全章；第4章语法分析器消费记号流。
概念卡 2
正则表达式（Regular Expression）
点击翻面 →
定义由 ε、单字符、并 |、连接、闭包 * 构成的有限表达式，描述一个正规语言。
解决问题给每类记号提供机器可读的规格说明书。
直觉正则表达式是"什么样"，不是"怎么认"。
误区以为正则表达式能数配对括号或任意嵌套结构。
何时用3.2 节定义记号；3.3 节 Thompson 构造把它变成 NFA。
概念卡 3
NFA（Nondeterministic Finite Automaton）
点击翻面 →
定义允许同一状态对同一符号有多条出边、允许 ε-转移的有限自动机。
解决问题作为正则表达式到 DFA 之间的中间表示，构造简单。
直觉NFA 是"可以同时走多条路"的并行探索器。
误区以为 NFA 比 DFA 更强大；其实两者识别能力等价。
何时用3.3 节 Thompson 构造的产物；3.4 节子集构造的输入。
概念卡 4
ε-闭包（ε-closure）
点击翻面 →
定义从 NFA 状态集合出发，只走 ε-边能到达的所有状态的集合（含传递）。
解决问题把"不读字符就能跳"的隐性可能性全部显式化。
直觉ε-闭包是"免费瞬移"能达到的最远范围。
误区只算一层 ε-边，忘记传递闭包。
何时用3.4 节子集构造中，每次 move 之后都要取 ε-闭包。
概念卡 5
子集构造（Subset Construction）
点击翻面 →
定义把 NFA 的每个状态集合映射为 DFA 的一个状态，通过 move+ε-闭包生成转换表。
解决问题把无法直接执行的 NFA 变成可机械执行的 DFA。
直觉DFA 状态 = NFA 的"可能位置集合"。
误区以为子集构造一定导致状态爆炸；实际词法分析中通常很温和。
何时用3.4 节核心算法；生成词法分析器的必经之路。
概念卡 6
DFA 最小化（Minimization）
点击翻面 →
定义通过划分求精合并等价状态，得到状态数最少的 DFA。
解决问题消除冗余状态，减少词法分析器的内存占用和表项。
直觉按"对未来所有后缀的行为"分类，行为一致即同一状态。
误区以为最小化改变识别的语言；其实它保持语言不变。
何时用3.5 节；Lex/Flex 生成最终扫描器前的优化步骤。

📝分层习题

L1 概念辨析判断：正则表达式 (a|b)*abb 和 (a|b)*a(a|b)(a|b) 描述的是同一个语言吗？
提示

注意第二个表达式中 a 后面跟两个任意字符，这限定了结尾三个字符的结构。

完整解答

不是同一个语言。

(a|b)*abb 要求串以 abb 结尾；而 (a|b)*a(a|b)(a|b) 只要求倒数第三个字符是 a，后两位可以是任意 a 或 b。例如 abba 属于后者（倒数第三是 a），但不属于前者（不以 abb 结尾）。

易错点：看到 (a|b)* 就以为"后面随便"，忽略了对结尾结构的具体约束。

L1 概念辨析选择：在词法分析中，"最长匹配"原则主要用于解决什么问题？
提示

想想 <= 和 < 、= 的关系。

完整解答

答案：解决多个模式同时匹配当前前缀时的选择问题。

例如扫描到 <= 时，< 和 <= 都能匹配前缀。最长匹配选吃掉字符更多的 <=，避免错误地拆成两个记号。

易错选项：以为最长匹配用来处理关键字 vs 标识符（那是优先级规则）；或以为用来处理嵌套括号（正则做不到）。

L2 手算推导用 Thompson 构造画出正则 (a|ε)b* 的 NFA，并数出状态总数。
提示

先构造 a、ε、b 的基本块，再做 a|ε 的并，然后 b* 的星，最后连接。

完整解答

状态总数：10 个。

逐块计算：

  • a：2 个状态（新初态+新终态）
  • ε：2 个状态
  • a|ε：并规则新增 2 个状态，内部保留 a 和 ε 的 4 个状态，共 6 个
  • b：2 个状态
  • b*：星规则新增 2 个状态，内部保留 b 的 2 个状态，共 4 个
  • 连接：不新增状态，直接把 (a|ε) 的终态通过 ε-边接到 b* 的初态

总计 6 + 4 = 10 个状态。

NFA 结构（文字版）：状态 0/1 是总初态/终态；0-ε→{2,4}（进入 a 块和 ε 块）；a 块 2-a→3；ε 块 4-ε→5；3-ε→6，5-ε→6；6-ε→{7,9}（进入 b*）；b* 中 7-ε→8（b块），8-b→9，9-ε→{7,10}，10 是 b* 终态；10-ε→1。

易错点：以为连接也新增 2 个状态；或忘记 ε 本身也是一个基本块，占 2 个状态。

L2 手算推导对正则 ab(a|b)* 做子集构造，给出 NFA→DFA 状态集合表与最终 DFA 转换表。
提示

先写 Thompson NFA 的关键状态，再按 move+ε-闭包逐步填表。注意 ab 是前缀，(a|b)* 是循环。

完整解答

Thompson NFA 关键状态编号（简化标记）：

  • s0 -a→ s1
  • s1 -ε→ s2
  • s2 -b→ s3
  • s3 -ε→ s10（进入星）
  • s10 -ε→ {s8, s11}
  • s8 -ε→ {s4, s6}
  • s4 -a→ s5
  • s6 -b→ s7
  • s5 -ε→ s9，s7 -ε→ s9
  • s9 -ε→ {s8, s11}
  • s11 是接受态

子集构造步骤：

  • A = ε-closure({s0}) = {s0}
  • move(A,a)={s1} → ε-closure = {s1,s2} = B
  • move(A,b)=∅
  • move(B,b)={s3} → ε-closure = {s3,s10,s8,s4,s6,s11} = C
  • move(C,a)={s5} → ε-closure = {s5,s9,s8,s4,s6,s11} = D
  • move(C,b)={s7} → ε-closure = {s7,s9,s8,s4,s6,s11} = E
  • move(D,a)={s5} → D；move(D,b)={s7} → E
  • move(E,a)={s5} → D；move(E,b)={s7} → E

验证：ab 走 A-a→B-b→C 接受；abba 走 A-a→B-b→C-b→E-a→D 接受。

L3 建模应用为一个迷你语言设计正则定义集：标识符、整数、关系运算符、关键字 if/else。说明关键字 vs 标识符冲突如何处理，并指出这些定义在 Lex/Flex 中对应什么。
提示

先写各记号的正则表达式，再想"当 if 同时匹配关键字模式和标识符模式时怎么办"。

完整解答

正则定义集：

  • digit → 0|1|…|9
  • letter → a|b|…|z|A|…|Z
  • id → letter(letter|digit)*
  • num → digit+
  • relop → <|<=|=|<>|>|>=
  • if → if
  • else → else

关键字 vs 标识符冲突：

if 和 else 都符合 id 的模式。解决办法是两条规则叠加：

  1. 最长匹配：if 和 id 都匹配前缀 "i" 时，id 匹配更长，但整个输入就是 "if" 时两者等长。
  2. 优先级：当多个模式匹配相同最长长度时，在 Lex/Flex 中写在前面（定义顺序靠前）的规则胜出。因此把 if、else 的定义放在 id 之前，扫描器遇到 "if" 优先返回记号 if，遇到 "ifx" 则由最长匹配归为 id。

在 Lex/Flex 中的对应：

每个正则定义对应 Lex 规则区的一条模式-动作对。Lex 把全部正则定义合并成一个大 NFA，再用子集构造转成 DFA，最后最小化生成 C 代码的扫描器。我们手写的 id、num、relop、if、else 五条规则，在 Lex 源程序里就是五行模式加返回动作。

下列关于词素、记号、模式的说法，哪一项正确？
  • A. 记号就是源程序中出现的字符串本身

自测 2
正则表达式 ab|c 的优先级等价于下列哪一项？
  • A. (ab)|c
  • B. a(b|c)

  • D. a(b|c)，因为并优先级高于连接

  • C. r|s 新增 4 个，r* 新增 2 个
  • D. 各新增 4 个状态

自测 4
在子集构造中，ε-closure(T) 的定义是？

  • B. 从 T 出发只走一条 ε-边到达的状态
