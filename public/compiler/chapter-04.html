4.1语法分析器要做什么：记号流进去，语法树出来

上一章的词法分析器把字符流切成了记号流：id + id * id。但记号流是扁平的——它不告诉我们 id * id 是一个整体（先乘后加）。语法分析器（Parser）的任务就是：读入记号流，按文法把它组织成嵌套的语法结构（语法树），并在这个过程中发现并报告语法错误。

全章统一使用表达式文法。它有两种写法，本章都会用到：

用途文法特点
自底向上（LR）用：原左递归文法 0: E′ → E（增广）
1: E → E + T　　2: E → T
3: T → T * F　　4: T → F
5: F → ( E )　　6: F → id 		左递归天然表达左结合，但自顶向下用不了
自顶向下（LL）用：消除左递归后 E → T E′
E′ → + T E′ ｜ ε
T → F T′
T′ → * F T′ ｜ ε
F → ( E ) ｜ id 		由原文法消除左递归而来（4.2 节详解），语言不变

面对语法错误，分析器有四个目标：清晰报告错误位置、从错误中恢复继续分析后面的代码、不能慢、不能漏报真错误。本章聚焦"正确输入怎么分析"，错误恢复只记住一个词：恐慌模式（Panic Mode）——报错后跳到某个同步记号（如分号）再继续。

图 4.1 语法分析两大路线：自顶向下像"预言家"先猜结构再验证；自底向上像"考古学家"先把碎片拼起来。

自底向上路线的核心动作是归约（Reduction）：把已看到的某个子串替换回某个非终结符——它是最右推导的逆操作。被替换的那个子串叫句柄（Handle）。4.4 节再精确定义，这里先有直觉：分析的全过程就是反复"找到句柄、把它归约掉"，直到只剩开始符号。

💡 关键一跃

无论自顶向下还是自底向上，本章所有技术的目标都是同一件事：把"下一步该选哪条产生式 / 该不该归约"这个决策，从人的直觉变成一张可以查的表。表从哪来？从文法的 FIRST、FOLLOW 和项集族里机械地算出来。

⚠️ 常见误区

误区："语法分析就是检查括号配不配对"。括号配对只是语法的一小部分；语法分析要对任意上下文无关文法重建完整嵌套结构，还要给出唯一确定的分析步骤——这正是需要形式化方法（FIRST/FOLLOW、项集）而不是手写一堆 if 的原因。

4.2自顶向下的拦路虎，与 FIRST/FOLLOW 这两把钥匙

自顶向下最朴素的实现是递归下降（Recursive Descent）：每个非终结符一个函数，遇到选择就试。但原表达式文法 E → E + T 是左递归（Left Recursion）的——第 2 章已经警告过：函数 E() 一进来就不消耗任何输入再次调用 E()，直接死循环。所以左递归对自顶向下是致命的，必须先消除。

消除左递归是机械的：把 A → A α ｜ β 改写成 A → β A′，A′ → α A′ ｜ ε。对 E → E + T ｜ T 应用，得 E → T E′，E′ → + T E′ ｜ ε；对 T → T * F ｜ F 同理。这就是 4.1 节那张 LL 文法的来历。另一个小手术是提取左因子（Left Factoring）：把 A → α β₁ ｜ α β₂ 的公共前缀 α 提出来，避免试错时反复读同一段输入——一句话带过，本章例子用不上它。

消完左递归还剩一个问题：分析到非终结符 A、当前输入是 id 时，该选 A 的哪条产生式？回答它需要两个集合。

FIRST 集（FIRST Set）：FIRST(α) = 串 α 能推出的所有首终结符的集合；若 α 能推出空串，则 ε ∈ FIRST(α)。它回答："选这条产生式，输入的第一个符号可能是什么？"

FOLLOW 集（FOLLOW Set）：FOLLOW(A) = 在任意句型中可能紧跟在 A 后面的终结符集合（含输入结束标记 $）。它回答："如果 A 推出了空串，我该期待下一个输入是什么？"

完整手算例：对 LL 文法逐项算 FIRST。规则只有两条：终结符的 FIRST 是它自己；对 A → X₁X₂…Xₙ，把 FIRST(X₁) 的非 ε 符号并入 FIRST(A)，若 X₁ 可空再看 X₂，依此类推；全可空则并入 ε。

步骤依据结论
1F → ( E ) 给 FIRST(F) 加入 (；F → id 加入 idFIRST(F) = { ( , id }
2T → F T′：FIRST(T) ⊇ FIRST(F)（F 不可空，不必看 T′）FIRST(T) = { ( , id }
3T′ → * F T′ 加入 *；T′ → ε 加入 εFIRST(T′) = { * , ε }
4E → T E′：FIRST(E) ⊇ FIRST(T)（T 不可空）FIRST(E) = { ( , id }
5E′ → + T E′ 加入 +；E′ → ε 加入 εFIRST(E′) = { + , ε }

完整手算例：逐项算 FOLLOW。规则三条：① 开始符号的 FOLLOW 含 $；② 若 A → α B β，则 FOLLOW(B) ⊇ FIRST(β) − {ε}；③ 若 A → α B 或 A → α B β 且 ε ∈ FIRST(β)，则 FOLLOW(B) ⊇ FOLLOW(A)。

步骤依据结论

FIRST(E) = FIRST(T) = FIRST(F) = { ( , id }　　FIRST(E′) = { + , ε }　　FIRST(T′) = { * , ε }
FOLLOW(E) = FOLLOW(E′) = { ) , $ }　　FOLLOW(T) = FOLLOW(T′) = { + , ) , $ }　　FOLLOW(F) = { * , + , ) , $ }

有了这两个集合，就能判定文法是不是 LL(1) 的（第一个 L = 从左向右扫描，第二个 L = 最左推导，1 = 只向前看 1 个记号）。对每对产生式 A → α ｜ β 检查三条：

✅ LL(1) 三条判定条件

① FIRST(α) ∩ FIRST(β) = ∅（两条路的首符号不撞车）；
② α、β 中至多一个能推出 ε；
③ 若 ε ∈ FIRST(β)，则 FIRST(α) ∩ FOLLOW(A) = ∅（走空的那条路不会和走实的那条路抢同一个输入符号）。
全部通过 ⇒ 文法是 LL(1) ⇒ 可以无回溯预测分析。本节的表达式文法三条全过。

💡 关键一跃

FIRST 消除"开头的不确定性"，FOLLOW 消除"消失（推 ε）后的不确定性"。两个集合合起来，就把"该选哪条产生式"变成查表：看当前输入符号落在哪个集合里，就走哪条路。

⚠️ 常见误区

误区一：FIRST(T′) 只写 {*}，漏掉 ε——只要产生式能推空，ε 必须进 FIRST，它决定预测表里的"消失列"。误区二：算 FOLLOW 时盯着符号的前面。FOLLOW(F) 里的 * 不是因为 T′ → * F T′ 中 * 在 F 前面，而是因为 T → F T′：F 充当 T 的开头，而 T 后面能跟 *（FIRST(T′) 含 *），所以 F 后面也能跟 *。算 FOLLOW 永远只看"B 后面是什么"。

4.3预测分析表：把 FIRST/FOLLOW 压成一张表，让栈来跑

上一节算出了 FIRST 和 FOLLOW，但它带出一个问题：这些集合怎么变成可执行的程序？答案是预测分析表（Predictive Parsing Table）M：行是非终结符，列是终结符（含 $），格子 M[A, a] 填"看到 a 时 A 该用的产生式"。

填表规则（对每条产生式 A → α）：

  1. 对 FIRST(α) 中每个终结符 a，把 A → α 填入 M[A, a]；
  2. 若 ε ∈ FIRST(α)，再对 FOLLOW(A) 中每个符号 b，把 A → α 填入 M[A, b]。

完整手算例：逐条产生式填出整张表。

E′ → + T E′{ + }—M[E′, +]

表配一台"栈驱动"的预测分析器就能跑：栈底放 $、栈顶先放开始符号；每步看栈顶 X 与当前输入 a——X 是终结符且 X = a 就匹配弹出、吃掉输入；X 是非终结符就查 M[X, a]，弹出 X、把产生式右部逆序压栈（这样左端先处理）；查到空格就报错；栈只剩 $ 且输入也只剩 $ 就接受。

💡 关键一跃

预测分析器 = 一张表 + 一个栈 + 一个输入指针。人的全部智慧在造表时一次性付清（FIRST/FOLLOW），运行时只剩机械查表。这就是"不用手写递归"的含义：递归下降里那些手写的 if-else 选择，全被 M 表替代了。

⚠️ 常见误区

压栈方向最易错：输出 A→X₁X₂…Xₙ 后要逆序压栈（先压 Xₙ），保证栈顶是 X₁、与最左推导一致。顺序压栈会让分析从右往左跑，立刻乱套。另一个误区：以为查表查到空格就该"再试试别的产生式"——LL(1) 的意义恰是每格至多一条，空格就是确定的语法错误，没有别的可试。

4.4换一条腿走路：自底向上与 LR(0) 项集族

LL(1) 很优雅，但它太挑文法：左递归必须消、左因子必须提，很多自然文法进不了 LL(1)。4.1 节说过还有第二条腿——自底向上（Bottom-Up）：从记号流出发，反复找句柄做归约，直到归约成开始符号。归约是推导的逆：E ⇒ E+T ⇒ E+T*F 倒过来走，就是把 F 归约成 T、再把 T*F 归约成 T……

关键难题：每步都要回答两件事——当前已看到的部分是不是某个产生式右部的一段？如果是完整的右部（句柄），要不要马上归约？LR 族用一台有穷自动机回答它，自动机的状态就是"项集"。

项（Item，也叫 LR(0) 项）：一条产生式右部某个位置上加一个点"·"。点左边是已看到的，右边是期待看到的。如 T → T * · F 表示"已看到 T*，期待一个 F"。

闭包（Closure）：若项集里有 A → α · B β（点后面是非终结符 B），那接下来看到的任何 B 的开头都合法，于是把 B 的所有产生式 B → · γ 统统补进来，递归直到不增长。

GOTO：GOTO(I, X) = 把 I 中所有"点紧挨 X 左边"的项的点右移一位，再取闭包。它是自动机的转移函数：在状态 I 看到符号 X，就跳到 GOTO(I, X)。

💡 关键一跃

一个项集就是"分析进行到这里时，所有可能的进度快照的并集"。点"·"是进度条：左边是已经匹配进栈的部分，右边是剩下的期望。自动机每读一个符号，所有快照的进度条同步右移一格——并行地跟踪了所有可能的分析路线，这正是 LR 不用回溯的原因。

⚠️ 常见误区

误区：闭包里只补一条产生式。规则是"点后面是非终结符 B ⇒ 把 B 的所有产生式 B→·γ 全部补入，再对新补入的项递归"。I₀ 之所以有 7 个项，正是 E′→·E 牵出 E 的两条、E 又牵出 T 的两条、T 又牵出 F 的两条，连锁到终结符为止。漏补任何一条，后面的 GOTO 全错。

4.5SLR：用 FOLLOW 把项集族压成 ACTION/GOTO 表

上一节的项集族给了我们一台自动机，但它带出一个问题：有的项集里同时存在"点在末尾"的完成项和"点后面还有符号"的期待项。看 I₂：E→T· 说"该按产生式 2 归约了"，T→T·*F 却说"如果下一个是 *，请移入"。纯 LR(0) 分析器在这里无所适从——这就是移入-归约冲突（Shift-Reduce Conflict）。

SLR（Simple LR）的解法朴素而有效：归约动作只在 FOLLOW(左部) 的符号列上填。E→T· 的左部是 E，FOLLOW(E) = {+, ), $}——只有当下一个输入是 +、) 或 $ 时按 2 归约；而 * ∉ FOLLOW(E)，所以 * 列只填移入 s7，冲突消失。直觉：如果 E 后面根本不可能跟 *，那么看到 * 时归约出 E 一定是错的，只能继续移入。

✅ SLR 造表规则

对每个状态 i 与项集 Iᵢ：
① Iᵢ 含 A→α·aβ（a 为终结符）且 GOTO(Iᵢ, a)=Iⱼ ⇒ ACTION[i, a] = s j（移入并进状态 j）；
② Iᵢ 含完成项 A→α·（A≠E′）⇒ 对 FOLLOW(A) 中每个 a，ACTION[i, a] = r k（k 是 A→α 的产生式编号）；
③ Iᵢ 含 E′→E· ⇒ ACTION[i, $] = acc；
④ GOTO(Iᵢ, A)=Iⱼ（A 非终结符）⇒ GOTO[i, A] = j。
所有空格 = 报错。若某格被填了两次 ⇒ 文法不是 SLR 的。

💡 关键一跃

SLR 表 = LR(0) 自动机 + FOLLOW 滤镜。自动机负责"看到了什么"（移入），FOLLOW 负责"什么场合才允许归约"。两张在第 4.2 节为 LL 准备的集合，在 LR 世界原样复用——FIRST/FOLLOW 是全章的通用货币。

⚠️ 常见误区

误区：归约时把 r k 填遍整行。SLR 的 r k 只填 FOLLOW(左部) 那几列——状态 2 的 * 列若也填 r2，就和 s7 冲突了，这张表根本造不出来。另一个误区：以为 ACTION 和 GOTO 是同一张表的两个名字。ACTION 的列是终结符（决定移入/归约/接受/报错），GOTO 的列是非终结符（归约后查下一个状态），运行时两者都查。

🃏概念卡：本章概念的一分钟画像

概念卡 1
FIRST 集（FIRST Set）
点击翻面 →
定义串 α 能推出的所有首终结符的集合；α 可推空则含 ε。
解决问题自顶向下选产生式时，"这条路的开头长什么样"无从知道；FIRST 给出答案。
直觉每条产生式的"门脸招牌"：看一眼招牌就知道该进哪家店。
误区漏掉 ε——只要右部能推空，ε 必须进 FIRST，否则预测表少填一列。
何时用本章填 LL(1) 表；第 5 章语法制导翻译沿语法树算属性时仍以产生式为单位。
概念卡 2
FOLLOW 集（FOLLOW Set）
点击翻面 →
定义句型中可能紧跟在非终结符 A 后面的终结符集合（含 $）。
解决问题A 推空（LL）或完成项归约（SLR）时，"下一个符号该是什么"由它裁决。
直觉A 的"朋友圈"：能在 A 身后出现的符号，才是它消失后合法的接棒者。
误区盯着 A 前面算——FOLLOW 只看 A 后面；且 A→αBβ 中 β 可空时还要并 FOLLOW(A)。
何时用本章 LL(1) 判定、SLR 消冲突；第 6 章中间代码生成的错误处理也用到同步集思想。
概念卡 3
LL(1) 预测分析表（Predictive Parsing Table）
点击翻面 →
定义M[非终结符, 终结符] = 该用的产生式；由 FIRST/FOLLOW 机械填出，每格至多一条。
解决问题把递归下降里手写的分支选择换成查表，实现无回溯的自顶向下分析。
直觉列车时刻表：当前"车站"（栈顶非终结符）+"来车"（输入符号）唯一决定班次。
误区以为空格可以"再试一条"——空格即确定报错；格子有两条以上则文法非 LL(1)。
何时用手写分析器（如 GCC 的递归下降）背后的决策依据；第 5 章的翻译方案嵌在展开动作里。
概念卡 4
句柄与归约（Handle & Reduction）
点击翻面 →
定义句柄 = 与某产生式右部匹配、归约它恰好对应最右推导逆一步的子串；归约 = 把句柄换回左部。
解决问题自底向上分析的全部工作就是"找句柄、归约"，直到开始符号。
直觉考古拼陶片：每片陶（句柄）一拼回去，整器（开始符号）就成型一分。
误区以为任何匹配右部的子串都是句柄——位置不对（不在栈顶）的匹配不能归约，归约了会得不到原句型。
何时用本章 LR 栈轨迹每一步；第 8 章指令选择把"树模式归约"思想复用到目标代码生成。
概念卡 5
LR(0) 项集（LR(0) Item Set）
点击翻面 →
定义带进度点"·"的产生式集合（闭包封闭），是 LR 自动机的一个状态。
解决问题记录"已看到部分的全部可能进度"，让分析器不回溯也能并行跟踪所有路线。
直觉多条小说剧情线的"书签夹"：每读一页，所有书签同步右移。
误区闭包只补一条产生式——点后是非终结符就要把它所有产生式连同新项递归补全。
何时用本章造 SLR 表；理解 yacc/bison 冲突报告（y.output）时直接读项集。
概念卡 6
SLR 分析表（SLR Parsing Table）
点击翻面 →
定义LR(0) 项集族 + FOLLOW 滤镜填出的 ACTION（终结符列）/GOTO（非终结符列）双表。
解决问题LR(0) 状态里的移入-归约冲突，用 FOLLOW 限定归约列后大批消失。
直觉红绿灯：移入是绿灯直行，归约只在 FOLLOW 的"许可时段"亮灯。
误区把 r k 填满整行——那只属于 LR(0)；SLR 的归约格由 FOLLOW(左部) 严格限定。
何时用理解 LALR（yacc/bison 实际算法）的台阶；第 5 章在 LR 栈上挂语义动作仍用这张表驱动。

C. 若 A→α 且 ε∈FIRST(α)，则 A→α 要填入 M[A, b] 对所有 b∈FOLLOW(A)；

提示

完整解答

正确的是 C。这正是填表规则②：ε∈FIRST(α) 时，A→α 填入 FOLLOW(A) 的每一列（本章 E′→ε、T′→ε 都是这么填的）。

A 错：T′→ε 使 ε∈FIRST(T′)，正确答案是 {*, ε}；漏 ε 会导致预测表 T′ 行少填 +、)、$ 三列。B 错：FOLLOW 只看后面不看前面；* 进 FOLLOW(F) 的真正路径是 T→FT′ 且 FIRST(T′) 含 *（F 充当 T 的开头，T 后能跟 *，故 F 后也能跟 *）。D 错：LL(1) = 从左向右扫描（L）、最左推导（L）、向前看 1 个记号（1），与栈内容数量无关。

L1 概念辨析判断对错并说明理由：「在自底向上分析中，只要栈里出现了某条产生式的完整右部，就应该立刻归约。」
提示

完整解答

错。反例就在本章：分析 id*id 时第 3 步栈顶已是完整右部 F（可看成 T→F 或更长的 T*F 的一部分），但若此刻遇 * 就归约 T→F 再归约 E→T，后面的 *id 将无家可归。SLR 的规则是：右部完整且下一个输入 ∈ FOLLOW(左部) 才归约；否则继续移入。句柄是"位置正确（栈顶）且时机正确（FOLLOW 许可）"的完整右部，二者缺一不可。

7. 0 4 8 11｜( E )｜$｜r5（F→(E)），弹出 11、8、4 三个状态，露出 0，GOTO[0,F]=3
8. 0 3｜F｜$｜r4（T→F），GOTO[0,T]=2
9. 0 2｜T｜$｜r2（E→T），GOTO[0,E]=1
10. 0 1｜E｜$｜acc 接受

关键看点：第 2–5 步在状态 4 内重走了 I₀ 的全部归约路径（括号里是一个完整子表达式）；第 7 步 r5 一次弹出 3 个状态，括号对 (…) 整体塌缩成一个 F——括号优先级最高，在栈轨迹里体现为"最先完整归约"。

L3 建模应用设计一个小计算器的表达式文法：支持 +、*、圆括号、一元负号（如 -3+4*-(2+1)），要求 * 高于 +、一元负号高于 *、同级左结合。写出文法，说明优先级与结合性是怎样"编码"进去的，并判断它是否 LL(1)。
提示

每个优先级一层非终结符；左结合用左递归；一元负号放在哪一层才能比 * 绑得紧？

完整解答

文法：E → E+T ｜ T；T → T*U ｜ U；U → −U ｜ F；F → ( E ) ｜ num。

优先级编码：一层非终结符 = 一级优先级。+ 在最外层 E，* 在中间层 T，一元负号在更内层 U——离开始符号越远、离运算对象越近的运算符绑得越紧。负号层放在 T 与 F 之间：T→T*U 的右操作数是 U，所以 -3*4 被解析为 (-3)*4 而非 -(3*4)，实现"负号高于 *"。结合性编码：左递归 E→E+T 使 a+b+c 归约成 (a+b)+c（左结合）；若想右结合（如幂运算 ^），改用右递归 P→F^P。

是否 LL(1)：否——E→E+T 与 T→T*U 是左递归，FIRST(E+T) 与 FIRST(T) 都含 {(, num, −} 且交集非空，过不了 LL(1) 判定①，自顶向下还会死循环。修复：按 A→Aα｜β 消左递归——E→TE′，E′→+TE′｜ε；T→UT′，T′→*UT′｜ε；U 与 F 不动。消除后各产生式首符号集两两不交、ε 路也不撞 FOLLOW，即得 LL(1) 文法。代价：左结合的"形状"被藏进 E′/T′ 的递归尾巴里，第 5 章用语义动作把结合性再补回来。

点击选项判分，答错会给出原因。

自测 1
对本章 LL 文法，FIRST(T′) 等于？
  • A. { * }
  • B. { * , ε }
  • C. { * , + , ) , $ }
  • D. { ε }
解析：B 对——T′→*FT′ 贡献 *，T′→ε 贡献 ε。A 错在漏 ε（会导致预测表少填 +、)、$ 三列）；C 错在把 FOLLOW(T′) 当成了 FIRST；D 错在丢了 *。
自测 2
对本章 LL 文法，FOLLOW(F) 等于？
  • A. { + , ) , $ }
  • B. { * , + , ) , $ }
  • C. { ( , id }
  • D. { * , + }
解析：B 对——T→FT′ 使 FOLLOW(F) ⊇ FIRST(T′)−{ε} = {*}，T′ 可空再并 FOLLOW(T) = {+,),$}。A 错在漏 *（那其实是 FOLLOW(T)）；C 错在拿的是 FIRST(F)；D 错在漏了 FOLLOW(T) 传来的 ) 和 $。
自测 3
为什么左递归文法（如 E→E+T｜T）不能直接写成递归下降分析器？
  • A. 函数 E() 不消耗任何输入就再次调用自身，无限递归
  • B. 左递归文法描述的语言不是上下文无关的
  • C. 因为 + 是左结合的，递归下降只支持右结合运算符
  • D. 因为 FIRST(E) 无法计算
解析：A 对——E() 第一件事是调 E()，输入指针原地不动，栈溢出。B 错：左递归文法仍是 CFG，只是自顶向下算法处理不了。C 错：结合性由文法决定，递归下降本身不挑结合方向。D 错：FIRST(E)={ (, id } 完全可以算。
自测 4
SLR 表中 ACTION[2, *] = s7 而不是 r2，原因是？
  • A. 因为状态 2 里没有完成项
  • B. 因为 * 是终结符，终结符列只能填移入
  • C. 因为 * ∉ FOLLOW(E)，E→T· 的归约不填 * 列，移入独占该格
  • D. 因为 GOTO[2, *] 不存在
解析：C 对——I₂ 的 E→T· 是完成项，但 SLR 只在 FOLLOW(E)={+,),$} 上填 r2；* 不在其中，于是 * 列只剩 T→T·*F 给的 s7。A 错：E→T· 就是完成项。B 错：终结符列同样可以填归约（如 ACTION[2, +]=r2）。D 错：GOTO[2,*]=I₇ 存在，且正是 s7 的目标；GOTO 表只管非终结符的说法也救不了 D。
自测 5
用 4.5 的 SLR 表分析输入 id：第 1 步 s5 后，状态栈为 0 5、剩余输入为 $，下一步动作是？
  • A. acc，直接接受
  • B. s6，移入 +
  • C. r6，按 F→id 归约
  • D. 报错，因为表达式不完整
解析：C 对——ACTION[5, $]=r6（$∈FOLLOW(F)），归约出 F 后继续 r4、r2，最终 acc。A 错：acc 只在状态 1 遇 $ 时出现，此时栈顶是 5。B 错：s6 要求当前输入是 +，而输入是 $。D 错：id 是合法表达式，归约链 F→T→E 会一路走到接受。
