12.2乔姆斯基层级：四级语言与四种机器

图 12.1 的每一站都声称自己"够强"又"够用"。强与够用由什么度量？由乔姆斯基层级（Chomsky Hierarchy）：按文法规则形态把形式语言分成四级，每级恰好对应一种自动机——这是整个计算机科学最漂亮的对应之一。

型别语言类文法规则形态对应自动机能表达不能表达
3 型正则语言A → aB 或 A → a（右线性）有穷自动机（FA）单词结构：标识符、数、ab*aⁿbⁿ（任意深的配对计数）
2 型上下文无关语言A → 任意串（左部单非终结符）下推自动机（PDA）嵌套括号、表达式结构、aⁿbⁿwcw、"先声明后使用"类上下文约束
1 型上下文有关语言αAβ → αγβ（左右带上下文）线性有界自动机（LBA）aⁿbⁿcⁿ、声明-使用约束——（分析代价不可承受）
0 型递归可枚举语言无限制图灵机（TM）一切可计算之物停机问题等不可判定问题

层级上升的实质是机器记忆能力的升级：FA 只有状态、没有外部记忆，所以数不清任意大的 n——泵引理说的就是：n 个状态的自动机走 n 步必有环，环上多绕几圈就分不清 aⁿbⁿ 的两头是否相等。PDA 加一个栈，一层嵌套就能数；但要表达 wcw（前一半与后一半相同），栈读完前一半就空了，没法再回头比对——所以"标识符先声明后使用"超出 CFG。LBA 的带长受输入线性限制，可以做局部上下文检查；TM 带长无限，能算一切可算的——同时也继承了不可判定性。

✅ 判定规则

编译器选型的原则是"最弱够用"：能用电线就不用电池。词法只数不配对 → 3 型正则足够；语法要处理任意深嵌套 → 必须升到 2 型 CFG；语义要查跨子树的上下文约束 → CFG 不够，但 1 型分析代价太高，于是工程上用属性文法在 CFG 语法树上外挂语义计算。

💡 关键一跃

乔姆斯基层级就是一张"记忆能力价格表"：每升一级，表达力更强，判定与分析的成本更高。编译器每一层都买刚好够用的那一档。

⚠️ 常见误区

以为 C / Java 的语法"就是"一个上下文无关文法。几乎对，但"先声明后使用""类型匹配""方法重载决议"都超出 CFG 的表达力。工程实践：用 CFG 描述语法骨架，把管不了的约束推给语义分析（属性文法 / 符号表）兜底——这正是 12.4 的主题。

12.3一条完整理论链：从 (a|b)*abb 到最小 DFA

第3章埋下的那条链——正则表达式如何变成可执行的词法分析器——现在是收拢它的时候。我们全程不跳步走完：正则 (a|b)*abb → NFA（Thompson 构造）→ DFA（子集构造）→ 最小 DFA（划分求精）。这个语言是"以 abb 结尾的所有 a/b 串"，够小能算到底，又够典型覆盖全部构造。

第一步：Thompson 构造。对每个基本符号建双态小自动机，再用模板拼装：并（r|s）加新起点分叉，星（r*）加新起点与回边，连接（rs）首尾相接。对 (a|b)*abb 得到 11 个状态的 NFA（状态编号沿用龙书图 3.26）：

第二步：子集构造（Subset Construction）。DFA 的每个状态 = NFA 状态的一个子集；起点 = ε-闭包({0})。每一步把闭包算全：

手算过程逐个写清：

  1. 起点 A = ε-闭包({0})：0 经 ε 到 1、7；1 再到 2、4 → A = {0,1,2,4,7}。
  2. move(A, a)：A 中读 a 的只有 2→3、7→8 → {3,8}；ε-闭包：3→6，6→1、7，1→2、4，8 无 ε 出边 → {1,2,3,4,6,7,8} = B（新状态）。
  3. move(A, b)：只有 4→5 → {5}；闭包：5→6→1、7，1→2、4 → {1,2,4,5,6,7} = C（新状态）。
  4. move(B, a)：3 由 2 来、8 由 7 来，同第 2 步 → B 自身。move(B, b)：4→5 且 8→9 → {5,9}；闭包 {1,2,4,5,6,7,9} = D（新状态）。
  5. move(C, a) = B，move(C, b) = C。
  6. move(D, a) = B。move(D, b)：4→5、9→10 → {5,10}；闭包 {1,2,4,5,6,7,10} = E（新状态，含 10 → 接受态）。
  7. move(E, a) = B，move(E, b) = C。没有新子集，构造终止：共 5 个状态。

第三步：最小化（划分求精）。初始按"接受 / 非接受"二分，反复检查同组状态对每个输入是否仍落在同组，不一致就分裂：

  1. 初始划分：{A,B,C,D} | {E}。
  2. 检查 {A,B,C,D} 对 b 的转移：A→C（组内）、B→D（组内）、C→C（组内）、D→E（组外）→ 把 D 分裂出去：{A,B,C} | {D} | {E}。
  3. 检查 {A,B,C}：对 a，A→B、B→B、C→B（都落在 {A,B,C}，一致）；对 b，A→C、C→C（组内），B→D（组外）→ 分裂 B：{A,C} | {B} | {D} | {E}。
  4. 检查 {A,C}：对 a，A→B、C→B（同组）；对 b，A→C、C→C（同组）→ 稳定。算法终止，共 4 个状态。

这条链的每一环都是机械可执行的：Thompson 是模板拼装，子集构造是闭包迭代，最小化是划分求精。没有任何一步需要"灵感"——所以词法分析器可以由 Lex/Flex 这类工具从正则描述自动生成。理论的价值在此显形：把一门手艺变成一台机器。

💡 关键一跃

NFA 是"并行试探所有可能"，DFA 是"把并行试探的结果预先算成状态"。子集构造就是把不确定性在编译期一次性付清，换运行期的线性时间。

⚠️ 常见误区

以为子集构造永远这么便宜。n 个状态的 NFA，子集最多 2ⁿ 个——理论上可能指数爆炸（本例 11 个 NFA 状态只生出 5 个 DFA 状态，属运气好）。但也别反向误读：最小化后的 DFA 在同构意义下唯一，这是 Myhill-Nerode 定理的礼物，与你怎么构造无关。

12.4语法之后还剩什么：PDA、LL/LR 与属性文法

正则世界收拢完毕，视线升到 2 型。CFG 的识别机器是下推自动机（Pushdown Automaton, PDA）= 有穷自动机 + 一个栈。理论要点有两层：其一，（非确定）PDA 与 CFG 识别能力恰好等价；其二，确定性 PDA 比非确定 PDA 弱——而编译器只玩得起确定性。这个"弱出来的空档"不是灾难，正是第4章 LL 与 LR 存在的理论理由：它们是"确定性地、在线性时间内可分析"的 CFG 子类。

LL 与 LR 的边界，各一句话：

LL（自顶向下，最左推导）LR（自底向上，最右推导的逆）
判定时机只看向前 k 个单词就要选定产生式展开整个右部都进栈之后，看向前 k 个符号再决定归约
能力边界容不下左递归与公共左因子（须改写文法）；LL(k) 文法类较小LR(1) 文法类严格大于任何 LL(k)；左递归天然无害
工程取舍分析器直观（递归下降），错误定位好表驱动、能力强，分析器由工具生成（Yacc/Bison）

直觉就一句：LR 比 LL 强，因为它见得更多才决策——LL 在只看到一个符号时就要押注展开式，LR 可以等右部全部现身再翻牌。

但即便最强实用的 LR，也仍然只是 CFG 世界的事。12.2 说过，"标识符先声明后使用"（wcw 型约束）超出 CFG；类型是否匹配、数组维度是否一致，也都不是语法树骨架能携带的信息。怎么办？第5章的答案是属性文法（Attribute Grammar）：保留 CFG 的骨架，在每个文法符号上挂属性、在每条产生式上挂语义规则，让值沿树流动——综合属性自底向上，继承属性自顶向下，求值顺序由依赖图的拓扑序决定。CFG 管"结构对不对"，属性文法管"结构上算的数对不对"。

💡 关键一跃

三道工序的理论机器各是：词法 = FA（无记忆），语法 = 确定性 PDA（一个栈），语义 = 属性文法（在树上外挂计算器）。表达能力一层比一层强，分析成本一层比一层高——分层不是偷懒，是精打细算。

⚠️ 常见误区

以为"LR 更强所以 LL 该淘汰"。错：能力之外还有工程维度——手写递归下降（LL 风格）可读、可调试、错误恢复好，GCC 与 Clang 的 C/C++ 前端都是手写递归下降加各种技巧的混合体。理论给出的是能力上界，选型看的是综合成本。

12.5毕业三问

全书的最后一公里，不留新知，只留三个问题。每个问题先自己作答，再展开参考答案比对——能讲到参考答案的八成，这门课就算真正毕业了。

问1：词法用正则、语法用 CFG、语义用属性文法——为什么一层比一层"强"，强的代价是什么？提示：从乔姆斯基层级的"记忆能力价格表"想，从各层分析算法的时间复杂度想。

参考答案
因为每一层只买"刚好够用"的表达力。正则配 FA：无记忆，识别只要 O(n)，还能从描述自动生成分析器（Lex）；但数不了配对，管不了嵌套。CFG 配确定性 PDA：一个栈换来任意深嵌套，LL/LR 仍保持 O(n)，代价是文法要满足子类约束、表构造复杂。语义面对的是上下文相关约束（声明-使用、类型），理论上是 1 型问题、一般分析 PSPACE 完全不可用，于是工程上用属性文法把语义计算挂在 CFG 树上，代价是属性求值顺序要另解依赖图、且表达力仍不是万能的。层级的"强"用更高的判定成本、更弱的自动化程度来换；分层的艺术在于让每个难题都沉到刚好能消化它的那一层。

问2：优化凭什么敢改代码？提示：语义保持的"证据"是什么？"两个程序行为完全一致"这件事本身可判定吗？

参考答案
凭的是语义保持（semantic preservation）：对所有输入，优化前后可观察行为一致。但"两个程序是否等价"在一般情形下不可判定——Rice 定理说程序语言的任何非平凡语义性质都不可判定，其根子是图灵机的停机问题：连"会不会停"都判不了，遑论"行为是否相同"。所以编译器不做精确分析，只做保守近似：数据流分析给出的答案保证安全（sound）但允许粗糙（"可能是"就当"是"）。保守的代价是漏掉一些优化机会，保守的底线是绝不能改错程序——这就是第11章指针别名让并行化变保守、第9章数据流方程取交汇运算的理论根源。停机问题的幽灵笼罩着整个优化篇：完美的优化器不存在，存在的只是安全的近似。

问3：从源程序到机器码，信息在每一站被"翻译"成了什么形态？提示：沿着图 12.1 的边走一遍，注意每站丢掉了什么、沉淀了什么。

参考答案
字符流 →（词法，Ch3）→ 单词流：丢掉空白注释，认出标识符与关键字；单词流 →（语法，Ch4）→ 语法树：丢掉线性排列，沉淀嵌套结构；语法树 →（语义，Ch5）→ 带类型的树：挂上声明、类型与作用域；带类型的树 →（中间代码，Ch6）→ 三地址码：树被拍平成线性指令，控制流显式化；三地址码 →（优化，Ch9）→ 优化后的三地址码：丢掉冗余计算，保留数据依赖本质；三地址码 →（代码生成，Ch8，再经 Ch10–11 重排与切块）→ 指令流：虚拟寄存器落到物理寄存器，指令带上调度与局部性安排。整条链是一部"不断丢失表面细节、沉淀执行本质"的翻译史——这就是编译原理这门课讲的事。

📝分层习题

L1 概念辨析判断："aⁿbⁿ 是上下文无关语言，因此也可以用正则表达式描述。"这句话对吗？说明理由。
提示

层级是严格包含关系：2 型真包含 3 型。想想泵引理说有穷自动机"数不了"什么。

完整解答
错。乔姆斯基层级是严格包含：正则 ⊂ 上下文无关，且包含是真子集关系。aⁿbⁿ 恰是分界的标准证人——PDA 用栈数 a 的个数再逐个对 b 弹栈即可，故它是上下文无关语言；但任何 n 状态有穷自动机走 n 步必成环，环上多绕一圈就分不清两头个数是否仍相等（泵引理），故它不是正则语言。"属于上级就能用下级描述"把包含关系搞反了。
L1 概念辨析判断："LR 能分析的文法类严格大于 LL；其根本原因是 LR 在决策前能看到更多信息。"对吗？
提示

比较两者的决策时机：LL 什么时候必须选定产生式？LR 什么时候才决定归约？

完整解答
对。LL 自顶向下，看到向前 k 个单词就必须选定展开式——决策时右部还一个符号都没确认；LR 自底向上，把整个右部都移进栈后才结合向前 k 个符号决定归约——决策时右部已全部现身。见得更多才决策，所以 LR(1) 文法类严格大于任何 LL(k)。推论：左递归对 LL 是死症（须改写），对 LR 天然无害。易错点：把"能力强"误读为"LL 无存在价值"——工程上递归下降可读可调试，能力不是唯一选型维度。
L2 手算推导设字母表 {a, b} 上的 NFA：状态 {0,1,2}，起点 0，接受态 {2}，转移为 0 -a→ 0、0 -a→ 1、1 -b→ 2。用子集构造求等价的 DFA，写出每个子集的 ε-闭包与 move 计算过程。
提示

本 NFA 没有 ε 边，ε-闭包各自平凡。起点子集是 {0}；注意 move({0}, a) 会同时命中 0 和 1；空集也要作为一个（陷阱）状态保留。

完整解答
① 起点：ε-闭包({0}) = {0} = S0。② move(S0, a) = {0,1}（0 读 a 到 0 和 1）；无 ε 边，闭包不变 → 新状态 S1 = {0,1}。move(S0, b) = ∅ → 陷阱状态 S∅。③ 处理 S1：move(S1, a) = move(0,a) ∪ move(1,a) = {0,1} ∪ ∅ = {0,1} = S1 自身；move(S1, b) = move(0,b) ∪ move(1,b) = ∅ ∪ {2} = {2} → 新状态 S2 = {2}，含 2 → 接受态。④ 处理 S2：move(S2, a) = ∅，move(S2, b) = ∅，都到 S∅。⑤ S∅ 对所有符号回到自身。终止：DFA 共 4 个状态 {S0, S1, S2, S∅}，接受态仅 S2。识别语言：先读若干个 a（至少一个），再读一个 b——即 a⁺b。验证串 aab：S0 -a→ S1 -a→ S1 -b→ S2，接受 ✓；串 ab 也接受 ✓；串 b：S0 -b→ S∅ 拒绝 ✓。
L2 手算推导对如下 DFA 做最小化：状态 {0,1,2,3}，起点 0，接受态 {3}；δ(0,a)=1，δ(0,b)=2，δ(1,a)=1，δ(1,b)=3，δ(2,a)=1，δ(2,b)=3，δ(3,a)=3，δ(3,b)=3。写出划分求精的每一步及分裂理由。
提示

初始按接受/非接受划分；之后逐组检查：对每个输入符号，组内成员是否都落到同一组。重点盯 b 转移。

完整解答
① 初始划分：非接受 {0,1,2} | 接受 {3}。② 检查 {0,1,2}：对 a，0→1、1→1、2→1，都落在 {0,1,2}，一致；对 b，0→2（组内）、1→3（组外）、2→3（组外）→ 0 与 {1,2} 行为不同，分裂为 {0} | {1,2} | {3}。③ 检查 {1,2}：对 a，1→1、2→1，都落在 {1,2}；对 b，1→3、2→3，都落在 {3} → 稳定，不再分裂。④ 终止：最小 DFA 三个状态 {0}、{1,2}、{3}。转移：{0} -a→ {1,2}，{0} -b→ {1,2}（因 2 ∈ {1,2}），{1,2} -a→ {1,2}，{1,2} -b→ {3}，{3} 自环。识别语言：以 b 结尾且此前全为 a 的串——即 a*b。
L3 建模应用设计一个"学号校验器"：合法格式 = 2 位年份数字 + 3 位学院码数字 + 4 位序号数字（共 9 位数字）。要求：① 选出该用乔姆斯基层级哪一级，说明理由；② 写出对应正则表达式；③ 说出把它变成程序的两条路线（手写 DFA / 工具生成）。④ 追问：若再加一条规则"第 9 位必须等于前 8 位数字之和的个位数"，你的选型还成立吗？
提示

格式里没有嵌套与配对，只有固定长度的字符类别——这是哪一级的标志？追问中的"校验和"是否引入了两段文本之间的数量约束？有限性还在不在？

完整解答
① 3 型正则语言：格式是"9 个固定位置各有字符类别"，没有任意深度的嵌套或配对，FA 的无记忆能力足够。② 正则：令 d = [0-9]，则 dd ddd dddd（即 [0-9]{9}；若学院码有枚举范围，再细化中间三位）。③ 路线一：手写 9+1 个状态的顺序 DFA（每位一个状态，读满 9 位进接受态），代码十几行；路线二：把正则交给 Lex/正则库，由 Thompson 构造 + 子集构造自动生成——12.3 的链就是为这种场景准备的。④ 校验和规则把"第 9 位"与"前 8 位的和"关联起来，这是一种跨位置的上下文约束。但注意：前 8 位只有 10⁸ 种可能，理论上仍可展开成一个（巨大的）正则——语言仍是正则的，只是正则表达式不再可写。工程结论：格式匹配部分留在正则层，校验和交给语义/代码层检查——这正是编译器"CFG 骨架 + 属性文法兜底"分工在微缩场景的重演。若约束升级成"任意深度括号配对"这类真无限结构，才必须升到 2 型。
