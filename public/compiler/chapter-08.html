8.1为什么代码生成是三大难题：指令选择、寄存器分配、求值顺序

第7章解决了「名字住在哪」，第6章给了三地址码。剩下的工作看上去是逐条「查表替换」：把 t1 := a + b 换成几条机器指令。真动手才发现每一步都有选择，而每个选择都在花同一笔预算——寄存器与访存次数。

三个互相纠缠的难题，各配一个「选不好会怎样」的反例：

难题问的是什么选不好的反例
指令选择（Instruction Selection）一条三地址语句用目标机的哪几条指令实现x := x + 1：一条 INC x 就能干完；选成 LD/ADD/ST 三条，代码体积膨胀 3 倍，还白占一个寄存器
寄存器分配（Register Allocation）众多名字挤几个寄存器，谁住、谁被赶到内存只有两个寄存器却要算 (a+b)×(c−d)：值放不开就得 ST/LD 来回倒腾（溢出），一次溢出多花 2 条访存指令，在内层循环里被放大百万倍
求值顺序（Evaluation Order）子表达式先算谁、后算谁8.5 将看到 (a+b)×c：一种顺序峰值占 2 个寄存器，另一种要 3 个——寄存器不够时直接逼出一次溢出

更麻烦的是三者互相牵制：选哪条指令决定了要用几个寄存器；寄存器余量反过来限制指令选择；求值顺序同时改变两者。理论结果也很冷酷——基本块内的最优代码生成是 NP 难问题。所以工程上全部用启发式：8.3 的最大口啃法、8.4 的 getReg 与图着色、8.5 的 Ershov 序，都是「够好且快」的近似。

💡 关键一跃

代码生成是带预算的翻译：预算就是寄存器个数与访存代价，三种选择——选哪条指令、谁住寄存器、先算谁——花的是同一笔钱。本章每个启发式，本质上都是一套「省钱纪律」。

⚠️ 常见误区

以为指令选择是机械查表：一条三地址码对应一条「标准」指令。错——同一条语句在不同上下文（寄存器还剩几个、操作数是否已在寄存器、下一条语句还用不用这个值）下，最优选择不同。代码生成没有脱离上下文的答案。

8.2目标语言：一台简化的寄存器机

三大难题要在具体的靶子上讨论。本章的目标机是一台简化的寄存器机：若干通用寄存器 R0、R1……，四类指令，六种寻址模式。后续所有例子都用它。

指令含义例子

寄存器RR 的内容0

指令代价定义为：1（指令本身）+ 各操作数寻址模式的附加代价之和。寄存器操作免费，沾内存或常量就加钱。

cost = 1 + ∑（每个源/目的操作数的寻址模式附加代价）

💡 关键一跃

代价模型就是指令的价目表：寄存器之间倒手免费，一沾内存就收税。代码生成的全部优化，归根到底是在少交这笔内存税。

⚠️ 常见误区

用「指令条数」比较两段代码。LD R1, *40(R0) 是 1 条指令但代价 2（一次额外访存）；ADD R0, R1, R2 也是 1 条但代价 1。条数相同、访存次数不同，速度就不同——比较代码必须用代价模型，不能数行数。

8.3指令选择：用树覆盖「啃」掉表达式树

有了指令集，第一个难题登场：一条三地址语句对应哪几条指令？系统化的做法分两步——把语句画成表达式树（Expression Tree）；把每条目标指令画成一块「树型瓦片」（tile）；用瓦片把整棵树不重不漏地铺满。选指令的问题，就变成了铺地砖的问题。

本章瓦片盒（部分）：

瓦片匹配的子树对应指令
T1叶子：内存名字 xLD R, x
T2内部结点 + ，两个操作数已在寄存器ADD Rd, Rs, Rt
T3内部结点「下标取值」：基址常量 c + 寄存器下标LD R, c(Ri)
T4根：赋值到内存名字 aST a, R

铺法用最大口啃法（Maximal Munch）：从根开始，在当前结点处选择能覆盖最多结点的瓦片，啃掉这一块，再对剩余的每棵子树递归重复。

合计代价：2 + 2 + 2 + 1 + 2 = 9。关键在第 2 步：T3 这口「大瓦片」把「算地址、取内容」压进了一条 LD R1, c(R0)——若瓦片盒里没有它，就得拆成「算偏移、加基址、间接取数」三条，多付两次访存税。瓦片越大，砖缝（多余访存）越少。

💡 关键一跃

指令选择 = 铺地砖：指令库是瓦片盒，表达式树是地面，最大口啃法从根往下贪心铺。目标机的指令越「强」（一条指令能干的事越多，即瓦片越大），铺出来的砖缝越少，代码越省。

⚠️ 常见误区

以为最大口啃法给出最优覆盖。它是贪心：瓦片重叠时，当前啃最大口可能逼得剩余子树只能用贵瓦片。真正保证代价最小的是动态规划式的最优覆盖；工程上贪心 + 一套好瓦片已足够好，这正是 8.1「NP 难 → 启发式」的又一例。

8.4寄存器分配：两个寄存器怎么周转

8.3 的例子随手用了 R0、R1、R2 三个寄存器。真实机器寄存器有限——把条件推到极端：只有 R0、R1 两个。这一节做本章的核心例题：先逐条做指令选择，再演示 getReg 式的分配全程，最后用图着色给出全局视角。

记账工具是两本账：寄存器描述符（Register Descriptor）记录每个寄存器当前持有哪些名字的值；地址描述符（Address Descriptor）记录每个名字的值当前在哪些位置（某寄存器、内存、或两者）。分配器 getReg 为操作数找寄存器的纪律：

情形动作
① 名字已在某寄存器直接用，零代价
② 有空寄存器LD 进来
③ 无空寄存器优先挑「值已有内存副本或此后不再活跃」的寄存器，直接腾（免 ST）；都不行就选「下次使用最远」的，先生成 ST 溢出再腾

全局视角：图着色。把「谁和谁不能同住一个寄存器」画成冲突图（Interference Graph）：结点 = 每个临时量/变量；两个名字在某个程序点同时活跃就在其间连边。K 个寄存器够用 ⟺ 图可 K 着色（同色结点共用一个寄存器，因为它们永不同时活着）。

三角形需要 3 种颜色——2 个寄存器不可着色，必须溢出。溢出谁？选代价最小的：t1、t2 各被使用 2 次，t3 只被使用 1 次（在 (5)），溢出 t3 只需在 (3) 后加一条 ST、(5) 前加一条 LD，重载次数最少。溢出后 t1、t2 分住 R0、R1，剩余冲突图退化为一条链，2 色足够。这就是溢出（Spill）的决策逻辑：不是「随便扔一个」，而是扔「使用最少、重载最便宜」的。

💡 关键一跃

寄存器分配的两副面孔：基本块内的 getReg 是边走边扔的在线贪心（两本账 + 三条纪律）；图着色是先看完全局再排座次的离线方法（同时活跃 ⟺ 不能同色）。两者都在逼近同一个 NP 难问题。

⚠️ 常见误区

以为溢出「随便扔一个」就行。溢出谁直接决定访存次数：扔了马上要用的，等于白溢出还多付两条指令（ST + LD）；纪律是——优先扔「已死」「有内存副本」的，其次「下次使用最远 / 使用次数最少」的。例 8.4-B 里溢出 t1 而非 t3，会多一次重载。

参考答案
两个名字在某程序点同时活跃就连边。三角形需 3 色 → 2 寄存器不够 → 溢出「使用最少、重载最便宜」的结点，再重新着色。

8.5求值顺序：先算哪棵子树，差一个寄存器

8.4 的第 (2) 步是被迫溢出的：算到一半发现寄存器不够。可如果换个子表达式计算顺序，有些溢出根本不会发生。这一节把「先算谁」量化成一个可手算的标号。

Ershov 数（Ershov Number，Sethi–Ullman 标号）给表达式树每个结点标一个数：

label(叶子) = 1；label(n) = max(l, r)，若 l ≠ r；= l + 1，若 l = r

它的含义：不溢出时计算该子树所需的最少寄存器数。配套求值规则只有一句：先算标号大的子树。

例 8.5-A（同一表达式，两种顺序，完整对比）：计算 (a + b) * c。标号：a = 1，b = 1 → (a+b) 为 2；c = 1；根结点 max(2, 1) = 2。

顺序 A（先算标号大的 (a+b)）：

指令峰值寄存器占用
LD R0, aR0
LD R1, bR0, R1
ADD R0, R0, R1R0（R1 释放）
LD R1, cR0, R1
MUL R0, R0, R1R0
峰值：2 个寄存器，5 条指令，无溢出

顺序 B（先算标号小的 c）：c 先占住 R0 不动，算 (a+b) 时手头只剩 R1，必须再借 R2：

指令峰值寄存器占用
LD R0, cR0
LD R1, aR0, R1
LD R2, bR0, R1, R2　★ 第三个寄存器登场
ADD R1, R1, R2R0, R1
MUL R0, R1, R0R0
峰值：3 个寄存器

若机器只有 2 个寄存器，顺序 B 被迫溢出：

指令说明
LD R0, cc 先算出来
ST t, R0★ 腾出 R0，c 暂存内存
LD R0, a / LD R1, b / ADD R0, R0, R1算 (a+b)
LD R1, t★ 重载 c
MUL R0, R0, R1收尾
7 条指令 vs 顺序 A 的 5 条，多付一次溢出（ST + LD）

同一表达式，仅仅因为先算了「便宜的」子树，峰值寄存器从 2 涨到 3，两寄存器机器上多付 2 条访存指令。原因一句话：先算出来的值要一直占着寄存器等另一个操作数；先啃硬骨头（标号大的子树），算完只剩一个值占位，再腾出手算简单的，占压时间最短。

代价收束：基本块内「选指令 + 排顺序 + 分寄存器」的联合最优是 NP 难；而一旦跨出基本块，「谁还活着」不再是局部信息，需要全程序的数据流分析（活跃变量分析）——那是第9章的开场。本章的 getReg、图着色、Ershov 序，都是基本块这个「安全区」里的启发式纪律。

💡 关键一跃

求值顺序的口诀：先啃硬骨头。需要更多寄存器的子树先算，算完只剩一个值占位；Ershov 数就是每块骨头的「硬度表」。它和图着色共享同一个世界观：寄存器压力来自「值要等另一个值」的占压时间。

⚠️ 常见误区

以为背了 Ershov 规则就能生成最优代码。Ershov 数只保证「寄存器够用时（标号 ≤ 可用寄存器数）无溢出且最优」；标号超过可用寄存器数时仍需溢出，且带溢出的最优排序同样是 NP 难。它是纪律，不是万能钥匙。

点击翻面 →

点击翻面 →

解决问题同一表达式不同顺序峰值寄存器可差 1 个甚至更多，直接决定是否溢出。
直觉先啃硬骨头：难的算完只剩一个值占位，再算简单的手头宽松。

点击翻面 →

📝分层习题

L1 概念辨析指令选择与寄存器分配，哪个先做？它们的目标分别是什么？为什么说「谁也离不开谁」？
提示

想想：选一条指令时是否需要知道还有几个寄存器可用？分配寄存器时是否已经有了指令？

完整解答

表面顺序是先指令选择、再寄存器分配（本章的讲法）；但两者互相依赖：指令选择决定用几个寄存器（选 ADD R0, R0, R1 要两个操作数都在寄存器），寄存器余量反过来限制指令选择（只剩一个寄存器时，某些瓦片根本铺不上）。指令选择的目标是指令少、代价低；寄存器分配的目标是溢出少。因为互相牵制，实际编译器常交替或联合考虑二者——这正是块内联合最优 NP 难的直观原因。

L1 概念辨析LD R1, 8(R0) 与 LD R1, *8(R0) 各取到什么？哪一个对应「数组元素 c[i]」，哪一个对应「指针解引用」？
提示

下标模式的有效地址是 c + R 的内容；间接下标在此基础上再多取一次。

完整解答

LD R1, 8(R0)：取地址 (8 + R0 的内容) 处的内容——一次访存，正是「基址 + 偏移」的数组元素 c[i]（c=8，i 在 R0）。LD R1, *8(R0)：先取地址 (8 + R0) 处的内容，把它当作新地址再取一次——两次访存，对应「指针解引用」（如 *(p + 8)，结构体里存的是指针）。两者代价同为 2，但访存语义差一层。

L2 手算推导基本块：(1) t1 := a - b　(2) t2 := a + b　(3) t3 := t1 * t2　(4) x := t3。只有 R0、R1 两个寄存器，a、b 在内存，x 出口活跃。用 getReg 走完全程：逐条写出生成的指令、每步的寄存器描述符与地址描述符，并指出是否发生溢出。
提示

先列活跃区间：t1 活到 (3)，t2 活到 (3)，a、b 在 (2) 之后全死。关键决策点在第 (2) 条：算 t2 时 t1 还活着且只占一个寄存器，另一个操作数还缺一个寄存器——够不够？

完整解答

(1) LD R0, a（R0: a）；LD R1, b（R1: b）；SUB R0, R0, R1 → R0: t1，R1: ∅。注意 a、b 此后还要用于 (2)，但它们都有内存副本，寄存器可直接弃用（地址描述符 a、b: {内存}）；地址描述符 t1: {R0}。

(2) 需要 a、b 同时在寄存器：LD R1, a（R1: a）；装 b 时无空寄存器——R0 的 t1 活跃且无内存副本，只能先 ST t1, R0 溢出（★），再 LD R0, b；ADD R1, R1, R0 → R1: t2，R0: ∅。地址描述符 t1: {内存}，t2: {R1}；a、b 用完即死。

(3) LD R0, t1（重载）；MUL R0, R0, R1 → R0: t3，R1: ∅（t1、t2 死）。

(4) ST x, R0 → x: {R0, 内存}。

结论：发生 1 次溢出（ST t1）+ 1 次重载。目标代码共 10 条：LD R0,a / LD R1,b / SUB R0,R0,R1 / LD R1,a / ST t1,R0 / LD R0,b / ADD R1,R1,R0 / LD R0,t1 / MUL R0,R0,R1 / ST x,R0，合计代价 2+2+1+2+2+2+1+2+1+2 = 17。溢出不可避免的原因：执行 (2) 的瞬间 t1、a、b 三个值需要同时在场，超过 2 个寄存器。

L2 手算推导给表达式 (a + b) * (c + d)：（1）标注每个结点的 Ershov 数；（2）写出 3 寄存器无溢出的指令序列；（3）说明只有 2 个寄存器时在哪里被迫溢出。
提示

叶子全为 1；(a+b) 与 (c+d) 的两子标号相等，各 +1；根结点两子相等再 +1。3 寄存器时先算任一边（对称），注意「先算出的结果要占一个寄存器等另一边」。

完整解答

（1）a=b=c=d=1；(a+b)：两子相等 → 1+1 = 2；(c+d) 同理 = 2；根：两子均为 2、相等 → 2+1 = 3。即不溢出至少需 3 个寄存器。

（2）3 寄存器序列：LD R0, a；LD R1, b；ADD R0, R0, R1（左边算完占 R0）；LD R1, c；LD R2, d；ADD R1, R1, R2（右边算完占 R1）；MUL R0, R0, R1。峰值 3，无溢出。

（3）只有 2 个寄存器：左边算完占 R0 后，算右边 (c+d) 需要两个寄存器，手头只剩 R1 → 被迫 ST t1, R0 溢出左边结果；算完右边后 LD R1, t1 重载，MUL R0, R0, R1。溢出点在「左子树算完、右子树开算」之间——根标号 3 与可用寄存器 2 的差额早已预言了这一点。

L3 建模应用为二次方程判别式 d := b * b - 4 * a * c（a、b、c 在内存，d 写回内存，d 出口活跃）在 8.2 的两寄存器机器上生成目标代码。要求：写出三地址码、目标指令序列、每条代价与合计，并说明你做的每个分配决策。允许把 4 * a 用立即数运算合并。
提示

三地址码：t1 := b * b；t2 := 4 * a（可用 MUL R, R, #4 合进指令选择）；t3 := t2 * c；t4 := t1 - t3；d := t4。注意 b 用两次、不必 LD 两次；t1 与 t2/t3 的生命期错开吗？

完整解答

三地址码：(1) t1 := b * b；(2) t2 := 4 * a；(3) t3 := t2 * c；(4) t4 := t1 - t3；(5) d := t4。活跃区间：t1 活到 (4)，t2 活到 (3)，t3 活到 (4)。

指令序列与决策：

(1) LD R0, b（2）；MUL R0, R0, R0（1）——b 用两次，一次 LD 即可，R0 自乘；R0: t1。

(2) LD R1, a（2）；MUL R1, R1, #4（2）——立即数瓦片把「4×」并进一条；R1: t2。

(3) MUL 需要 t2 与 c 同时在寄存器：R1 住着 t2，c 只能装入 R0——但 R0 的 t1 活到 (4) 且无内存副本，只能先溢出：ST t1, R0（2，★溢出）；LD R0, c（2）；MUL R1, R1, R0（1）→ R1: t3，R0: ∅。

(4) LD R0, t1（2，重载）；SUB R0, R0, R1（1）→ R0: t4。(5) ST d, R0（2）。

合计：2+1+2+2+2+2+1+2+1+2 = 17，含 1 次溢出。关于求值顺序：左子树 b*b 与右子树 4*a*c 的 Ershov 标号均为 2，根标号 = 3 > 可用寄存器 2——标号早已预言至少溢出一次；我们的序列恰好只溢出一次（ST t1 + LD 重载），已达 2 寄存器约束下的最优。
