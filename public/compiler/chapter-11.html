11.1为什么单核见顶：从指令级并行到线程级并行

第10章给了我们一整套在一个核内部榨取并行的办法：流水线、超标量、乱序执行、软件流水。但它们共享一个天花板——指令窗口里能同时找到的独立指令终究有限，分支与访存延迟又不断吃掉收益。更硬的约束来自物理：功耗墙——频率每提一档，功耗近似按立方上涨，2005 年前后单核频率基本停摆。同样的晶体管预算，与其堆一个更快的核，不如放多个核。

于是并行粒度从指令级抬到线程级并行（Thread-Level Parallelism, TLP）：程序显式或半显式地分成多个执行流，跑在不同核上。本章假设最主流的硬件模型——共享内存（Shared Memory）多核：所有核看到同一个地址空间，通信靠读写共享变量，天然省事；代价是写同一数据时需要同步（锁、栅栏），否则结果出错。

最小例子：向量加。对 for i = 0..N−1: C[i] = A[i] + B[i]，4 个核各拿连续的四分之一区间，互不需要通信，干完汇合即可。这类循环是 11.2 要正式判定的"天然可并行"形态。

但"能拆"不等于"快 p 倍"。阿姆达尔定律（Amdahl's Law）给出加速比上界：设程序中必须串行执行的部分占 fs，用 p 个核，则

S(p) = 1fs + (1 − fs) / p

手算一遍：设 fs = 5% = 0.05，p = 64。分母 = 0.05 + 0.95 / 64 = 0.05 + 0.0148 = 0.0648，S(64) = 1 / 0.0648 ≈ 15.4 倍。就算 p → ∞，上界也只有 1 / 0.05 = 20 倍。结论：串行部分不消灭，堆核没用。

💡 关键一跃

并行不是"让同一批人跑快点"，而是"把一件事换成一群人同时做"。前提是这件事能拆——拆的合法性由 11.2 的依赖分析裁决，拆完快不快由 11.3 的局部性裁决。

⚠️ 常见误区

以为开 p 个线程就近乎快 p 倍。错：Amdahl 定律说明加速比被串行部分死死压住（5% 串行 ⇒ 64 核也只有约 15 倍）。此外还有同步开销、负载不均、伪共享（false sharing）——两个核写同一 cache 行的不同字节，也会互相把对方的行挤掉。

11.2哪些迭代能同时跑：迭代空间与依赖距离向量

上一节说"能拆才能快"，这一节给出"能不能拆"的判官。科学计算与大循环是并行化的主战场，而循环的迭代天然成千上万，是线程级并行最肥的肉。问题：哪些循环可以原样切开分给多核？

先把循环变成几何对象。d 层嵌套循环的所有迭代构成迭代空间（Iteration Space）：每个迭代用下标向量 (i₁, i₂, …, id) 表示，是 ℤd 中的一个整点；两层循环就是一张二维网格，每个格子是一次迭代。执行顺序按字典序（先行后列）。

迭代之间的冲突用依赖（Dependence）刻画：若迭代 I₁ 先于 I₂ 执行，且两者访问同一内存位置、至少一次是写，则 I₂ 依赖 I₁。写后读（RAW）是流依赖（flow dependence），是真正的数据传递；写后读之外还有反依赖（WAR）与输出依赖（WAW），理论上可通过改名消除，本章聚焦流依赖。

把依赖量化：依赖距离向量（Dependence Distance Vector）。若迭代 (i₁, j₁) 写入的位置被迭代 (i₂, j₂) 读取，则距离向量 d = (i₂ − i₁, j₂ − j₁)。因为读必然发生在写之后（字典序），合法的距离向量必须字典序非负（第一个非零分量为正）。

有了距离向量，可并行性变成一行判定：DOALL 循环（DOALL Loop）指所有迭代互不依赖、可以任意顺序同时执行的循环。对嵌套循环的第 k 层：

✅ 判定规则

若所有依赖距离向量的第 k 个分量都为 0，则第 k 层循环是 DOALL，可以把该层迭代切块分给多个核；只要存在一个距离向量第 k 分量非零，该层就携带依赖，不能原样并行。

例1（两层都是 DOALL）：逐元素矩阵加。

for i = 1..N
  for j = 1..N
    C[i][j] = A[i][j] + B[i][j]

一步步查依赖：① 写 C[i][j]：每个 (i, j) 恰好写一次，不存在两次迭代写同一位置 → 无输出依赖。② A、B 在整个循环里只读不写 → 读的双方永远不会和写冲突。③ 结论：依赖集为空，距离向量集合为空集 → 空集上"所有第 k 分量为 0"平凡成立 → 内外两层都是 DOALL。4 个核按 i 切成 4 段即可，零通信。

例2（因跨迭代依赖而不可并行）：递推。

for i = 2..N
  for j = 2..N
    A[i][j] = A[i−1][j] + A[i][j−1]

距离向量手算，不跳步：

  1. 写 A[i][j] 与读 A[i−1][j]：同一位置 ⟺ (i, j) = (i′ − 1, j′)，即 i′ = i + 1, j′ = j。源 (i, j) → 汇 (i+1, j)，距离 d₁ = (1, 0)。
  2. 写 A[i][j] 与读 A[i][j−1]：同一位置 ⟺ (i, j) = (i″, j″ − 1)，即 i″ = i, j″ = j + 1。源 (i, j) → 汇 (i, j+1)，距离 d₂ = (0, 1)。
  3. 距离向量集 D = {(1, 0), (0, 1)}，均字典序非负，合法。
  4. 判 i 层（k=1）：d₁ 的第一分量是 1 ≠ 0 → i 层携带依赖，不可并行。
  5. 判 j 层（k=2）：d₂ 的第二分量是 1 ≠ 0 → j 层也携带依赖，不可并行。

两个例子对照：例1 没有跨迭代依赖，随便拆；例2 每个迭代都要等"上一行同一列"和"同一行前一列"算完，逐行逐列都串行。

图 11.2 例2 的迭代空间与依赖：横向箭头是距离 (0,1)，纵向箭头是距离 (1,0)。注意对角线 (1,1)、(2,2)、(3,3) 之间没有箭头——这是 11.4 波前并行的伏笔。

再看一个粒度更细的对照：把例2 改成 A[i][j] = A[i−1][j] + 1。距离向量只剩 {(1, 0)}：i 层不可并行，但所有向量的第二分量都是 0 → j 层是 DOALL。也就是说，固定一行，行内 N 个元素可以同时算；行与行之间排队。并行化不必"全有或全无"，逐层判定才有意义。

💡 关键一跃

距离向量就是"这次写，多久之后被读"的网格坐标差。分量为 0 的那一层，写和读永远落在同一迭代行上，那一层就是自由的。

⚠️ 常见误区

看到语句里出现 A[i−1] 就断言"整个循环不可并行"。错：A[i−1][j] 只产生距离 (1, 0)，它锁死的是 i 层，j 层仍然 DOALL。必须写出全部距离向量再逐层判定，不能凭下标里有没有减号下结论。

11.3数据离计算有多近：矩阵乘的 cache 账

11.2 解决了"跑得对吗"，但一个 DOALL 循环拆到 64 核，若每个核都在等内存，就是 64 份等待。现代机器一次 L1 命中约 1 纳秒，一次主存访问约 100 纳秒——访存比计算慢两个数量级。所以并行化之后，真正的速度由数据局部性（Data Locality）决定。局部性分两种：时间局部性（Temporal Locality）：同一数据短期内被反复用；空间局部性（Spatial Locality）：相邻数据被连着用。cache 以"行"为单位搬运，正是押注这两种局部性。

本节核心例题：N×N 矩阵乘 C = A × B（i-j-k 序），把 cache 账算到底。机器参数：cache 容量 C 字节、行大小 L 字节、元素为 8 字节 double，每行 cache 行装 L/8 个元素；数组按行优先（Row-Major）存储——A[i][j] 与 A[i][j+1] 在内存中相邻。

for i = 1..N
  for j = 1..N
    for k = 1..N
      C[i][j] += A[i][k] × B[k][j]

不分块版本，逐数组算 miss（设 L = 64 字节，即每行 8 个元素）：

  1. B[k][j]：内层循环是 k，固定 (i, j)。行优先下 B[k][j] 与 B[k+1][j] 相距一整行 = N×8 字节 → 内层每次访问落在不同 cache 行，每次访问都 miss。每个 (i, j) 对内层执行 N 次 → miss 数 = N² × N = N³。跨 i 也无复用：两次使用 B[k][j] 之间，内层扫过整列 N 个元素，涉及 N × N×8 字节 ≫ C，早被挤出。
  2. A[i][k]：内层步长为 1（连续），一行 cache 行服务 8 次访问 → 每 8 次访问 miss 1 次 → miss 数 = N³ / 8。跨 j 能否复用第 i 行？行大小 N×8 = 8 KB（N=1024），看似能留在 32 KB 的 L1 里；但两次使用之间扫过 B 的一整列（8 MB 的访问面），把 A 的行也挤掉了 → 保持 N³/8。
  3. C[i][j]：内层固定引用同一元素，N 次访问至多 miss 1 次；全部 (i, j) 对共 N² 个，按行连续 → miss ≈ N²/8，相对 N³ 可忽略。
miss不分块 ≈ N³（B 按列）+ N³8（A 按行）+ N²8（C）≈ 98 N³

分块（tiling / blocking）版本。循环分块（Loop Tiling，又称 blocking）把 i、j、k 各切成 N/B 段，先固定三个块下标 (ii, jj, kk)，再算块内 B³ 的局部乘加。关键是：每个内层块计算需要 A、B、C 各一个 B×B 子块同时驻留在 cache，于是块大小受约束：

3 × B² × 8 ≤ C

代入数字求 B：C = 32 KB = 32768 字节（典型 L1），则 B² ≤ 32768 / 24 ≈ 1365.3，B ≤ 36.9。取 2 的幂方便地址计算 → B = 32。验证：3 × 32² × 8 = 24576 ≤ 32768 ✓；而 B = 37 时 3 × 37² × 8 = 32856 > 32768 ✗（B = 36 也可行，但 32 对地址计算更友好）。

分块版 miss 账：每个块三元组 (ii, jj, kk) 需要装载 A 块与 B 块各一次。一个 B×B 块：块内每行 B 个连续元素 = B×8 字节 = B/8 个 cache 行，共 B 行 → 每块 miss B²/8 次。两块合计 B²/4。块三元组总数 = (N/B)³。于是

miss分块 ≈ N³B³ × B²4 = N³4B

从 O(N³) 压到 O(N³/B)——每把块放大一倍，miss 减半，而块的上界由 cache 容量卡死。

N = 1024 的具体数字对比（C = 32 KB，L = 64 B，元素 8 B）：

方案A 的 missB 的 missC 的 miss合计（约）
不分块（i-j-k）N³/8 = 134,217,728N³ = 1,073,741,824N²/8 = 131,0721.208 × 10⁹
分块 B = 32合计 N³/(4B) = 8,388,608N²/8 = 131,0728.52 × 10⁶

比值：1.208 × 10⁹ / 8.52 × 10⁶ ≈ 142 倍。同一份代码、同一个编译器，只因循环结构不同，访存开销差两个数量级——这就是局部性优化的分量。

数据布局与循环序：不动数据也能救。若不能改存储，还有一个零成本手段：把循环换成 i-k-j 序——

for i = 1..N
  for k = 1..N
    for j = 1..N
      C[i][j] += A[i][k] × B[k][j]

内层变成 j：B[k][j] 步长 1 ✓（按行连续），C[i][j] 步长 1 ✓，A[i][k] 是内层不变量 ✓（可放寄存器）。三个数组全部空间局部性拉满，miss 从 9N³/8 降到约 N³/8（B）+ N³/8（C）= N³/4，一行数据布局都不用改。反过来，若语言是列优先（Column-Major，Fortran/MATLAB），A[i][j] 与 A[i+1][j] 相邻，同样的 i-j-k 序里遭殃的就是 A——同一行代码在不同布局下快慢相反，数据布局（Data Layout）决定了哪个下标方向是"免费"的。

💡 关键一跃

cache 优化的全部要义只有一句：让"下一次要用的数据"此刻已经在 cache 里。分块是把时间局部性捏出来（三个小块反复用，直到用完再扔）；换循环序是把空间局部性顺出来（让步长全部变成 1）。

⚠️ 常见误区

以为块越大越好。错：块超过 3B²×8 ≤ C 的容量线，三个块互相挤压，miss 立刻反弹回 O(N³)。分块的全部艺术在于贴着容量线取最大可用 B，而不是越大越豪迈。另外别忘了 TLB 与多级 cache：L2、L3 各有自己的最优块大小，工程上常做两级分块。

11.4仿射变换：把循环变换统一成线性代数

前三节看似给了三个互不相干的技巧：循环交换（治布局）、循环分块（治容量）、循环倾斜（治依赖）。本节把它们收进同一个数学框架。每个循环迭代是 ℤd 里的整点，那么一切循环变换无非是对迭代空间做一次仿射变换（Affine Transformation）：i′ = M·i + c，其中 M 是整数矩阵。编译器据此为每个语句寻找一个仿射调度，把迭代空间切成可并行的片——这套机制称为仿射分割（Affine Partitioning），是龙书第11章的"终极机器"。

变换矩阵 M效果
交换（interchange）M = [[0,1],[1,0]]，即 i′=j, j′=i内外层互换，把按列访问变成按行访问（11.3 的 i-k-j 即两次交换）
分块（tiling）引入块下标 ⌊i/B⌋，坐标重塑大迭代空间切成小块，块内数据驻留 cache（11.3）
倾斜（skewing）M = [[1,1],[0,1]]，即 s=i+j, t=j把 11.2 例2 变成沿反对角线的波前并行

倾斜的手算（接续例2）：对 D = {(1,0), (0,1)} 施加 M：d₁′ = M·(1,0) = (1, 0)，d₂′ = M·(0,1) = (1, 1)。变换后所有距离向量的第一维都 ≥ 1——意味着每条依赖都跨越不同的 s = i+j；换言之，同一反对角线 s 上的迭代互不依赖，可以同时跑。原本完全串行的例2，倾斜后获得"按波前推进"的并行形态：第 s 条对角线上的所有格子一批算完，再推进到 s+1。

变换不能乱做，合法性条件一句话：对每个依赖距离向量 d，M·d 必须仍然字典序非负——读不能跑到写之前。在此约束下搜索"让某层分量全为 0"的 M，就是自动并行化编译器每天在做的事。

本章的终点，也是全书的暗线：这套机器的正确性完全押在依赖分析的精确性上。而 C 语言里两个指针是否指向同一位置（指针别名，Pointer Alias）无法精确判定——分析只能保守地说"可能相等"，于是一条本可并行的循环被判成串行。理论上可行与工程上可做之间的这道缝，正是第12章要从"可判定性"高度回看的东西。

💡 关键一跃

循环变换 = 迭代空间上的矩阵乘法。把"换序、分块、倾斜"背成三个技巧，不如记住一张图：网格旋转/剪切一下，依赖箭头全部指向"外面"，自由的维度就露出来了。

⚠️ 常见误区

以为仿射变换总能把串行循环变并行。错：若依赖本身把迭代串成一条链（如 A[i] = A[i−1] + A[i−2] 这类强递推），任何合法矩阵都变不出 DOALL 层。仿射框架能做的只是在合法变换空间里搜索最优，不能无中生有。

📝分层习题

L1 概念辨析判断：只要外层循环存在跨迭代依赖，整个嵌套循环就彻底不可并行，任何层都不能拆。这句话对吗？
提示

回到 DOALL 的逐层判定规则：依赖距离向量是"逐分量"看的。想想 11.2 里 A[i][j] = A[i−1][j] + 1 这个变体。

完整解答
错。DOALL 是逐层性质：判定第 k 层只看所有距离向量的第 k 分量。A[i][j] = A[i−1][j] + 1 的距离向量只有 (1, 0)，i 层不可并行，但 j 层所有分量都是 0，j 层是 DOALL——固定一行，行内元素可以同时算。把"外层有依赖"直接等同于"整个循环不可并行"，是因为没把依赖量化到分量级别。
L1 概念辨析循环分块主要利用的是时间局部性还是空间局部性？换循环序（i-k-j）呢？
提示

分块前后，数据的"复用间隔"发生了什么变化？换序前后，内层循环的"访问步长"发生了什么变化？

完整解答
分块主要利用时间局部性：它不改变访问顺序的相邻关系，而是把"同一个 B 块两次被用"之间的间隔压缩到块内 B³ 步，使三个小块在被挤出 cache 前被反复用完。换循环序主要利用空间局部性：i-k-j 序把内层对 B、C 的访问步长从 N 变成 1，让每行 cache 行服务 8 次访问。易错点：说"分块也改善了空间局部性"——块内行本来就是连续的，分块没有创造连续性，它创造的是复用窗口。
L2 手算推导对循环 for i = 1..N, for j = 2..N: A[i][j] = A[i][j−1] + B[i][j]，写出全部依赖距离向量，并逐层判定是否 DOALL。
提示

先列出"写 A[i][j]"可能与哪些读冲突：读 A[i][j−1]（B 只读不写，不参与依赖）。然后解"写者下标 = 读者下标"的方程。

完整解答
① B[i][j] 全程只读，不产生依赖。② 写 A[i][j] 与读 A[i][j−1]：同一位置 ⟺ (i, j) = (i′, j′ − 1)，即 i′ = i，j′ = j + 1。源 (i, j) → 汇 (i, j+1)，距离 d = (0, 1)。③ 没有其他读写对。距离向量集 D = {(0, 1)}，字典序非负，合法。④ 判 i 层：唯一向量的第一分量是 0 → i 层 DOALL：可以把行分给多个核，每核独立处理若干行。⑤ 判 j 层：第二分量是 1 ≠ 0 → j 层携带依赖，行内必须从左到右串行。结论：按行切块并行，行内顺序执行。
L2 手算推导某机器 cache 容量 C = 16 KB、行大小 L = 32 字节，矩阵元素为 4 字节 float，N = 512。分别计算 i-j-k 序不分块版本与最优分块版本的 cache miss 量级与具体数值。
提示

先算每行 cache 行装几个元素；不分块照搬 9N³/8 的推导（注意 N 与 C 的相对大小，N×4 = 2 KB ≤ 16 KB 也别被迷惑——两次复用之间扫过的是 B 的整列访问面 N²×4 = 1 MB）。分块先解 3B²×4 ≤ 16384。

完整解答
① 每行元素数 = 32 / 4 = 8 个。② 不分块：B 按列访问，步长 N×4 = 2 KB，每次访问新行 → miss = N³ = 512³ = 134,217,728；A 按行，每 8 次 miss 1 次 → N³/8 = 16,777,216；C ≈ N²/8 = 32,768。合计 ≈ 134,217,728 + 16,777,216 + 32,768 = 151,027,712 ≈ 1.51 × 10⁸ 次。③ 分块：3 × B² × 4 ≤ 16384 ⟹ B² ≤ 1365.3 ⟹ B ≤ 36.9，取 B = 32（验证：3 × 32² × 4 = 12,288 ≤ 16,384 ✓）。④ 分块 miss ≈ N³/(4B) = 134,217,728 / 128 = 1,048,576；加 C 块 N²/8 = 32,768，合计 ≈ 1,081,344 ≈ 1.08 × 10⁶ 次。⑤ 比值 ≈ 151,027,712 / 1,081,344 ≈ 140 倍。
L3 建模应用一台 4 核服务器，每核私有 L1 = 32 KB（L = 64 B），要跑 1024×1024 的 double 矩阵乘。请给出"并行 + 分块"的组合方案：怎么切迭代、块大小取多少、每核 miss 量级多少；并指出方案之外还必须担心的一个多核访存陷阱。
提示

先判定哪层是 DOALL 决定怎么切核；再按 3B²×8 ≤ C 定 B；每核只承担 1/4 的块三元组。陷阱往"多个核写同一 cache 行"上想。

完整解答
① 可并行性：矩阵乘 C[i][j] += A[i][k]×B[k][j] 中每个 C 元素独立累加（不同 (i,j) 写不同位置），最外层 i 是 DOALL（亦可在块层切）。方案：外层块循环按 ii 切成 4 份，每核负责 N/4 行带。② 块大小：3B²×8 ≤ 32768 ⟹ B = 32（与正文一致）。③ 每核 miss：全机合计 ≈ N³/(4B) = 8,388,608 次，4 核均分 → 每核 ≈ 2.1 × 10⁶ 次；加各自 C 块装载 N²/32 ≈ 32,768，量级不变。④ 陷阱：伪共享（false sharing）——C 的某行 cache 行 64 B = 8 个元素，若切分边界不按 8 的倍数对齐，两个核会写同一 cache 行的不同元素，行的所有权在两核间来回弹跳，性能崩塌。对策：切分边界按 cache 行对齐，或让每个核先写私有缓冲再合并。
