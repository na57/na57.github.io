5.1链接文字与真实地址是两回事：要看的是地址，不是文字

前两讲，我们把一封信的「谁发的」和「它说什么」各过了一遍。这一讲进入第三个检查点——它要你点什么。一封钓鱼邮件兜了那么大圈子，最后几乎总要落在一个按钮或一段链接上：它让你「点此验证」「查看附件」「登录系统」。看懂这个动作，比背任何破绽清单都管用。

先看那封演练邮件。正文最后写着「点击这里：系统验证」。四个字端正、克制，没有错别字，也没有夸张的感叹号。如果只盯着文字，你很难挑出毛病。问题不在文字里，而在文字背后：这四个字并不通向学校的系统，它通向的是一台演练平台的服务器。

这里要分清两样东西。链接文字（也叫显示文字、锚文本）是你在邮件里读到的那串字，比如「系统验证」「查看详情」「点此登录」；真实地址（网址，URL，Uniform Resource Locator，统一资源定位符）是你点下去之后浏览器真正要去的地方。在网页的底层，一个链接大致写成 <a href="真实地址">显示文字</a>：显示文字写在标签之间，真实地址写在 href 属性里。邮件客户端把显示文字渲染给你看，却把真实地址藏在背后。两者可以完全一致，也可以毫无关系。

骗子要的就是这种「分离」。他不需要你读懂地址，只需要你认得「系统验证」四个字，再把这个词和心里信任的机构绑在一起。文字负责让你放心，地址负责把你带走。这是钓鱼邮件里最常见、也最好用的一招——它利用的不是你的粗心，而是「邮件这种媒介本来就看不见地址」的天然特性。所以本讲的第一条主线是：链接文字可以随便写，真实目标藏在链接属性里。

💡 关键一跃

判定规则只有一条：信地址，不信文字。电脑上把鼠标悬停在链接上（先别点），浏览器左下角的状态栏会显示真实地址；手机上用手指长按链接，弹出的预览里能看到完整网址。看到地址后从右往左读：先找域名主体，再看它是不是你熟悉的那所学校。域名对不上，文字写得再像也一律不点。换句话说，真正的动作不是「读文字」，而是「读地址」。

⚠️ 常见误区

「链接上写着学校名字，就是学校的链接」——错。显示文字是写信人随便填的，谁都能把「系统验证」「学校官网」写成指向任何地方。反过来，「没看到网址就等于安全」也错：看不到地址不是地址不存在，只是客户端替你藏起来了。看不见，恰恰是该停下来的理由，而不是放行的理由。顺带提醒：旁边那封正常学术期刊邮件同样带「陌」字，它却是真的——「陌」只看不判，核实才下结论。

5.2短链与多级跳转：地址被藏起来，就更该停下来

上一节我们学会了把真实地址读出来。但有些邮件从一开始就打定主意不让地址被读懂——它给你的是一串短得可疑的网址，或者点下去连跳好几道。这一节讲这类「把地址藏起来」的伪装。

先说短链（短链接，short link）。正常的网址可能很长，短链服务把它压缩成一小串，比如把一长串地址缩成 t.cn/A5xKp 这样。短链本身是中性的技术，快递通知、地图分享都在用；问题在于，压缩之后你光看那串短字母，完全看不出终点在哪。骗子正好利用这一点：把钓鱼地址打包成短链，邮件里只露出人畜无害的一小截。

再说多级跳转（重定向，redirect）。你点开第一个地址，它不直接给你页面，而是回一句「请去另一个地址」，浏览器又跟着去第二个，第二个再去第三个……每跳一次，地址就换一副面孔。最后一站才落到假登录页。这种链条让追查变难：你盯着的第一眼地址往往是干净的「中转站」，真正的问题藏在几次跳转之后。这也是为什么「展开短链看看它去哪」不是个好主意——你为了看清它而点的那一下，正是它等着你做的动作。

✅ 判定规则

遇到短链，把「它背后是什么」这个问题交给独立通道，而不是交给那一下点击。三步：第一，不点、不扫码、不为了看清而展开；第二，问自己「这件事真的需要我在这封信里完成吗」——补贴、工资、账号核验，官方系统都有独立入口；第三，离开这封信，从书签或学校官网进入对应系统查看，或换一个电话核实。短链和跳转本身就是「请停下」的信号，不是「请点开」的邀请。

⚠️ 常见误区

「短链只是网址变短了，内容和原网址一样安全」——错。变短的是显示形式，不变的是终点由写信人决定。还有一个更隐蔽的误区：以为「复制到浏览器新标签打开就安全」。在新标签里打开，执行的仍然是同一次跳转，照样会到假页面，还可能因为脱离了邮件客户端的提示而更没有防备。记住：短链的风险不在你用什么打开它，而在你根本不该把它当成入口。

5.3形近字域名：地址摆在那里，眼睛也会看错

短链是把地址藏起来；还有一类更狡猾——地址就明明白白摆在那儿，你的眼睛却会替它认错人。这一节讲形近字域名，也就是那种「看着像学校、其实不是学校」的地址。

先建立一个读地址的习惯：从右往左读。一个域名由若干段组成，用点号隔开，例如 ynu.edu.cn。真正决定「这是谁的网站」的，是靠近右边的主干部分，而不是最左边那一段。爬虫式地从左到右扫，很容易被开头的字母带偏；从右往左看，才能抓住注册域名主体。记住这个动作，下面四种伪装就都好认了。

第一种是形近字替换（同形字，homoglyph）。把域名里的字母换成长得几乎一样的字符：用 rn 冒充 m，用数字 0 冒充字母 o。比如真入口是 mail.ynu.edu.cn，伪装可能写成 rnail.ynu.edu.cn——开头那个 m 被两个字母 rn 顶替，在正常字体下几乎看不出差别；再如 portal 被写成 p0rtal，o 换成 0。第二种是子域混淆：把学校的名字塞进别人的域名里当子域，例如 ynu.edu.cn.evil.example，看着前面一堆熟悉的字样，可真正的注册域名是最后两段 evil.example，前面那些都只是它的子域，与你学校无关。第三种是 punycode（国际化域名的编码形式，常以 xn-- 开头）：骗子可以用其他语言里长得像拉丁字母的字符注册域名，浏览器把它显示成 punycode，肉眼更难分辨。

还要补一类最常见的漏网之鱼：前后缀伪装。它不把学校域名放到别人的域名里，而是把学校域名原样留在地址中，只在前面或后面多添一点点东西——比如 service@i.ynu.edu.cn、system@sso.ynu.edu.cn、oa@mail.ynu.edu.cn-vpn、it@ynu.edu.cn_。它们看着都有 ynu.edu.cn，可完整域名其实是 i.ynu.edu.cn、sso.ynu.edu.cn、mail.ynu.edu.cn-vpn、ynu.edu.cn_，没有一条逐字等于你从学校官网记住的 ynu.edu.cn 完整域名。判法不变：从右往左读，再和你从官方渠道记住的完整地址逐字比对；只要多出一个前缀或尾巴，就不认。这一类与 3.3 讲的「域名里藏着 ynu.edu.cn」是同一场骗局的两面，详见 3.3。

这四种伪装的共同点，是都赌你「扫一眼就点」。它们骗的不是技术，是你在几十个字里辨认细微差别的能力——而人的眼睛恰恰不擅长这个。所以不要靠「看起来对不对」来判，要靠「是不是逐字等于我记得的那个官方域名」来判。这也是为什么统一身份认证页绝不要从邮件链接进：一旦你自己不点链接，这些形近字就一个都碰不到你。

✅ 判定规则

读域名时从右往左，盯住主干那两三段，逐字比对官方域名：多一段、少一段、换了字符、后缀陌生，任何一种都判为「不是」。遇到 xn-- 开头或一眼分不清的字母数字混排，一律按可疑处理。拿不准时不要靠猜，直接走官方入口或电话核实——你不需要证明它是假的，只需要它没能证明自己是真的。

⚠️ 常见误区

「域名里含有学校缩写，就一定是学校官网」——错。ynu.edu.cn.evil.example 里学校缩写一个不少，可它属于 evil.example。另一个误区是「只要以 .cn 或 .edu.cn 结尾就可信」：形近字替换完全可以出现在这个位置附近，单看结尾不足以定论。真正可靠的只有一条——完整、逐字地等于你从官方渠道记下来的那个域名，等于才认，不等于就不认。

5.4小锁只证明加密，不证明身份：登录页只从官方入口进

前面三种伪装都倒在「读地址」这一关。可就算地址看着没问题，还有最后一关：你打开的登录页本身可能是假的。这一节讲 HTTPS 小锁到底能保证什么，以及进统一身份认证页的正确姿势。

很多人判断网站真伪，靠的是浏览器地址栏那把小锁，以及网址开头的 https://。这里必须把概念说清：HTTPS 表示你和网站之间的通信经过加密（底层是 TLS 传输层安全协议），旁人看不到你们传了什么，也改不了。可是，加密只证明「这段连接是私密的」，不证明「对面坐着的是谁」。骗子同样能给自己的假页面申请证书、开启 HTTPS，于是他的假登录页也有一把一模一样的小锁。小锁证明的是传输安全，不是身份可信——把两者划等号，正是这一类钓鱼的核心陷阱。

更关键的是统一身份认证页（学校里登录各个系统的那个共用入口）该怎么进。演练里的教训很直接：凡是从邮件链接点进去的「登录页」，哪怕域名看着像、小锁挂着，都不能作为输入账号密码的地方。可靠的入口只有两类——你自己收藏在浏览器里、平时反复使用的那个地址，或者从学校官网首页一层层点进去。这两类的共同点是：入口由你主动掌握，不由邮件递到你手上。只要坚持「认证页只从书签或校内官网进」，前面所有形近字、短链、假小锁就都在你之外，根本没机会发挥作用。

认证入口：https://login.ynu-edu.cn/verify

页面显示 HTTPS 小锁　域名实为 ynu-edu.cn（中间是连字符，不是 ynu.edu.cn）
案例解析：这是按校内样式自制的仿真邮件。危险信号：① 域名 login.ynu-edu.cn 用连字符代替点号，与官方 ynu.edu.cn 逐字不等；② 页面挂着 HTTPS 小锁，但它只证明传输加密，不证明是学校官方页；③ 「今日失效」制造紧迫；④ 带「陌」标，但那只是陌生来信提示。正确动作：不点这个「认证入口」，更不在里面输入账号密码；打开浏览器书签，或从学校官网首页进入统一身份认证页查看状态；确认异常后按流程上报。
💡 关键一跃

把本讲四个检查点压成一句话：看到要你点的东西，先读地址；地址可疑就停；要输入密码的页面，只从书签或校内官网进。小锁不是通行证，它只能告诉你「这条路是加密的隧道」，不能告诉你「隧道尽头是不是学校」。判断身份靠的是域名逐字核对和独立入口，不是那把锁。

⚠️ 常见误区

「有 HTTPS 小锁的页面一定是官方页，可以放心输密码」——本讲最危险的一条误区。小锁和官方身份是两件事：加密保护的是传输过程，而你把密码交给了谁，取决于页面背后是谁，跟加不加密无关。另一个误区是「我已经在官方页面登录过了，从邮件链接再进一次没关系」——重新输入密码的那一页是谁，才是关键；只要入口不是你主动掌握的，就按可疑处理。

点击翻面 →

解决问题识破「地址摆着看却认错人」的伪装，以及子域混淆。

概念卡 4

点击翻面 →
定义浏览器地址栏的小锁表示通信经 TLS 加密、传输私密且不被篡改。
解决问题说清它能证明什么：加密；以及不能证明什么：对面是谁。

何时用看到小锁只当作「传输加密」，身份一律用域名和独立入口另行核实。

统一身份认证页
点击翻面 →
定义学校各系统共用的登录入口，一个账号密码通行多个校内系统。
解决问题明确输入凭据的唯一安全场景：由自己主动进入的官方认证页。
直觉家门钥匙只交给自己开的门；别人递来的门看着再像，也不在里面掏钥匙。
误区以为从邮件链接进的「认证页」也算官方；入口不由你掌握就不可信。
何时用凡要输账号密码，只用书签或从校内官网首页进入。
概念卡 6
域名主体与「从右往左读」
点击翻面 →
定义域名用点号分段，靠近右侧的主干决定网站归属；读它应从右往左。
解决问题拆穿子域混淆，例如 ynu.edu.cn.evil.example 真正属于 evil.example；也拆穿前后缀伪装，例如 service@i.ynu.edu.cn 的域名是 i.ynu.edu.cn。

误区从左往右扫、被开头熟悉字母带偏，或只盯结尾后缀。
何时用每次读地址都用：盯住主干逐字与官方域名比对，不等就不认。

✍️分层习题：先自己写，再点开核对

L1 概念辨析判断下列说法的正误并说明理由：①「链接上写着『系统验证』，说明它通向学校系统」；②「页面有 HTTPS 小锁，说明这是学校官方登录页」；③「短链只是把网址变短，终点和原网址一样安全」。
提示

逐句找出被混淆的那一对：文字 vs 地址、加密 vs 身份、变短的显示 vs 由谁决定的终点。

完整解答
① 错。显示文字由写信人随便填写，和真实去向无关；必须悬停或长按读出 href 里的真实地址再判断。演练邮件里「系统验证」实际指向 phishsim.cacter.com，与校内域名无关。② 错。HTTPS 小锁只证明传输加密（TLS），不证明对面是谁；骗子也能给假登录页申请证书挂上同样的小锁。判断身份靠域名逐字核对和独立入口。③ 错。短链压缩的是显示形式，终点仍由写信人决定，可以指向任何地方；所以短链本身是「请停下」的信号，不是安全保证。
L1 概念辨析有人说：「我把邮件里的短链复制到新标签打开、再看清它跳到哪，就能确认安不安全。」这句话错在哪？请说出为什么「为了看清而点开」本身就是问题。
提示

想清楚：在新标签打开，是否改变了「点下去会执行跳转」这件事？看清终点的代价是什么？

完整解答
错在把「换个地方打开」当成「取消了点击」。复制到新标签后访问，执行的仍是同一次跳转，照样会到达骗子设定的终点，可能是高仿登录页；而且脱离了邮件客户端的环境，更缺少提示，防备心反而更低。更根本的问题是：你根本不需要知道它跳去哪——补贴、工资、账号核验都有官方独立入口。正确做法是不点、不展开，离开这封信从书签或官网进入对应系统查看，或电话核实。
L2 逐字段标注请对着「系统验证」演练邮件卡逐项写出判断，每写一项都要给出依据：① 列表里的「陌」字说明了什么、不说明什么？② 显示文字与真实地址分别是什么，为什么构成危险信号？③ 「24 小时后冻结」属于哪类话术、起什么作用？④ 最后给出的正确动作是什么？
提示

按「列表标识 → 链接 → 话术 → 动作」顺序走一遍四个检查点；记住「陌」是提示不是判决。

完整解答
① 「陌」表示这是陌生发件人，是校内邮箱给的免费提示，提醒你多查一步；它不说明这是钓鱼邮件——正常外校学术邮件同样带「陌」，所以不能凭它下结论，也不能凭它放行。② 显示文字是「系统验证」，真实地址是 phishsim.cacter.com/verify/...，一个指向演练平台、与 ynu.edu.cn 毫无关系的域名。两者分离正是危险信号：文字让你放心，地址把你带走。③ 「24 小时后冻结」是「权威 + 紧急」组合话术，目的是制造时间压力，让你来不及核实就先点链接。④ 正确动作：不点这封信里的链接；改从自己收藏的地址或学校官网首页进入邮箱系统确认；确属异常后按流程上报，而不是在信里完成它要求的操作。四个检查点里，本讲新增的是「点哪里」——读地址。
L2 逐字段标注请对着「财务处绩效补贴」仿真邮件卡逐项写出判断：① 短链 t.cn/A5xKp 的风险在哪？② 跳转终点 p0rtal.ynu-edU.cn 用了哪两种形近伪装？它和官方 ynu.edu.cn 逐字相等吗？③ 页面上的 HTTPS 小锁能证明什么、不能证明什么？④ 写出完整正确动作。
提示

逐字段套用概念卡 2、3、4；「逐字相等」是判断域名的唯一标准，不用「看起来像」。

完整解答
① 短链把真实终点压成一小串字符，光看 t.cn/A5xKp 看不出要去哪，终点由写信人决定；它还可能多级跳转，第一眼中转地址干净、问题藏在后面。② 两种伪装：数字 0 冒充字母 o（p0rtal 对应 portal），以及用连字符和大小写混淆（ynu-edU.cn 冒充 ynu.edu.cn）。它与官方 ynu.edu.cn 逐字都不相等——官方是点号分隔的 ynu.edu.cn，这里是连字符且字母被替换，所以判为「不是」。③ 小锁证明传输经过 TLS 加密、途中不可看不可改；不能证明页面属于学校，骗子同样能申请证书开 HTTPS。④ 正确动作：不点短链、不为看清而展开；不在这封信里「确认收款信息」；离开邮件从学校官网或校内办公系统入口进入查看，或向财务处电话核实；确认异常后按流程上报。
L3 处置演练某老师在手机上收到一封「学院教务」来信：主题「选课系统密码即将失效，请重新验证」，正文给出「认证入口 https://login.ynu-edu.cn/verify」，页面挂着 HTTPS 小锁，并要求「今日内重新验证」。请你写出完整的处置顺序（每一步做什么、为什么），并说明如果你已经在这封信链接的页面里输过一次密码，接下来该怎么办。
提示

按「停 → 读地址 → 判身份 → 换通道 → 上报」的顺序写；误输密码属于已经交出凭据，要按补救路径处理。

完整解答
第一步，停：不点链接、不在页面输入任何账号密码；「今日失效」是时间压力，越急越要先停。第二步，读地址：手机上长按链接看预览，逐字读出 login.ynu-edu.cn，发现它用连字符代替点号，与官方 ynu.edu.cn 不等，判为形近字伪装；即使有小锁也不改变判断——小锁只管加密不管身份。第三步，换通道：不在这封信里验证，打开浏览器书签或从学校官网首页进入真正的统一身份认证页查看密码状态，必要时电话向学院教务核实。第四步，上报：确认是钓鱼后按流程上报，保留原信便于追溯，不转发给同事。若已经在那页输入过密码：立刻通过官方入口修改密码；如在其他系统复用过同一密码，一并修改；联系信息技术中心报备并说明情况；保留邮件与页面信息作为证据。关键顺序是先改密、不要先删邮件——凭据一旦交出，后续只能补救，越早改密损失越小。

对着空气（或室友）说出这三句。说卡壳的那句，回去重读对应小节。

句1：这讲解决什么问题？——

🚪 合上书挑战：能全写出来，这一讲才毕业

  1. 说清链接文字与真实地址的区别，并写出电脑上和手机上各怎么读真实地址。
  2. 说出短链与多级跳转的风险，以及为什么不该为了「看清终点」而点开或展开。
  3. 举出形近字替换、子域混淆、punycode 各一个例子，并说明读域名为什么要从右往左。
  4. 解释 HTTPS 小锁能保证什么、不能保证什么，为什么假登录页也能挂小锁。
  5. 写出进入统一身份认证页的唯一可靠方式，并说明它为什么能挡住本讲所有链接伪装。
  6. 设在假登录页输过一次密码，写出改密、报备、留证的正确顺序，并说明为什么不能先删邮件。
  7. 一句话回答本讲的主线问题：链接文字和真实去向不一致时，该看哪里？
