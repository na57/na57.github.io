3.1为什么需要堆：每次都要"找最大"，但不想每次重排整个数组

第2章的分治给了我们归并排序：O(nlgn)，但要付出 Θ(n) 的辅助空间。先别急着想"更快的排序"，先看一个更朴素的需求：很多场景不是一次性排好序，而是反复地"取当前最大，再补进新的"——操作系统的进程调度、医院急诊的分诊台，都是这样。用无序数组，取最大要扫一遍 O(n)；用全排序数组，插入一个新元素要挪动 O(n)。能不能让"取最大"和"插入"都只要 O(lgn)？这就是堆（Heap）存在的理由。

最大堆：一个"近似有序"的二叉树

最大堆（Max-Heap）是一棵近似完全的二叉树，满足最大堆性质（Max-Heap Property）：除根以外，每个节点的值都不大于它父亲的值。也就是对一切 i ≠ 1：

A[PARENT(i)] ≥ A[i]

堆直接用数组存放，不做任何指针。下标从 1 开始，三个导航公式背下来：

PARENT(i) = ⌊i/2⌋ LEFT(i) = 2i RIGHT(i) = 2i+1

例如下标 4 的父亲是 ⌊4/2⌋=2，孩子是 8 和 9。树的高度是 ⌊lgn⌋：n=10 时高度 3，n=15 时高度 3。

MAX-HEAPIFY：让一个"只有根不对"的子树归位，代价 O(lgn)

核心操作 MAX-HEAPIFY：假设 LEFT(i) 和 RIGHT(i) 为根的两棵子树都已经是最大堆，只有 A[i] 可能"太小"。做法：比较 A[i] 与两个孩子，若最大的不是 A[i]，就把 A[i] 与最大的孩子交换，然后对那个孩子位置递归调用 MAX-HEAPIFY。每下沉一层做一次比较交换，最多沉到叶子，路径长度不超过树高，所以代价 O(lgn)。

建堆的账：为什么是 O(n) 而不是 O(nlgn)

BUILD-MAX-HEAP 从最后一个内部节点 i=⌊n/2⌋ 到根 i=1，依次做 MAX-HEAPIFY。粗看：n 次调用 × 每次 O(lgn) = O(nlgn)。这个上界对但不紧，因为大多数节点离叶子很近，根本沉不了几层。

拿 n=15 真算一遍账（满二叉树，高度 3）。按节点的高度分类——高度 0 是叶子，高度 3 是根：

高度 h该层节点数每个节点至多下沉次数小计
0（叶子）800×8 = 0
1411×4 = 4
2222×2 = 4
3（根）133×1 = 3
合计15—11 ≤ 2n = 30

一般情形：高度为 h 的节点至多 ⌈n/2h+1⌉ 个，每个代价 O(h)，所以总代价

T(n) = ∑h ⌈n/2h+1⌉·O(h) = O(n·∑h h/2h) = O(2n) = O(n)

这里用到一个求和事实：∑h≥0 h/2h = 2。验证一下为什么：记 S = 1/2 + 2/4 + 3/8 + 4/16 + …；则 2S = 1 + 2/2 + 3/4 + 4/8 + …；两式相减，2S − S = 1 + (2/2−1/2) + (3/4−2/4) + (4/8−3/8) + … = 1 + 1/2 + 1/4 + 1/8 + … = 2，所以 S = 2。

💡 关键一跃

建堆里"贵的节点少、便宜的节点多"：一半的节点是叶子（0 次交换），只有 1 个根最贵。n 个操作的总代价由分布决定，不由最坏那次决定——这正是第2章递归树之外另一种常见的紧界分析手法：按深度/高度分档求和。

优先队列：堆的直接产品

基于最大堆，优先队列（Priority Queue）的三个操作都是 O(lgn)：HEAP-MAXIMUM 直接读 A[1]（O(1)）；HEAP-EXTRACT-MAX 把末尾元素提到根再 MAX-HEAPIFY；MAX-HEAP-INSERT 把新元素放末尾、键设为 −∞，再 INCREASE-KEY 到目标值，沿父亲链上浮。堆排序、第7章的 Prim 与 Dijkstra 算法都建立在这三个操作上。

⚠️ 常见误区

"堆是一棵排序好的树"——错。堆只保证父亲 ≥ 孩子，兄弟之间、不同子树之间没有任何顺序保证。想拿"全局第 k 大"，堆不能一次给你答案，只能一次次 EXTRACT-MAX。把"局部偏序"误当"全局全序"，是堆题最常见的丢分点。

3.2堆排序：把"取最大"重复 n−1 次，原地 O(nlgn)

上一节给了 O(lgn) 的"取最大"。排序的整个思路因此变得直白：把数组建成最大堆，然后反复把堆顶（当前最大）换到数组末尾、堆规模减一、对新堆顶做 MAX-HEAPIFY。这就是堆排序（Heapsort）。

代价账：建堆 O(n)，之后 n−1 次 EXTRACT-MAX，每次 MAX-HEAPIFY 至多 O(lgn)，合计

T(n) = O(n) + (n−1)·O(lgn) = O(nlgn)

排序全程在原数组内进行，只用 O(1) 辅助空间——这是它比归并排序（Θ(n) 辅助空间）多出来的一张王牌。

⚠️ 常见误区

"堆排序是稳定排序"——错。交换堆顶与堆末会把元素长距离甩到前面，相等元素的原始相对顺序无法保证。比如两个等值元素分别在堆顶附近和堆底，一次 extract 就可能让后者越过前者。需要稳定性时别选堆排序。

✅ 判定规则

三种 O(nlgn) 排序怎么选：要原地 + 最坏情况保证选堆排序；要稳定选归并排序；要平均常数最小选快速排序（3.3、3.4 节）。堆排序最坏 O(nlgn) 是硬保证，快排最坏会掉到 Θ(n²)。

3.3快速排序的分区：用一次扫描把数组切成"小 | 主元 | 大"

堆排序保证了最坏 O(nlgn)，但工程师更爱另一个平均更快的家伙：快速排序（Quicksort）。它是第2章分治思想最直接的传人——分（PARTITION）：把 A[p..r] 重排成"≤主元的 | 主元 | ≥主元的"三段；治：递归排左右两段；合：什么都不用做（这是它比归并省的地方）。

PARTITION(A, p, r) 取主元 x = A[r]，维护指针 i = "≤x 区域的右边界"（初始 p−1）。j 从 p 扫到 r−1：若 A[j] ≤ x，则 i 加一、交换 A[i] 与 A[j]。扫完交换 A[i+1] 与 A[r]，返回 q = i+1。

最坏情形：分区每次切出 0 对 n−1

如果每次分区都极度不平衡——一边 0 个元素、一边 n−1 个（例如数组已经有序且总取末位当主元），递归式变成：

T(n) = T(n−1) + Θ(n) ⟹ T(n) = Θ(n²)

拿 n=5 真算：每层分区代价就是当前子问题规模，5 + 4 + 3 + 2 + 1 = 15 = n(n+1)/2 = 5·6/2 ✓。这是一条每层层代价减 1 的"斜树"，深度 n，总代价 Θ(n²)。

💡 关键一跃

快排的命运完全由"主元切得均不均"决定。切得均（比如每次 1:9）依然是 Θ(nlgn)——用递归树验证：每层代价 n，深度 log10/9n = Θ(lgn)。真正致命的是每次都 0:(n−1)，而固定取末位主元碰上已排序输入就必然如此。下一节的任务：让这种坏运气变成小概率事件。

3.4随机化快排：把"坏输入"变成"坏运气"，期望 O(nlgn)

上一节的坏消息是：固定主元让某些输入必然 Θ(n²)。修复方案简单到不像正经算法——RANDOMIZED-PARTITION：先在 A[p..r] 里均匀随机抽一个下标，与 A[r] 交换，再走普通 PARTITION。从此没有任何特定输入能稳定触发最坏情形；最坏情形仍然存在，但发生的概率小到可以忽略。算法分析的口径也从"最坏输入"换成"期望运行时间"。

期望比较次数：指示器随机变量的经典一课

快排的运行时间由比较次数主导。设输入元素按值从小到大记为 z₁ < z₂ < … < zₙ。定义指示器随机变量（Indicator Random Variable）：Xij = 1 当且仅当 zi 与 zj 在整次快排中被比较过（每对元素至多比较一次——因为比较只发生在主元与另一元素之间，比完主元就退场了）。总比较次数 X = ∑i<j Xij，于是

E[X] = ∑i<j E[Xij] = ∑i<j Pr{ zi 与 zj 被比较 } = ∑i<j 2j−i+1

为什么概率是 2/(j−i+1)：zi 与 zj 被比较，当且仅当在集合 {zi, zi+1, …, zj} 这 j−i+1 个元素中，第一个被选为主元的恰好是 zi 或 zj（若先选中中间的 zk，i<k<j，则 zi 与 zj 被分进两个子问题，永远不再见面）。随机选主元下，每个元素等概率 1/(j−i+1) 成为该集合里的首个主元，两个端点合计 2/(j−i+1)。

拿 n=4 真算：6 对元素逐对求概率

元素对 (zᵢ, zⱼ)区间大小 j−i+1比较概率 2/(j−i+1)
(1,2)21
(1,3)32/3
(1,4)41/2
(2,3)21
(2,4)32/3
(3,4)21
合计 E[X]—3×1 + 2×(2/3) + 1/2 = 4.83

对比：n=4 的最坏情形比较次数是 3+2+1 = 6 次（每次切出 0 对 n−1）。期望 4.83 次比最坏 6 次省了近 20%，n 越大差距越是量级级的。

一般放缩：把求和按 k = j−i 重新分组，每个 k 恰有 n−k 对，每对概率 2/(k+1)，所以

E[X] = ∑k=1n−1 (n−k)·2k+1 < 2n·∑k=1n−1 1k ≈ 2n·ln n = Θ(nlgn)

（调和级数 Hn ≈ ln n + 0.577，放缩时把 n−k 放松成 n、把 2/(k+1) 放松成 2/k。）

⚠️ 常见误区

"随机化快排把最坏情形消灭了"——错。Θ(n²) 仍在，只是从"某些输入必触发"变成"任何输入都以极小概率触发"。期望 O(nlgn) 是对算法的随机选择取平均，不是对输入分布取平均——这叫随机化算法，不是平均情形分析。对敌手（知道代码不知道随机数）依然安全。

对算法内部的随机选择（随机主元）取期望，输入是任意固定的。这意味着不存在"专克快排的坏输入"——同样的最坏输入，换次随机数就跑得飞快。

3.5比较排序下界：决策树告诉你 Ω(nlgn) 是天花板

堆排序 O(nlgn)，随机化快排期望 Θ(nlgn)——还能更快吗？这一节给出一个普适的否定答案：任何只靠"两两比较"获取信息的排序算法，最坏情形都要 Ω(nlgn) 次比较。工具是决策树（Decision Tree）模型。

决策树：把任何比较排序画成一棵二叉树

一个基于比较的排序算法，在固定输入规模 n 下的全部行为，可以画成一棵二叉树：每个内部节点是一次比较 "ai : aj"，左分支走 ≤、右分支走 >，每片叶子是一个确定的输出排列。n 个元素有 n! 种可能排列，算法要区分它们，所以树至少有 n! 片叶子。一次运行就是从根到某片叶子的一条路径，路径长度 = 这次运行的比较次数；树高 h = 最坏情形比较次数。

n=3 真算：3! = 6 种排列，树必须 ≥ 6 片叶子。高度 h 的二叉树至多 2h 片叶子，所以 2h ≥ 6，h ≥ ⌈lg 6⌉ = ⌈2.58⌉ = 3。即排 3 个元素最坏至少要 3 次比较——画出这棵树：根比较 a₁:a₂；若 a₁≤a₂，比较 a₂:a₃；若 a₂≤a₃ 得叶 [a₁a₂a₃]，否则再比 a₁:a₃ 区分 [a₁a₃a₂] 与 [a₃a₁a₂]；对称地处理 a₁>a₂ 分支。深度确实 3，与下界吻合。

从 2ʰ ≥ n! 到 Ω(nlgn)

2h ≥ n! ⟹ h ≥ lg(n!) = ∑k=1n lg k

逐项放缩（不用 Stirling 也能证）：把求和砍掉前一半，剩下的每一项都 ≥ lg(n/2)：

lg(n!) = ∑k=1n lg k ≥ ∑k=⌈n/2⌉n lg k ≥ n2·lgn2 = n2(lg n − 1) = Ω(nlgn)

（若用 Stirling 公式 n! ≈ (n/e)n·√(2πn)，则 lg(n!) ≈ n lg n − n lg e + O(lg n)，结论相同且更精确。）

✅ 判定规则

比较排序下界 Ω(nlgn) 是对信息获取方式的限制：每次比较最多带回 1 比特，而确定 n! 个排列中的哪一个需要 lg(n!) ≈ n lg n 比特。它不禁止任何具体算法，只禁止"纯比较 + 更快"的组合。想更快，必须绕过"比较"这个信息瓶颈——这正是 3.6 节的事。

⚠️ 常见误区

"下界说排序至少要 Ω(nlgn)，所以计数排序 O(n) 是矛盾/作弊"——错。下界的前提是"算法只通过比较获取顺序信息"。计数排序一次比较都不做，它用"值即下标"直接定位，根本不在决策树模型的管辖范围内。下界没有错，线性排序也没有作弊，是模型边界划得好。

3.6线性时间排序：不比较，改用"键的结构"直接定位

3.5 节说了：比较的路线最多走到 Ω(nlgn)。但下界只封住了"比较"这一条路。如果键本身带有可利用的结构——范围小、位数有限、分布均匀——就能绕过比较，直接算出每个元素该去的位置，跑到 O(n)。这一节看三位选手：计数排序、基数排序、桶排序。

计数排序（Counting Sort）：键值是 0..k 的小整数，"数人数 + 算站位"

前提：n 个元素的键都是 0 到 k 之间的整数，且 k = O(n)。两趟扫描：第一趟数出每个值出现几次（计数数组 C）；把 C 改成前缀和——C[j] = "≤j 的元素个数"，也就是值 j 的元素在输出中的最后站位；第二趟从右往左扫输入，把 A[j] 放到 B[C[A[j]]]，然后 C[A[j]] 减一。从右往左扫是稳定性（Stability，相等元素保持原始相对顺序）的关键。

完整 trace（CLRS 图 8.2）：A = [2, 5, 3, 0, 2, 3, 0, 3]，k=5。

基数排序（Radix Sort）：键是 d 位整数，逐位用稳定子排序

前提：每个键是 d 位数字，每位取自 k 种符号。做法：从最低位到最高位，逐位用一个稳定排序（通常计数排序）排一遍。每轮 Θ(n+k)，共 d 轮，总代价 Θ(d(n+k))；d 为常数、k = O(n) 时即 Θ(n)。

桶排序（Bucket Sort）：键均匀分布在 [0,1)，"分桶 + 桶内快排"

前提：键独立均匀地分布在 [0,1) 区间。做法：开 n 个等宽桶，A[i] 进第 ⌊n·A[i]⌋ 号桶；每个桶内用插入排序；按桶序拼接。

💡 关键一跃

三种算法共享同一个哲学：用"键是什么"代替"键比谁大"。计数用值当下标，基数用各位数字分桶，桶排序用数值大小映射区间。它们不违反 Ω(nlgn) 下界，因为它们根本不在"比较模型"里玩。线性时间不是免费的——是用键的结构信息换来的。

📝分层习题

L1 概念辨析堆排序是不稳定排序。判断这个说法对不对，并说明机制层面的原因。
提示

想想 EXTRACT-MAX 那一步发生了什么距离的移动；再想想"稳定"要求相等元素保持什么。

完整解答

对，堆排序不稳定。机制：每轮把堆顶 A[1] 与堆末 A[heap-size] 交换——这是一次跨越几乎整个数组的长途搬运。若两个等值元素 x、y 原本 x 在前 y 在后，y 可能因位于堆末被一次交换甩到堆顶附近，最终排在 x 前面，原始相对顺序被破坏。对比：归并排序的合并是顺序比较、等值时先取左半，天然稳定；插入排序只与相邻元素交换，也稳定。堆排序的不稳定不是实现缺陷，是"原地 + O(lgn) 修复"这套机制的固有代价。

L1 概念辨析基数排序的第 2 轮（按十位排）为什么必须用稳定排序当子过程？如果换成不稳定的快排按位排，会发生什么？
提示

第 2 轮里十位相同的两个数，它们在低位（个位）上的次序是谁保证的？

完整解答

基数排序的正确性靠归纳：第 i 轮结束后，数组按"低 i 位"整体有序。第 2 轮按十位排时，十位相同的元素（如 457 与 355）的先后，必须沿用第 1 轮按个位排好的次序（355 个位 5 < 457 个位 7，所以 355 应在前——最终 355 < 457 ✓）。这个"沿用"正是稳定性的定义。若子排序不稳定，十位相同的元素次序随机，低位轮次的工作作废，最终结果可能乱序。例如 [29, 21]：第 1 轮按个位排得 [21, 29]；第 2 轮十位都是 2，若子排序不稳定可能把 29 换到 21 前面，输出 [29, 21]——错了。所以 CLRS 规定基数排序的子排序必须稳定。

L2 手算推导对数组 A = [3, 9, 2, 1, 4, 5] 手算 BUILD-MAX-HEAP，给出每一步 MAX-HEAPIFY 之后的数组，并验证最终堆性质。
提示

先定起点：i 从 ⌊n/2⌋ = 3 开始往根走。每次只动"当前下标为根、两棵子树已是堆"的那棵子树。

完整解答

n=6，初始 [3, 9, 2, 1, 4, 5]。

i=3（值 2）：孩子只有 LEFT(3)=6，A[6]=5 > 2，交换 → [3, 9, 5, 1, 4, 2]。

i=2（值 9）：孩子 A[4]=1、A[5]=4，9 最大，不动 → [3, 9, 5, 1, 4, 2]。

i=1（值 3）：孩子 A[2]=9、A[3]=5，与最大的 9 交换 → [9, 3, 5, 1, 4, 2]；继续在下标 2：A[2]=3，孩子 A[4]=1、A[5]=4，与最大的 4 交换 → [9, 4, 5, 1, 3, 2]；到下标 5 是叶子，停止。

最终堆 [9, 4, 5, 1, 3, 2]。验证：A[1]=9 ≥ A[2]=4、A[3]=5 ✓；A[2]=4 ≥ A[4]=1、A[5]=3 ✓；A[3]=5 ≥ A[6]=2 ✓。下标 4、5、6 是叶子无需检查。交换总次数 3 次，远小于 2n=12，符合 O(n) 的账。

L2 手算推导对数组 A = [5, 2, 4, 1, 3] 手算 PARTITION（主元取末位 A[5]=3），逐 j 给出 i 与数组状态，并给出返回的 q。
提示

i 从 p−1=0 开始；只有 A[j] ≤ 3 时 i 才加一并交换 A[i]↔A[j]；最后别忘了主元归位那一步。

完整解答

初始 i=0，主元 x=3。

j=1：A[1]=5 > 3，不动。i=0。数组 [5, 2, 4, 1, 3]。

j=2：A[2]=2 ≤ 3，i=1，交换 A[1]↔A[2] → [2, 5, 4, 1, 3]。

j=3：A[3]=4 > 3，不动。i=1。

j=4：A[4]=1 ≤ 3，i=2，交换 A[2]↔A[4] → [2, 1, 5, 4, 3]。

收尾：交换 A[i+1]=A[3] ↔ A[5] → [2, 1, 3, 4, 5]，返回 q=3。

验证：A[1..2]=[2,1] ≤ 3 ✓；A[3]=3 主元就位 ✓；A[4..5]=[4,5] ≥ 3 ✓。本例碰巧两段都有序，但分区本身只承诺三段不变式，不承诺两段有序——那只是小数组的巧合。

L3 建模应用某养老系统要给 100 万条老人记录按年龄排序，年龄是 0–120 的整数，记录还携带姓名等数据。选什么排序算法？论证你的选择，并估算它比随机化快排省多少。
提示

把"年龄 0–120 整数"映射到哪种前提？k 与 n 的量级关系是什么？记录携带数据这点对算法有什么额外要求？

完整解答

选计数排序。论证三步：

① 前提匹配：键是 0..120 的整数，k=121，n=10⁶，k ≪ n 即 k=O(n)，恰好落在计数排序的甜区。计数数组 C 只有 121 个格子，内存可忽略。

② 代价对比：计数排序 Θ(n+k) ≈ 2n ≈ 2×10⁶ 次操作；随机化快排期望约 2n·ln n ≈ 2×10⁶×13.8 ≈ 2.8×10⁷ 次比较——计数排序快约一个量级（约 14 倍）。

③ 稳定性要求：记录携带姓名等数据，且若记录此前已按其他键（如入住时间）排过序，按年龄再排时通常要保住旧次序——计数排序稳定（从右往左回填），满足要求。若改用基数排序（年龄视作 3 位十进制数，d=3，k=10）也可行：Θ(3(n+10)) ≈ 3n，比计数慢些但仍线性；桶排序不适合（整数非均匀实数）；堆排/快排则白白放弃键结构。

结论：计数排序，Θ(n) 且稳定；这正是"用键的结构换时间"的标准应用。

自测 1
BUILD-MAX-HEAP 对 n 个元素的总代价是 O(n)，其紧界分析的关键论据是？
  • A. 每次 MAX-HEAPIFY 只需 O(1)，所以 n 次是 O(n)
  • B. 高度为 h 的节点至多 ⌈n/2^(h+1)⌉ 个，代价按高度分档求和 n·∑h/2ʰ = 2n
  • C. 堆是完全二叉树，所以任何操作都是 O(n)
  • D. 主定理 case 2 直接给出 O(n)
解析：B 对——代价按高度分档，贵的节点（高 h 大）数量指数级少，求和收敛到 2n。A 错：MAX-HEAPIFY 单次最坏 O(lgn) 不是 O(1)，是"多数节点根本沉不了几层"摊薄了代价。C 错：完全二叉树只决定结构，EXTRACT-MAX 就不是 O(n) 而是 O(lgn)，"完全"推不出 O(n)。D 错：BUILD-MAX-HEAP 不是分治递归式，主定理用不上。
自测 2
以下哪种输入会让"固定取末位主元"的快排跑出 Θ(n²)？
  • A. 元素全随机的数组
  • B. 所有元素相等的数组以外的任何数组都不会
  • C. 已经升序排好的数组
  • D. 先升序后降序的"山峰形"数组
解析：C 对——已排序时末位主元恰是当前最大，每次分区切出 0 对 n−1，T(n)=T(n−1)+Θ(n)=Θ(n²)。A 错：随机输入下固定主元近似随机主元，期望 nlgn。B 错：全相等数组按本章 PARTITION 定义（≤x 进左区）会全部进左区再主元归位，实际切得很均匀；且"不会"说得太满——逆序数组同样触发最坏。D 错：山峰形不保证每次 0 对 n−1，一般不至于 Θ(n²)。
自测 3
随机化快排中，zᵢ 与 zⱼ（i<j）被比较的概率是 2/(j−i+1)，这个结论依赖的关键事件是？
  • A. 在 {zᵢ,…,zⱼ} 中第一个被选为主元的恰是 zᵢ 或 zⱼ
  • B. zᵢ 和 zⱼ 在数组中相邻
  • C. zᵢ 和 zⱼ 都被选为主元各一次
  • D. 输入必须是随机打乱的
解析：A 对——只有两者之一先当主元才会互相比较；若中间的 zₖ 先当主元，两者被永久分到两个子问题。集合大小 j−i+1，等概率下两个端点合计 2/(j−i+1)。B 错：概率取决于值的距离 j−i，与数组物理位置无关。C 错：一对元素至多比较一次，"各当一次主元"既不可能也没必要。D 错：随机性来自算法自己抽主元，不依赖输入分布——这是随机化算法与平均情形分析的分界线。
自测 4
"比较排序最坏情形需要 Ω(nlgn) 次比较"这条下界的准确含义是？
  • A. 任何排序算法（包括计数排序）最坏都要 Ω(nlgn)
  • B. 堆排序没有达标，因为它偶尔是 O(n²)
  • C. 对某个固定输入，所有比较排序都恰好需要 nlgn 次比较
  • D. 任何只靠比较获取顺序信息的算法，最坏输入下需 Ω(nlgn) 次比较；不计数排序的管辖
解析：D 对——决策树论证的前提是"信息只来自两两比较"，结论是最坏情形（存在某个输入）需要 Ω(nlgn)。A 错：计数排序不做比较，不在模型内，O(n) 不与下界矛盾。B 错：堆排序 O(nlgn) 恰好达到下界，是最优的比较排序之一。C 错：下界是"最坏情形"而非"每个输入"；且是 Ω 级别的渐近说法，不是精确 nlgn。
自测 5
下列哪组"数据 → 算法"的配对是错的？
  • A. 50 万条 0–999 的整数编号 → 计数排序
  • B. 100 万个 64 位无符号整数，值域跨满整个 2⁶⁴ → 计数排序
  • C. [0,1) 上均匀采样的浮点概率值 → 桶排序
  • D. 定长 8 位手机尾号字符串 → 基数排序（每字符一位）
解析：B 错——计数排序要开 k+1 个计数格，k=2⁶⁴ 根本开不下，且 k=O(n) 前提完全不满足；这种场景该用快排（或按字节做 d=8、k=256 的基数排序）。A 对：k=1000 = O(n)，计数排序甜区。C 对：均匀分布正是桶排序期望线性的前提。D 对：定长数字串按位 d=8、k=10，基数排序 Θ(8(n+10)) 线性。
