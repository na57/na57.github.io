8.1为什么需要动态规划：从钢条切割的指数爆炸说起

前七章里，问题要么自带结构（数组有序、图有边），要么我们能施加结构（堆、红黑树）。本章面对一类新问题：组合最优化（Combinatorial Optimization）——方案总数随规模指数增长，但答案只有一个最优值。入门例子是 CLRS 的钢条切割（Rod Cutting）。

问题。一根长度为 n 的钢条，可以切成若干整数段出售。长度 i 的段售价 pi。怎么切总收入最大？设价格表为：

长度 i1234
价格 pi1589

长度为 4 时，切法有 2³ = 8 种（每个缝切或不切）：不切得 9；1+3 得 1+8 = 9；2+2 得 5+5 = 10；3+1 得 9；1+1+2 得 7；……最优是 2+2，收入 10。一般地，长度 n 有 2n−1 种切法——枚举随 n 指数爆炸。

递归为什么也爆炸。设 r(n) 为长度 n 的最优收入。第一刀切在 i 处，剩下 n−i 递归求解：

r(n) = max1≤i≤n ( pi + r(n−i) )，r(0) = 0

用 T(n) 记朴素递归的调用次数：T(n) = 1 + Σj<n T(j)，展开得 T(n) = 2n。n = 4 时共 16 次调用，其中 r(2) 被算了 4 次、r(1) 被算了 8 次。爆炸不是因为问题难，而是因为同一个子问题被反复重算。

💡 关键一跃

递归树里重复出现的子问题只有 n 个（r(0)…r(n−1)），却被算了 2ⁿ 次。把每个子问题的答案存下来、只算一次，指数就变线性——这就是动态规划的全部起点。

⚠️ 常见误区

把动态规划理解成"递推"。递推只是填表的机械动作；DP 的本质是发现问题结构（重叠子问题 + 最优子结构），递推式只是结构的代数表达。只会背方程、不会判断结构，换一道题就报废。

8.2两张入场券：最优子结构与重叠子问题

上一节给了"存答案"的动机，但它带出一个问题：凭什么子问题的最优解能拼出原问题的最优解？凭什么子问题会重复？这两个"凭"就是 DP 的两张入场券。

入场券一：最优子结构（Optimal Substructure）。问题的最优解内部，包含子问题的最优解。钢条切割里，若最优第一刀切在 i，则剩下那段必须按 r(n−i) 的最优方案切——否则换个更好的切法总收入更高，矛盾。证明套路永远是剪切—粘贴（cut-and-paste）：假设子解不最优，换上更优的，得到更优的原解，矛盾。

入场券二：重叠子问题（Overlapping Subproblems）。递归树中不同子问题总数是多项式的，且同一子问题反复出现。钢条切割只有 n+1 个不同子问题。对比分治（第2章）：归并排序每次拆出的是新子问题，互不重叠，所以分治不需要存答案。

缺一会怎样（两个反例）。

  • 无最优子结构："经过顶点数最多的简单路径"（最长简单路径）。q→t 的最长简单路径若经过 r，并不保证 q→r 段是 q 到 r 的最长简单路径——绕路可能撞上 t 端的顶点，子问题之间互相干扰，剪切—粘贴失效。该问题实际是 NP 难的（第10章）。
  • 无重叠子问题：归并排序。子数组互不相同，存答案纯属浪费空间，分治直接做就是最优。
✅ 判定规则

判断能否 DP 的两步走：① 写出递归式，用剪切—粘贴验证最优子结构；② 数递归树中不同子问题的个数，若为多项式级（通常由参数的取值范围决定），重叠性成立。两步都过，DP 入场。

8.3矩阵链乘：完整填表手算

钢条切割是一维结构，子问题只有一个参数。上一节留下一个问题：子问题有两个参数时，表怎么设计、按什么顺序填？矩阵链乘（Matrix-Chain Multiplication）是最经典的两参数 DP。

问题。矩阵乘法满足结合律但不满足交换律。链 A₁A₂…Aₙ 的加括号方式不同，标量乘法总次数天差地别。维度序列为 ⟨p₀, p₁, …, pₙ⟩，Aᵢ 是 pi−1×pi 矩阵。目标：找总乘法次数最少的加括号方案。

状态设计。设 m[i][j] = 计算 Aᵢ…Aⱼ 的最少乘法次数。枚举最后乘的位置 k：

m[i][j] = mini≤k<j ( m[i][k] + m[k+1][j] + pi−1·pk·pj )，m[i][i] = 0

同时记 s[i][j] = 最优的 k，用于重构括号方案。填表顺序按链长 ℓ = 2, 3, …, n 递增——因为长链依赖短链。

完整手算（4 个矩阵）。A₁: 30×35，A₂: 35×15，A₃: 15×5，A₄: 5×10，即 ⟨p₀,…,p₄⟩ = ⟨30, 35, 15, 5, 10⟩。

第 1 步：ℓ = 2（相邻两矩阵）。

  • m[1][2] = 30·35·15 = 15750
  • m[2][3] = 35·15·5 = 2625
  • m[3][4] = 15·5·10 = 750

第 2 步：ℓ = 3。

  • m[1][3]：k=1 → m[1][1]+m[2][3]+30·15·5 = 0+2625+2250 = 4875；k=2 → m[1][2]+m[3][3]+30·35·5 = 15750+0+5250 = 21000。取 4875，s[1][3]=1。
  • m[2][4]：k=2 → 0+m[3][4]+35·5·10 = 750+1750 = 2500；k=3 → m[2][3]+0+35·5·10 = 2625+1750 = 4375。取 2500，s[2][4]=2。

第 3 步：ℓ = 4（全链）。

  • m[1][4]：k=1 → 0+m[2][4]+30·5·10 = 2500+1500 = 4000；k=2 → m[1][2]+m[3][4]+30·35·10 = 15750+750+10500 = 27000；k=3 → m[1][3]+0+30·15·10 = 4875+4500 = 9375。取 4000，s[1][4]=1。

重构方案。s[1][4]=1 → 最后乘 A₁·(A₂A₃A₄)；s[2][4]=2 → (A₂)·(A₃A₄)。最优加括号：(A₁(A₂(A₃A₄)))，总乘法 4000 次。对比最差的 ((A₁A₂)A₃)A₄ = 27000 次，差近 7 倍。时间复杂度 Θ(n³)，空间 Θ(n²)。

💡 关键一跃

两参数 DP 的填表顺序不是按行或按列，而是按"链长"这条斜线——任何 m[i][j] 只依赖更短的链。状态依赖关系决定填表顺序，这是所有区间 DP 的通用读法。

⚠️ 常见误区

贪心"先乘最小的相邻对"在这里不成立：本例中 m[2][3]=2625 是最小的相邻乘积，但先做 A₂A₃ 会把链锁进次优结构（验证：((A₁(A₂A₃))A₄) 不在最优路径上，最优解根本不把 A₂A₃ 作为顶层决策）。矩阵链乘没有贪心选择性质——这正是它属于第8章而非第9章的原因。

8.4最长公共子序列：两个串上的完整 DP 表

矩阵链乘的子问题是"区间"。上一节留下一个问题：子问题由两个序列的前缀组合而成时，表长什么样？这引出生物信息学与 diff 工具的基石——最长公共子序列（Longest Common Subsequence, LCS）。

问题。给定 X = ⟨x₁…x_m⟩，Y = ⟨y₁…y_n⟩，找最长的序列 Z，它同时是 X 和 Y 的子序列（不要求连续）。设 c[i][j] = X 前 i 个字符与 Y 前 j 个字符的 LCS 长度。按末尾字符分情况：

若 xi = yj：c[i][j] = c[i−1][j−1] + 1
若 xi ≠ yj：c[i][j] = max( c[i−1][j], c[i][j−1] )
边界：c[0][j] = c[i][0] = 0

完整手算。取 X = ABCBDAB（m=7），Y = BDCABA（n=6）。逐行填表（每格按上式，从 c[1][1] 推到 c[7][6]）：

💡 关键一跃

LCS 的状态 c[i][j] 是"两个前缀"的二维组合。凡是"两个序列对齐比较"类问题（编辑距离、diff、序列比对），状态几乎总是 c[i][j] 型——双前缀。看到双序列，先想双前缀。

⚠️ 常见误区

把 LCS 与"最长公共子串"混淆。子串要求连续，子序列不要求。本例中 ABCBDAB 与 BDCABA 的最长公共子串长度只有 2（如 AB、BD），而 LCS 是 4。状态设计完全不同：子串不匹配就清零，子序列不匹配取两侧最大。

8.5记忆化 vs 自底向上：同一张表的两种填法

前三节都默认"自底向上填表"。上一节留下一个问题：既然递归+缓存也能做到每个子问题只算一次，为什么还要费劲设计填表顺序？

路线一：自顶向下记忆化（Top-Down with Memoization）。照抄朴素递归，只加一张哈希表/数组：入口先查缓存，命中即返回；未命中则计算并写入。钢条切割的记忆化版与朴素版代码只差三行，复杂度从 2ⁿ 降到 Θ(n²)（n 个子问题，每个最多试 n 刀）。

路线二：自底向上填表（Bottom-Up）。先分析子问题依赖关系（DAG），按拓扑序从小到大填表。无递归开销，常数因子更小；还能做空间优化——LCS 每行只依赖上一行，空间可从 Θ(mn) 压到 Θ(min(m,n))。

维度自顶向下记忆化自底向上填表
思维负担低：递归式即代码高：须设计依赖顺序
常数开销递归调用 + 缓存查询纯循环，更省
实际求解的子问题只算真正用到的全部算一遍
空间优化难可滚动数组压缩
适用场景状态空间稀疏、原型验证状态空间稠密、性能敏感
✅ 判定规则

两者渐近复杂度相同（都等于"不同子问题数 × 每子问题转移代价"）。实际选择只看两点：递归深度是否安全、是否需要滚动数组省空间。面试写记忆化，生产写填表。

8.6状态设计为什么是难点：一个设计失误的反例

上一节说明"表怎么填"有章可循。但真正的难点在这之前：状态怎么定义？这是 DP 教学中唯一没有通用公式的一步。用一个具体反例看清楚错在哪。

问题：最长递增子序列（LIS）。给序列，找最长的严格递增子序列。

失败的设计。新手直觉：仿照前缀型 DP，设 dp[i] = 前 i 个元素中 LIS 的长度。然后试图从 dp[i−1] 推出 dp[i]："如果 a[i] 能接在 LIS 后面就 +1"。

反例（证明这个转移不存在）。两个前缀 P = [1, 100] 和 Q = [50, 60]，它们的 dp 值相同（都是 2）。现在同时追加元素 70：

  • P + [70] = [1, 100, 70]：LIS = [1, 70] 或 [1, 100]，长度 2；
  • Q + [70] = [50, 60, 70]：LIS = [50, 60, 70]，长度 3。

前缀 dp 值相同、追加元素相同，结果 dp 值却不同。这说明 dp[i] 的取值不包含转移所需的信息——你还需要知道"LIS 的末尾元素是几"，才能判断新元素接不接得上。转移函数在数学上就不存在，任何"递推"都是错的。

正确的设计。把缺失的信息塞进状态：设 dp[i] = 以 a[i] 结尾的 LIS 长度。则

dp[i] = 1 + max { dp[j] : j < i 且 a[j] < a[i] }（集合为空时 dp[i] = 1）

答案是 maxi dp[i]（注意：不是 dp[n]）。在序列 [10, 9, 2, 5, 3, 7, 101, 18] 上手算：dp = [1, 1, 1, 2, 2, 3, 4, 4]，LIS 长度 4（如 [2, 3, 7, 18] 或 [2, 5, 7, 101]）。

💡 关键一跃

状态设计的黄金检验：状态里必须装下"做转移决策所需的全部信息"。写出转移方程前，先问——知道 dp 值，够不够我决定下一步？不够就把缺的信息加进状态（加维度、加"以 i 结尾"之类的限定）。

⚠️ 常见误区

以为"加维度"总能让状态合法。维度可以救回信息，但每加一维，子问题总数乘一个因子——状态膨胀过快时 DP 失去意义（参数范围乘积必须多项式有界，重叠子问题这张入场券才有效）。设计状态是在"信息完整"与"状态数可控"之间走钢丝。

回忆 8.6-1
LIS 中"dp[i] = 前 i 个元素的 LIS 长度"为什么是错误状态设计？
点击翻面 →
参考答案
dp 值不含"LIS 末尾元素"，无法判断新元素能否接上：前缀 [1,100] 与 [50,60] dp 同为 2，追加 70 后结果分别为 2 和 3，转移函数不存在。
回忆 8.6-2
LIS 的正确状态设计与转移方程？答案为什么不是 dp[n]？
点击翻面 →
参考答案
dp[i] = 以 a[i] 结尾的 LIS 长度，dp[i] = 1 + max{dp[j] : j<i, a[j]<a[i]}。LIS 不一定以末元素结尾，故答案是所有 dp[i] 的最大值。

🃏概念卡：本章概念的一分钟画像

翻面前先自问：这个概念我能用一句话讲清楚吗？

概念卡 1
最优子结构（Optimal Substructure）
点击翻面 →
定义问题的最优解内部包含子问题的最优解。
解决问题保证"用子问题最优解拼原问题最优解"合法，是 DP 的第一张入场券。
直觉拼乐高：整体最优作品的每个局部，本身也是该局部的最优拼法。
误区以为所有最优化问题都有——最长简单路径就没有（子问题不独立）。
何时用第9章贪心同样需要它；第10章用它理解"为什么难问题连 DP 都救不了"。
概念卡 2
重叠子问题（Overlapping Subproblems）
点击翻面 →
定义递归树中不同子问题只有多项式个，同一子问题被反复求解。
解决问题是"缓存答案"有利可图的前提，DP 的第二张入场券。
直觉同一道题被布置了一万次——当然该把答案抄下来。
误区与分治混淆：分治的子问题互不重叠（归并排序），缓存无收益。
何时用估算 DP 复杂度：不同子问题数 × 单点转移代价。
概念卡 3
状态与状态转移方程（State & Recurrence）
点击翻面 →
定义状态是子问题的参数化标识；转移方程给出状态间的依赖计算关系。
解决问题把"指数搜索"改写为"多项式个状态的填表"，是 DP 的核心设计动作。
直觉状态 = 压缩过的历史：只保留做未来决策所需的信息。
误区状态信息不足（如 LIS 只记长度）导致转移函数不存在；或状态膨胀失控。
何时用一切 DP 题的第一步；第10章还会用"状态数是否多项式"理解难解性边界。
概念卡 4
记忆化（Memoization）
点击翻面 →
定义在朴素递归上加缓存：算过的子问题直接查表返回。
解决问题用最小改动把指数递归降到多项式，且只计算真正用到的子问题。
直觉开卷考试：遇到做过的题直接翻笔记。
误区以为比自底向上慢一个量级——渐近相同，只差常数与空间优化能力。
何时用状态空间稀疏或快速原型时首选。
概念卡 5
解的重构（Solution Reconstruction）
点击翻面 →
定义DP 表只存最优值；具体方案需另记选择表（如 s[i][j]）或沿转移规则回溯。
解决问题多数应用要的不仅是"最优值是多少"，更是"方案是什么"。
直觉登山时在每个岔口钉个路标，下山沿路标走。
误区压缩空间（滚动数组）后才发现无法回溯——重构需要历史信息。
何时用矩阵链输出括号方案、LCS 输出公共序列、diff 输出编辑脚本。
概念卡 6
填表顺序（Evaluation Order）
点击翻面 →
定义自底向上时按子问题依赖 DAG 的拓扑序计算各状态。
解决问题保证填到任何格子时，它依赖的格子都已就绪。
直觉先修地基再盖楼；矩阵链乘按链长、LCS 按行，都是拓扑序。
误区以为只能按行或按列——顺序由依赖关系决定，区间 DP 按斜线。
何时用设计任何自底向上 DP 时与状态设计同步考虑。

📝分层习题

L1 概念辨析判断：归并排序的子问题也"重叠"——merge 过程会反复处理同样大小的子数组，所以可以用记忆化加速。这个说法对吗？
提示

回忆重叠子问题的定义：关键是"不同子问题的个数"，而不是"子数组的大小"。

完整解答
错。重叠指的是同一个子问题（同样的输入内容）被反复求解。归并排序每次处理的子数组内容互不相同，不同子问题有 O(n log n) 量级且每个只出现一次，缓存没有命中机会，反而白耗空间。易错点：把"参数规模相同"误当作"子问题相同"——判定重叠要看参数取值，不看参数大小。
L1 概念辨析判断：只要一个问题有最优子结构，就一定能用动态规划高效求解。
提示

DP 有两张入场券，这里只给了一张。想想另一张缺失时的复杂度。

完整解答
错。还缺"重叠子问题"。若不同子问题的个数是指数的（如旅行商问题的子集 DP 有 2ⁿ·n 个状态），即使每个只算一次，总量仍是指数。最优子结构只保证递推正确，不保证递推高效。易错点：把正确性条件当成效率条件。
L2 手算推导钢条价格表 p = [1, 5, 8, 9, 10]（长度 1 到 5）。用转移方程 r(n) = max(pᵢ + r(n−i)) 完整计算 r(1)…r(5)，并给出 r(5) 的最优切法。
提示

对每个 n，枚举第一刀位置 i = 1…n，逐项比较；同时记录最优的 i。

完整解答
r(0)=0。
r(1) = p₁+r(0) = 1（不切）。
r(2) = max(p₁+r(1), p₂+r(0)) = max(1+1, 5+0) = 5（不切）。
r(3) = max(1+5, 5+1, 8+0) = max(6, 6, 8) = 8（不切）。
r(4) = max(1+8, 5+5, 8+1, 9+0) = max(9, 10, 9, 9) = 10（切 2+2）。
r(5) = max(1+10, 5+8, 8+5, 9+1, 10+0) = max(11, 13, 13, 10, 10) = 13。
最优切法：第一刀 i=2 或 i=3 均可，得 2+3 两段，收入 5+8 = 13。
L2 手算推导三个矩阵 A₁(5×10)、A₂(10×3)、A₃(3×12)。完整计算 m[1][2]、m[2][3]、m[1][3]，给出最优加括号与乘法次数。
提示

m[1][3] 需要枚举 k=1 与 k=2 两种最后乘法位置。

完整解答
⟨p₀,p₁,p₂,p₃⟩ = ⟨5,10,3,12⟩。
m[1][2] = 5·10·3 = 150；m[2][3] = 10·3·12 = 360。
m[1][3]，k=1：m[1][1]+m[2][3]+p₀p₁p₃ = 0+360+5·10·12 = 360+600 = 960；
k=2：m[1][2]+m[3][3]+p₀p₂p₃ = 150+0+5·3·12 = 150+180 = 330。
最优加括号：((A₁A₂)A₃)，330 次标量乘法（比另一种 960 次省近三分之二）。
L3 建模应用你负责一个文本编辑器的新功能：给用户展示"旧文档 → 新文档"的最少编辑步骤说明。需求是突出显示未改动的部分。请说明：把什么建模成 X 和 Y？用什么算法？输出的 Z 对应产品里的什么？若要进一步给出"最少插入/删除次数"，状态转移该怎么改？
提示

"未改动的部分"在结构上是什么？想想 git diff 为什么长得像 LCS 的输出。

完整解答
建模：X = 旧文档的行序列，Y = 新文档的行序列；Z = LCS(X, Y) 即未改动行，产品上就是"正常显示、不加高亮"的部分（X 中不在 Z 里的行标红删除，Y 中不在 Z 里的行标绿新增）。
最少插入/删除数：编辑距离（Levenshtein 的插删版）。状态仍是双前缀 d[i][j]，转移改为：xᵢ=yⱼ 时 d[i][j]=d[i−1][j−1]；不等时 d[i][j]=1+min(d[i−1][j], d[i][j−1])。若允许替换，再加 d[i−1][j−1]+1 一项。这正是 LCS 转移的孪生兄弟——同一个"双前缀"状态设计，换代价函数而已。

自测 1
一个问题能用动态规划高效求解的充分条件是？
  • A. 有最优子结构
  • B. 有最优子结构且不同子问题数为多项式（重叠子问题）
  • C. 能写出递归式
  • D. 子问题可以并行计算
解析：B 对，两张入场券缺一不可。A 错——只有最优子结构，递归式正确但子问题数可能是指数（如 TSP）；C 错——任何分治都有递归式，与效率无关；D 错——并行性既不保证正确也不保证多项式。
自测 2
矩阵链乘 ⟨30,35,15,5,10⟩ 的最优乘法次数与最后乘的位置是？
  • A. 4875，k=2
  • B. 9375，k=3
  • C. 4000，k=1
  • D. 27000，k=2
解析：C 对，m[1][4]=4000，最优括号 (A₁(A₂(A₃A₄)))。A 错——4875 是 m[1][3] 的值，不是全链；B 错——9375 是 k=3 的候选值，被淘汰；D 错——27000 是 k=2 的候选值，是最差的一档。
自测 3
X=ABCBDAB，Y=BDCABA，c[7][6] 的值与含义是？
  • A. 4，LCS 长度为 4
  • B. 2，最长公共子串长度为 2
  • C. 6，两串较短者的长度
  • D. 7，两串较长者的长度
解析：A 对，一条 LCS 是 BCBA。B 错——那是"最长公共子串"问题的答案，混淆了连续与不连续；C、D 错——把 LCS 长度误读成输入规模，公共子序列长度不可能等于整个较短串（两串并不相同）。
自测 4
关于自顶向下记忆化与自底向上填表，正确的是？
  • A. 记忆化的渐近复杂度严格高于填表
  • B. 填表法总能用更少内存且不影响解的重构
  • C. 记忆化必须把所有子问题都算一遍
  • D. 两者渐近复杂度相同；记忆化只算用到的子问题，填表便于滚动数组省空间
解析：D 对。A 错——渐近相同，只差常数；B 错——滚动数组会丢掉重构所需的历史；C 错——记忆化恰恰只算递归真正触达的子问题，这是它的优点之一。
自测 5
LIS 问题中，状态"dp[i] = 前 i 个元素的 LIS 长度"失败的根本原因是？
  • A. 时间复杂度太高
  • B. dp 值不含转移所需的全部信息（LIS 的末尾元素未知），转移函数不存在
  • C. 该问题没有最优子结构
  • D. 该问题不满足重叠子问题
解析：B 对——[1,100] 与 [50,60] dp 值同为 2，追加 70 后结果不同，证明转移无法表达。A 错——失败是"正确性"层面的，不是效率；C 错——LIS 在"以 i 结尾"的正确定义下有最优子结构；D 错——正确设计下子问题只有 n 个，完全重叠。
