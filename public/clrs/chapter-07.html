7.1为什么 MST 可以贪心：割性质与环性质

第6章解决了"图里有什么、怎么走到"，但它带出一个更贪心的问题：给每条边标了价之后，怎么选边最省钱？全枚举所有生成树有指数级棵（完全图 Kn 有 nn−2 棵），必须找到"哪条边一定要、哪条边一定不要"的判定规则——这就是本节的两个定理。

定义：连通无向带权图 G = (V, E) 的一棵最小生成树（Minimum Spanning Tree, MST）是包含全部顶点、恰好 |V|−1 条边、无环、且总权重最小的子图。本章统一用下面这张贯穿图 G1（7 顶点 {a,b,c,d,e,f,g}、11 条边）：

边a–ba–db–cb–db–ec–ed–ed–fe–fe–gf–g
权重7589751568911

割性质（Cut Property）：把顶点集任意切成两半 (S, V−S)，所有横跨这个割（Cut）的边里，权重最小的那条轻边（Light Edge）必属于某棵 MST。
环性质（Cycle Property）：任取图中的一个环，环上权重最大的那条边（若唯一最重）必不属于任何 MST。

在 G1 上看两个具体实例：

  • 割的实例：取 S = {a}，V−S = {b,c,d,e,f,g}。横跨割的边只有 a–b(7) 与 a–d(5)，轻边是 a–d(5)，它必在某棵 MST 中（本章算出的那棵就有它）。
  • 环的实例：取环 b–d–e–b，三条边权重 9、15、7，最重边 d–e(15) 不在任何 MST 中——绕过它的 b–e(7) 永远更便宜。
✅ 判定规则

割性质给出"安全边"的判据：每次只要找到某个割的轻边，把它加进答案就是安全的。Kruskal 与 Prim 并不神秘——它们只是两种不同的、保证每步都能找到一条割轻边的调度方式。环性质是它的镜像：最贵边可以安心扔掉。两条性质合起来，就是 MST 全部贪心算法的正确性根基。

💡 关键一跃

把 MST 想成"用最少的钱把所有村子接上网"：任何把村子分两组的方案里，最便宜的那条跨组电缆不买就是浪费（割性质）；任何绕圈的电缆网里，最贵的那一段必然多余（环性质）。

⚠️ 常见误区

误区一："轻边必在每一棵 MST 中"。错——等权时可能有多棵 MST，割性质只保证"存在某棵包含它"。误区二："最重边一定不在 MST"——必须是环上唯一最重才成立；若最重边有并列，结论弱化为"存在一棵不含它的 MST"。

7.2Kruskal：按价格从小到大买，成环就退货

上一节给了"哪条边安全"的判据，但它带出一个工程问题：割有指数多个，难道每个都检查一遍？Kruskal 算法（Kruskal's Algorithm）的回答极其朴素——把所有边按权重升序排好，一条一条看：能买就买，会成环就跳过。为什么"成环"是唯一退货理由？因为成环意味着新边两端已被更便宜的边连通（环性质：它必是环上最贵者）；而"能买就买"的每一步，恰好都是某个割的轻边（割性质保证安全）。

判定"两端是否已连通"用并查集（Disjoint-Set / Union-Find）：每个顶点初始自成一个集合，find(x) 返回 x 所在集合的代表元，union 合并两集合。下面在 G1 上完整手算（11 条边按升序）：

次序边（权）find 两端同集？选/弃理由与集合并的变化累计权重

2c–e (5)否选合并 {c,e}10
3d–f (6)否选{a,d,f}16

选满 |V|−1 = 6 条边即停：{a–d, c–e, d–f, a–b, b–e, e–g}，总权重 5+5+6+7+7+9 = 39。这就是 G1 的 MST 权重。

复杂度：排序占 O(E lg E)；并查集在路径压缩 + 按秩合并下，E 次 find/union 摊还近似 O(E·α(V))，α 是反阿克曼函数，增长慢到可视为常数。故总复杂度

T(V, E) = O(E lg E) = O(E lg V)

（因为 E < V²，lg E 与 lg V 只差常数因子。）

💡 关键一跃

Kruskal 是"全局价格导向"：它从不关心树长在哪里，只关心还没买的边里哪条最便宜。并查集是它的"账本"，O(α(V)) 就能回答"这两个村子通了吗"。

⚠️ 常见误区

误区："Kruskal 每一步加的都是当前树能伸出去的最短边。"错——那是 Prim。Kruskal 加的边可能离已有部分很远（比如第 2 步的 c–e 与 {a,d} 毫不相邻），它维护的是一片森林，最后才合成一棵树。把两算法的"生长方式"混为一谈是最常见的丢分点。

7.3Prim：从一棵树苗开始，每次接最便宜的枝

Kruskal 带出一个互补的思路：如果我不喜欢"满森林乱长"，能不能让一棵树从单个顶点连续长大？Prim 算法（Prim's Algorithm）正是如此：维护一棵树 T，每一步在所有"一端在 T 内、一端在 T 外"的边里选最轻的那条接上——这恰是割 (T, V−T) 的轻边，割性质再次保证安全。为快速找到轻边，给每个树外顶点 v 维护一个 key：v 接到当前树的最轻边权，用最小优先级队列（Priority Queue）取 key 最小者。

此时 Prim（甚至 O(V²) 的数组版）优于 Kruskal；稀疏图（E = Θ(V)）上两者同为 O(E lg V) 级别，选谁都行。

💡 关键一跃

Prim 像涟漪：从一滴水（起点）开始，每步把离岸最近的那块陆地并进来。key 就是"每块陆地离水面的最近距离"。

⚠️ 常见误区

误区："key 是顶点到起点的距离。"错——key 是顶点到当前树的最轻连接边权，与"距离"无关；把 Prim 的 key 和 Dijkstra 的 d 值混用，是 7.4 节最容易连环出错的地方。另一个误区："MST 唯一所以两算法必出同一边集"——本章只是恰好唯一；等权边多时两算法可给出不同但同价的 MST。

7.4Dijkstra：非负权图上的"取出即定值"

前三节解决了"连通一切最便宜"，但带权图还有第二个基本问题：从源点 s 出发，到每个顶点的最短距离是多少？这就是单源最短路（Single-Source Shortest Paths）。记 δ(s, v) 为 s 到 v 的最短路权（不可达为 ∞）：

δ(s, v) = min { w(p) : p 是从 s 到 v 的路径 }

所有算法的通用零件是松弛（Relaxation）：维护上界估计 d[v]，对边 (u, v) 尝试"借道 u 是否更划算"：

d[v] ← min( d[v], d[u] + w(u, v) )

换一张有向带权图 G2（5 顶点 10 条边）：s→t 10, s→y 5, t→x 1, t→y 2, y→t 3, y→x 9, y→z 2, x→z 4, z→x 6, z→s 7。

图 7.2 有向带权图 G2：注意 t 与 y 之间有双向边（2 与 3），z 有一条指回 s 的长边。

Dijkstra 算法（Dijkstra's Algorithm）与 Prim 同构：每次取出 d 值最小的未确定顶点 u，宣布 d[u] 就是 δ(s,u)，再用 u 松弛所有出边。从 s 完整手算（每格 d/π，✓ 表示已确定）：

最终结果：d[y]=5（直达），d[z]=7（s→y→z），d[t]=8（s→y→t），d[x]=9（s→y→t→x）。注意第 4 轮取出的是 t(8) 而不是 x(13)：堆顶永远先取当前最小估计。

✅ 判定规则（收敛引理）

Dijkstra 每次从堆中取出 u 时必有 d[u] = δ(s, u)（收敛引理，Convergence Lemma）。证明骨架：设 u 是首个被取出时 d[u] > δ(s,u) 的顶点，取 s⇝u 最短路上第一个不在已确定集 S 中的顶点 y′，其前驱 x′ ∈ S 已确定。x′ 被取出时已松弛过 x′→y′，故 d[y′] = δ(s,y′) ≤ δ(s,u) < d[u]，与"u 是堆顶最小者"矛盾。证明用到 w ≥ 0 的环节：δ(s,y′) ≤ δ(s,u) 这步要求 y′⇝u 这段非负。负权边会让"已确定"的顶点事后被更便宜的路径追上——贪心前提崩塌。

反例一（临界侥幸）：给 G2 加一条 x→y 权 −4 的边。重跑 Dijkstra，第 5 轮取出 x(9) 时松弛 x→y：9+(−4)=5，恰好等于 d[y]=5，不更小——Dijkstra 侥幸逃过。但 −4 是临界值：权再小一点，y 就将在被取出之后收到更便宜的报价，定值被推翻，算法出错（此时环 y→t→x→y 的权 3+1+w < 0，已成负环（Negative Cycle），最短路本身也不存在了）。

反例二（真正失败，且无负环）：三顶点图 s→a 1, s→b 3, b→a −3。Dijkstra 第 2 轮取出 a(1) 并宣布定值；第 3 轮取出 b(3) 松弛 b→a 得 3+(−3)=0 < 1——真正的 δ(s,a)=0 出现在 a 被"盖棺定论"之后。图是 DAG、根本没有环，Dijkstra 依然答错。负权边不需要成环就足以杀死 Dijkstra。

💡 关键一跃

Dijkstra 像水位上涨：非负权保证"水先到的地方就是离源最近的地方"。负权边像暗渠，会让水从你以为已经涨过的方向倒灌回来。

⚠️ 常见误区

误区："含负权边的图 Dijkstra 一定算错。"错——反例一显示它可能碰巧对，但没有保证；工程上的正确姿势是"有负权就上 Bellman-Ford"。误区二："Prim 的 key 和 Dijkstra 的 d 是一回事。"key 只量"离树多近"，d 量"离源多远"，前者与路径无关，后者是路径总长。

7.5Bellman-Ford：允许负权的代价是 |V|−1 轮全体松弛

Dijkstra 的失败带出一个问题：有没有不贪心、不怕负权的算法？Bellman-Ford 算法（Bellman-Ford Algorithm）放弃"取出即定值"，改为最笨也最稳的策略：每一轮把图中所有边全部松弛一遍，重复 |V|−1 轮。为什么 |V|−1 轮封顶？不含负环时，任何最短路都可取成简单路径，至多 |V|−1 条边；第 i 轮结束时，所有"至多 i 条边的最短路"都已被找到，|V|−1 轮后收敛。第 |V| 轮再做一次全体松弛：若还能改进，说明存在可无限走短的环路——负环。于是 Bellman-Ford 顺带成为负环检测器。

在 G2 加上负边 x→y(−4) 后的图（11 条边）上完整手算。固定每轮边的处理顺序：s→t, s→y, t→x, t→y, y→t, y→x, y→z, x→z, z→x, z→s, x→y。

轮次stxyz本轮发生的关键松弛
0（初始）0∞∞∞∞初始化
1081157s→t 得 10，随后 y→t 改 8；t→x 得 11；s→y 得 5；y→z 得 7
208957t→x：8+1=9 改 9；x→y：9−4=5 不更小

结果与 Dijkstra 相同（t=8, y=5, z=7, x=9）——这印证了 7.4 的"侥幸"：这条 −4 的边恰好没造成破坏。把这条边改成 −7 再跑：第 2 轮 x→y 把 y 改成 2，第 3 轮 y→t、y→z 继续下压，第 4 轮 x→y 又把 y 压到 −1……到第 |V|=5 轮仍有边可松弛 ⟹ 检出负环 y→t→x→y（权和 3+1−7 = −3 < 0）。负环上所有顶点的 δ 应报 −∞，算法如实报警。

代价写在复杂度里：每轮松弛全部 E 条边，共 |V|−1 轮，

TBF = O(V·E) ，TDijkstra = O((V + E) lg V)

稀疏图上 V·E 与 E lg V 差约一个 V 因子——用平方级的时间，换"负权可用 + 负环可查"两件礼物。

💡 关键一跃

Dijkstra 是"每次拍板一个"，Bellman-Ford 是"谁也不拍板，全体报价刷新 |V|−1 轮"。第 i 轮 = 允许路径用满 i 条边；边数上限就是轮数上限。

⚠️ 常见误区

误区："第 |V| 轮还能松弛说明算法写错了。"恰恰相反——还能松弛说明图里有负环，这是 Bellman-Ford 的设计功能，不是故障。另一个误区："Bellman-Ford 能算出负环图的最短路。"负环可达的最短路是 −∞，不存在有限答案；算法的职责是检测并报告，而不是给出数字。

7.6差分约束：负环是"无解"的报警器

Bellman-Ford 的负环检测看似只是报错功能，但它带出一个漂亮的应用：一大类"谁比谁至多晚多少"的约束系统，可以整体翻译成最短路问题。差分约束（Difference Constraints）系统由若干形如 xj − xi ≤ c 的不等式组成；建图规则是每个不等式变一条边：xj − xi ≤ c ⟺ xj ≤ xi + c，对应边 i→j 权 c。再加一个超级源点（Super Source）s，向每个变量连权 0 的边，从 s 跑 Bellman-Ford：x = (δ(s,x₁), …, δ(s,xn)) 就是一组可行解；检出负环 ⟺ 系统无可行解。

完整例。系统（5 条约束、3 个变量）：

  • ① x₂ − x₁ ≤ 2　⟹ 边 1→2 权 2
  • ② x₃ − x₂ ≤ 3　⟹ 边 2→3 权 3
  • ③ x₃ − x₁ ≤ 4　⟹ 边 1→3 权 4
  • ④ x₁ − x₃ ≤ −1　⟹ 边 3→1 权 −1
  • ⑤ x₂ − x₃ ≤ 0　⟹ 边 3→2 权 0

加 s→1、s→2、s→3 各权 0 后跑 Bellman-Ford：第 1 轮边 3→1 给出 δ₁ = −1，其余保持 0；第 2 轮起无任何松弛。解得 x = (−1, 0, 0)。逐条验证：① 0−(−1)=1 ≤ 2 ✓；② 0−0=0 ≤ 3 ✓；③ 0−(−1)=1 ≤ 4 ✓；④ −1−0=−1 ≤ −1 ✓（恰好取等，这就是约束 ④ 在"拽紧"解）；⑤ 0 ≤ 0 ✓。（(0,1,1) 也是解——可行解不唯一，Bellman-Ford 给出的是以 s 为锚的"最紧"解。）

无解侧：把①换成 x₂ − x₁ ≤ −3（边 1→2 权 −3）。此时环 1→2→3→1 的权和 = −3+3+(−1) = −1 < 0——Bellman-Ford 第 |V| 轮必然报警。代数上也确实矛盾：x₂ ≤ x₁−3、x₃ ≤ x₂+3、x₁ ≤ x₃−1 三式相加得 0 ≤ −1。负环上的约束链，正是互相打架的不等式链。

✅ 判定规则

差分约束系统可行 ⟺ 约束图无负环。证明方向：(⟸) 无负环时最短路过定义良，δ 本身满足所有约束（三角不等式 δ(s,v) ≤ δ(s,u) + w(u,v) 正是约束的图形式）；(⟹) 有解时任意环上约束相加得 0 ≤ 环权，故环权必非负。

💡 关键一跃

把不等式链想成一圈齿轮：每个约束限定了相邻齿轮的转角差。绕一圈回来要求总转角差既要 ≤ 0 又要 ≥ 0——如果约束逼出一圈"负转角"，齿轮卡死，这就是负环 = 无解。

⚠️ 常见误区

误区："不等式 xj − xi ≤ c 画边 j→i。"方向记反是最常见错误——对照三角不等式 δ(v) ≤ δ(u) + w(u,v)，被约束的变量 xj 是箭头指向的终点，边永远是 i→j。另一个误区："超级源点的边权随便设。"必须是 0 且连向每个变量，否则 δ 会被平移或漏连。

概念卡 1
最小生成树（Minimum Spanning Tree, MST）
点击翻面 →
定义连通无向带权图中含全部顶点、|V|−1 条边、无环且总权重最小的子图。
解决问题用最低成本把网络连通：布线、管网、集群互联的底价。

误区以为 MST 总是唯一、以为它同时保证两点间路径最短（它只优化总价，不优化任意两点距离）。

概念卡 2
割性质与环性质（Cut / Cycle Property）
点击翻面 →
定义割的轻边必在某棵 MST 中；环上唯一最重边必不在任何 MST 中。
解决问题给出"哪条边安全可选、哪条边放心可弃"的局部判据，使贪心成为可能。
直觉分组谈判时最便宜的跨组桥梁必买；绕圈路网里最贵一段必拆。
误区忽略"唯一最重"前提，或在等权边存在时把"某棵"误读成"每棵"。
何时用Kruskal/Prim 正确性证明；第9章论证贪心选择性质的模板。
概念卡 3
并查集（Disjoint-Set / Union-Find）
点击翻面 →
定义维护元素分族的数据结构：find 查代表元，union 并族；路径压缩 + 按秩合并后摊还近 O(α(V))。
解决问题让 Kruskal 能用近乎常数时间回答"加这条边会不会成环"。
直觉村庄合并的族谱：问两人是否同村只看族长；合并时小族并入大族。
误区忘记它只维护连通性、不维护路径——find 相同不代表知道怎么走过去。
何时用Kruskal 内部；动态连通性问题的标准件。
概念卡 4
松弛（Relaxation）
点击翻面 →
定义对边 (u,v) 执行 d[v] ← min(d[v], d[u]+w(u,v))，并维护前驱 π。
解决问题把"最短路"这一全局最优拆成一系列局部改进步，是所有最短路算法的通用原子操作。
直觉报价单刷新：听说邻居有更便宜的到货价，立刻更新自己的估价。
误区以为松弛顺序无关紧要——Dijkstra 的全部正确性恰恰押在"谁先来谁定值"的顺序上。
何时用Dijkstra、Bellman-Ford、差分约束；第8章会看到松弛与动规状态转移的同构。
概念卡 5
收敛引理（Convergence Lemma）
点击翻面 →
定义Dijkstra 每次从堆中取出 u 时，d[u] 已等于 δ(s,u)。
解决问题给"取出即定值"的贪心打包票，使每顶点只进一次堆、复杂度得以控制。
直觉水面上涨：非负权保证先到岸的必最近，后浪不会抄近道反超。
误区忘记它依赖非负权；在含负权图上引用它等于引用一个不成立的定理。
何时用Dijkstra 正确性证明；判断"这个贪心能不能用"时的检查清单第一条。
概念卡 6
差分约束（Difference Constraints）
点击翻面 →
定义一组 xⱼ − xᵢ ≤ c 形不等式；系统可行 ⟺ 约束图（边 i→j 权 c）无负环。
解决问题把排程、时序、界估计类问题整体翻译成单源最短路，一次 Bellman-Ford 同时给解与可行性判定。
直觉一圈齿轮的转角差约束；能顺畅咬合就是可行，卡死就是负环。
误区边方向记反（被约束的变量是终点）；忘记超级源点及其 0 权边。
何时用任务排程（开始时间差约束）、VLSI 时序、各类"区间可行解"问题。

提示

①用割性质或换边论证每条树边的不可替代性；②只需找一个有等权边但 MST 唯一的小图作反例。

完整解答
①正确。反证：设有两棵不同 MST，取对称差中权最小的边 e（它在一棵中、不在另一棵中），把 e 加进另一棵必成环；环上边权互异，故存在比 e 严格更重的边，换掉它得到更小的生成树，矛盾。②错误。反例：取一棵本身就是树的图——四顶点路径 a–b–c–d，三条边权全为 5。MST 被迫取全部三条边，显然唯一，但边权并不互异。逻辑关系要记牢：互异 ⟹ 唯一，反之不成立。

自测 3
Prim 的 key[v] 与 Dijkstra 的 d[v] 的本质区别是？
  • A. key 是 v 到当前树的最轻单边权；d 是 s 到 v 的当前最短路径总长
  • B. key 只对无向图定义，d 只对 DAG 定义
  • C. key 只能增不能减，d 只能减不能增
  • D. 二者完全等价，只是名字不同
解析：A 对——一个是"离树的距离"（单边），一个是"离源的距离"（路径和）；松弛式 d[v] ← min(d[v], d[u]+w) 含累加项，而 key 的更新不含。B 错：d 用于一般非负权有向/无向图，不限 DAG。C 错：二者都只降不升。D 错：同构的是算法框架（堆 + 贪心取出），量的含义不同——这正是"Prim 不需要累加、Dijkstra 需要"的根源。
自测 4
Dijkstra 遇到负权边可能出错的根本原因是？
  • A. 堆不支持负数关键字
  • B. 负权边会使边数超过 |V|−1
  • C. 负权图一定含负环
  • D. 收敛引理失效：已取出定值的顶点可能被后经负边的更便宜路径追上
解析：D 对——证明中 δ(s,y′) ≤ δ(s,u) 依赖 y′⇝u 段非负；负边让"后来者居上"成为可能，7.4 的三顶点 DAG 反例（s→a 1, s→b 3, b→a −3）即现场。A 错：二叉堆完全支持负数键。B 错：边数与权重符号无关。C 错：负权边不必成环（该反例就无环），而无负环也不能保证 Dijkstra 正确。
自测 5
Bellman-Ford 跑到第 |V| 轮（检测轮）发现仍有一条边可以松弛，说明什么？
  • A. 算法实现有 bug，应减少轮数重跑
  • B. 图中存在从 s 可达的负环，相关最短路为 −∞，算法应报告
  • C. 说明图是稠密图，应改用 Dijkstra
  • D. 说明 |V|−1 轮不够，应继续跑到收敛为止
解析：B 对——|V|−1 轮已覆盖全部至多 |V|−1 条边的简单路径，第 |V| 轮仍可改进只能意味着存在可无限绕短的负环；这正是差分约束"无可行解"的判定信号。A 错：这是设计功能而非故障。C 错：负环时 Dijkstra 更不可用。D 错：负环上永远收敛不了，继续跑只是无限降价；正确动作是报警停机。
