1.1为什么要分析算法：插入排序 vs 归并排序

全书的主线是"为问题找更快的算法"。但"更快"到底怎么定义？最自然的想法是：把两个算法都写出来，找台机器跑一下，掐秒表。这个做法有三个致命缺陷：

  1. 结果依赖机器与实现：换台电脑、换种语言、换个编译器，结论可能反过来。
  2. 只测了有限几个输入：你测的输入快，不代表所有输入都快。
  3. 测不出规模趋势：n = 100 时 A 赢，n = 10⁷ 时谁赢？实验必须重跑一遍才知道。

所以我们要的度量必须满足：与机器无关、对所有输入有论断、能预测大规模行为。这就是算法分析（Analysis of Algorithms）存在的理由。先看一个具体到能数清次数的例子。

插入排序（Insertion Sort）：像在手里整理扑克牌

维护"已排好的左手部分"，每次把下一张牌插回左边合适位置。对 A = [5, 2, 4, 6, 1, 3] 逐步执行（加粗的是被移动的元素）：

轮次 jkey哪些元素被右移移动次数本轮结束后的数组
2251[2, 5, 4, 6, 1, 3]
3451[2, 4, 5, 6, 1, 3]
46（无，6 已到位）0[2, 4, 5, 6, 1, 3]
516, 5, 4, 24[1, 2, 4, 5, 6, 3]
636, 5, 43[1, 2, 3, 4, 5, 6]
合计——9排序完成

规律：插入排序每轮的移动次数，恰好等于 key 左边比它大的元素个数；整趟总移动次数 = 数组的逆序对（Inversion）总数。[5,2,4,6,1,3] 的逆序对：5 贡献 4 个（对 2,4,1,3），2 贡献 1 个（对 1），4 贡献 2 个（对 1,3），6 贡献 2 个（对 1,3），1 贡献 0 个——合计 4+1+2+2+0 = 9，与表中移动总次数吻合。这不是巧合，1.3 节会把它变成平均情形的分析武器。

代价方程的正面对决：8n² vs 64n·lg n

假设插入排序在某机器上每条内层操作代价摊到 8 个单位时间，最坏约 8n²；归并排序（Merge Sort，第 2、3 章细讲）常数大，约 64n·lg n（lg 表示以 2 为底的对数）。谁快？答案是"看 n"——我们手算交叉点附近三个值：

n插入 8n²归并 64n·lg n谁赢
328 × 1024 = 819264 × 32 × 5 = 10240插入（lg 32 = 5）
438 × 1849 = 1479264 × 43 × 5.426 ≈ 14932插入（lg 43 ≈ 5.426）
448 × 1936 = 1548864 × 44 × 5.459 ≈ 15373归并（lg 44 ≈ 5.459）

结论：n ≤ 43 时插入排序更快，n ≥ 44 时归并排序反超，而且 n 越大差距越悬殊（n = 10⁶ 时 8n² = 8×10¹²，64n·lg n ≈ 1.3×10⁹，差约 6300 倍）。这正是"增长率"而非"秒表"给出的论断：一次手算，对所有规模有效。

💡 关键一跃

算法分析比的不是"某次赛跑谁快"，而是"体型谁大"：n² 与 n·lg n 是两种身材，身材决定了当输入变大时谁先被压垮。

⚠️ 常见误区

"插入排序是平方级，所以永远比归并慢"——错。n ≤ 43 时插入反而更快。渐进结论只对"充分大的 n"发言；小规模的赢家由常数因子决定。这也是很多语言标准库在短数组上回落到插入排序的原因。

1.2先别谈快慢：循环不变式证明算法是对的

上一节比较了插入排序和归并排序的快慢，但它带出一个更根本的问题：快的前提是"对"——你凭什么确信插入排序对所有输入都输出有序数组？测试只能证明"有 bug"，不能证明"没 bug"（Dijkstra）。我们需要的是数学证明，工具是循环不变式（Loop Invariant）。

循环不变式 = 在循环每次迭代开始前都为真的一个命题。用它证明正确性要走三步，结构与数学归纳法完全同构：

  1. 初始化（Initialization）：第一次迭代开始前，命题成立（= 归纳基础）。
  2. 保持（Maintenance）：若某次迭代前成立，则该次迭代后仍成立（= 归纳递推）。
  3. 终止（Termination）：循环结束时，命题 + 终止条件一起给出我们要的结论。

插入排序的循环不变式：在外层 for 循环第 j 次迭代开始前，子数组 A[1..j−1] 由原来 A[1..j−1] 中的元素组成，且已排好序。

✅ 完整证明（插入排序的正确性）

初始化：j = 2 时，A[1..j−1] = A[1..1] 只含一个元素 A[1]。单元素天然有序，且当然是原数组的元素。不变式成立。✓

保持：假设第 j 次迭代前 A[1..j−1] 有序且元素没变。本轮循环把 key = A[j] 与 A[j−1], A[j−2], … 依次比较，把比 key 大的元素各右移一格，再把 key 插入空位。由于左半有序，key 被插在"第一个 ≤ 它的元素"之后，于是 A[1..j] 有序；移动只是重排，没有引入或丢失元素，故 A[1..j] 仍由原 A[1..j] 的元素组成。迭代后不变式对 j+1 成立。✓

终止：外层循环在 j = n+1 时结束。代入不变式：A[1..(n+1)−1] = A[1..n] 即整个数组，由原来全部元素组成且已排好序。这正是排序问题的定义。✓

💡 关键一跃

循环不变式是"藏在循环里的数学归纳法"：初始化是归纳基础，保持是归纳步骤，终止把"每一步对"兑换成"最终结果对"。

⚠️ 常见误区

两个高发错误：① 只证初始化和保持、漏掉终止——不变式对了但循环结束条件没接上，结论出不来；② 不变式只写"A[1..j−1] 有序"、漏掉"由原元素组成"——一个每次往数组里写 42 的程序也满足前者，但它显然不是排序。

1.3最坏与平均情形：逆序对告诉我们的秘密

上一节证明了插入排序总是对的，这一节问：它花多少时间？1.1 节的 trace 已经提示了答案——运行时间由输入本身决定：已排序的输入每轮移动 0 次，完全逆序的输入每轮移动 j−1 次。同一个算法，时间随输入天差地别，所以谈时间必须先声明"哪种输入"。

最坏情形（Worst Case）：输入完全逆序时，第 j 轮移动 j−1 次，总移动次数

T(n) = 1 + 2 + … + (n−1) = n(n−1)2 = Θ(n²)

为什么我们最爱最坏情形？因为它是对所有输入的上界保证——承诺"绝不会比这个更慢"；而且对排序这类问题，平均情形往往和最坏情形一样糟（下面就算给你看）。

平均情形（Average Case）：设输入是 n 个互异元素的均匀随机排列。由 1.1 节，插入排序总移动次数 = 逆序对数。数逆序对的期望：n 个元素中共有 C(n,2) = n(n−1)/2 对位置 (i, j)，i < j；在均匀随机排列里，每一对恰好以 1/2 的概率成为逆序对（对称性：交换这两个元素给出一一对应的另一半排列）。由期望的线性性：

E[逆序对数] = C(n,2) × 12 = n(n−1)4

用 n = 4 的全部 24 个排列验证（按逆序对数 k 统计排列个数，即 Mahonian 数）：

逆序对数 k0123456合计
排列个数135653124 ✓
k × 个数0310182015672

平均逆序对数 = 72 / 24 = 3，恰好等于公式给出的 n(n−1)/4 = 4×3/4 = 3 ✓。注意 3 与最坏情形的 C(4,2) = 6 只差一半——平均情形同样是平方级。例如逆序输入 4321 有 6 个逆序对（k=6 那一列的 1 个排列），有序输入 1234 为 0。

💡 关键一跃

"平均 = 最坏的一半"对插入排序成立：平均移动次数 n(n−1)/4 仍含 n² 项，所以平均情形也是 Θ(n²)。常数减半，身材不变。

⚠️ 常见误区

① "平均情形"≠"最好情形"，也不天然等于"随便取个输入"——平均必须声明输入的概率分布（这里是均匀随机排列），换个分布结论就变；② 期望的线性性不要求事件独立，所以"每对 1/2 概率"可以直接相加，不需要各对之间独立。

1.4渐进记号：Θ / O / Ω 的严格定义与常见误用

上一节我们反复说"平方级"，但它一直没有精确定义。1.1 节又看到常数因子（8 vs 64）只影响小规模。两件事合在一起，催生了本章的核心工具：扔掉常数因子与低阶项，只保留增长趋势的记号体系。

设 f(n)、g(n) 是定义在自然数上的非负函数：

Θ 记号：f(n) = Θ(g(n)) ⟺ 存在正常数 c₁, c₂, n₀，使对所有 n ≥ n₀：0 ≤ c₁g(n) ≤ f(n) ≤ c₂g(n)
O 记号（渐近上界）：f(n) = O(g(n)) ⟺ 存在正常数 c, n₀，使对所有 n ≥ n₀：0 ≤ f(n) ≤ cg(n)
Ω 记号（渐近下界）：f(n) = Ω(g(n)) ⟺ 存在正常数 c, n₀，使对所有 n ≥ n₀：0 ≤ cg(n) ≤ f(n)

关系：f = Θ(g) 当且仅当 f = O(g) 且 f = Ω(g)。Θ 是"夹出来的"精确渐近，O 只管上面，Ω 只管下面。

✅ 完整手算：证明 ½n² − 3n = Θ(n²)

按定义，要找 c₁, c₂, n₀ 使 n ≥ n₀ 时 c₁n² ≤ ½n² − 3n ≤ c₂n²。两半分别处理：

右半（找 c₂）：对任意 n ≥ 0 有 −3n ≤ 0，故 ½n² − 3n ≤ ½n²。取 c₂ = ½ 即可，对所有 n ≥ 0 成立。✓

左半（找 c₁ 与 n₀）：需要 c₁n² ≤ ½n² − 3n，两边同除以 n²（n > 0）：c₁ ≤ ½ − 3/n。注意 3/n 随 n 增大而减小，所以只要 n 足够大，½ − 3/n 就能大于任何小于 ½ 的固定 c₁。取 c₁ = 1/14，需要 1/14 ≤ ½ − 3/n，即 3/n ≤ ½ − 1/14 = 7/14 − 1/14 = 6/14 = 3/7，即 n ≥ 7。✓

合起来：取 c₁ = 1/14，c₂ = ½，n₀ = 7。验证边界 n = 7：c₁n² = 49/14 = 3.5，f(7) = 24.5 − 21 = 3.5，c₂n² = 24.5，确实 3.5 ≤ 3.5 ≤ 24.5 ✓。故 ½n² − 3n = Θ(n²)。

这个证明示范了两件可迁移的手艺：① 低阶项 −3n 被 c₂ = ½ 直接"吸收"；② 负的低阶项对下界造成麻烦，靠"n₀ 取大一点"躲过——1/14 与 7 不是唯一的答案，任何 c₁ < ½ 配上足够大的 n₀ 都行，定义只要"存在"。

💡 关键一跃

Θ 是给函数发"身材尺码"：½n² − 3n 与 100n² + 7 穿同一件衣服（n² 码），尽管少年时期（小 n）高矮不同。n₀ 的意思就是"等它发育定型后再量"。

⚠️ 常见误区（本章最容易丢分的点）

"O 表示最坏情形、Ω 表示最好情形"——错。渐进记号描述的是函数的上下界，最坏/平均/最好情形描述的是对哪类输入取时间，两个维度完全独立。正确说法是：插入排序最坏情形时间是 Θ(n²)；它的最好情形时间（已排序输入）是 Θ(n)——注意用的是 Θ 而不是 Ω，因为线性既是上界又是下界。O(n²) 甚至不排除算法其实是线性的："f = O(n²)"只说 f 不超过平方量级，n、lg n 都是 O(n²)。

最后一行值得默背：指数算法面前，摩尔定律失效——硬件翻倍只换来 n+1。这就是为什么第 10 章要把"是否存在多项式算法"当作问题难度的分水岭。

💡 关键一跃

增长率的排序 lg n ≺ √n ≺ n ≺ n lg n ≺ n² ≺ n³ ≺ 2ⁿ 是全书反复使用的"成本坐标系"。拿到任何 T(n)，先定位它在坐标系的哪一格，再谈优化。

⚠️ 常见误区

① "2n 和 n² 差不多吧，反正 n 大了都快"——错，n = 10⁶ 时两者差 5×10⁵ 倍；② "指数慢是因为我们机器不够好"——错，2ⁿ 的慢是结构性的，硬件翻倍只 +1；③ 把 n lg n 当成"和 n 差不多"——它是超线性的，只是超出得很慢（比值 lg n 无界增长）。

回忆 1.5-1
输入翻倍时，lg n、n、n²、2ⁿ 的时间分别怎么变？
点击翻面 →
参考答案
lg n：+1（加法）；n：×2；n²：×4；2ⁿ：平方（2ⁿ → 2²ⁿ）。
回忆 1.5-2
可用时间翻倍时，Θ(lg n) 与 Θ(2ⁿ) 算法能处理的规模各怎么变？
点击翻面 →
参考答案
Θ(lg n)：n → n²（平方级扩容）；Θ(2ⁿ)：n → n + 1（只能多处理一个元素）。这就是"硬件救不了指数算法"的定量表述。

🃏概念卡：本章概念的一分钟画像

翻面前先自问：这个概念我能用一句话讲清楚吗？

概念卡 1
循环不变式（Loop Invariant）
点击翻面 →
定义循环每次迭代开始前都成立的命题；靠初始化、保持、终止三步证明算法正确。
解决问题测试只能证伪，不能证实；不变式给出"对所有输入都对"的数学证明。
直觉藏在循环里的数学归纳法。
误区只证前两步漏掉终止；不变式漏掉"由原元素组成"这类完整性条件。
何时用Ch3 排序正确性、Ch5 红黑树性质、Ch6 图算法（如 BFS 距离性）证明。
概念卡 2
Θ 记号（Theta Notation）
点击翻面 →
定义∃c₁,c₂,n₀：n ≥ n₀ 时 0 ≤ c₁g(n) ≤ f(n) ≤ c₂g(n)，渐近紧确界。
解决问题给出函数的精确"身材尺码"，抹掉常数与低阶项的干扰。
直觉上下两块夹板把 f 夹在同阶函数之间。
误区以为常数必须取最优值——定义只要求"存在"，c₁ = 1/14 这种丑数完全合法。
何时用全书所有复杂度结论的标准表述（如归并排序 Θ(n lg n)）。
概念卡 3
O 记号（Big-O Notation）
点击翻面 →
定义∃c,n₀：n ≥ n₀ 时 0 ≤ f(n) ≤ cg(n)，渐近上界。
解决问题只关心"不会比什么更糟"时，用单边约束即可，不必找下界。
直觉给函数盖天花板。
误区"O 表示最坏情形"——错，O 谈的是函数的上界，与输入情形无关；n 也是 O(n²)。
何时用分析上界即可的场景，如"该算法至多是 O(n²)"；下界不明时的保守承诺。
概念卡 4
Ω 记号（Big-Omega Notation）
点击翻面 →
定义∃c,n₀：n ≥ n₀ 时 0 ≤ cg(n) ≤ f(n)，渐近下界。
解决问题断言"任何算法/该算法至少要多慢"，用于难度下界与不可能性结论。
直觉给函数铺地板。
误区"Ω 表示最好情形"——错，理由同 O；最好情形时间照样可以用 Θ 或 O 描述。
何时用Ch3 比较排序下界 Ω(n lg n)、Ch10 难解性讨论。
概念卡 5
最坏 / 平均情形（Worst / Average Case）
点击翻面 →
定义最坏：所有规模为 n 的输入上的最大时间；平均：对输入分布取期望的时间。
解决问题同一算法时间随输入波动，必须先声明"哪类输入"才能谈时间。
直觉最坏情形是保险条款，平均情形是精算表。
误区平均情形不需要分布假设——错，均匀随机排列就是一种（且经常被默认的）分布。
何时用Ch3 快速排序（最坏 Θ(n²)、平均 Θ(n lg n)）是这对概念的最佳案例。
概念卡 6
增长率（Rate of Growth）
点击翻面 →
定义T(n) 中起主导作用的最高阶项（忽略系数与低阶项）所决定的增速。
解决问题让我们一句话回答"输入变大时谁先垮"，无需逐点计算。
直觉算法的"体型"：幼年高矮不算数，发育定型后看骨架。
误区忘记它只对充分大的 n 发言——8n² 在 n ≤ 43 时击败 64n·lg n 并不矛盾。
何时用全书每一章的算法比较；Ch2 递归式求解后第一件事就是定位增长率。

📝分层习题

L1 概念辨析习题 1：判断正误并说明理由——"f(n) = O(n²) 意味着该算法的最坏情形运行时间是平方量级"。
提示

拆开两个维度：O 谈论的对象是"函数"，最坏情形谈论的对象是"输入类别"。再想想 n 是不是 O(n²)。

完整解答
错误，有两层问题。① 概念错位：O 是关于函数的渐近上界，最坏情形是关于输入的选择，两者独立——完全可以说"某算法最坏情形时间是 O(n²)"，也可以说"最好情形时间是 O(n)"，O 本身不携带"最坏"的含义。② 即使改写成"最坏情形时间 f(n) = O(n²)"，也不能得出"最坏情形是平方量级"：O(n²) 只说不超过平方，线性函数 n、对数函数 lg n 都是 O(n²)。要断言"就是平方量级"必须用 Θ。这正是 1.4 节 warning 框强调的混淆。
L1 概念辨析习题 2：下列关于循环不变式的说法，哪一个是正确的？A. 只要初始化成立，正确性就得证；B. 终止步骤把"不变式 + 循环结束条件"兑换成目标结论；C. 不变式必须在每次迭代后变得更"强"；D. 循环不变式与数学归纳法无关。
提示

回忆三步各自的角色，尤其第三步在干什么。

完整解答
B 正确。终止步代入循环结束条件（如 j = n+1），让不变式直接说出"整个数组有序"，这是归纳法没有、循环特有的一步。A 错：只有初始化没有保持，第二次迭代就可能破坏不变式。C 错：不变式是"同一个命题"每次迭代都成立，内容不递增；递增的是它覆盖的前缀长度 j−1。D 错：初始化 = 归纳基础、保持 = 归纳递推，不变式证明本质就是归纳法。
L2 手算推导习题 3：6n³ = Θ(n²) 是否成立？给出证明或反证。
提示

假设成立，则由 Θ 可得 O：存在 c₂ 使 6n³ ≤ c₂n² 对所有大 n 成立。把两边除以 n² 看看得到什么。

完整解答
不成立。反证：若 6n³ = Θ(n²)，则 6n³ = O(n²)，即存在正常数 c₂、n₀ 使所有 n ≥ n₀ 满足 6n³ ≤ c₂n²。两边同除以 n²（n > 0）得 6n ≤ c₂，即 n ≤ c₂/6。但 c₂/6 是一个固定常数，而 n 可以任意大——取 n = ⌈c₂/6⌉ + 1 即矛盾。所以 6n³ 连 O(n²) 都不是，更不可能是 Θ(n²)。（事实上 6n³ = Θ(n³)：取 c₁ = 6、c₂ = 6、n₀ = 1，6n³ ≤ 6n³ ≤ 6n³ 平凡成立。）教训：Θ 两边必须同阶，阶不同怎么取常数都救不回来。
L2 手算推导习题 4：证明 T(n) = 3n² + 10n + 100 = Θ(n²)，要求给出具体的 c₁、c₂、n₀ 并验证不等式。
提示

下界直接丢低阶项；上界把 10n 和 100 分别"升级"成 n²——先找 n 多大时 10n ≤ n²、100 ≤ n²。

完整解答
按定义需 0 ≤ c₁n² ≤ 3n² + 10n + 100 ≤ c₂n² 对所有 n ≥ n₀ 成立。
下界：n ≥ 0 时 10n + 100 ≥ 0，故 3n² + 10n + 100 ≥ 3n²，取 c₁ = 3 对所有 n ≥ 0 成立。✓
上界：当 n ≥ 10 时，10n ≤ n·n = n²（因为 n ≥ 10）；同时 100 ≤ n²（因为 n ≥ 10 即 n² ≥ 100）。于是 n ≥ 10 时 T(n) ≤ 3n² + n² + n² = 5n²，取 c₂ = 5。✓
合并：c₁ = 3，c₂ = 5，n₀ = 10。边界验证 n = 10：c₁n² = 300；T(10) = 300 + 100 + 100 = 500；c₂n² = 500。确实 300 ≤ 500 ≤ 500 ✓。故 T(n) = Θ(n²)。（常数不唯一：c₂ 取 113 配 n₀ = 1 也对——10n ≤ 10n²、100 ≤ 100n² 对 n ≥ 1 成立。）
L3 建模应用习题 5：你在做两套系统的排序模块选型。系统甲：温湿度传感器节点，内存极小，每批数据 n ≤ 40 条，代码必须极简；系统乙：数据中心离线任务，n ≈ 10⁷ 条。候选方案：插入排序（代价约 8n²）与归并排序（代价约 64n·lg n）。请为两个系统分别选型并给出定量论证。
提示

把两个系统的 n 分别代入两个代价方程，算出具体数字再比；别忘了 1.1 节算过的交叉点。

完整解答
系统甲选插入排序。由 1.1 节手算，交叉点在 n = 43/44：n ≤ 43 时插入更快。甲的 n ≤ 40 全部落在插入的优势区。具体看 n = 40：插入 8 × 1600 = 12800；归并 64 × 40 × lg 40 ≈ 64 × 40 × 5.32 ≈ 13619，插入小胜，且代码量、内存占用（归并需要 O(n) 辅助数组）对传感器节点都是硬约束。
系统乙选归并排序。n = 10⁷：插入 8 × (10⁷)² = 8×10¹⁴；归并 64 × 10⁷ × lg(10⁷) ≈ 64 × 10⁷ × 23.25 ≈ 1.49×10¹⁰。归并快约 8×10¹⁴ / 1.49×10¹⁰ ≈ 5.4 万倍。若每条单位时间是 1 纳秒，插入要约 9.3 天，归并约 15 秒。
方法论：增长率决定"大规模选谁"（归并必胜），常数因子与工程约束决定"小规模选谁"（插入更优）——这正是本章主线问题在工程中的完整答案。

点击选项判分，答错会给出原因。

自测 1
关于渐进记号与算法情形，下列说法正确的是？
  • A. 只有 O(n²) 的算法，其最坏情形才是平方量级
  • B. 渐进记号描述函数的界，最坏/平均/最好描述输入类别，两者是独立的维度
  • C. Ω 记号专门用来描述算法的最好情形
  • D. 平均情形分析不需要对输入分布做任何假设
解析：B 正确——记号是函数语言，情形是输入语言，正交的两个维度。A 错：O(n²) 只是上界，函数可能是 n；且"最坏情形"也可配 Ω、Θ。C 错：Ω 是渐近下界，最好情形照样用 Θ 描述（如插入排序最好情形 Θ(n)）。D 错：平均 = 对分布取期望，1.3 节的 n(n−1)/4 正是在"均匀随机排列"假设下推出的。
自测 2
下列函数中，是 O(n²) 但不是 Θ(n²) 的是？
  • A. 5n + 3
  • B. ½n² − 100n
  • C. 7n²
  • D. n³
解析：A 正确——5n+3 ≤ 8n²（n ≥ 1）故为 O(n²)，但不存在 c₂ 使 c₂n² ≤ 5n+3 对大 n 成立（两边除 n：c₂n ≤ 5 + 3/n 不可能对任意大 n 成立），故不是 Θ(n²)。B、C 错：它们都是 Θ(n²)（B 可用 c₁ = 1/4 配大 n₀，−100n 被吸收）。D 错：n³ 连 O(n²) 都不是（习题 3 同款论证）。
自测 3
n = 10 的均匀随机排列，平均逆序对数（即插入排序的平均移动次数）是多少？
  • A. 45
  • B. 22.5
  • C. 10
  • D. 90
解析：B 正确——平均逆序对数 = n(n−1)/4 = 10×9/4 = 22.5。A 错：45 = C(10,2) 是总对数，忘了乘 1/2 概率。C 错：把对数和对数个数搞混，n 本身不出现于公式主体。D 错：90 = n(n−1) 是最坏情形 n(n−1)/2 = 45 的两倍，方向完全反了。
自测 4
某算法运行时间为 Θ(n³)。输入规模翻倍（n → 2n）后，运行时间约变为原来的？
  • A. 2 倍
  • B. 3 倍
  • C. 6 倍
  • D. 8 倍
解析：D 正确——(2n)³ = 8n³。A 错：2 倍是线性算法的翻倍效果。B 错：3 是把指数误当底数。C 错：6 = 3! 是把 n³ 与排列数混淆。记法：多项式 nᵏ 翻倍变 2ᵏ 倍；指数 2ⁿ 翻倍变平方。
自测 5
1.1 节算出 8n²（插入）在 n ≤ 43 时击败 64n·lg n（归并）。这与"归并是 Θ(n lg n)、插入是 Θ(n²)，归并更优"矛盾吗？
  • A. 矛盾，说明渐进分析在小规模上完全失效，没有实用价值
  • B. 矛盾，说明 Θ(n²) 其实比 Θ(n lg n) 好
  • C. 不矛盾——Θ 只承诺"存在 n₀，超过后结论成立"；n₀ 之前常数因子可以反转胜负
  • D. 不矛盾——因为 lg n 比 n² 增长快
解析：C 正确——Θ 定义里的 n₀ 正是"发育定型线"：渐近结论只对充分大的 n 发言，交叉点 43/44 就是这两个具体代价方程的"定型线"。A 错：渐进分析在 n ≥ 44 后完全正确且越往后越准，何来失效。B 错：n → ∞ 时任何 c₁n lg n 都会被任何 c₂n² 反超之外地压制（n lg n / n² = lg n / n → 0）。D 错：lg n 增长远比 n² 慢，说反了。
