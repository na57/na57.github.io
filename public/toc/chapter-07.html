7.1从"可判定"到"算多快"：为什么需要大 O 记号

第 5 章用归约证明了一大批问题不可判定——连"原则上能算"都谈不上。但反过来，"可判定"也不够：一个判定算法若要跑 2ⁿ 步，输入稍大就等于永远跑不完。所以复杂性理论提出一个更细的问题：把输入长度 n 固定，算法最坏要跑多少步？记为 运行时间（running time）f(n)。

精确的步数依赖机器细节，没有意义；我们只看渐近骨架。大 O 记号（big-O notation）：说 f(n) = O(g(n))，若存在常数 c 和 n₀，使对所有 n ≥ n₀ 都有 f(n) ≤ c·g(n)。直觉：g 是 f 的"渐近上界"，常数因子和低阶项一律忽略。例如：

f(n) = 5n³ + 2n² + 22n + 6 = O(n³)

因为取 c = 6，当 n ≥ 10 时 2n² + 22n + 6 ≤ n³，故 f(n) ≤ 6n³。同时也有 f(n) = O(n⁴)——上界不唯一，但我们总报最紧的那个。反过来，小 o 记号（small-o）：f(n) = o(g(n)) 表示 f/g → 0，即"严格低阶"，如 n² = o(n³)、n log n = o(n²)。

例 1（完整手算）：同一个问题，模型不同差多少？

考察语言 A = {0ᵏ1ᵏ | k ≥ 0}（第 1 章里它超出正则语言的能力）。在单带图灵机上判定它：

算法思路每轮成本轮数总时间
M₁（朴素配对）从左扫到右划掉一个 0，回头再划一个 1，重复O(n) 一趟扫描n/2 轮O(n²)
M₂（隔位消去）每趟划掉每隔一个的 0 和 1，并奇偶校验O(n)O(log n) 轮O(n log n)
M₃（多带机）把 0 段复制到带 2，再两带头同步右移比对O(n)1 轮O(n)

单带机最优也要约 n log n，多带机只要 n——模型确实影响时间。但关键定理是：任何 t(n) 时间的多带机，都能被单带机在 O(t(n)²) 时间内模拟（单带头用"扫描整条带"来模拟多带的一次移动，最多 O(t) 趟）。同理，随机存取机、非确定机与确定机之间，时间差距都不超过多项式。

💡 关键一跃：多项式是模型无关的

模型之间只差平方（多项式），所以"是否存在多项式时间算法"这个问题与模型无关——n² 和 n³ 算同一档，n 和 2ⁿ 才是两档。这正是复杂性理论敢用"多项式 vs 指数"作分界线的底气：这条线划在任何合理的计算模型上都一样。

⚠️ 大 O 不等于实用

n¹⁰⁰ 也是"多项式"，0.001·2ⁿ 在 n ≤ 40 时比 n¹⁰⁰ 快得多。大 O 是渐近骨架，回答"规模变大时谁先失控"，不回答"这个实例跑几秒"。把它当工程指标是张冠李戴——但在理论上，多项式与指数的鸿沟恰好对应"问题结构被利用"与"只能蛮力枚举"的本质差别。

7.2P：把"有效可解"钉在多项式上

上一节说"多项式 vs 指数"是模型无关的分界，现在把快的一侧命名：P（Polynomial Time）是所有能被确定性单带图灵机在多项式时间内判定的语言组成的类，即 P = ⋃k TIME(nᵏ)。PATH、素数判定（AKS）、线性规划、最大流，都在 P 里。

例 2（完整手算）：PATH ∈ P

PATH = {⟨G, s, t⟩ | 有向图 G 中存在从 s 到 t 的路径}。朴素思路是枚举所有可能的路径：n 个顶点的排列有 n! 条，n! ≈ (n/e)ⁿ 是超指数——这条路走不通。但下面的标记算法是多项式的：

✅ 标记算法（宽度优先的图灵机版）

① 给顶点 s 打标记；② 扫描所有边：若边 (a,b) 中 a 已标记而 b 未标记，给 b 打标记；③ 重复 ② 直到一轮中没有新标记产生；④ 若 t 被标记则接受，否则拒绝。

flowchart LR s(("s")) --> a(("a")) a --> b(("b")) s --> c(("c")) c --> b b --> t(("t")) classDef hot fill:#fbeedd,stroke:#c4651f,stroke-width:2.5px,color:#c4651f; class s hot;
图 7.1 PATH 手算实例。标记顺序：第 0 轮标 s；第 1 轮由边 s→a、s→c 标 a、c；第 2 轮由 a→b（或 c→b）标 b；第 3 轮由 b→t 标 t。t 被标记 → 接受。共 4 轮扫描。

时间分析：顶点至多 n 个，每轮至少新标一个顶点，故至多 n 轮；每轮扫描全部边，O(m)。总时间 O(n·m) = O(n³)——多项式，PATH ∈ P。✓

对照一下：同一个问题，"枚举路径"要 n! 步，"标记法"只要 n³ 步。指数与多项式的差别不是机器快慢的差别，而是算法思想的差别——有没有利用问题的结构（可达性具有"可传递、可贪心扩展"的结构）。

⚠️ 找不到多项式算法 ≠ 不在 P

素数判定曾被认为可能需要指数时间，直到 2002 年 AKS 算法证明它 ∈ P。"我不会做"和"不存在"是两回事——这预告了 7.6 节的核心误区，也是 P 对 NP 问题如此难缠的原因：证明下界远比设计上界难。

7.3NP：找答案难，验答案易

把 PATH 换一个问题：HAMPATH = {⟨G, s, t⟩ | G 中有从 s 到 t 且经过每个顶点恰好一次的路径}（哈密顿路径）。微小的改动，局面全变：至今没有人知道多项式算法。注意——不是"证明了没有"，而是"没人找到"。但有一条出路：如果有人声称存在这样的路径并直接给出它，你只需 O(n) 时间就能核对（按顺序检查相邻顶点是否有边、每个顶点是否恰好出现一次）。

这就是 NP（Nondeterministic Polynomial time，非确定多项式时间）的精神：验证易、求解未必易。形式化用验证者定义：

✅ NP 的验证者定义

语言 A 的验证者（verifier）是一台多项式时间算法 V，使得 A = { w | 存在字符串 c（证书 certificate）使 V 接受 ⟨w, c⟩ }，且 |c| 不超过 |w| 的多项式。NP = 所有具有多项式时间验证者的语言组成的类。

例 3：CLIQUE ∈ NP。CLIQUE = {⟨G, k⟩ | 图 G 含 k 个顶点两两相邻的子图（k-团）}。证书 c = 一份 k 个顶点的名单；验证者逐对检查这 k 个顶点间的边是否齐全，共 C(k,2) = O(k²) 对，多项式时间。✓ 但"找到"这 k 个顶点，已知的最好办法仍是指数级的枚举。

NP 还有一个等价定义（这正是名字的来源）：A ∈ NP 当且仅当存在非确定图灵机在多项式时间内判定 A——非确定的"猜"对应证书 c，"验"对应 V。两个定义随手互推：验证者枚举证书 = 非确定分支；非确定机的接受分支就是证书。

关系论证
P ⊆ NPP 中的算法自己就是验证者：忽略证书直接判定
NP ⊆ EXPTIME证书只有 2poly(n) 个候选，逐个验证即得指数时间上界
P = NP ？未知。即："验证易"是否蕴含"求解易"？
⚠️ NP 不是"非多项式"

NP 的 N 是 Nondeterministic（非确定），不是 Non-polynomial。恰恰相反：P ⊆ NP，NP 里的问题全都有指数级算法。把 NP 读成"不可解"或"超多项式"是本课程流传最广的错误，7.6 节专门清算它。

7.4多项式归约与 NP 完全：3SAT ≤ₚ CLIQUE 完整走一遍

第 5 章用映射归约传递"不可判定"；这里用它的多项式版传递"难解"。多项式时间归约（polynomial time reduction）：A ≤ₚ B，若存在多项式时间可计算的函数 f，使 w ∈ A ⟺ f(w) ∈ B。它有两条直接推论：

  • 若 A ≤ₚ B 且 B ∈ P，则 A ∈ P（归约 + 解 B，两段多项式复合仍多项式）；
  • 若 A ≤ₚ B 且 A 很难，则 B 至少同样难——难度沿箭头传递。

NP 完全（NP-complete）：语言 B 满足 ① B ∈ NP；② 每个 A ∈ NP 都有 A ≤ₚ B（此条称 NP 难，NP-hard）。若任一 NP 完全问题落入 P，则 P = NP——它们是 NP 中"最难"的一群，一荣俱荣、一损俱损。

例 4（完整归约）：3SAT ≤ₚ CLIQUE

3SAT：每个子句恰好 3 个字面量的 CNF 公式的可满足性问题（它是 NP 完全的，由 Cook–Levin 定理 + SAT ≤ₚ 3SAT 得到）。给定 3CNF 公式 φ，构造图 G 与数 k：

✅ 归约构造（三条规则）

① 顶点：φ 中每个字面量的每次出现是一个顶点（k 个子句 → 3k 个顶点，按子句分 k 组）；② 边：两个顶点连边，当且仅当它们来自不同子句且标签不矛盾（不能一个是 x、另一个是 ¬x）；③ 目标：k = 子句个数。

拿一个具体公式从头做到尾（Sipser 书上的例子）：

φ = (x₁ ∨ x₁ ∨ x₂) ∧ (¬x₁ ∨ ¬x₂ ∨ ¬x₂) ∧ (¬x₁ ∨ x₂ ∨ x₂)

第 1 步：列顶点。3 个子句 → 9 个顶点：

子句组顶点（记法：标签@组号）
组 1：(x₁ ∨ x₁ ∨ x₂)x₁@1a，x₁@1b，x₂@1
组 2：(¬x₁ ∨ ¬x₂ ∨ ¬x₂)¬x₁@2，¬x₂@2a，¬x₂@2b
组 3：(¬x₁ ∨ x₂ ∨ x₂)¬x₁@3，x₂@3a，x₂@3b

第 2 步：连边。跨组全连，只排除矛盾对：{x₁, ¬x₁} 对、{x₂, ¬x₂} 对。例如 x₁@1a 与 ¬x₁@2、¬x₁@3 不连；x₂@1 与 ¬x₂@2a、¬x₂@2b 不连；其余跨组对全连。

第 3 步：报参数。k = 3（子句数）。归约完成——9 个顶点、按规则连边、问"有没有 3-团"。整个构造只需扫一遍公式，O(子句数²)，多项式时间。✓

图 7.2 归约产物中的一个 3-团（全图共 9 个顶点，此处只画出被选中的 3 个）。三顶点跨组、标签两两不矛盾，故两两有边——这正对应满足赋值 x₂=1、x₁=0。

第 4 步：双向论证（正确性证明，不许跳步）。

⇒ 若 φ 可满足：取一个满足赋值，如 x₁ = 0，x₂ = 1。每个子句至少一个真字面量：子句 1 由 x₂=1 满足，子句 2 由 ¬x₁=真满足，子句 3 由 ¬x₁=真满足。从每个子句各取一个真字面量：{x₂@1，¬x₁@2，¬x₁@3}。它们跨组（连边条件 1 ✓）；它们同为真，不可能矛盾——若两个标签矛盾（x 与 ¬x），不可能在同一个赋值下同真（连边条件 2 ✓）。所以两两有边，构成 3-团。✓

⇐ 若 G 有 3-团：团内无同组顶点（同组顶点间按规则不连边），而团有 3 个顶点、共 3 组 → 每组恰好一个顶点。把这些顶点的标签赋为真：不会出现 x 与 ¬x 同时被要求为真（矛盾对之间没有边，不可能同团）。未被指定的变量随便赋值。此时每个子句的那个入选字面量为真 → φ 可满足。✓（本例中团 {x₂@1，¬x₁@2，¬x₁@3} 对应 x₂=1、x₁=0，回代验证三个子句全真。）

💡 归约的三板斧

每个 NP 完全性证明都是这个套路：① 给构造（多项式时间）；② ⇒：好实例的解变成目标实例的解；③ ⇐：目标实例的解读回原实例的解。其中 ⇐ 方向最容易出漏洞——必须论证目标解的"额外自由度"（本例：团内顶点为什么能拼出一个不矛盾的赋值）不会造假。

7.5Cook–Levin 定理：SAT 为什么能代表整个 NP

7.4 节把 3SAT 归约到 CLIQUE，但这一切需要一个"第一个"NP 完全问题。Cook–Levin 定理（Cook–Levin theorem，1971/1973 独立证明）：SAT（布尔公式的可满足性）是 NP 完全的。SAT ∈ NP 显然（证书 = 赋值，代入验证即可）；难点在 NP 难：要对任意 NP 语言 A，把"w ∈ A 吗"编译成一个布尔公式。

证明骨架：tableau 是一张可以被公式看管的表格

A ∈ NP，故有非确定机 N 在 n^k 时间内判定 A。固定输入 w（|w| = n）。N 在 w 上的一条计算分支可以写成一张 画面表（tableau）：n^k 行 × n^k 列的表格，第 i 行是第 i 步的格局（configuration：带内容 + 头位置 + 状态，两端加 # 标记）。

核心观察："这张表是 N 的一条合法接受计算"完全是一堆局部条件的合取——而局部条件可以写成布尔公式。令 C = Q ∪ Γ ∪ {#}（状态、带符号、端标记），设变量：

xi,j,s ：第 i 行第 j 列的格子里是符号 s （i, j ∈ [1, nᵏ]，s ∈ C）

变量总数 n^k × n^k × |C| = O(n²ᵏ)——多项式。公式 φ = φcell ∧ φstart ∧ φmove ∧ φaccept：

子句部件管什么怎么写规模
φcell每格恰好一个符号每格：(∨s xi,j,s) ∧ ∧s≠t(¬xi,j,s ∨ ¬xi,j,t)O(n²ᵏ)
φstart第 1 行 = 起始格局 q₀w₁…wₙx1,1,# ∧ x1,2,q₀ ∧ x1,3,w₁ ∧ … ∧ 空白与末端 # 的单元子句O(nᵏ)
φmove每相邻两行是 N 的一步合法转移每个 2×3 窗口：析取所有"合法窗口"的变量组合O(n²ᵏ)
φaccept某格出现接受状态∨i,j xi,j,q_acceptO(n²ᵏ)

φmove 是心脏：格局 i+1 与格局 i 的差别只可能出现在读写头附近的 2×3 窗口里（头一步最多移动一格），而"合法窗口"的样式由转移函数 δ 决定，只有有限多种。逐个窗口枚举合法样式写成析取——每个窗口 O(1) 大，共 O(n²ᵏ) 个窗口。

等价性：φ 可满足 ⟺ 存在一张满足全部局部条件的 tableau ⟺ 它是 N 在 w 上的合法接受计算（起始对、步步合法、最终接受）⟺ N 接受 w ⟺ w ∈ A。规模：总公式长 O(n²ᵏ)——多项式，归约成立。∎（骨架完）

小规模实例：看看公式长什么样

设 N 是一台一步机器：读头下若是 0 就接受，否则拒绝；输入 w = 0（n = 1，取 k = 1，tableau 只画 2 行 5 列，# 为端标记）。合法计算：

行格1格2格3格4格5
1（起始）#q₀0␣#
2（接受）#q_acc0␣#

对应公式片段（C = {#, q₀, q_acc, 0, ␣}）：

  • φcell 对格 (1,2)：(x1,2,# ∨ x1,2,q₀ ∨ x1,2,q_acc ∨ x1,2,0 ∨ x1,2,␣) ∧ (¬x1,2,# ∨ ¬x1,2,q₀) ∧ (¬x1,2,# ∨ ¬x1,2,q_acc) ∧ …（共 1 条"至少一个" + C(5,2) = 10 条"至多一个"）；10 个格子各来一份。
  • φstart：x1,1,# ∧ x1,2,q₀ ∧ x1,3,0 ∧ x1,4,␣ ∧ x1,5,#——把第 1 行钉死。
  • φmove：对窗口（行1–2，列1–3），合法样式之一是 (#, q₀, 0 / #, q_acc, 0)，对应 (x1,1,# ∧ x1,2,q₀ ∧ x1,3,0) → (x2,1,# ∧ x2,2,q_acc ∧ x2,3,0) 形式的约束，与所有其他合法窗口析取；远离头的窗口（列 3–5 中头不在场）只能是"三格原样照抄"的合法样式。
  • φaccept：x1,1,q_acc ∨ x1,2,q_acc ∨ … ∨ x2,5,q_acc（10 个字面量的析取）。

这个 50 变量的小公式可满足（上面的表就是证据）；若把输入改成 w = 1，则没有任何合法表能同时满足 φstart 与 φaccept——公式不可满足。公式把"计算"冻结成了"约束满足"，这就是 Cook–Levin 的全部魔法。

💡 为什么 SAT 能代表整个 NP

因为"非确定计算"本质是一堆局部一致性约束：格子像格子、起步像起步、步步像转移、结局像接受。SAT 恰好是"局部约束满足"的通用语言。任何 NP 问题的证书验证过程都能铺成 tableau，所以 SAT 难就等价于"验证与求解的差距"本身难。

7.6错误直觉清算：三个最流行的误解

⚠️ 误区一："NP 就是不可解"

错得离谱。不可判定问题（第 4–6 章）是任何算法都不存在；NP 里的问题全都有指数时间算法（枚举证书逐个验），只是不知道有没有多项式算法。"难算"与"不能算"之间隔着整个第 5 章。HAMPATH 输入 30 个顶点时蛮力已经吃力，但输入 10 个顶点时秒解——这是工程问题，不是数学禁令。

⚠️ 误区二："P vs NP 只是理论家的游戏"

恰恰相反，它是最"实用"的未解问题。现代密码学（RSA、椭圆曲线）的安全性赌注就是"求逆易验证、难求解"——若 P = NP，公钥密码体系整体崩塌；反之若证明 P ≠ NP，则任何"多项式破解"的幻想可以停止。物流调度、芯片布线、蛋白质折叠、编译器寄存器分配，全都是 NP 难问题——它们的最优解要不要继续追，取决于这个问题的答案。

⚠️ 误区三："证明 NP 完全 = 判死刑，别做了"

NP 完全只排除"所有实例都多项式可解"，不排除：① 近似算法（第 10 章：顶点覆盖有 2-近似）；② 参数化算法（k 小时快）；③ 特殊实例（树宽小的图上很多问题变容易）；④ 平均情形 / 启发式（SAT 求解器在工业实例上千万变量照跑）。证明 NP 完全是换赛道的信号，不是终点。

概念卡 1
大 O 记号（Big-O Notation）
点击翻面 →
定义f = O(g)：存在 c、n₀ 使 n ≥ n₀ 时 f(n) ≤ c·g(n)，即 g 是 f 的渐近上界。
解决问题把运行时间从机器细节中抽象出来，只留增长骨架。
直觉只报数量级："万级、亿级"，不报精确账。
误区当成实际运行时间；n¹⁰⁰ 也是多项式但毫无实用价值。
何时用全课程所有复杂度陈述；P、NP、层级定理（Ch9）的语言。
概念卡 2
P（Polynomial Time）
点击翻面 →
定义P = ⋃k TIME(nᵏ)：确定性多项式时间可判定的语言类。
解决问题给"有效可解"一个模型无关的数学定义。
直觉规模翻倍，耗时只翻固定倍数，不会爆炸。
误区以为 P = "快"：n¹⁰⁰ ∈ P 但不快；P 是"不随规模失控"。
何时用一切算法的及格线；与 NP 对照定义了世纪难题。
概念卡 3
NP（Nondeterministic Polynomial Time）
点击翻面 →
定义证书可多项式时间验证的语言类；等价于非确定机多项式时间可判定。
解决问题刻画"答案好验、难求"的一大批自然问题（HAMPATH、CLIQUE、SAT）。
直觉阅卷容易出题难；看答案一眼懂，自己想破头。
误区读成"非多项式"——N 是非确定；P ⊆ NP，NP 全有指数算法。
何时用NP 完全理论的地基；IP、PCP（Ch10）都是它的亲属。
概念卡 4
多项式时间归约（≤ₚ）
点击翻面 →
定义A ≤ₚ B：多项式可计算 f 使 w∈A ⟺ f(w)∈B。
解决问题让"难度"在问题间传递：B 容易则 A 容易，A 难则 B 难。
直觉把 A 的卷子多项式时间翻译成 B 的卷子。
误区方向搞反：证 B 难要 A ≤ₚ B（难的归到 B），不是 B ≤ₚ A。
何时用所有 NP 完全性证明；Ch8 的 PSPACE/NL 完全同理。
概念卡 5
NP 完全（NP-complete）
点击翻面 →
定义B∈NP 且所有 A∈NP 都 A ≤ₚ B；NP 中最难的一批问题。
解决问题把"P 对 NP"这一个大问题压缩成"SAT（或任一 NP 完全问题）在不在 P"一个小问题。
直觉多米诺骨牌的第一张：任何一张倒（进 P），全倒（P=NP）。
误区以为 NP 完全 = 最难的可解问题——NP 之外（PSPACE 等）还有更难的。
何时用遇到新问题时先判它在不在 P、是不是 NP 完全，再定求解策略。
概念卡 6
Cook–Levin 定理
点击翻面 →
定义SAT 是 NP 完全的：任意 NP 语言的成员判定可多项式编译成 SAT 实例。
解决问题提供"第一个"NP 完全问题，之后靠归约链扩散（SAT→3SAT→CLIQUE→…）。
直觉计算 = 局部一致性约束；SAT = 约束满足的通用语言。
误区以为证明是枚举所有 NP 问题逐一归约——它只归约一次：归约"非确定计算"这个概念本身。
何时用一切 NP 完全性链条的起点；tableau 技巧在 IP=PSPACE（Ch10）中重演。
概念卡 7
验证者 / 证书（Verifier / Certificate）
点击翻面 →
定义w∈A ⟺ ∃c 使 V 接受 ⟨w,c⟩；V 多项式时间，c 多项式长。
解决问题绕开非确定机，用普通算法定义 NP——更贴近"解题与验题"的直觉。
直觉证书是标准答案，验证者是阅卷老师。
误区以为证书必须好找——它只须"存在且好验"，找它就是求解本身。
何时用证某问题 ∈ NP 的标准动作；交互证明（Ch10）是它的对话版。

📝分层习题

L1 概念辨析判断对错："f(n) = n² + 1000n 是 O(n²)，但不是 O(n³)。"说明理由。
提示

回到定义：O(n³) 只要求存在某个 c、n₀ 使 f(n) ≤ c·n³。上界需要"最紧"吗？

完整解答
前半对、后半错。f = O(n²)：取 c = 2，n ≥ 1000 时 1000n ≤ n²，故 f(n) ≤ 2n²。f 也 = O(n³)：取 c = 1，n ≥ 1001 时 n² + 1000n ≤ n³。O 是上界，不唯一，"是 O(n²) 但不是 O(n³)"把 O 误读成了精确阶——精确的低阶严格说法用小 o：f = o(n³) 成立，f = o(n²) 不成立。
L1 概念辨析判断对错："若 A ≤ₚ B 且 A 是 NP 完全的，则 B 一定是 NP 完全的。"
提示

NP 完全有两个条件。≤ₚ 的传递性给你哪一个？另一个从哪来？

完整解答
错，少了 B ∈ NP 这一条。由 A NP 难 + A ≤ₚ B + ≤ₚ 传递，可得 B 是 NP 难；但若 B 本身不在 NP 中（比如 B = 某个 PSPACE 完全问题 TQBF，它 NP 难却不在已知属于 NP），就称不上 NP 完全。正确命题：A ≤ₚ B、A NP 完全、且 B ∈ NP ⟹ B NP 完全。这也是每个 NP 完全性证明先证"∈ NP"的原因。
L2 手算推导对公式 φ = (x ∨ y ∨ z) ∧ (¬x ∨ ¬y ∨ ¬z) 执行 3SAT ≤ₚ CLIQUE 归约：写出顶点、边规则、k，并给出一个团与对应的满足赋值。
提示

2 个子句 → 6 个顶点。矛盾对是哪些？k 等于几？

完整解答

顶点：组1 {x@1, y@1, z@1}，组2 {¬x@2, ¬y@2, ¬z@2}。边：跨组全连，排除矛盾对 {x@1,¬x@2}、{y@1,¬y@2}、{z@1,¬z@2}——共 C(6,2)−3−3（同组 3+3）= 15−6 = 9 条边。k = 2。

取团 {x@1, ¬y@2}：跨组、不矛盾，有边，是 2-团。读出赋值 x=1、y=0（z 任意，取 z=0）：子句1 由 x=1 满足，子句2 由 ¬y=1 满足。✓

验证反面：φ 可满足（如上述赋值）⟺ G 有 2-团——任何 2-团都不能含矛盾对，必能读出不矛盾赋值，且两个顶点分属两组各满足一个子句。

L2 手算推导对图 7.1（边：s→a、s→c、a→b、c→b、b→t，外加一条孤立顶点 d）手算 PATH 标记算法 ⟨G, s, t⟩ 与 ⟨G, t, s⟩ 两个实例，各给出每轮标记集合与结论。
提示

逐轮列出"本轮新标了谁"；注意边有方向，t→s 方向没有任何出边。

完整解答

实例 ⟨G, s, t⟩：第 0 轮 {s}；第 1 轮加 {a, c}；第 2 轮加 {b}；第 3 轮加 {t}；第 4 轮无新增，停。t 被标记 → 接受。

实例 ⟨G, t, s⟩：第 0 轮 {t}；t 无出边，第 1 轮无新增，停。s 未标记 → 拒绝。孤立点 d 两轮均从未被标记，符合预期（它与可达性无关）。

耗时：每实例至多 5 轮（顶点数），每轮扫 5 条边，远小于枚举路径的开销。

L3 建模应用某航空公司要上线两个查询功能：①"能否从昆明经若干次中转到达哈尔滨？"②"能否安排一条恰好经过全部 100 个通航城市各一次的巡回航线？"分别判断这两个功能背后的判定问题属于哪个类、敢不敢承诺秒级响应，并说明理由。
提示

把两个场景分别翻译成本章学过的两个命名问题。它们的已知地位分别是什么？

完整解答

① 是 PATH（有向可达性）∈ P：标记算法 O(n·m)，100 城市毫秒级，敢承诺秒级响应。

② 是 HAMPATH（哈密顿路径，巡回版本即 TSP 的判定版）——NP 完全：验证一条给出的航线容易（O(n) 检查相邻有航班、城市不重不漏），但目前已知算法最坏指数。不敢承诺秒级精确响应；工程上应改承诺"近似/限时启发式"，这正是 7.6 节误区三指出的换赛道思路（第 10 章会正式讲近似）。

同一组数据（航线图），一个问题的结构（可达性可贪心扩展）被多项式算法利用，另一个（全局不重复约束）目前只能枚举——P 与 NP 完全的分界线就是这两句话的分界线。

选 D。图灵机的一步是局部的：头下符号改写、头左/右移一格，其余照抄——所以"步步合法"等价于"每个 2×3 窗口合法"。A 错：tableau 是 nᵏ×nᵏ 的；B 错：φ_move 的子句可以很长（析取所有合法窗口），3SAT 是后来再归约得到的；C 把"验证者"与 tableau 构造混为一谈。
自测 5
已知 A 是 NP 完全问题，且发现 A ≤ₚ B，可以推出：
  • A. B 是 NP 完全的
  • B. B 是 NP 难的；若再有 B ∈ NP，则 B 是 NP 完全的
  • C. B 不在 P 中
  • D. A ≤ₚ B 说明 B ≤ₚ A
选 B。归约传递 NP 难，但 NP 完全还需 B ∈ NP 这个独立条件（自测 L1 第 2 题同款）。A 少了前提；C 错：B 完全可能是平凡在 P 中的语言（归约方向决定难度从 A 传到 B 的上界，不能反推下界——除非 P≠NP 已证）；D 错：≤ₚ 不对称。
