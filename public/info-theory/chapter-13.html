13.1为什么需要通用编码：错分布的代价恰好是相对熵

第 5 章我们造出了最优码：给分布 p 配上 Shannon 码或 Huffman 码，平均码长逼近熵 H(p)。但那份蓝图有个隐蔽的前提——你得先知道 p。这一节先承认这个前提在现实中不成立，再把"用错分布"的代价算成一个精确的数字。

现实里的数据长什么样？英文文本的字母分布随作者与文体漂移；DNA 序列里碱基与短串的统计没人能先验给出；工厂传感器 24 小时不停吐数据流，连"符号表"都可能随工况变化。你手里没有 p，只有一个猜测 q。问题是：按 q 设计的码，用来压缩真实分布 p 的数据，亏多少？

答案是一个漂亮的恒等式。按 q 的最优码，给符号 x 分配码长 l(x) = log₂(1/q(x))（先忽略取整）。数据其实来自 p，所以期望码长：

Ep[l(X)] = ∑x p(x)·log₂1q(x) = ∑x p(x)·log₂p(x)q(x) + ∑x p(x)·log₂1p(x) = H(p) + D(p‖q)

也就是说：冗余（Redundancy）——超出熵的那部分期望码长——恰好等于相对熵 D(p‖q)。相对熵这个在第 2 章登场的量，在这里第一次露出它的工程真身：它就是"信源分布猜错"的每符号比特罚款。

例 1：真分布 Bern(1/4)，错用均匀分布 q

信源每符号独立地发 0/1，真实分布 p = Bern(1/4)：P(1)=1/4，P(0)=3/4。工程师不知道，按均匀猜测 q = (1/2, 1/2) 设计码。

第一步：q 码长什么样。q 下两个符号各配码长 log₂ 2 = 1 bit，所以 0→0、1→1，每个符号恒用 1 bit，期望码长 L = 1 bit。

第二步：真实熵是多少。二元熵函数：

h(14) = −14·log₂14 − 34·log₂34 = 14×2 + 34×0.4150 = 0.5 + 0.3113 = 0.8113 bit

第三步：冗余直接相减。每符号浪费 1 − 0.8113 = 0.1887 bit——近 19% 的码长白白烧掉。

第四步：验证恒等式，展开 D(p‖q) 一步不跳：

D(p‖q) = 14·log₂1/41/2 + 34·log₂3/41/2 = 14·log₂12 + 34·log₂32
= 14×(−1) + 34×0.5850 = −0.25 + 0.4387 = 0.1887 bit ✓

与第三步直接相减的结果严丝合缝。这不是巧合，就是恒等式 E_p[l] = H(p) + D(p‖q) 在数字上显形。

💡 关键一跃

相对熵不是抽象的"距离"——它是真金白银的比特罚款：分布猜偏多少，每符号就多付 D(p‖q) 比特。于是"分布未知"这件事从模糊的担心变成了可定价的风险，全章的工作就是把这个罚款压到最低。

⚠️ 常见误区

"分布估计得差不多就行"——错。D(p‖q) 对 q 的尾部极敏感：若某个真实概率不小的符号被 q 给了接近 0 的概率，log₂(p/q) 会爆炸，罚款无界。通用编码的出发点正是：不要赌分布，要设计对一切分布都不离谱的码。

13.2最坏情况与贝叶斯：把"罚款"压到最低的两条路线

上一节把错分布的代价标了价：D(p‖q)。这一节的问题自然浮现——在 p 完全未知时，选哪个 q 最稳？统计学家给出两种世界观：盯住最坏情况（minimax），或给参数一个先验求平均（贝叶斯）。两条路线各有一个干净的答案，而且答出来的数常常惊人地接近。

路线一：minimax 与归一化最大似然

设信源分布来自参数族 {pθ}（如伯努利族 Bern(θ)）。选一个码等价于选一个分布 q。最坏情况下的遗憾（Regret）定义为：

R* = minq maxθ D(pθ‖q)

即：我选 q，自然选最不利于我的 θ，我先把最坏情况压到最小。这个最小最大值 R* 有个出人意料的显式解（Shtarkov）：最优 q 是归一化最大似然分布（Normalized Maximum Likelihood, NML），

q*(xⁿ) = supθ pθ(xⁿ)Cn，其中 Cn = ∑xⁿ supθ pθ(xⁿ)
R* = log₂ Cn（Shtarkov 值）

直觉：给每条序列打分时，不用固定 θ，而用"事后最偏袒它的 θ"来打分，再把所有分数归一化。Cn 度量这个参数族有多"大"：族越丰富，自归一化的开销越大，遗憾越高。

例 2：n=2 伯努利序列的 NML 遗憾（完整手算）

参数族 Bern(θ)，序列长 n=2，共 4 条序列。对每条序列 xⁿ，先算 supθ pθ(xⁿ)——最大似然在 θ̂ = （序列中 1 的比例）处取到：

序列 xⁿθ̂（ML 估计）supθ pθ(xⁿ)数值
000(1−0)²1
011/2(1/2)·(1/2)1/4
101/2(1/2)·(1/2)1/4
1111²1

求和：C₂ = 1 + 1/4 + 1/4 + 1 = 5/2 = 2.5。

取对数：minimax 遗憾

R* = log₂ 2.5 = log₂52 = 1.3219 bit

含义：无论真实 θ 是谁，存在一个码（NML 码），它对 2 比特伯努利数据的期望码长比"知道 θ 后才能达到的极限"最多多 1.3219 bit——这是对"整段 2 比特序列"而言的一笔固定罚款，不随 θ 变坏。注意它相当贵：序列本身才 2 bit，可见短序列上"无知"很贵；但 Cn 随 n 只以约 (1/2)·log₂ n 的速度增长（参数族维数决定的渐近），摊到每符号就趋向 0。

路线二：贝叶斯混合码

贝叶斯派拒绝只盯最坏情况：给 θ 一个先验权重 w(θ)，用混合分布（Mixture Distribution）

m(xⁿ) = ∫ w(θ)·pθ(xⁿ) dθ

来编码（码长 log₂(1/m(xⁿ))）。对先验 w 求平均的冗余有一个精确的身份：

∫ w(θ)·D(pθ‖m) dθ = I(θ; Xⁿ)

即贝叶斯平均冗余 = 参数与数据之间的互信息。互信息在这里有了操作意义：它就是你为"不知道 θ"平均多付的比特数——学 θ 值多少钱，不知道 θ 就亏多少钱。

例 3：两点先验下的 I(θ;X)（与例 1 呼应）

取先验 w：θ ∈ {1/4, 3/4} 各以概率 1/2，n=1。

第一步：算混合分布。m(1) = ½·(1/4) + ½·(3/4) = 1/2；m(0) = ½·(3/4) + ½·(1/4) = 1/2。混合恰为均匀分布。

第二步：算互信息。I(θ;X) = H(X) − H(X|θ)。边缘 X 是均匀的，H(X) = 1 bit；条件期望 H(X|θ) = h(1/4) = 0.8113 bit（两个 θ 的熵相同，加权不变）。

I(θ; X) = 1 − 0.8113 = 0.1887 bit ≈ 0.189 bit

第三步：对照例 1。例 1 中真分布 Bern(1/4)、错用均匀 q 的冗余是 0.1887 bit——本例中"先验下的平均冗余"与"某个真实 θ 碰上混合 m 的罚款"数值一致，因为这里 m 恰好是均匀分布，而 D(Bern(1/4)‖均匀) 与 D(Bern(3/4)‖均匀) 相等。两条路线在同一个数上握手：minimax 与贝叶斯在最坏/平均两个方向上量的是同一枚硬币。

另一种比较：竞争最优性

minimax 和贝叶斯都问"平均/最坏差多少"，还可以问一个更个性化的问题：Shannon 码在逐符号上被别的码大幅击败的概率有多大？答案是竞争最优性（Competitive Optimality）：设 l(X) 是 Shannon 码长（l(x)=⌈log₂(1/p(x))⌉），l′ 是任意其他唯一可译码的码长，则对任意整数 c ≥ 1：

P(l(X) ≥ l′(X) + c) ≤ 2−(c−1)

读 c=3 这一格：任何别的码想在某个符号上比 Shannon 码省 3 bit 以上，这种情况发生的概率 ≤ 2−2 = 1/4。换句话说，对手可以在少数符号上赢你，但赢得越多，能赢的机会就越指数级萎缩。Shannon 码不只是平均最优，还是"最不容易被单挑打爆"的码。

💡 关键一跃

三条路线同一个主题：把"无知"定价。minimax 的价签是 log₂ Cn（参数族的大小），贝叶斯的价签是 I(θ;Xⁿ)（参数值多少信息），竞争最优性的价签是 2−(c−1)（被单挑击败的概率上限）。价格都付得起，而且渐近都趋向 0——这就是"通用"二字能成立的原因。

⚠️ 常见误区

"minimax 遗憾摊到每符号还有 1.3 bit，通用编码不划算"——错在忘了除法。例 2 的 1.3219 bit 是整段序列的一次性罚款，n 增大时 log₂ Cn ≈ (k/2)·log₂ n（k 为参数维数），每符号遗憾 ≈ (k log₂ n)/(2n) → 0。短数据贵、长数据近乎免费，这正是通用编码在流媒体时代大行其道的数学原因。

13.3Lempel-Ziv：不知道任何统计，照样压到熵率

上一节的两条路线都还要先假设一个参数族 {pθ}——这已经是妥协：很多真实数据连"族"都给不出。这一节的主角更激进：完全不要概率模型，边读数据边建字典，照样渐近压到熵率。这就是 Lempel 和 Ziv 1977–78 年的工作，今天藏在每一个 zip、gzip、png 文件里。

LZ78 的规则：边读边长字典

LZ78（Lempel-Ziv 1978）把输入串切成一连串互异的短语：每读到一个"此前字典里没有的最短串"就切一刀，把它登记进字典，然后输出一个二元组（前缀的字典编号，新添的字符）。规则一句话：新短语 = 字典里的旧短语 + 一个新字符。

例 4：串 1011010100010 的完整 LZ78 编码

输入 13 bit：1 0 1 1 0 1 0 1 0 0 0 1 0。从左往右读，维护字典，一步不跳：

步读到的位置切出的短语为何在此切入字典输出（指针，新字符）
111字典空，首字符即新短语#1 = 1(0, 1)
2000 不在字典#2 = 0(0, 0)
311111 在字典（#1），11 不在#3 = 11(1, 1)
401010 在字典（#2），01 不在#4 = 01(2, 1)
501001001 在字典（#4），010 不在#5 = 010(4, 0)
600000 在字典（#2），00 不在#6 = 00(2, 0)
710101 在字典（#1），10 不在，串正好读完#7 = 10(1, 0)

短语切分结果：1 | 0 | 11 | 01 | 010 | 00 | 10；输出序列：(0,1) (0,0) (1,1) (2,1) (4,0) (2,0) (1,0)。

图 13.1 LZ78 字典生长：每个新短语都是"旧短语 + 一个字符"（如橙色 #5 = #4 的 01 再添 0）。解码端拿同样的规则重建同一张表。

数账：输出一共多少 bit？第 k 个输出的指针要能从 0 指到 #k−1，需要 ⌈log₂ k⌉ bit（k=1 时 0 bit），再加 1 bit 新字符：

指针位数 = 0 + 1 + 2 + 2 + 3 + 3 + 3 = 14 bit，新字符 7 bit，合计 21 bit

输入才 13 bit，输出 21 bit——短串反而膨胀了 62%！这不是实现错误，而是 LZ 的"启动成本"：字典还没长大，指针开销 > 复用收益。

为什么长串会翻盘？设一条 n 长的串被切成 c 个互异短语。互异意味着短语长度必须参差：c 个互异串的总长度至少是 1+2+…+c 量级，即 n ≳ c²/2 的阶，也就是 c 最多约 √(2n)。每个输出花约 log₂ c + 1 bit，总码长约 c(log₂ c + 1)。代入 c ≈ √(2n)：码长/n ≈ (√(2n)·log₂√(2n))/n → 0 的阶……更精细的分析（LZ 定理）给出精确结论：对任何平稳遍历信源，LZ78 的每符号码长渐近收敛到熵率 H(𝒳)。直觉一句话：短语越来越长，指针的 log c 开销被越来越长的短语摊薄，而长短语正是信源统计规律性的化身——重复出现的模式被字典捕获，等价于隐式地学到了分布。

工程事实一句。更早的 LZ77（Lempel-Ziv 1977）用"滑窗 +（位移，长度）匹配"代替显式字典；你日常用的 zip/gzip = LZ77 变体（DEFLATE）+ Huffman 码二次压缩指针与字面量——第 5 章的 Huffman 和本章的 LZ 在每个压缩包里联手干活。

💡 关键一跃

LZ78 把"学统计"和"压缩"合并成同一个动作：字典就是隐式的概率模型。它从不计算任何概率，却用"这个短语我见过"记录下了信源的全部规律性。通用编码的深刻之处在于：压缩极限只由信源本身决定，与你是否显式建模无关。

⚠️ 常见误区

"LZ 对 13 bit 短串膨胀，所以 LZ 不行"——错在把渐近算法当短串工具。渐近定理的承诺是 n→∞ 时码率→熵率，从不承诺短串赚钱。短数据的正确工具恰恰是 13.2 的 NML/贝叶斯路线（一次性罚款 log₂ Cn 已知）；长流式数据才轮到 LZ 上场。选工具要看 n 的量级，不看算法名气。

c 个互异短语总长 ≳ c²/2，故短语数 c 只以 √n 增长而短语越来越长；每个输出的指针开销 log₂c 被长短语摊薄，重复模式被字典捕获，每符号码长渐近趋于熵率。

13.4算术编码与"小数码长"：通往柯氏复杂度的桥

前三节给了三种通用码的设计思想，但都还欠一个工程零件：码长 log₂(1/q(xⁿ)) 几乎从不是整数，逐符号取整会丢掉宝贵的分数比特。补上这个零件的是算术编码（Arithmetic Coding）：把整条序列 xⁿ 映射到单位区间内一个长度为 q(xⁿ) 的子区间，再输出区间内某个短二进制小数。区间长度就是概率，码长天然是 log₂(1/q(xⁿ)) 这个"小数"，整条序列只付一次取整费（≤2 bit），摊到每符号约等于 0。

它对本章的意义是机制性的：13.2 的 NML 码、贝叶斯混合码，码长函数都是 log₂(1/q(xⁿ)) 形状的理论对象，算术编码是让这些理论码长可执行的标准引擎——只要你能逐符号递推算出条件概率 q(xi|xi−1)（NML 与混合分布都可以链式分解递推），算术编码就把它们落成真实的比特流。

更重要的是承上启下的一步。回看本章三种码，它们对具体序列 xⁿ 给出的码长都只依赖于序列自身（及其在族中的典型性），而不需要任何人报告 p：每条序列自带一个"可压缩度"。把这件事推到极致——不问分布、不问参数族，只问"这条序列本身最短能被描述成什么样"——就得到了一个只依赖序列本身的复杂度量。第 14 章给它正式的名字：柯氏复杂度（Kolmogorov Complexity），K(x) = 能输出 x 的最短程序长度。通用编码是它的"概率版本"，柯氏复杂度是它的"终极个体版本"。

💡 关键一跃

算术编码是"分数比特"的搬运工，而本章真正的思想出口是：压缩的下限不在分布里，在序列本身里。分布只是描述序列规律性的一件外衣——第 14 章把外衣脱掉。

⚠️ 常见误区

"算术编码是一种新的信源模型"——错。算术编码不产生任何概率估计，它只负责把已有的概率 q 精确兑换成比特。模型好坏（q 离真分布多远）决定码长好坏；算术编码只保证你付出的码长不多不少就是 log₂(1/q)。模型与引擎，别混为一谈。

概念卡 1
冗余与相对熵代价（Redundancy as Divergence）
点击翻面 →
定义用 q 的最优码压 p 的数据，期望码长 = H(p) + D(p‖q)，冗余即 D(p‖q)。
解决问题给"分布猜错"标价，把模糊风险变成每符号的比特罚款。
直觉相对熵是罚款单：猜偏多少，每符号多付多少。
误区以为冗余 ≈ 分布差的绝对值；其实 q 尾部给 0 时罚款爆炸。

概念卡 2
minimax 遗憾与 NML（Minimax Regret / Shtarkov）
点击翻面 →
定义R* = min_q max_θ D(p_θ‖q) = log₂ C_n，C_n = ∑ sup_θ p_θ(xⁿ)；最优码为归一化最大似然。
解决问题在"自然选最坏 θ"的对局里，给出谁都不能更差的最稳码。

概念卡 3
贝叶斯混合码（Bayesian Mixture Code）
点击翻面 →
定义m(xⁿ) = ∫ w(θ)p_θ(xⁿ)dθ，码长 log₂(1/m(xⁿ))；平均冗余 = I(θ;Xⁿ)。
解决问题有先验时把"学参数值多少信息"精确兑换成平均多付的比特。
直觉先验是保险单：互信息 I(θ;Xⁿ) 就是无知的平均保费。
误区以为混合码要对 θ 做硬估计；它从不估计，只按后验自动加权。
何时用有合理先验时的在线编码；与 minimax 互为最坏/平均两面。
概念卡 4
竞争最优性（Competitive Optimality）
点击翻面 →
定义Shannon 码 l 对任意唯一可译码 l′：P(l(X) ≥ l′(X)+c) ≤ 2^(−(c−1))。
解决问题回答"别的码能不能在个别符号上把我打爆"——能，但概率指数衰减。
直觉对手每想多赢 1 bit，能赢的机会就腰斩一半。
误区以为它说"Shannon 码处处最优"；它只说被大幅击败的概率很小。
何时用比较编码方案的逐符号稳健性，而非只比平均码长时。
概念卡 5
LZ78（Lempel-Ziv 1978）
点击翻面 →
定义切出互异短语（旧短语+新字符），输出（字典编号，新字符）；字典边读边长。
解决问题完全不知统计（连参数族都不给）时的压缩，渐近码率收敛到熵率。
直觉字典是隐式概率模型：我见过你，就不用再教你一遍。
误区拿短串膨胀否证 LZ；渐近定理从不承诺短数据赚钱。
何时用长流式数据（文本/日志/基因）；zip/gzip 的内核（LZ77+Huffman）。
概念卡 6
算术编码（Arithmetic Coding）
点击翻面 →
定义把序列映到长度 = q(xⁿ) 的区间，输出区间内短二进制小数，码长 = log₂(1/q)。
解决问题让分数比特码长可执行：整条序列只付一次取整费。
直觉概率兑换机：区间多长，码就多短，分毫不差。
误区以为它是信源模型；它只是引擎，模型好坏全在 q。
何时用NML/混合码/自适应编码的落地实现；通往 Ch14 柯氏复杂度的桥。

📝分层习题

L1 概念辨析判断正误并说明理由：① "只要 q 与 p 很接近（比如每个符号概率误差都不超过 0.01），冗余 D(p‖q) 就一定可以忽略。"② "LZ78 需要扫描两遍数据：第一遍统计，第二遍编码。"
提示

① 想 D(p‖q) 里 log₂(p/q) 对 q 的小概率有多敏感，而不仅是概率差的大小。② 回忆 LZ78 字典是什么时候建的。

完整解答

① 错。冗余是 p·log₂(p/q) 的和，敏感的是比值 p/q 而非差值 |p−q|：若某符号 p=0.01 而 q=0.0001（绝对误差仅 0.0099），该符号贡献 0.01·log₂100 ≈ 0.066 bit；若 q 把某真实正概率符号压到 0，罚款直接无界。"逐点接近"不等于"编码上接近"。

② 错。LZ78 是单遍在线算法：字典在读数据的同一遍里边切分边生长，输出即时产生，解码端用同一规则同步重建字典。需要两遍的是"先估分布再 Huffman"的两阶段方案——这正是 LZ 相对它的核心优势之一。

L1 概念辨析选择：贝叶斯混合码 m(xⁿ) 的先验 w(θ) 选得"不准"（真实 θ 在 w 的低概率区），下列哪种说法最准确？A. 码长无界爆炸；B. 平均冗余仍等于 I(θ;Xⁿ)，与真实 θ 无关；C. 对该真实 θ 的冗余 = D(p_θ‖m)，可能比 I(θ;Xⁿ) 大；D. 混合码失效不再可译。
提示

区分"对先验平均"和"对某个具体 θ"两个口径；I(θ;Xⁿ) 是哪个口径的量？

完整解答

C 正确。对具体真实 θ，冗余是 D(p_θ‖m)——θ 落在先验低概率区时 m 会低估它，罚款变大。A 错：只要 m(xⁿ)>0（先验不全为零），码长有界，只是变长。B 错：I(θ;Xⁿ) 是按先验 w 求平均的冗余，"真实 θ 固定"时它不是这个数字——口径混淆是本题要抓的错。D 错：混合分布仍归一，码照常可译，只是不优。

L2 手算推导对伯努利族 Bern(θ)、序列长 n=3，计算 NML 的 minimax 遗憾 R* = log₂ C₃，所有步骤写全。
提示

8 条序列按 1 的个数分四组；每组的最大似然估计 θ̂ = k/3；k 个 1 的序列 sup 值 = (k/3)^k·((3−k)/3)^(3−k)。

完整解答

第一步：分组并求各组 sup 值。

· 000（k=0）：θ̂=0，sup = 1³ = 1；

· 001、010、100（k=1，共 3 条）：θ̂=1/3，每条 sup = (1/3)¹·(2/3)² = (1/3)·(4/9) = 4/27；

· 011、101、110（k=2，共 3 条）：θ̂=2/3，每条 sup = (2/3)²·(1/3)¹ = (4/9)·(1/3) = 4/27；

· 111（k=3）：θ̂=1，sup = 1³ = 1。

第二步：求和。

C₃ = 1 + 3×427 + 3×427 + 1 = 2 + 2427 = 2 + 89 = 269 ≈ 2.8889

第三步：取对数。

R* = log₂269 = log₂ 2.8889 ≈ 1.5315 bit

对照例 2 的 n=2（1.3219 bit）：n 从 2 到 3，遗憾只增了 0.21 bit——印证 log₂ Cn 亚线性（约 (1/2)log₂ n）增长，每符号遗憾随之下降。

L2 手算推导对串 01011001011（11 bit）执行完整 LZ78 编码：切分短语、建字典、写出全部输出对，并数出总码长与输入码长比较。
提示

每步找"字典里有的最长前缀"，再多吃一个字符；第 k 个输出的指针占 ⌈log₂ k⌉ bit。

完整解答

逐步步进：

步短语依据入字典输出
10字典空#1 = 0(0,0)
211 不在字典#2 = 1(0,1)
3010=#1 在，01 不在#3 = 01(1,1)
4101=#2 在，10 不在#4 = 10(2,0)
501001=#3 在，010 不在#5 = 010(3,0)
6111=#2 在，11 不在，串读完#6 = 11(2,1)

切分：0 | 1 | 01 | 10 | 010 | 11；输出：(0,0) (0,1) (1,1) (2,0) (3,0) (2,1)。

码长：指针位数 = 0+1+2+2+3+3 = 11 bit，新字符 6 bit，合计 17 bit > 输入 11 bit。与例 4 同病：短串膨胀，字典尚未盈利。

L3 建模应用场景：你负责两种数据通道——（甲）一种濒危语言的田野录音转写文本，无人能给出可靠字母/词分布；（乙）一条工业传感器数据流，连续运行一年。候选方案：A. 拍脑袋先验 + Huffman；B. 两阶段"先估分布再 Huffman"；C. LZ。请为两个通道各选一个方案，并用本章的量（D(p‖q)、log₂ Cn、LZ 渐近性）论证，同时比较 B 与 C 的代价。
提示

问自己三件事：估分布的样本从哪来？数据是短有限批还是长流？方案 A 的罚款用什么量定价、会不会无界？

完整解答

通道甲（濒危语言文本）：选 B 或 C，坚决不选 A。A 的罚款是 D(p真‖q拍脑袋)，q 一旦给真实常见字符过低概率，罚款可无界（13.1 的教训）。B 的代价：先用样本估 p̂ 再 Huffman，冗余 ≈ D(p‖p̂)，样本量有限时这个量不可控且需两遍扫描、需把码表随文件传输。C 的代价：LZ 单遍在线、无需任何先验，短文本上有启动膨胀（例 4 的 62%），但对成书规模的文本，每符号码长已明显压向熵率。若文本量小，可用 13.2 的 NML/贝叶斯混合码，罚款 log₂ Cn 已知可控。结论：甲选 C（量大）或混合码（量小）。

通道乙（一年传感流）：选 C。这是 LZ 的主场：n 极大，启动成本被无限摊薄，每符号码长渐近收敛到熵率，且单遍在线天然适配流式；B 需要预设分布且工况漂移时 p̂ 过期，D(p新‖p̂旧) 持续出血。

B vs C 的代价总结：B 付的是"估计误差罚款 D(p‖p̂) + 码表开销 + 两遍扫描"，且分布漂移时持续付费；C 付的是"启动膨胀 + 每符号约 c log₂c/n 的收敛项"，随 n 单调消失。n 小且需精确可控 → 选统计路线（含 NML）；n 大或为流 → 选 LZ。

对着空气（或室友）说出这三句。说卡壳的那句，回去重读对应小节。

句1：这章解决什么问题？——
参考答案：第 5 章的最优码要求已知分布 p，但现实数据（文本、DNA、传感流）分布未知。本章回答：不知道分布还能不能压到极限、代价是多少。错用 q 的罚款恰为 D(p‖q)，通用编码就是把这个罚款压到最小的编码。
句2：核心机制是什么？——
参考答案：三条路线给"无知"定价并付款——minimax 路线用 NML 码付 log₂ C_n（最坏情况最优）；贝叶斯路线用混合码付 I(θ;Xⁿ)（先验平均最优）；LZ78 干脆不要模型，边读边建字典，用"旧短语+新字符"的输出格式渐近收敛到熵率；算术编码把分数码长落成可执行的比特流。
句3：它和前后章怎么分工？——
参考答案：Ch5 给已知分布的最优码，Ch12 用最大熵处理部分先验，本章处理"分布完全未知"的压缩；本章发现每条序列自带可压缩度，Ch14 把它抽象成不依赖任何概率的柯氏复杂度 K(x)；Ch15–17 则把单信源思想推广到多用户网络场景。
