# PGM 互动讲义编写规范（v1，固化自 chapter-03.html）

> 本规范是生产第 4 章及以后所有章节的唯一标准。照此文件 + `chapter-template.html` 即可产出与第 3 章同款、并满足"抗遗忘 + 建结构"两个教学目标的页面。
> **红线**：不得改动 chapter-01/02/03.html；style.css 只允许追加，不允许改写已有规则。

## 0. 两个教学目标（一切结构为它们服务）

1. **抗遗忘**：读者"看懂"不算数，必须反复被迫主动回忆。手段：回忆卡（flip-card）、概念卡（5 字段 tall flip-card）、分层习题（折叠答案）、自测题（quiz-block）、合上书挑战、间隔复习计划。
2. **建结构**：读者随时知道自己在哪、为什么学这一步。手段：position-bar（全书地图定位）、推导主线图（mermaid 因果链）、每节开头的"为什么需要它"、章末三句话复述框架。

## 3. 公式方案（与 ch3 完全一致，不用任何 JS 数学库）

- 行内/独立公式一律 HTML：下标 `X₁…Xₙ`、上标 `2¹⁰⁰` 用 Unicode 上下标字符；乘积连加用 `∏` `∑` 加 `<sub>`。
- 分数用三分结构：
  `<span class="frac"><span class="num-part">分子</span><span class="den-part">分母</span></span>`
- 独立公式放 `<div class="formula">`；变量用 `<span class="var">` 保持斜体。
- 数学符号用 Unicode：⊥（独立）、⊥̸（不独立，写 `⊥̸`）、⟹、∏、∑、∝、≈、≠、∈、𝒢/ℋ（图）、𝒳、φ/ψ（势函数）、Θ。

## 4. 教学法规范（每章固定板块与顺序）

### 4.1 章首四件套（顺序固定）
1. `position-bar`：一句话说清本章在主线上回答什么问题 + `map-inline` 全链路地图（前驱章 → **本章 .here** → 后继章，标注章号与一句话功能）。
2. `objectives`：4–6 条可检验的能力（"说出/写出/画出/手算/解释"），不写"理解/掌握"。
3. **推导主线图**（mermaid flowchart LR）：一条"为什么需要下一步"的**因果链**，不是知识点并列。每个节点是一个问题或一步机制，末尾落到"代价/遗留问题"（通向后续章节）。
4. 进入正文。

### 4.2 正文节（每节讲透一个"为什么"）
- 节标题即问题或结论（如"为什么需要 XX：从 YY 说起"），不写"XX 简介"。
- 节内顺序：动机/反例 → 定义（术语首现给英文）→ 最小完整例子 → 公式 → 直觉提炼（`.box.idea`）→ 常见误区（`.box.warning`）→ **回忆卡 2 张**（`.recall-zone`）。
- 每章至少 3 个带完整推导/手算步骤的例子，全部步骤写全，不跳步。
- 宁精不滥：一个概念讲不透宁可砍掉下一个概念。

### 4.3 章末五件套（顺序固定，全部强制）
1. **概念卡**（🃏，4–8 张 `.flip-card.tall`）：背面固定 5 字段，`.cc-k` 标签依次：
   `定义`（一句话）/ `解决问题`（它为什么存在）/ `直觉`（一句话比喻）/ `误区`（最常见的错误理解）/ `何时用`（在后续哪章/什么任务出现）。
2. **分层习题**（📝，用 `.exercise` + `<details>` 折叠答案）：
   - L1 概念辨析（`.ex-level.l1`，2 题）：判断/选择概念的边界；
   - L2 手算推导（`.ex-level.l2`，1–2 题）：必须能纸笔完成，答案写全步骤；
   - L3 建模应用（`.ex-level.l3`，1 题）：给一个现实场景，要求选模型、画图、写因子分解。
   - 每题先给"提示"再给"完整解答"（两个折叠或一个折叠内分段）。
3. **本章自测**（✍️，4–6 道 `.quiz-block`）：覆盖本章所有"毕业要求"，解析里必须写"为什么错"。
4. **三句话复述框架**（`.retell`）：固定三句骨架——
   句1「这章解决什么问题：____」；句2「核心机制是：____」；句3「它和前后章的分工是：____」。每句一个折叠，内含参考答案。
5. **复习计划**（`.review-plan` 表格）：按 1 / 3 / 7 / 15 天列出"复习哪几张卡/重做哪几题"，卡片用编号引用（如"概念卡 2、5 + 回忆 4.2-1"）。
6. **合上书挑战**（`.final-challenge`）：5–7 条凭记忆完成的任务，最后一条永远是"一句话回答本章的主线问题"。

## 5. 图示规范（mermaid，替代 ch3 的手写 SVG）

> 用户全局规则：示意/结构/流程图一律 **mermaid**，禁止 ASCII 图、禁止代码块画图。
> 从第 4 章起统一用 mermaid；ch1–3 的内联 SVG 属历史存量，不返工。

### 5.1 引入与初始化（每个含图页面必须原样使用）

```html
<script src="assets/mermaid.min.js"></script>
<script>
mermaid.initialize({
  startOnLoad: true,
  theme: "base",
  themeVariables: {
    primaryColor: "#e3edf7",
    primaryBorderColor: "#1d5f9e",
    primaryTextColor: "#1d5f9e",
    lineColor: "#5c554b",
    secondaryColor: "#fbeedd",
    tertiaryColor: "#f5f1e8",
    fontFamily: "-apple-system, PingFang SC, sans-serif",
    fontSize: "14px"
  },
  flowchart: { curve: "linear", htmlLabels: false }
});
</script>
```

### 5.2 画图约定
- 一律用 `flowchart`（LR/TB），节点文字带引号：`A["困难 D"]`；纯字母节点可直接 `D`。
- 有向边 `-->`；无向边 `---`；道德化新增边用虚线 `-.->` 或 `-.-` 并配 linkStyle 染红。
- 重点节点用 `classDef`（配色只允许取自 §2 的变量值）：
  `classDef hot fill:#fbeedd,stroke:#c4651f,stroke-width:2.5px,color:#c4651f;`
  `classDef danger fill:#fae9e7,stroke:#b03a2e,stroke-width:2.5px,color:#b03a2e;`
- 图必须包在 `<div class="figure"><div class="mermaid">…</div><div class="caption">图 N.k 一句话说明（指出该看什么）</div></div>`。
- mermaid 代码里禁用中文标点以外的特殊符号（避免解析失败）；标签含括号/逗号时必须整体加引号。
- 推导主线图放章首 `.figure`，方向 LR，节点 = 问题/机制，最后节点标 `.danger` 或 `.hot` 表示"代价/遗留问题"。

## 6. 文案与交互细节

- 中文写作；术语首次出现给英文原名（用 `.term`）：如 <span class="term">配分函数</span>（Partition Function）。
- 每节至少一次"承上启下"：开头一句"上一节给了 X，但它带出一个问题：Y"。
- 所有可交互元素必须无 JS 也可读：`<details>` 天然可折叠；quiz/flip 退化时文字仍在 DOM 中。
- emoji 只在约定位置使用：🎯 目标 / 💡 idea / ⚠️ warning / ✅ insight / 🧠 回忆 / 🃏 概念卡 / 📝 习题 / ✍️ 自测 / 📕 挑战 / 🔁 复习。
- 章间导航：上一章指真实文件；下一章未产出时 `<a href="index.html" class="next">…（待生成）</a>`，产出后改为真实文件。
- 页脚格式：`第N章 章名 · PGM 互动讲义 · 基于 Koller &amp; Friedman (2009)`。
