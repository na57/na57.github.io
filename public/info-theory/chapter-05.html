5.1从"能解码"到"立刻解码"：唯一可译码与前缀码

第 1 章例 1 里我们已经偷偷用过一个好码 {0, 10, 110, 111}，当时只说它"无歧义"。本章要把压缩做成工程，第一件事是问：码流里可没有空格，接收方拿到一串 0 和 1，凭什么知道在哪儿下刀？

例 1：一个会出事的码

给三符号信源配码：A→0，B→01，C→1。接收方收到 001，怎么切？

  • 切成 0, 0, 1 → A A C；
  • 切成 0, 01 → A B。

两种切法都合法——这个码根本没法用。毛病出在哪？A 的码字 0 恰好是 B 的码字 01 的前缀：看到开头的 0，你无法断定它是一个完整的 A，还是某个 B 的开头，只能干等后面的比特。

定义：一个码叫唯一可译码（Uniquely Decodable Code），如果任意码字串的拼接只有一种切分方式；叫前缀码（Prefix Code，也叫即时码 Instantaneous Code），如果没有任何码字是另一个码字的前缀。前缀码收到一个码字就能立刻宣布译码，不用回头看也不用向前等——这正是"立刻解码"。

例 2：前缀码长什么样

码 {0, 10, 110, 111}：0 不是 10、110、111 的前缀（它们都以 1 开头），10 不是 110、111 的前缀（第 3 位一个是 1 一个是 0……逐位查便知），两两检查全部通过。收到 0101100111 可以贪心切分：0｜10｜110｜0｜111，边走边判，看到完整码字立即落锤——即时可译。

前缀码有一个干净的几何形象：把二进制树画出来，每个码字是树上一个节点，"互不为前缀"等价于"所有码字都落在叶子位置，谁也不挡谁向下长的路"。5.2 节的 Kraft 不等式就靠这棵树数出来。

💡 关键一跃

唯一可译码比前缀码更宽（存在唯一可译但不是前缀的码，如 {0, 01}——看到 0 要等下一位才能判定）。但 5.2 节将证明：任何唯一可译码的码长集合，前缀码也能做到。既然即时译码更爽且最优性一分不亏，本章以后只谈前缀码。

⚠️ 常见误区

"不同符号给了不同码字就能解码"——错。单符号映射一一对应只保证单个码字不撞车，不保证拼接后可切分。例 1 的码 {0, 01, 1} 单符号层面完美，拼起来就是歧义。可译性是码流层面的性质，必须按"任意拼接"来检验。

5.2Kraft 不等式：码长集合的几何约束

上一节说前缀码的码字都坐在二叉树的叶子上。这带来一个硬约束：叶子们瓜分的"树荫"总量不能超过整棵树。把它写成数，就是本章第一个定理。

码树直觉：每个码字占一份子树

无限深的二叉树上，一个长为 l 的码字占据一个节点，它的后代子树占整棵树的"份额"是 2−l（每深一层减半）。前缀条件 = 任意两个码字的子树互不相交，所以所有份额加起来不能超过 1：

∑i 2−li ≤ 1　　（Kraft 不等式，Kraft Inequality）

例 3：两次手算，一次恰好占满、一次直接判死刑

码长 (1, 2, 3, 3)——就是例 2 的码 {0, 10, 110, 111}：

2⁻¹ + 2⁻² + 2⁻³ + 2⁻³ = 12 + 14 + 18 + 18 = 1　✓ 恰好占满（码树是满树，一片叶子都不浪费）

码长 (1, 2, 2, 3)——假设有人想给 4 个符号配这组长度：

2⁻¹ + 2⁻² + 2⁻² + 2⁻³ = 12 + 14 + 14 + 18 = 98 > 1　✗ 不可能存在这样的前缀码

不必真的去树上试——份额超支了，怎么摆都摆不下。Kraft 不等式把"能不能造"变成一个算术判定。

✅ 定理（Kraft）

(i) 任何前缀码满足 Σ2−li ≤ 1；更进一步，任何唯一可译码也满足同一不等式（McMillan 加强）。(ii) 反过来，任何满足 Σ2−li ≤ 1 的码长集合，都能构造出前缀码（按长度从小到大逐个往树上放即可）。合起来：谈最优码长时，前缀码与唯一可译码的可行域完全相同——限制在前缀码里找最优，一分不亏。这就是 5.1 节末尾那句话的兑现。

⚠️ 常见误区

"Σ2−li ≤ 1 说明这个码是前缀码"——方向反了。Kraft 约束的是码长集合，不是具体的码字分配。码 {0, 01, 011} 与 {0, 10, 110} 码长同为 (1,2,3)，Kraft 和同为 7/8 ≤ 1，但前者里 0 是 01 的前缀、01 是 011 的前缀，根本不是前缀码。满足不等式只保证"存在某个前缀码用这组长度"，不保证你手里这个码就是。

5.3最优码的界：L ≥ H，香农码 L < H+1

码长受 Kraft 约束，那在约束下"期望码长最小"能小到什么程度？这一节给出下界（熵 H）与第一个可达构造（香农码），两者只差不到 1 比特——极限问题至此基本被封口。

下界：用相对熵非负推 L ≥ H

设信源分布 p₁,…,pₘ，前缀码码长 l₁,…,lₘ，记 Kraft 和 c = Σ2−li ≤ 1，并定义辅助分布 ri = 2−li/c（它是合法分布：非负且和为 1）。由 ri 的定义取对数：

−log₂ ri = li − log₂ c　　即　　li = −log₂ ri + log₂ c

代入期望码长，一步一行：

L = Σi pili = Σi pi(−log₂ ri + log₂ c) = −Σi pi log₂ ri + log₂ c
L − H = Σi pi log₂ piri + log₂ 1c = D(p‖r) + log₂(1/c) ≥ 0

第一项 D(p‖r) ≥ 0 是第 2 章的相对熵非负；第二项 log₂(1/c) ≥ 0 因为 c ≤ 1。等号成立当且仅当两者同时为 0：r = p 且 c = 1，也就是每个 pi 恰好等于 2 的负整数幂（这种分布叫二进分布，dyadic）。第 1 章例 1 的 (1/2,1/4,1/8,1/8) 正是二进分布，所以那个码恰好打到 H = 1.75——现在你知道那不是巧合。

香农码：差不到 1 比特的构造

下界建议理想码长是 li = log₂(1/pi)，可惜它一般不是整数。香农码（Shannon Code）的做法是向上取整：

li = ⌈log₂(1/pi)⌉

合法性（满足 Kraft，故前缀码存在）：2−li ≤ pi，所以 Σ2−li ≤ Σpi = 1 ✓。性能：由 li < log₂(1/pi) + 1，取期望得

L = Σ pili < Σ pi(log₂(1/pi) + 1) = H + 1

合起来就是本章的中心不等式：H ≤ L最优 < H + 1。

例 4（全章主例）：p = (0.4, 0.2, 0.15, 0.15, 0.1) 的香农码

先算这个信源的熵（后面每一节都要拿它当标尺），各项摆开：

H = 0.4×1.3219 + 0.2×2.3219 + 2×(0.15×2.7370) + 0.1×3.3219
= 0.5288 + 0.4644 + 0.8211 + 0.3322 ≈ 2.146 比特

香农码长 ⌈log₂(1/p)⌉：0.4→2，0.2→3，0.15→3，0.15→3，0.1→4。期望码长：

L = 0.4×2 + 0.2×3 + 0.15×3 + 0.15×3 + 0.1×4 = 0.8 + 0.6 + 0.45 + 0.45 + 0.4 = 2.7 比特

检验中心不等式：2.146 ≤ 2.7 < 3.146 ✓。香农码合法但不惊艳——2.7 离 2.146 还有半比特多的缝。下一节 Huffman 把这个缝收到 0.054。

💡 关键一跃

L − H = D(p‖r) + log(1/c) 这个恒等式值得背下来：超出熵的每一比特都有名有姓——D(p‖r) 是"码长没按 log(1/p) 分配"的代价，log(1/c) 是"码树没占满"的代价。好码的设计就是让这两项同时归零。

⚠️ 常见误区

"香农码是最优码"——不是。它只是一个保证 L < H+1 的通用构造；对具体分布它可能相当平庸（例 4 里 0.15 的符号被取整顶到 3 比特，浪费近 0.27 比特/次）。真正的最优构造是下一节的 Huffman。香农码的价值在理论：它证明了"上取整"这一步最多赔 1 比特。

5.4Huffman 编码：贪心合并为何最优

上一节留下半比特的缝。Huffman 编码（Huffman Coding，1952）用一条简单到令人起疑的规则把它补上：反复把当前概率最小的两个节点合并成一个新节点，直到只剩根；再沿树回退赋 0/1。

为什么贪心是对的：两条引理

引理一：最优码中，概率最小的两个符号可以安排为码长最长、且互为兄弟（只差最后一位）。理由：若最小概率的符号没占最深叶子，把它和最深叶子交换，期望码长只会变小；同深的两个叶子互换标签不产生代价，所以可以让它俩当兄弟。引理二：把这两个兄弟合并成一个概率相加的新符号后，原问题的最优码 = 新问题的最优码再展开一步——问题规模缩小一，且代价只差一个与后续无关的常数。两条合起来：每一步合并两个最小者都不会把最优解弄丢，归纳到只剩一个节点时构造完成。贪心因此精确最优，而非近似。

例 5：主例 p = (0.4, 0.2, 0.15, 0.15, 0.1) 的完整构造

合并过程（每步取当前最小的两个）：

  1. 0.1 + 0.15 → 0.25（剩 0.4, 0.2, 0.15, 0.25）
  2. 0.15 + 0.2 → 0.35（剩 0.4, 0.25, 0.35）
  3. 0.25 + 0.35 → 0.6（剩 0.4, 0.6）
  4. 0.6 + 0.4 → 1.0（根）

回退赋码：根把 0 给 0.4、1 给 0.6；0.6 分出 10 给 0.35、11 给 0.25；0.35 分出 100 给 0.2、101 给 0.15；0.25 分出 110 给 0.15、111 给 0.1。

⚠️ 常见误区

"Huffman 最优 = 达到熵"——错。Huffman 是单符号无前缀码中的最优，定理只保证 H ≤ LHuffman < H + 1。例 5 的 0.054 比特缝，在单符号层面无解。要再逼近 H 只有两条路：把符号打包成块联合编码（块长 n 时浪费摊到 1/n），或者干脆放弃逐符号码——下一节的算术编码。

5.5算术编码：把整串消息映进一个子区间

单符号前缀码的浪费源于一个刚性约束：每个符号的码长必须是整数比特，而 log₂(1/p) 一般不是整数。唯一的出路是不给单个符号配码，给整条消息串配一个码——这就是算术编码（Arithmetic Coding）的想法：把消息映进 [0,1) 里层层细分的一个子区间，区间里随便挑一个二进制小数就是码字。

规则：按累计概率切区间，逐符号缩小

例 6（完整手算）：信源 p(A)=0.5，p(B)=0.25，p(C)=0.25，累计边界定为 A 占 [0, 0.5)、B 占 [0.5, 0.75)、C 占 [0.75, 1)。编码消息 "ABC"：

  1. 读 A：区间 [0,1) 中 A 的份额是 [0, 0.5) → 当前区间 [0, 0.5)；
  2. 读 B：把 [0, 0.5)（宽 0.5）按同样比例切：A[0, 0.25)、B[0.25, 0.375)、C[0.375, 0.5) → 当前区间 [0.25, 0.375)；
  3. 读 C：把 [0.25, 0.375)（宽 0.125）再切：A[0.25, 0.3125)、B[0.3125, 0.34375)、C[0.34375, 0.375) → 最终区间 [0.34375, 0.375)。

取码：在最终区间内找二进制展开最短的数。端点 0.34375 = 0.01011₂、0.375 = 0.011₂，取 0.010111₂ = 0.359375，确实落在 [0.34375, 0.375) 内——码字就是小数点后的 "010111"，共 6 比特。对照理想长度：消息概率 = 0.5×0.25×0.25 = 1/32，−log₂(1/32) = 5 比特，只多 1 比特；一般定理保证算术编码每条消息 ≤ 理想 + 2 比特，摊到 n 个符号上每符号浪费 ≤ 2/n → 0。

💡 关键一跃

盯住表格最后一列：区间宽度 = 消息的概率，所以码长 ≈ −log₂ 宽度 = −log₂(消息概率) = 消息的自信息。前缀码只能把"码长 = 自信息"凑到整数位，算术编码把它做到了分数比特精度——这就是它能贴着 H 走的全部原因。

⚠️ 常见误区

"算术编码是一种更聪明的前缀码"——不是。它不是逐符号码，码流无法按符号切开：6 比特的 "010111" 里找不出哪几位属于 A。这也意味着两件事：其一，解码必须从头顺序进行（随机访问某个符号要额外设计）；其二，切分区间需要已知分布——分布未知时的自适应版本与通用编码，是 Ch13 的课题。

🃏概念卡：本章概念的一分钟画像

翻面前先自问：这个概念我能用一句话讲清楚吗？

概念卡 1
唯一可译码（Uniquely Decodable Code）
点击翻面 →
定义任意码字串的拼接只有唯一切分方式的码。
解决问题码流无分隔符，保证接收方至少"原则上"能还原消息。
直觉一篇没有空格但绝不会读岔的文章。
误区以为"单符号一一对应"就够了——拼接歧义才是杀手（{0,01,1} 收到 001）。
何时用Ch5 定理陈述的最宽可行域；Kraft–McMillan 说明它与前缀码同码长。
概念卡 2
前缀码（Prefix Code）
点击翻面 →
定义没有任何码字是另一个码字前缀的码（即时码）。
解决问题收到完整码字立即译码，零等待、零回看。
直觉码字全坐在二叉树叶子上的码，谁也不挡谁的路。
误区以为限制前缀会损失最优性——Kraft–McMillan 证明不损失。
何时用Ch5 全部构造（香农/Huffman）的落点；Ch7 信源信道分离里压缩模块的标准形态。
概念卡 3
Kraft 不等式（Kraft Inequality）
点击翻面 →
定义前缀码（乃至任何唯一可译码）的码长满足 Σ2^{−lᵢ} ≤ 1；反之满足即可造前缀码。
解决问题把"能不能造码"变成一次算术判定，并圈定最优化的可行域。
直觉每个码字认领一份 2^{−l} 的树荫，总树荫不超过整棵树。
误区拿它判定"这个码是不是前缀码"——它只约束码长集合，不验具体码字。
何时用Ch5 推 L ≥ H 的约束条件；Ch6 与赌博赔率对偶的桥梁。
概念卡 4
期望码长与最优码（Expected Length / Optimal Code）
点击翻面 →
定义L = Σpᵢlᵢ；最优码是 Kraft 约束下使 L 最小的前缀码，满足 H ≤ L* < H+1。
解决问题把"压缩极限"翻译成约束优化问题，并给出上下 1 比特以内的封口。
直觉L − H = D(p‖r) + log(1/c)：浪费 = 码长配错 + 树没占满。
误区以为 L 总能等于 H——仅当分布为二进分布（pᵢ 全为 2 的负幂）。
何时用Ch10 率失真把它推广到允许失真的 R(D)；Ch6 换成赛马赔率语言重述。
概念卡 5
Huffman 编码（Huffman Coding）
点击翻面 →
定义反复合并两个最小概率节点构造码树的算法；产出单符号最优前缀码。
解决问题给定分布，机械地造出期望码长最小的逐符号无前缀码。
直觉冷门符号先抱团沉入树底，热门符号留在浅处用短码。
误区"最优 = 达到 H"——单符号层面仍受整数比特约束，最多浪费 1 比特。
何时用实际压缩器的内核（ZIP、JPEG 的熵编码级）；Ch13 自适应版本处理未知分布。
概念卡 6
算术编码（Arithmetic Coding）
点击翻面 →
定义把整条消息映为 [0,1) 的子区间（宽度=消息概率），取区间内短二进制小数为码字。
解决问题绕开"每符号整数比特"的刚性，把码长做到分数精度，随串长逼近 H。
直觉码长 ≈ −log(区间宽) = 消息自信息——自信息即码长的精确兑现。
误区当成逐符号码——码流不能按符号切开，且需要已知分布。
何时用现代压缩标准（H.264/265 的 CABAC）；Ch13 通用编码的主力引擎。

📝分层习题

L1 概念辨析判断对错：任何唯一可译码的平均码长都不小于同分布下任何前缀码的平均码长。说明理由。
提示

Kraft 不等式对哪两类码成立？两类码的"可行码长集合"是不是同一个？

完整解答
错（方向不对）：真相是两者可行域相同。Kraft–McMillan 定理说唯一可译码也满足 Σ2^{−lᵢ} ≤ 1，而任何满足该式的码长都能造成前缀码——所以给定任意唯一可译码，存在同码长的前缀码，平均码长一样。结论应改为：唯一可译码的最优值与前缀码的最优值相等，"扩大到唯一可译码里找更短的码"没有油水。这正是本章只在前缀码里做最优化的合法性来源。
L1 概念辨析判断对错：Huffman 码的平均码长等于信源熵。
提示

回忆主例 p=(0.4, 0.2, 0.15, 0.15, 0.1) 的两个数；再想什么条件下等号才成立。

完整解答
错。主例中 Huffman 码 L = 2.2 比特，而 H ≈ 2.146 比特，差 0.054。定理只保证 H ≤ LHuffman < H + 1；等号成立当且仅当分布是二进分布（所有 pᵢ 为 2 的负整数幂），此时 D(p‖r) = 0 且 Kraft 取等。一般分布下 Huffman 是"单符号前缀码中的最优"，不是"达到熵"。
L2 手算推导对信源 p = (0.5, 0.3, 0.2) 构造 Huffman 码，计算期望码长 L，并与熵 H 比较（log₂(1/0.3) ≈ 1.737，log₂(1/0.2) ≈ 2.322）。
提示

只有三个符号，合并一次再合并一次就到根；熵按 −Σp log p 逐项算。

完整解答

构造：合并最小的 0.2 + 0.3 = 0.5；再合并 0.5 + 0.5 = 1.0。回退赋码：0.5 → 0；0.3 → 10；0.2 → 11。

期望码长：L = 0.5×1 + 0.3×2 + 0.2×2 = 0.5 + 0.6 + 0.4 = 1.5 比特。

熵：H = 0.5×1 + 0.3×1.737 + 0.2×2.322 = 0.5 + 0.5211 + 0.4644 ≈ 1.486 比特。

比较：1.486 ≤ 1.5 < 2.486 ✓。浪费 0.014 比特——0.3 与 0.2 不是 2 的负幂，单符号编码的小缝。

L2 手算推导信源 p(A)=0.5, p(B)=0.25, p(C)=0.25（边界 A[0,0.5)、B[0.5,0.75)、C[0.75,1)）。用算术编码对消息 "CA" 编码：写出每步区间、最终码字与码长，并对照理想长度。
提示

先取 C 的区间，再在其中按比例切出 A 的份额；码字取区间内二进制展开最短的数。

完整解答

第 1 符号 C：[0, 1) 中 C 占 [0.75, 1) → 当前区间 [0.75, 1)（宽 0.25）。

第 2 符号 A：把 [0.75, 1) 按比例切，A 占前一半：[0.75, 0.75+0.125) = [0.75, 0.875)（宽 0.125）。

取码：0.8125 = 0.1101₂ ∈ [0.75, 0.875) ✓，码字 "1101"，共 4 比特。（检验：0.75 = 0.11₂、0.875 = 0.111₂，0.1101 在两者之间。）

理想长度：消息概率 = 0.25×0.5 = 1/8，−log₂(1/8) = 3 比特。实耗 4 比特 = 理想 + 1，在"≤ 理想 + 2"的保障之内。

L3 建模应用工厂传感器每秒上报一次状态：正常(0.7) / 预警(0.2) / 故障(0.1)，各秒近似独立，需无差错存档一年（约 3.15×10⁷ 秒）。(a) 定长码每符号多少比特？(b) Huffman 码每符号多少比特？(c) 熵是多少？(d) 若把两秒联合编码，为什么能更逼近 H？
提示

(a) 3 个状态定长要几位？(b) 合并 0.1+0.2。(c) log₂(1/0.7)≈0.5146，log₂(1/0.2)≈2.3219，log₂(1/0.1)≈3.3219。(d) 想单符号编码那 ≤1 比特的浪费摊到几个符号上。

完整解答

(a) 3 个状态定长需 ⌈log₂3⌉ = 2 比特/符号，一年约 6.3×10⁷ 比特。

(b) Huffman：合并 0.1 + 0.2 = 0.3，再 0.3 + 0.7 = 1.0。赋码：0.7 → 0；0.2 → 10；0.1 → 11，码长 (1, 2, 2)。L = 0.7×1 + 0.2×2 + 0.1×2 = 0.7 + 0.4 + 0.2 = 1.3 比特/符号，一年约 4.1×10⁷ 比特，比定长省 35%。

(c) H = 0.7×0.5146 + 0.2×2.3219 + 0.1×3.3219 = 0.3602 + 0.4644 + 0.3322 ≈ 1.157 比特。

(d) 单符号前缀码受整数比特约束，定理只保证浪费 < 1 比特/符号（此处 1.3 − 1.157 ≈ 0.143）。把 n 个符号联合成一个"超级符号"（分布为联合分布，共 3ⁿ 种）再做 Huffman 或算术编码，浪费仍 < 1 比特但摊到 n 个原始符号上，每符号浪费 < 1/n → 0。两秒联合（9 个状态）已能把每符号码长压到 H + 0.5 以内，且分布已知，正是本章主线问题"任意逼近 H"的工程答案。
